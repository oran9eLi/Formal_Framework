# Formal Framework 整机测试方案

## 1. 测试目标

本方案用于 `STM32F407 + HAL + FreeRTOS + ATK-MD0700 + LoRa + SD + 树莓派 USART6 + 四路电机控制` 整机联调。

整机测试不是只看“能亮、能跑”，而是确认以下闭环都真实成立：

1. 固件可以全量编译、烧录、启动，无异常复位。
2. 传感器数据进入 Framework topic，并被显示、通信、日志读取到。
3. 屏幕本地页面、远端页面、日志页、告警页、电机页显示一致。
4. LoRa 能发送本机遥测，也能接收远端遥测并同步显示。
5. 树莓派能通过 USART6 下发 MAVLink 电机命令，并收到 ACK。
6. 电机控制只能通过 Control 层输出，急停、低压保护、降落拒绝非零油门等安全规则有效。
7. SD 日志长期写入不阻塞采集、显示和通信任务。
8. 运行数小时后任务栈、heap、队列、通信统计无明显劣化。

## 2. 测试前准备

### 2.1 工具和设备

| 类型 | 内容 |
|---|---|
| 编译烧录 | Keil MDK-ARM v5、ST-Link、当前工程 `MDK-ARM/formal_framework.uvprojx` |
| 串口调试 | USB-TTL 或 ST-Link VCP，查看 USART1 调试输出 |
| 电源 | 可限流直流电源，或带保护的电池供电方案 |
| 通信 | 两套 LoRa/E22 模块，或本机 + 远端显示端 |
| 树莓派 | UART 使能，安装 `pymavlink`，串口 115200 8N1 |
| 存储 | FAT32 格式 SD 卡 |
| 电机测试 | ESC、电机、示波器或逻辑分析仪；初期必须拆桨 |

### 2.2 安全前置

电机相关测试必须按这个顺序走：

1. 第一轮只接示波器或逻辑分析仪，不接电机。
2. 第二轮接 ESC 和电机，但必须拆桨。
3. 第三轮低油门短时点动，确认方向和急停。
4. 未完成急停验证前，不允许做高油门和一键起飞测试。
5. 树莓派、STM32、LoRa、电源必须共地；串口电平必须是 3.3V TTL。

## 3. 固件构建与烧录

### 3.1 全量编译

打开：

```text
MDK-ARM/formal_framework.uvprojx
```

执行 `Rebuild All`，验收标准：

```text
0 Error(s), 0 Warning(s)
```

发布或正式测试时，`hex`、`axf`、`map`、构建日志和 `MANIFEST.md` 必须来自同一次构建。

### 3.2 调试开关建议

整机联调阶段建议在 `Debug/Inc/debug_config.h` 打开：

```c
#define DEBUG_BOOT_LOG_ENABLE              1U
#define DEBUG_STACK_MONITOR_ENABLE         1U
#define DEBUG_GNSS_MONITOR_ENABLE          1U
#define DEBUG_IMU_MONITOR_ENABLE           1U
#define DEBUG_BARO_MONITOR_ENABLE          1U
#define DEBUG_POWER_MONITOR_ENABLE         1U
#define DEBUG_LORA_MONITOR_ENABLE          1U
#define DEBUG_ALARM_MONITOR_ENABLE         1U
#define DEBUG_STORAGE_MONITOR_ENABLE       1U
```

如果串口输出太多，先保留 `BOOT + STACK + 当前被测模块`，逐项打开。

## 4. 上电冒烟测试

### 4.1 不插外设上电

目的：确认主控、时钟、RTOS、屏幕和基础任务可以启动。

步骤：

1. 只接 STM32 主板、屏幕、调试串口。
2. 不插 SD、LoRa、GNSS、树莓派和电机。
3. 上电观察屏幕是否进入主界面。
4. 串口观察 boot log、heap、stack、模块状态。

验收：

| 项目 | 通过标准 |
|---|---|
| 启动 | 不 HardFault，不反复复位 |
| 屏幕 | 页面能显示，切页不卡死 |
| 任务 | sensor、estimator、health、comm、display、storage、debug 等任务存在 |
| 栈 | 各任务 `min_free` 保留余量，不出现栈溢出 |
| heap | `heap_peak_used` 不超过配置上限，建议低于 75% |
| 外设缺席 | 缺席模块显示 OFFLINE/缺席，不阻塞系统启动 |

### 4.2 插全外设上电

目的：确认整机上电初始化顺序正常。

步骤：

1. 插入 GNSS、IMU、BME280/气压计、电源采样、LoRa、SD、屏幕。
2. 树莓派先不发控制命令，只连线。
3. 上电观察 3 分钟。

验收：

| 模块 | 通过标准 |
|---|---|
| GNSS | 能输出 NMEA 解析状态；室外或有信号时 fix、星数、经纬度更新 |
| IMU | 姿态角或加速度随板子姿态变化 |
| Baro | 气压、温度、气压高度有合理数值 |
| Power | 电压、电流、电量百分比显示稳定，无大幅跳变 |
| LoRa | 已插入时本机 LoRa 状态正常；未插入时不影响其他模块 |
| SD | 插卡后能创建或追加 CSV 日志 |
| 屏幕 | 页面刷新流畅，切页后数据继续更新 |

## 5. 传感器链路测试

### 5.1 GNSS

步骤：

1. 将设备放到 GNSS 信号较好的位置。
2. 观察串口 `GNSS` 输出和屏幕定位页。
3. 记录从上电到首次有效定位的时间。
4. 拔掉 GNSS 或遮挡天线，观察超时和恢复。

验收：

| 场景 | 通过标准 |
|---|---|
| 有信号 | fix 状态、星数、经纬度、地速或时间持续更新 |
| 无信号 | 状态进入 DEGRADED/OFFLINE，不阻塞系统 |
| 恢复 | 信号恢复后状态回到 ONLINE 或正常可用状态 |
| 显示一致 | 串口、屏幕、LoRa 发出的导航数据来自同一条快照链路 |

### 5.2 IMU

步骤：

1. 静置设备 30 秒，观察姿态是否稳定。
2. 手动绕 roll、pitch、yaw 三个方向缓慢转动。
3. 观察屏幕姿态页和 `ATT` 调试输出。

验收：

| 项目 | 通过标准 |
|---|---|
| 静态 | 姿态角不大幅漂移 |
| 方向 | roll/pitch/yaw 方向符合项目约定 |
| 数据年龄 | age 持续刷新，不长时间 stale |
| 异常 | I2C 错误不会导致显示卡死或任务阻塞 |

### 5.3 气压计和电源

步骤：

1. 观察温度、气压、气压高度、垂直速度。
2. 改变供电电压或使用不同电池档位，观察电压、电量和低压标志。
3. 快速插拔传感器或模拟读失败，观察状态恢复。

验收：

| 项目 | 通过标准 |
|---|---|
| Baro | 温度、气压在合理范围，显示无明显跳变 |
| Power | 电压一位小数显示稳定，低压标志符合阈值 |
| 状态 | 断线、恢复、数据过期能被 Health 检测 |

## 6. 屏幕和业务页面测试

步骤：

1. 逐页切换：自检页、定位页、姿态页、环境/电池页、日志页、告警页、电机页。
2. 本地模式下确认页面显示本机数据。
3. 远端模式下确认页面显示 LoRa 接收到的远端数据。
4. 制造告警，例如拔 LoRa、拔 GNSS、模拟低压，观察告警页。
5. 连续切页 5 分钟，确认无卡死、无花屏、无明显刷新延迟。

验收：

| 项目 | 通过标准 |
|---|---|
| 数据来源 | 本地/远端切换后显示来源正确 |
| 电机页 | 本机电机页能显示 Control 输出 |
| 告警页 | 活动告警最多 16 行滚动显示，最高告警和完整表一致 |
| 日志页 | 新日志增量出现，不重复刷屏 |
| 性能 | 切页立即刷新，不影响 sensor 和 comm 周期 |

## 7. LoRa 整机通信测试

### 7.1 本机发送和远端显示

步骤：

1. 准备两套设备：A 作为本机，B 作为远端显示端。
2. A、B 都插 LoRa，并确认频点、空速、串口参数一致。
3. A 上电后观察 B 是否收到 A 的导航、姿态、电池、告警、日志、电机数据。
4. 在 A 上产生日志和告警，观察 B 是否同步。

验收：

| 数据 | 通过标准 |
|---|---|
| Heartbeat | 远端能判断对端在线 |
| GNSS/姿态 | 远端页面持续更新 |
| 电池/环境 | 电压、温度、气压等能同步 |
| 告警 | `ALRMHI/ALRMMSK/TUNNEL 0x8001` 信息显示完整 |
| 日志 | `LOGSYNC` 增量同步，不重复、不丢关键变化 |
| 电机 | `MOTOR12/MOTOR34/SERVO_OUTPUT_RAW` 能在远端看到 |

### 7.2 LoRa 热插拔

步骤：

1. 上电前不插 LoRa，启动后观察状态。
2. 运行中插入 LoRa，观察状态变正常并恢复发送。
3. 运行中拔出 LoRa，观察停止发送并显示缺席。
4. 重复插拔 10 次。

验收：

| 场景 | 通过标准 |
|---|---|
| 上电未插 | 系统正常启动，LoRa 缺席不阻塞 |
| 运行插入 | 自动初始化，恢复发送 |
| 运行拔出 | 停发，不死等，不影响显示/传感器 |
| 重复插拔 | 不 HardFault，不出现永久忙状态 |

## 8. 树莓派 USART6 下行控制测试

### 8.1 接线和参数

| 项目 | 配置 |
|---|---|
| USART | USART6 |
| STM32 TX | PC6 |
| STM32 RX | PC7 |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 电平 | 3.3V TTL |

接线：

```text
树莓派 TX -> STM32 PC7(USART6_RX)
树莓派 RX <- STM32 PC6(USART6_TX)
GND       <-> GND
```

### 8.2 下发四路油门

树莓派发送 `COMMAND_LONG(76)`：

| 字段 | 值 |
|---|---|
| source_system | 250 |
| source_component | 193 |
| target_system | 0 |
| target_component | 0 |
| command | 31011 |
| param1..param4 | 0.0..100.0 |

测试用例：

| 用例 | 输入 | 通过标准 |
|---|---|---|
| 全 0 | 0,0,0,0 | 四路目标为 0，ACK accepted |
| 全 50 | 50,50,50,50 | 四路目标保持 50%，电机页显示 50 |
| 独立油门 | 10,20,30,40 | 四路分别显示对应百分比 |
| 越界 | -1 或 101 | 拒绝，ACK denied，不改变旧目标 |
| 单次保持 | 只发一次 50 | 目标锁存，不要求持续重发 |
| 本机覆盖 | 拖动本机滑条 | 本机新目标覆盖树莓派旧目标 |
| 树莓派再覆盖 | 再发 30 | 树莓派新目标覆盖本机旧目标 |

### 8.3 急停

树莓派发送：

| 字段 | 值 |
|---|---|
| command | 31090 |
| param1..param7 | 0 |

验收：

1. 四路目标立即清零。
2. ESC 状态退回未解锁或安全态。
3. ACK 返回 accepted。
4. 急停锁存后，再发非零油门应被拒绝或临时拒绝。
5. 复位或恢复逻辑前，不允许绕过 Control 层直接恢复输出。

## 9. 电机和 PWM 输出测试

### 9.1 不接电机，只测 PWM

步骤：

1. 使用示波器或逻辑分析仪测四路 PWM。
2. 分别设置 0%、50%、100%。
3. 观察脉宽。

验收：

| 油门 | 期望脉宽 |
|---:|---:|
| 0% | 1000 us |
| 50% | 1500 us |
| 100% | 2000 us |

### 9.2 接 ESC 和电机，拆桨测试

步骤：

1. 拆桨。
2. 先 0%，再 5%、10%、20% 逐步增加。
3. 测试四路方向和响应。
4. 按急停，确认立即停止。

验收：

| 项目 | 通过标准 |
|---|---|
| 四路独立 | 任一路变化不误改其他路 |
| 急停 | 任意油门下能立即归零 |
| 低压保护 | 低压时禁止继续升油门或触发停机策略 |
| 降落保护 | 一键降落期间拒绝非零油门，继续降到 0 |

### 9.3 一键起飞和降落

只在拆桨或固定测试台上做。

| 用例 | 通过标准 |
|---|---|
| 一键起飞 | 四路从当前值线性升到 60%，约 6000 ms |
| 起飞中拖滑条 | 取消起飞斜坡，滑条目标生效 |
| 一键降落 | 四路从当前值线性降到 0%，约 8000 ms |
| 降落中给非零 | 拒绝非零油门，继续降落 |
| 降落中急停 | 清除斜坡，四路立即 0 |

## 10. SD 日志测试

步骤：

1. 插入 FAT32 SD 卡。
2. 上电运行 10 分钟。
3. 观察 `SENSOR.CSV`、`ERROR.CSV` 是否创建和增长。
4. 运行中拔卡，再插回，观察错误记录和恢复。
5. 长稳测试后导出 CSV 检查时间戳连续性。

验收：

| 项目 | 通过标准 |
|---|---|
| 写入 | 数据行周期写入，不空文件 |
| 错误 | 传感器/通信/存储错误进入错误日志 |
| 性能 | SD 写入不导致屏幕卡死或采集丢周期 |
| 拔插 | 拔卡有错误记录，插回可恢复或至少不影响主系统 |

## 11. 故障注入测试

| 故障 | 操作 | 通过标准 |
|---|---|---|
| GNSS 断开 | 拔 GNSS 或遮挡信号 | 超时后 OFFLINE/DEGRADED，恢复后 ONLINE |
| IMU 断开 | 断开 I2C 设备 | 不阻塞总线，状态异常可见 |
| Baro 断开 | 断开气压计 | 环境数据 stale，告警或状态更新 |
| LoRa 拔出 | 运行中拔模块 | 停发，显示缺席，插回恢复 |
| SD 拔出 | 写日志时拔卡 | 记录错误，不拖死系统 |
| 树莓派乱帧 | 发送错误 MAVLink 或 JSON | 解析失败计数增加，不执行命令 |
| 树莓派越权 | `source_system=0` 或等于本机 sysid | 命令被忽略或拒绝 |
| 电机越界 | 下发 -1%/101% | 拒绝，不改变旧目标 |
| 低压 | 降低供电或模拟低压 | 告警出现，电机保护生效 |

## 12. 长时间稳定性测试

### 12.1 2 小时联调

适合每天开发结束前执行。

步骤：

1. 插全外设。
2. LoRa 两端互通。
3. SD 开启记录。
4. 树莓派每 30 秒发送一次安全油门命令，例如全 0 或低油门。
5. 每 10 分钟切换一次屏幕页面。

通过标准：

1. 不复位、不 HardFault。
2. LoRa、SD、屏幕、传感器仍持续更新。
3. `heap_min` 不持续下降。
4. 任务 `min_free` 不逼近 0。
5. 错误计数没有持续快速增加。

### 12.2 24 小时老化

正式验收前执行。

步骤：

1. 电机不接桨，必要时不接电机只测 PWM。
2. 插全传感器、LoRa、SD。
3. 每小时记录一次串口资源统计。
4. 结束后导出 SD 日志，检查数据连续性和异常点。

通过标准：

| 项目 | 标准 |
|---|---|
| 稳定性 | 24 小时无异常复位 |
| 内存 | heap 和栈水位稳定 |
| 通信 | LoRa 发送统计持续增长，失败率可解释 |
| 存储 | CSV 可打开，时间戳连续，无大量空行 |
| UI | 屏幕仍可切页和刷新 |

## 14. 判定规则

满足以下条件，才建议认为整机测试通过：

1. 全量编译 `0 Error(s), 0 Warning(s)`。
2. 冒烟、传感器、显示、LoRa、树莓派下行、SD、电机安全全部通过。
3. 所有故障注入不会导致系统卡死、HardFault 或不可恢复异常。
4. 至少完成 2 小时全外设联调。
5. 正式交付前完成 24 小时老化。
6. 所有失败项都记录到 `Development_Guide/Change_History/` 或问题台账，不能口头跳过。
