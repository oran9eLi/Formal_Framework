### 1.3 全局产品与开发约束

1. **学生主动操作。** 实验由学生发起、调整、停止和恢复；操作形成“操作—观察—比较—解释”的闭环。自动执行采集、协议处理、参数校验和保护，不替学生自动配对、选信道或开始实验。
2. **屏幕精简直接。** 屏幕只保留数据、单位、状态、操作对象、参数、按钮、短结果和必要导航。原理、完整步骤、故障排查说明及长篇解释放入实验手册；不新增欢迎语、重复标题和说明型页面。
3. **资源开销可控。** 每项新增能力核算控件、缓冲、刷新面积、频率及执行耗时；采用固定容量、局部更新，避免装饰动画和无变化的整页刷新。
4. **配置可在设备上完成。** 通信地址、信道等已确认的课堂配置提供本机操作入口和实际生效反馈，多台设备使用同一份固件，无需为分组或解决地址冲突逐台改源码、重建和烧录。
5. **保护自动执行。** 低压闭锁、异常输出撤收、数据过期、看门狗及已验证的外设恢复持续工作。学生操作经过统一校验；页面冻结、通信停止或配置失败不影响本机保护。
6. **以减少新增范围控制开发量。** 优先取消尚未实现的复杂功能，现有底层按需保留；必要的接口收缩和布局调整集中完成。隐藏按钮不能代替修复仍可触达的缺陷，也不为“精简”启动无关的大规模重构。

## 3. 界面与文字改版

### 3.1 顶部区域

确认移除以下整个品牌组合：

- 左上角 Logo 图片。
- “东创大为”。
- “CNS 飞控系统”。
- 与当前页面标题重复、无助于实验判断的装饰性说明，例如重复的系统名称。

保留并重新安排：当前页面名称、必要节点标识、时间信息、告警提示及二级页面返回入口。取消顶部全局 `local / remote` 切换；常用设备标识采用简短的 `Node 01` 等形式，完整产品 ID 放设备信息页。时间和时长名称必须对应真实数据来源，不能将开机时长误称为实际飞行时长。

### 3.2 语言规则

| 内容 | 目标口径 |
|---|---|
| 六个主要页面名称 | 保留“自检、飞行、姿态、定位、电机、告警” |
| 数据来源标识 | 需要区分时使用小写 `local`、`remote`；不再提供全局远端模式 |
| 事件日志标题 | `Event Log` |
| 当前活动告警摘要 | `Active Alarms` |
| 开机相对时间 | `Uptime` |
| 日志严重度 | `INFO`、`WARN`、`ERROR`，颜色与文字同时表达 |
| 数据状态 | 使用一致的 `STALE`、`N/A`、`FROZEN` 等短标签 |
| 二级诊断术语 | 可使用 `Raw`、`Decoded`、`Messages`、`RX`、`TX` |
| 操作按钮、单位和关键提示 | 保持易懂；优先精简，保留必要的操作对象、限制及失败原因 |

英文用于短标签与事件反馈；长篇原理、步骤和说明移入实验手册，不通过翻译成长英文继续占屏。按钮名称与日志事件必须指向同一动作，不能按钮写“同步升速”，日志却写“一键起飞”。

### 3.3 页面空间

- **自检页保留模块状态灯/状态网格**，用于集中判断设备状态。
- 飞行、姿态、定位、电机等页面移除重复模块状态侧栏，将空间交给数据、实验操作和日志。
- 告警页现有主体为完整告警表，继续以告警详情为主，不新增重复模块灯。
- 一般实验概览保留内容区与 `Event Log`；Raw 帧、字段表、曲线等二级页面可以使用全宽内容区。
- 日志采用底部最近 3 条静态摘要，完整历史集中二级页；不使用循环滚动。历史是有限容量，不等同于完整运行日志归档。
- 全宽页面仍保留当前对象、关键告警和返回入口；需要本机急停的控制场景保持急停可达。
- 不在每页重复铺设系统概况，不通过删除必要单位、有效性或拒绝原因来节省空间。

### 3.4 自检、告警与日志的职责

当前自检右侧“自检汇总”实际来自活动告警表，与告警页共享数据；它不是事件历史。

| 区域 | 显示内容 | 更新规则 |
|---|---|---|
| 自检模块网格 | 当前模块状态、启动检查结果 | 按模块事实更新，区分 STARTING/ONLINE/DEGRADED/OFFLINE/FAILED |
| 自检 `Active Alarms` | 当前尚未解除的主要告警摘要 | 告警出现或解除时更新 |
| 告警页 | 完整活动告警、原因、时间和对象 | 与自检摘要使用同一可信数据源 |
| 各页 `Event Log` | 本机已发生的状态变化与操作事件 | 同一事件源的不同视图，页面刷新不新增事件；不镜像对端完整日志 |
| 二级事件历史 | 更完整的事件浏览、筛选及详情 | 固定容量；与活动告警状态分开 |

活动告警解除后可从当前列表消失，同时留下 raised/cleared 历史。清除当前日志视图不等于清除告警，也不删除 SD 记录。

## 4. 一级与二级页面结构

以下是已确认方向下的页面划分，具体按钮位置、每页字段数量和刷新率在实现时按 800×480 实屏验证收敛。

| 一级入口 | 一级主要内容 | 二级页面目标 |
|---|---|---|
| 自检 | 模块状态网格、活动告警摘要 | 模块详情、故障原因、运行诊断 |
| 飞行 | 保留概览入口，集中呈现电源、环境和实验概况 | 电源实验、环境实验、实验统计 |
| 姿态 | 姿态仪、角度、有效性、校准/零位操作、日志 | 原始 IMU、校准详情、姿态曲线 |
| 定位 | fix、卫星数、坐标、海拔、速度、质量和日志 | 定位质量、漂移实验、原始 NMEA |
| 电机 | 四路目标/输出/PWM、模式、过程状态、操作及日志 | 单路控制、目标与输出对比、实验参数 |
| 告警 | 完整活动告警与原因 | 故障详情、事件历史 |
| 现有连接/通信入口 | 本机通信配置、收发概况与实验操作 | 远端数据（含对端选择）、MAVLink Inspector、串口实验 |

上述六个主要页面始终呈现本机数据；远端数据只进入通信下的一个二级页，不为各本机实验页新增远端版本。模块、故障和运行诊断合并到 Diagnostics；曲线等尚待决策，不能机械地把每个功能名称都做成独立页面。

### 4.1 导航与状态规则

- 一级页面之间可直接切换，二级页面能一键返回所属一级页面；本轮采用两层结构。
- 对端选择仅作用于远端数据页及明确选择该来源的诊断视图；切换对端不改变本机主页面的数据来源。
- 远端数据页只读；`本机急停`始终指向本机，不因当前查看对象改变作用对象。
- 切页、返回、冻结显示均不能隐式修改油门、校准状态、通信参数或实验参数。
- `FROZEN` 只冻结观察内容；采集、控制、告警、保护和事件记录继续运行。
- 曲线、统计、捕获记录均绑定数据源与实验会话，避免切换节点后混合不同设备的数据。

### 4.2 远端数据页的最小范围

- 对端身份、在线状态和距上次接收的时间。
- 当前选定实验的数据，例如姿态、定位或环境；不强求全部数据域同时存在。
- 接收帧数、接收频率、错误及丢帧估计，统计名称与实际计算含义一致。
- 选择对端、选择查看的数据及暂停观察；未发送/无有效值显示 `N/A`，断流显示 `STALE`，暂停显示 `FROZEN`。
- 本机观察到的连接、超时和恢复事件；不拉取对方完整事件日志或历史记录。

选择查看内容不隐式改变对方发送设置。发送内容在发送端由学生选择；V1.0 不新增远程订阅、自动补齐数据域或自动补发历史的协议。

## 5. 教学数据与可操作点

### 5.1 基础功能与进阶目标

| 页面/实验 | 基础内容与操作 | 进阶目标 |
|---|---|---|
| 电源 | 两路电压、电流、估算电量、数据年龄；电压/电流有效时计算功率 | 峰值/均值、短时曲线、统计开始/停止/重置 |

| 姿态 | roll/pitch/相对 yaw、角速度、校准状态；BIAS/ZERO/RESTORE 对应已有动作 | 原始加速度/陀螺数据、校准详情、两通道短曲线、冻结观察 |
| 定位 | fix、参与解算卫星数、HDOP、经纬度、海拔、速度、测量年龄 | 设置实验参考点、局部位移、静止漂移统计、受控 NMEA 查看 |

| 实验记录 | 沿用已有 SD CSV 数据/错误记录能力，明确记录状态 | 开始/停止及选定数据记录按资源冻结；屏内回放建议延期，见 2.2 |

### 5.2 数据必须表达真实含义

- 电机 PWM 和输出百分比是控制器输出命令，**不标成实测转速**；没有转速传感器时不显示虚构 RPM。
- 当前 yaw 是相对偏航，不能标为真北航向；GNSS 地面航迹与机体姿态分开显示。
- 电池百分比注明估算含义；输入无效时，不计算看似有效的功率、均值和峰值。
- `--`/`N/A` 表示无有效值，`STALE` 表示已过期；合法零值单独保留。
- 统计和曲线只纳入满足有效性、时间和数据源要求的样本；缺测显示断点，不能以旧值伪造连续新采样。
- 漂移实验的参考点只用于实验坐标与统计，不覆盖原始 GNSS 测量或导航状态。

### 5.3 操作边界

- 显示层通过 App API 提交请求，所属模块确认接受、执行、完成或拒绝。
- 单路电机调节、参数应用继续经过统一控制校验与低压闭锁，不能直接写 PWM 寄存器。
- 参数实验限定在可解释、可验证的范围；步长、上下限、运行中是否可改及默认值须在对应实现项中明确。
- 通信 Node ID、信道支持明确的保存与恢复；其他实验参数默认采用运行态值。持久化格式、有效性校验、断电行为及恢复默认需在实现前明确，不将所有实验状态一律写入持久化存储。
- 记录操作要反馈 SD 是否可用、是否真正写入、是否发生丢弃。若后续纳入屏内回放，仅用于观察，不向控制链重放历史命令。
- 2026-10-12已确认手动CSV记录及已有课程有界参数纳入M5；具体清单、会话/同步和资源门限在M5设计中评审并验证。通用参数编辑和屏内回放已延期。已确认的通信配置是必需项，不能归入可随意省略的条件增强。

## 6. 通信实验、身份配置与 MAVLink Inspector

### 6.1 三种视图

| 视图 | 目标内容 |
|---|---|
| `Messages` | 按链路、RX/TX、SYSID、COMPID、MSGID 汇总；消息名称、计数、频率和最近时间 |
| `Raw` | 所选完整原始帧的十六进制字节，显示长度、方向、时间和帧版本 |
| `Decoded` | 按实际消息定义解释所支持的字段、单位、有效性和特殊值 |

支持 LoRa / RPi 链路选择、RX/TX 筛选、开始/暂停捕获、选择帧及清除捕获内容。首批字段解释优先覆盖工程实际使用的消息；尚无字段解释的消息仍可显示元数据和原始字节，不把部分支持描述成全部 MAVLink 消息均可解码。

### 6.2 当前代码约束与所需改动

当前 RX 结构只保留时间、消息编号、来源、序号、长度和 payload，缺少原始帧头、校验及可能的签名字节。因此，现有结构不能直接满足“查看完整原始 MAVLink”目标。

现有 `App_CopyCommRxFrame()` 最终从生产 RX 队列出队；RPi 接收复制也会消费待处理帧。**Inspector 不能调用这些消费接口，否则会抢走正常遥测、命令或 H1 处理所需的帧。**

所需设计：

1. 由既有通信资源所有者在收发路径生成独立诊断副本，保留真实线上字节。
2. 使用固定容量的捕获环与快照，经 Framework、App API 提供给显示；显示不直接读取 UART 或 DMA。
3. 诊断容量满时按明确策略覆盖/丢弃诊断记录，生产收发与控制继续运行。
4. 捕获覆盖数、诊断丢弃数、生产队列溢出、CRC/解析错误及序号缺失分别统计，不能合并成一个“丢包数”。
5. 原始字节按帧或分页显示，限制格式化与刷新工作量；退出捕获后停止不必要的诊断复制。

首批 Raw 以完整帧捕获为目标；连续串口字节流、任意噪声片段与全部坏帧保存不作为默认全量抓取承诺。CRC/解析失败仍需独立统计。

### 6.3 收发状态的准确含义

- LoRa `Send()` 返回 OK 仅表示进入异步发送流程；`Queued` 与真实 UART `TX complete` 分开。
- LoRa UART 完成以现有 DMA TC 回调事实为准，不能把入队标记成已发送完成。
- RPi 侧按其现有发送接口的实际完成语义记录，不能套用另一条链路的状态。
- UART 发送完成不等于远端接收或业务执行成功；只有相应回显/ACK 能支持后两类结论。
- ISR 只记录完成事实或通知任务；不得在 ISR 格式化、解析、渲染或复制大型诊断记录。

### 6.4 与已有 H1/切速率能力衔接

保留 beta.2 已有的 H1 `TUNNEL 0x8003` 类型 1/2 回显及版本 1 类型 3/4 受控切换：115200 临时切至 57600，接受响应在旧速率完整发送后再切换，复位回到 115200，参数不写 Flash。

串口实验页应展示请求、当前已应用速率、等待响应、成功/超时/拒绝及复位恢复的实际状态。新增 F407 页面不会自动形成 Pi/Server 的全链路能力；如需对端协同，沿用已有跨端契约并分别记录验证结果。

NMEA 查看同样采用独立、限量诊断副本，不抢占 GNSS 正常解析数据，也不依赖长期打开串口 raw NMEA 打印。

### 6.5 LoRa 发送范围收缩

当前 LoRa 目录有 18 类调度项，并有日志增量发送和周期历史重播。V1.0 改为以下范围，仍需实现后验证：

| 数据 | 目标策略 |
|---|---|
| 心跳、节点身份 | 保留必要发现与在线判断信息，具体周期按预算固定 |
| 关键状态摘要 | 保留低电、故障、输出是否运行等实验所需摘要；变化发送加低频当前状态重复，避免只发一次后长期丢失 |
| 选定实验数据 | 学生在发送端选择一种实验模式和发送间隔，只发送该模式所需数据 |
| 完整模块表、完整告警表、电机明细、额外时间扩展 | 不再作为所有实验默认全量发送项；具体消息按课程模式清单冻结 |
| 对端完整日志与历史重播 | 取消 LoRa 发送及远端页面导入；保留本机事件记录 |
| 原始 IMU/NMEA 长流、历史记录 | 不作为默认无线同步内容；Inspector 查看本机收发路径已捕获的帧 |

LoRa 与 RPi 需采用各自的启用项、周期和状态推进，不能直接关闭共用宏而误删 RPi 上行、H1 或既有地面站契约需要的数据。双向实验仍可由双方分别设置发送内容，不要求两台设备的完整状态相互复制。

### 6.6 设备身份与可配置通信地址

| 项目 | 当前代码事实 | V1.0 目标 |
|---|---|---|
| 长产品 ID | `DCDWCNS1` + 12 位 SN，共 20 字符，由 STM32 UID 派生；供 RemoteID 并上报 RPi | 保留为稳定产品身份，在设备信息页查看 |
| 短地址 | UID 哈希压缩到 `1..250`，同时作为 node_id 和 MAVLink system_id；可能重号 | 默认仍可由 UID 派生，增加本机手动设置、保存和恢复入口 |
| 常用显示 | 当前为 `DCDW-XXX` | 简化为 `Node 01` 等短标识，取消第二套产品名称的展示负担 |

同一通信网络的 Node ID 必须区分。当前固件没有现场地址配置入口，同一份固件可自动生成默认地址，但发生重号或需人为指定时不能在界面修改；这些能力均待实现。

Node ID 保存后在重启时统一生效，界面区分当前值与待生效值。该值目前被 LoRa、RPi MAVLink 及 RemoteID 消息帧头共用，变更时必须一致切换并验证对端识别，不能只修改显示文本或某一条链路。长产品 ID 不随通信地址改变；相关身份描述需同步。

完整说明见[设备标识符固件实现说明](设备标识符固件实现说明.md)。当前接收路径会忽略与本机 system_id 相同的帧；地址重号不能通过增加远端缓存槽位解决。

### 6.7 手动无线配置与冲突处理

**地址重号与同信道争用是两类问题。** 修改 Node ID 解决设备识别冲突；不同实验组可选择经过验证的不同无线信道，或降低发送频率、轮流发送，以减少无线争用。软件分组名称或仅修改地址不能替代实际信道配置。

硬件配置指向 E22-400T30D，M0/M1/AUX 已接入；现有驱动主要进入正常模式收发，尚未提供完整信道参数读写流程。厂商资料提供 CH 配置能力，实施时应核对实际模块版本并限定课堂可用信道，不能仅修改 F407 中的常量或屏幕显示就认定射频参数已改变。参考：[E22-T 系列用户手册](https://www.ebyte.com/Uploadfiles/Files/2024-3-21/2024321943172544.pdf)。

最小交互范围：

| 控件/反馈 | 含义 |
|---|---|
| `Node ID` | 本机地址，支持保存；重启后生效并明确提示 |
| `Channel` | 从已验证的课堂信道中选择；同组通信双方分别设置为匹配值 |
| 内容选择、`Interval` | 选择发送实验数据和有界发送间隔 |
| `Send / Start / Stop` | 单次发送、开始连续发送、停止实验发送；不因进入页面自动开始 |
| `Apply / Restore` | 应用并核验参数、恢复明确的课堂默认配置；不混用为整机恢复出厂 |
| 实际状态 | 当前生效参数、待生效项、TX/RX、接收频率、丢帧估计、最近数据年龄 |

信道配置流程为：停止实验发送并等待发送路径空闲 → 本机进入配置过程 → 写入并读回核验 → 返回正常收发模式 → 显示实际生效值 → 学生重新开始。由 CommTask 持有配置过程，UI 只发请求；配置响应不能送入普通 MAVLink 解析器。失败或超时不能报成功，无法确定当前参数时显示未知并允许本机重试/恢复，不能依赖已经断开的无线链路救回本机配置。

同组两端应按手册设置匹配信道与无线参数。不同组的信道间隔、功率和距离仍需课堂实测，不能承诺只要频道数字不同就完全无干扰。Node ID、信道持久化需验证断电、模块拔插与恢复默认，避免主控保存值和 E22 实际值不一致。

学生实验闭环：制造/观察同信道负载 → 记录收发结果 → 分别调整地址、信道或发送间隔 → 比较结果 → 恢复课堂配置。丢帧不是干扰的唯一证据，页面展示事实统计，不自动断言故障原因。

V1.0 不加入自动配对、自动分配地址、自动选信道或自动跳频。收发、校验、配置读回和保护继续自动执行，具体规则与排查步骤写入实验手册。

### 7.2 事件时序

1. **请求**：用户按下按钮只代表提出请求；不能直接记为动作成功。
2. **接受或拒绝**：由控制/校准/通信等所属模块给出；被拒绝时写明原因。
3. **开始**：状态机实际进入动作阶段时记录。
4. **完成、失败或中止**：按完成条件、错误或保护动作记录，不靠预计时长推断。
5. **恢复**：从异常状态回到满足条件的正常状态后记录，单独于首次正常状态。

传感器和模块状态采用经定义的稳定确认/去抖；现有约 1.5 s 去抖及 3 s 拒绝提示限频需要按事件类型复核。急停、致命错误和保护撤收不等待普通状态去抖。防刷屏只合并重复提示，不能吞掉首次异常或状态变化。

日志时间显示 `Uptime`，采用事件事实时间；如需保留首次检测与确认时间，应分别保存，避免将稍后补写时间冒充首次发生时间。RTC/UTC 可作为独立信息，不与开机相对时间混用。

| 动力电池低电 | `Motor battery low` | WARN |
| 动力条件导致油门请求拒绝 | `Throttle blocked: low power` | WARN |
| 同步升速 / 缓降实际开始 | `Motor ramp started` / `Ramp-down started` | INFO |
| 本机急停生效 | `Local E-stop triggered` | WARN |
| 已达到最小输出 | `Output at minimum` | INFO |

示例用于统一风格，最终逐条与事件来源、当前保护策略和显示宽度核对。重要事件可提供二级详情，避免一行文本过长而丢失关键原因。

## 9. 性能与资源设计

### 9.1 现有预算基线

| 资源 | 审查基线 | 对新增功能的约束 |
|---|---|---|
| 主 SRAM | 119048 / 131072 B，链接余量 12024 B，约 11.7 KiB | 不是运行时空闲堆；新增静态缓冲需逐项核算 |
| FreeRTOS heap_4 | 已配置 40960 B，位于主 SRAM | 峰值使用率须保持在 75% 以下 |
| LVGL 堆 | CCM 固定 40960 B | 需测控件、文本、切页和曲线的实际峰值与碎片 |
| LCD 绘制缓冲 | 38400 B，800×24 RGB565 | 占用约 37.5 KiB 主 SRAM |
| ROM 装载大小 | 412956 B，约 403.28 KiB | 新字体、字段解释与图表代码需重新核算 |
| Logo 常量 | 64×64×2，8192 B | 删除主要节省 Flash，不等于释放 8 KiB RAM |
| 曲线能力 | 当前 `LV_USE_CHART=0` | 需要实现/启用并验证，当前未具备 |

### 9.2 性能改动原则

- 删除装饰能减少绘制和控件开销；把文字改为英文的主要直接收益是字体资源与文案空间，不能据此保证 CPU 负载大幅降低。
- 中文字符减少后才重新裁剪字体；仅删除标签文本不会自动移除字库常量。主要页面仍保留中文，必须确保剩余字形齐全。
- 只刷新发生变化的数字、状态和局部区域，日志无新事件时不重排整栏。
- 原始字节、字段表和曲线采用受限刷新频率；控制、传感器和通信任务周期不随画面刷新降速。
- 诊断和曲线使用固定容量，内存用尽有可见统计及明确行为，不能无限积累。
- 优先共享实验曲线工作区与格式化缓冲，限制同时活动的重型视图；未显示的诊断页面不持续格式化和绘制。
- 按仓库规则，启动后不新增动态内存分配。控件和数据工作区在初始化阶段预分配并复用；现有切页清空/重建控件的路径需要在本次页面生命周期调整中处理。不能以一次性创建全部页面导致内存超预算。
- DMA 缓冲保留在 `0x20000000` 主 SRAM；CCM 的可用空间不能当作 DMA 缓冲来源。

当前显示接口虽有 2 ms 刷新预算参数，但 LVGL 路径尚未落实该预算，LCD 刷新仍有逐像素 CPU 写入。V1.0 需实测并落实单步耗时控制，不能仅减少 Logo 或文字后宣称满足预算。

### 9.3 新增容量的初始估算

- MAVLink 完整帧上限按当前捆绑库为 280 B；原始帧捕获初始以约 2 KiB、少量固定槽位估算，最终需连同元数据、并发读写及格式化缓冲核算。
- 两通道、各 120 点、每点 16 bit 的 Y 值本体为 480 B；时间、有效性、缩放、控件和绘制成本另计。
- 这些数值是设计估算，不是已经通过的配置或性能承诺。
- 具体采样率、刷新率、捕获深度和事件历史容量在每项实现中形成可检查的配置表，并在候选冻结时固定。屏内回放按D05已延期，不预留大历史缓冲作为默认支出。

资源不满足时，先降低诊断刷新率、缓存深度和同时活动的视图数量；保护逻辑、数据真实性和生产收发不能降级。
