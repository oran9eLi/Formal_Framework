## 最新范围调整与调研（2026-10-27）

- 已确认约束：取消下文原拟定的Diagnostics/Outputs、Beep、RGB test、Stop页面入口；保留底层通用驱动。第1、4、5、6节涉及手动页面、自检事务和“不做自动提示”的旧描述均已被本节取代，不能据此编码。
- AP与PX4当前源码使用相同的经典启动旋律（忽略字符串空格）；可用固定音符/时长表与硬件PWM复现音高、节奏，无需移植整套飞控或MML解析器。原拟1000～4000Hz范围尚未实施，后续须按实际音符和蜂鸣器听感重新确定，不能裁剪低音后称原曲复刻。
- AP的RGB初始化序列为红/蓝交替、100ms一步；PX4的RGB由飞行状态控制，包含呼吸、常亮、错误闪烁，不能把所有板载状态灯合称为一种开机灯效。
- 拟采用教学语义：上电初始化期间红蓝交替，应用就绪后播放一次启动音并转低亮度蓝色待机；操作完成绿闪＋短音，拒绝/失败黄闪＋区别音。关键故障/急停优先于普通反馈。以上颜色、时长、覆盖范围和静音规则为建议，尚未冻结；不照搬GPS/解锁状态，不将未接IMU/LoRa/SD自动变成持续蜂鸣。
- 触发边界：请求入队不能当成执行成功；保存以落盘结果、记录以服务状态、校准以完成结果为准。通信入队/DMA完成/对端确认分别有不同语义，不用同一个成功提示混淆。普通翻页及连续滑块原则上不逐次鸣叫，重复事件限频，不积压过期旋律。
- 资源与听感：沿用下文TIM9、TIM8＋DMA的资源建议；静态音符表存Flash、无PCM录音、无新任务或新增显示控件。增量需构建实测；蜂鸣器规格为2048Hz共振，音色/各音符响度只能实板确认，不保证与飞控原件完全相同。
- 本次仅记录范围修订与公开源码调研；具体反馈映射待确认后再写实施计划，未编码，故不运行Keil。原硬件连接/DRC待补充边界保留。

## 1. 目标、范围和方案选择

以 STM32F407ZG + HAL + FreeRTOS + ARMCC5.06 为基础，为新扩展板提供可复用蜂鸣器与单颗 RGB 灯驱动，以及学生可手动执行的声光自检。驱动只负责输出能力，实验组织仍由现有业务承担。

| 方案 | 内容与代价 | 本次决定 |
|---|---|---|
| 通用驱动＋手动自检 | 提供音调、时长、RGB、停止和状态接口，人工检查新板；占用与触发范围小 | 用户选定 |
| 同时接入自动声光提示 | 还需确定启动、故障、实验状态映射及优先级、静音和重复规则 | 本轮不实施 |

保持现有 UART1/UART6、MAVLink、LoRa、串口实验与电机控制协议。第一版仅支持一颗灯，不扩展灯带、音乐、动画脚本、Flash 配置保存或远程命令。上述约束与接口细节为主代理提出，随本文确认。

## 2. 已指定硬件与 PCB 核对边界

| 输出 | 用户指定连接 | 外围 |
|---|---|---|
| 蜂鸣器 | PE5 → BUZZ-PWM → R5 220Ω → AO3400A 栅极 | YS-MBZ12085C05R42，5V-BEC供电；10kΩ栅极下拉、SS14续流、100nF＋10μF去耦 |
| RGB | PC9 → LED-DATA → SN74AHCT1G125 → R3 330Ω → DIN | XL-5050RGBC-2812B，5V-407供电；10kΩ输入下拉；灯珠和缓冲器各100nF去耦 |

原理图与 PCB 可见极性/器件布局相符：Q1单独焊盘为漏极接BUZZ-D，另两脚为栅极与源极；最终封装必须为1=G、2=S、3=D。续流二极管阴极接5V-BEC，阳极接BUZZ-D。

PCB截图中R5-2的PE5走线路径、LED1/C6地网接入系统地的完整路径不能确认。用户说明已经布线完成，将补充铺铜视图或DRC。因此以上两项保留待核对，不判为断路，也不宣称整板已通过DRC。焊盘/阻焊、铜皮连续性、全板间距和电源完整性不由局部截图验收。

## 3. 资源分配（拟采用）

| 资源 | 分配 | 现状核对 |
|---|---|---|
| 蜂鸣器引脚 | PE5 / AF3 / TIM9_CH1 | 当前未配置PE5/TIM9 |
| 音调输出 | TIM9硬件PWM，50%占空比 | 不用逐周期中断；任务只推进时长 |
| RGB引脚 | PC9 / AF3 / TIM8_CH4 | 当前未配置PC9/TIM8 |
| RGB发送 | DMA2_Stream7 / Channel7 → TIM8_CCR4，普通模式 | 当前BSP未占用此Stream；依据RM0090表44 |
| GPIO与IRQ | 完整RCC/GPIO/MSP/DMA/NVIC链；DMA中断优先级按现有RTOS规则配置 | 已有HAL_TIM/HAL_DMA；需新增DMA2_Stream7 IRQ入口 |
| 毫秒/微秒时基 | 沿用TIM6与平台时间API | 不调整TIM6 |
| 既有电机 | TIM3/TIM4保持50Hz | 不复用其时基 |

DMA2 Stream7会成为RGB专用资源，后续USART1/USART6若改DMA发送，必须重新核对Stream分配，不能仅因Channel不同而并用同一Stream。

RGB用约800kbit/s单线脉宽编码、GRB顺序、高位先发。具体计数由实际TIM8时钟推导，采用同时满足手册表格和注释的脉宽范围；手册复位低电平表格80μs、注释100μs存在差异，设计至少120μs连续低电平。首码预装、CCR预装载、帧尾低电平及DMA完成语义在实现时明确，禁止省略首位或在最后数据位完成前复用缓冲。

单份静态半字DMA缓冲只容纳24数据位和必要复位槽，目标小于256B；放在0x20000000主SRAM，不能放CCM。全功能新增主SRAM以小于1KiB为设计目标，实际增量必须用同基线Keil MAP复核，目标不是构建结果。

## 4. 分层、调度与初始化

- BSP：拆分蜂鸣器PWM、RGB定时器/DMA原始输出，配置集中在bsp_config.h。含MX_xxx_Init风格入口、MSP、DMA句柄/IRQ、停止与反初始化；不承载GRB编码、提示含义或屏幕逻辑。GRB编码放设备驱动/适配路径，保持BSP只发送原始波形。
- 平台适配：Framework唯一接触BSP的接口，提供音调/停音、颜色发送/忙闲、错误事实与有界恢复入口。
- Framework：小型输出服务管理请求、时长、自检序列、状态和恢复。由既有sensor任务统一拥有并按10ms周期推进；不新建任务，不在Health任务执行输出I/O。
- Business：通过app_data_api.h提交测试/停止请求并复制输出状态；不得直接包含BSP或消费DMA缓冲。
- Display：在既有Diagnostics中，通过Next增加Outputs视图；复用控件池，提供Beep、RGB test、Stop。只展示最少必要的英文状态；该入口是本设计建议，待随本文确认。

请求使用固定容量邮箱，只有一个自检事务；重复启动返回Busy，Stop优先。运行中不分配堆内存，不使用阻塞延时、忙等待或长时间关中断发送灯珠数据。ISR只处理已有HAL IRQ链并记录完成/错误事实，序列推进、超时和重初始化均留在资源所属任务。

可选输出采用独立使能开关；旧硬件配置关闭，新扩展板候选显式开启并记录构建配置。GPIO初始化先保持低电平，PWM初始关闭，RGB初始化发送黑色帧。可选输出初始化失败通过独立状态上报，不扩大既有BSP关键启动门禁，不让未安装新扩展板的旧箱子失去运行能力。

不新增或重排既有MAVLink模块枚举，不把驱动就绪混同为原逻辑Alarm模块状态。提供独立App输出状态快照，包含配置使能、初始化结果、忙闲、自检阶段、发送结果和错误计数。

## 5. 接口行为与手动自检（拟采用）

| 接口/操作 | 行为 |
|---|---|
| 通用音调请求 | 1000～4000Hz、时长1～2000ms、固定50%占空比；非法参数拒绝，0音量/音乐不纳入首版 |
| 通用RGB请求 | R/G/B各0～255；每次完整发送一帧；忙时返回Busy，不覆盖正在DMA发送的缓冲 |
| Beep | 手动触发约2048Hz、200ms单声，自动停音 |
| RGB test | 手动触发低亮度红→绿→蓝，各300ms，然后发送黑色；测试通道值32/255 |
| Stop | 请求停止当前自检与音调，并安全发送黑色；不在DMA中途直接覆盖缓冲 |
| 切页/重启 | 离开Outputs视图停止自检；复位后静音，初始化完成后黑灯，不恢复上次序列 |
| 参数查询 | 返回驱动状态、当前音调/RGB请求、自检阶段、完成与错误事实 |

自检序列均有固定结束时间，正常调度下自动撤收。音调持续时间和RGB阶段由真实毫秒差值计算，处理32位时间回绕；任务调度与已有I/O可能带来时长偏差，实际偏差需实板测量。

灯珠是单向器件，蜂鸣器也没有反馈。界面可显示Ready/Running/Sent/Error，但不自动宣称实际发声/发光通过；测试者人工确认声音、颜色和强度。断开灯珠或蜂鸣器后，单靠GPIO/DMA成功不能识别器件在位。

Stop/黑灯必须发送全零颜色帧并满足复位时间；单纯将DIN拉低不会熄灭已锁存的颜色。致命异常路径立即撤收蜂鸣器PWM并停止RGB波形请求，不等待HAL超时或在异常中播放/发送；灯珠可能保留最后颜色，下一次正常初始化再发黑帧。

## 6. 故障处理与集成文件

RGB发送设置有界超时，超时/错误后在sensor服务中关闭并重新初始化对应资源；重试按现有恢复思路限速，不每拍反复初始化。软件错误不关闭或重置电机/串口等无关外设。保存错误计数，驱动停用/故障时手动请求得到明确拒绝结果。

预计涉及：Bsp/Inc、Bsp/Src新增输出资源文件；设备驱动层新增GRB编码；Framework新增轻量输出服务与平台接口；Core/Src/stm32f4xx_hal_msp.c、Core/Src/stm32f4xx_it.c与必要的致命撤收；Business/Inc/app_data_api.h及实现；Display/Src/display_lvgl.c；HAL配置核对与MDK-ARM/formal_framework.uvprojx源码列表。实际文件清单在实施计划中冻结。
