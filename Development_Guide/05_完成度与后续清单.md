# 完成度与后续清单

## 1. 文档用途

本文件是模块完成度的唯一事实来源，用于回答：

- 当前真实跑通了哪些能力。
- 哪些只是骨架、占位或预留。
- 每个阶段还缺什么。
- 后续开发者从哪里继续。

不得仅凭目录、任务、函数声明或空实现存在，就把模块标为完成。

## 2. 状态标记规则

| 标记 | 含义 |
|---|---|
| 完成 | 真实实现、调用链闭合、通过规定验证 |
| 基础完成 | 主流程可运行，但算法、覆盖或异常处理不完整 |
| 骨架完成 | 接口和结构存在，尚无完整消费者或业务闭环 |
| 占位 | 为保持架构和编译而存在，不提供真实设备功能 |
| 预留 | 只有设计边界，尚未进入代码实现 |

优先级为：`完成` > `基础完成` > `骨架完成` > `占位` > `预留`。

## 5. 剩余开发步骤

### 阶段 2：基础系统闭环补齐

1. 完成公开接口和关键内部函数的参数、返回值、上下文注释。
2. 固定模块注册、初始化、自检、启动、停止和恢复接口。
3. 实现 POST 结果汇总和启动状态快照。
4. 扩展业务告警来源、告警仲裁策略和恢复输出动作；现有模块状态告警管理器继续作为唯一活动告警事实来源。
5. 扩展 Health Monitor，加入任务、队列、栈、heap 和 deadline 监控。

### 阶段 3：普通传感器接入

已完成 IMU、气压计和电源数据接入。后续替换正式器件时，必须继续沿用单一 `sensor` 任务、强类型快照、状态单写者和恢复边界。

### 阶段 4：运算和融合

1. 完善 IMU 标定、姿态解算和坐标系转换。
2. 完善气压高度、垂直速度和滤波。
3. 对齐 GNSS、IMU 和气压计采样时间。
4. 增加范围、变化率、跳变和质量过滤。
5. 发布带有效位和置信度的融合导航快照。

### 阶段 5：应用和外部输出

显示、LoRa 发送、日志显示和 SD 存储已完成。后续任意外设按状态类/数据类分流接入：

- 状态类：只通过 `App_GetModuleStatus()` 或 `App_CopySystem()` 暴露。
- 数据类：有真实业务消费时再新增 topic 和 `App_Copy*`；界面显示值和 LoRa 外发值必须来自同源快照。
- LoRa/MAVLink：原生消息优先；外发必须新增 Telemetry Catalog 条目，不得拼全量大包；模块状态使用 `MODSTAT0/1` 标准 `NAMED_VALUE_INT` 分片；接收侧由 Framework 解码为远端遥测快照，再通过 `App_CopyRemoteDisplaySnapshot()` 进入 Display 视图，主从字段和时隙后续单独定义。
- 5G-A：复用通信类控制面发送 AT 指令并上报模块状态。
- Remote ID：数据流不从本 STM32 板直通，只保留边界状态。

### 阶段 6：可靠性和产品化

1. 实现任务心跳门控的 IWDG。
2. 保存 HardFault、栈溢出、malloc 失败和复位原因。
3. 加入参数、标定、版本、Bootloader 和升级机制。
4. 完成 24/72 小时稳定性、故障注入和硬件在环测试。
5. 定义未来 Linux A 核 IPC 协议，并保证 MCU 可独立运行。

## 6. 当前边界收口记录

- Business 层普通任务文件不直接访问 Framework Registry；Business 拥有的 Display 模块注册、启动状态写入和恢复回调统一收口在 `Business/Src/business_platform_adapter.c`。
- Driver 需要保护短快照复制或状态标志时，统一使用 `BSP_Critical_Enter()` / `BSP_Critical_Exit()`，避免在 Driver 文件中散落 CMSIS PRIMASK 操作。
- Display 页面层不直接包含 Framework 故障头文件或模块枚举；模块状态灯、告警列表、离线清屏策略、模块名和故障原因统一由 `app_data_api.h` 的 Display 视图输出。
- LoRa E22 已迁入 `Driver/Comm/Inc/lora_e22.h` 和 `Driver/Comm/Src/lora_e22.c`，按通信类 Driver 管理，由 `comm` 任务服务；后续新增通信 Driver 不再放入 `Sensor/`。
- 周期任务禁止在栈上放完整系统快照、完整告警表、全量显示视图或 LoRa 大 payload；当前 Display 聚合视图、告警更新 scratch、LoRa TX buffer 均使用静态存储或轻量 summary 接口。
- 模块生命周期 descriptor 的空回调使用 `NULL`；普通外设 init 回调返回底层真实结果，由 Registry/Health/Alarm 记录失败，不得吞掉错误伪装启动成功。
- App DateTime 快照使用独立 `APP_DATETIME_MAX_AGE_MS` 新鲜度；新增 App 快照必须按业务节奏设置独立年龄阈值。
- 远端数据接收显示闭环已形成：LoRa RX 帧事实 -> Framework MAVLink RX 远端槽位表 -> `App_CopyRemoteDisplaySnapshot()` -> Display 数据源；KEY0 由 Business 显示服务去抖后切换本机/对端，KEY1 继续保留电机急停。主机默认选从机1，从机默认选主机；后续多从机通过切换远端槽位扩展。
- LoRa 收发计数和接收侧丢包率已闭环到 Display：TX 计数来自本机发送完成，RX 计数来自合法 MAVLink 帧，丢包率由 Driver 和远端槽位按 MAVLink `seq` 跳号估算；对端视图显示当前选中远端节点的 RX/丢包率；ACK 计数当前为 0，等待后续真实 ACK/重传协议。

## 7. 每次移植必须记录

每加入一个模块，必须在本文件和 `Change_History/` 中记录：

1. 模块名称、型号、总线、引脚、DMA、中断和资源占用。
2. 从哪个工程或版本移植，保留和删除了哪些内容。
3. BSP、Driver、Framework、Business 各层新增接口。
4. 发布的数据类型、单位、坐标系、频率和最大年龄。
5. 模块状态、故障码、超时、恢复和降级规则。
6. 任务所有者、调用周期、栈水位和最长执行时间。
7. 队列、FIFO、topic、静态 buffer 的所有权和容量。
8. 调试功能及关闭调试后不影响正式逻辑的证明。
9. 编译、台架、断线恢复、长稳和故障注入结果。
10. 当前未完成项和下一位开发者的接续入口。
