# 完成度与后续清单

## 1. 文档用途

本文件是模块完成度的唯一事实来源，用于回答：

- 当前真实跑通了哪些能力。
- 哪些只是骨架、占位或预留。
- 每个阶段还缺什么。
- 后续开发者从哪里继续。

不得仅凭目录、任务、函数声明或空实现存在，就把模块标为完成。

## 2. 状态标记规则

| 标记 | 含义 |
|---|---|
| 完成 | 真实实现、调用链闭合、通过规定验证 |
| 基础完成 | 主流程可运行，但算法、覆盖或异常处理不完整 |
| 骨架完成 | 接口和结构存在，尚无完整消费者或业务闭环 |
| 占位 | 为保持架构和编译而存在，不提供真实设备功能 |
| 预留 | 只有设计边界，尚未进入代码实现 |

优先级为：`完成` > `基础完成` > `骨架完成` > `占位` > `预留`。

5. 扩展 Health Monitor，加入任务、队列、栈、heap 和 deadline 监控。

### 阶段 3：普通传感器接入（已关闭）

GNSS、IMU、气压计和电源数据已完成当前产品基线接入，采集所有权、快照发布、状态判定和 App 出口已闭环，本阶段关闭。

后续替换正式器件或新增普通传感器时，不重新打开阶段 3；按 `03_模块接入手册.md` 新增接入项，并继续沿用单一 `sensor` 任务、强类型快照、状态单写者和恢复边界。

### 阶段 4：运算和融合（基础闭环）

已完成基础闭环：IMU 开机水平静止 5 秒基准标定、姿态质量评分、气压高度、气压垂直速度、GNSS 地速航向到 N/E 速度转换、GNSS/Baro 高度基础融合、采样时间窗口对齐、范围/跳变/质量过滤和带有效位/质量分的 Navigation 发布。Display 启动日志提示“水平静止5秒”，基准完成后记录“基准完成”。

RTC/GNSS 时间职责已收口：显示、日志和文件时间可由 RTC 顶替，GNSS 定位成功后再校准 RTC；融合采样对齐只使用 `sample_time_ms` 单调毫秒，不依赖 GNSS UTC 是否已经定位成功。

后续增强项：

1. 增加可持久化的 IMU 多姿态/多点标定参数和温漂补偿。
2. 将一阶互补滤波升级为更完整的姿态解算和坐标系管理。
3. 加入更严格的 GNSS 位置跳变、速度跳变和高度离群检测。
4. 引入可配置的融合权重、置信度模型和台架/飞行数据回放验证。
5. 根据正式结构件和传感器安装方向复核轴向映射和标定流程。

### 阶段 5：应用和外部输出

显示、LoRa 发送、日志显示和 SD 存储已完成。后续任意外设按状态类/数据类分流接入：

- 状态类：只通过 `App_GetModuleStatus()` 或 `App_CopySystem()` 暴露。
- 数据类：有真实业务消费时再新增 topic 和 `App_Copy*`；界面显示值和 LoRa 外发值必须来自同源快照。
- LoRa/MAVLink：原生消息优先；外发必须新增 Telemetry Catalog 条目，不得拼全量大包；模块状态使用 `MODSTAT0/1` 标准 `NAMED_VALUE_INT` 分片；接收侧由 Framework 解码为远端遥测快照，再通过 `App_CopyRemoteDisplaySnapshot()` 进入 Display 视图。多从机采用唯一 `node_id`、低频错峰心跳在线发现、主机自动慢速 poll 兜底和选中节点租约发送主数据，未选中节点不主动连续发送完整遥测；选中查看时后台 poll 自动退让；双方同时互看时主数据自动降频，心跳、命令和 ACK 保持优先。
- 5G-A：复用通信类控制面发送 AT 指令并上报模块状态。
- Remote ID：数据流不从本 STM32 板直通，只保留边界状态。

### 阶段 6：可靠性和产品化

1. 实现任务心跳门控的 IWDG。
2. 保存 HardFault、栈溢出、malloc 失败和复位原因。
3. 加入参数、标定、版本、Bootloader 和升级机制。
4. 完成 24/72 小时稳定性、故障注入和硬件在环测试。
5. 定义未来 Linux A 核 IPC 协议，并保证 MCU 可独立运行。
