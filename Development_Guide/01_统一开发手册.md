# Formal Framework 统一开发手册

## 1. 手册定位

本手册是 `Formal_Framework` 的统一开发入口。所有长期有效的架构规则、模块接入规则、验证门禁和完成度口径，都以 `Development_Guide/` 下当前编号手册为准。

手册和代码必须同步演进：

1. 代码框架、目录职责、任务模型、接口边界、配置入口、外设接入方式发生变化时，必须同步修改本手册。
2. 只改代码不改手册，视为开发闭环未完成。
3. 只改手册不改代码时，必须明确说明这是规则调整、设计收敛或事实记录更新。
4. 历史原因、问题处理和一次性背景记录放入 `Change_History/`，不得散落为新的长期指南。

## 2. 项目基线

- 平台：STM32F407 + HAL + FreeRTOS + Keil MDK-ARM。
- 编译器：ARMCC 5.06，C 标准 `--c99`。
- 唯一工程入口：`MDK-ARM/formal_framework.uvprojx`。
- 输出目录：`MDK-ARM/Objects/` 和 `MDK-ARM/Listings/`。
- 发布构建必须 Rebuild All，并达到 `0 Error(s), 0 Warning(s)`。
- 构建产物不进入 Git；发布包按 `Release/README.md` 归档。

## 3. 规则优先级

当文档之间存在冲突时，按以下顺序处理：

1. `AGENTS.md` 中的强制规则。
2. 本目录当前编号手册。
3. `README.md` 中的仓库说明。
4. `Change_History/` 中的历史记录。
5. `YJ/`、模板目录和旧迁移资料。

完成度事实只以 `05_完成度与后续清单.md` 为准，不得因为文件、任务、函数声明或空实现存在，就把模块标记为完成。

## 4. 分层总原则

工程采用严格单向依赖：

```text
Core -> Business -> Framework -> Platform Adapter -> Driver -> BSP -> HAL
```

| 层级 | 可以做 | 禁止做 |
|---|---|---|
| Core | `main.c` 组合根、启动链路、中断入口转发 | 协议解析、业务策略、长耗时恢复 |
| Business | 通过 `app_data_api.h` 读取快照，组织业务流程和显示业务入口 | 包含 BSP/Sensor 头文件，读取 DMA buffer 或驱动私有变量 |
| Framework | 管理 topic、registry、状态、生命周期、恢复和调度 | 包含 Business 头文件 |
| Platform Adapter | Driver/BSP 类型到 Framework 类型的转换 | 把 BSP 细节扩散到 Framework 其他文件 |
| Driver | 芯片协议、解析、校准、设备事实和驱动内部状态 | 调用 `HAL_*`，声明 OFFLINE/FAILED 最终状态 |
| BSP | GPIO、时钟、总线、DMA、中断和原始收发 | 协议解析、业务逻辑、状态策略 |
| HAL | STM32 HAL 底层库 | 项目业务逻辑 |

`Framework/Src/px4lite_platform_f407.c` 是 Framework 层唯一允许包含 BSP 头文件的位置。

## 5. 必守工程规则

1. 启动后不得再动态分配内存，新增状态、队列、DMA buffer 和缓存优先静态分配。
2. DMA buffer 必须放在 `0x20000000` 起始的 128 KB SRAM 中，禁止放入 `0x10000000` 起始的 CCM。
3. 周期任务必须使用 `vTaskDelayUntil()`，不得用 `vTaskDelay()` 代替固定周期调度。
4. `_ms` 字段必须是真实毫秒值，来源为 `PlatformGetMs()` 或 `BSP_Time_GetTickMs()`；`_ticks` 字段才表示 RTOS tick。
5. Sensor / Driver 层不得调用 `HAL_GetTick()`。
6. ISR 只允许更新计数、写位置、轻量标志或发送任务通知。
7. ISR 禁止 `printf`、协议解析、写 SD、渲染页面、总线重初始化和阻塞 I/O。
8. 使用 `__enable_irq()` 前必须保存 `__get_PRIMASK()`，只有原本允许中断时才恢复；Driver 或边界适配文件需要短临界区时统一使用 `BSP_Critical_Enter()` / `BSP_Critical_Exit()`。
9. 通信层禁止直接发送 C struct 内存，必须逐字段编码并带长度、版本、序号和校验。
10. 状态单写者：驱动只记录硬件事实并提升 ONLINE/DEGRADED，OFFLINE/FAILED 由 Health task 独占判定。
11. 除 `Framework/Src/px4lite_platform_f407.c` 这个唯一平台适配文件，以及 BSP 内部封装如 `Bsp/Inc/bsp_critical.h` 外，非 BSP/Core 文件不得直接包含 `stm32f4xx_hal.h`；需要时间延时走 `BSP_Time_DelayMs()`，需要硬件访问或临界区保护走 BSP 或平台适配层。
12. 周期任务不得在栈上放完整系统快照、完整告警表、全量显示视图或通信大 payload；聚合显示、调试摘要、LoRa 分段和外设批量数据必须使用静态 scratch、summary 接口、固定块池或固定队列。

## 6. 任务模型

一个硬件资源只能有一个任务所有者。普通传感器统一由 `sensor` 任务采集，不得为每个普通传感器单独创建任务。

| Task | 周期 | 优先级 | 归属和职责 |
|---|---:|---|---|
| `sensor` | 10 ms | idle+4 | GNSS、IMU、Baro、Battery 等普通传感器唯一硬件采集者 |
| `estimator` | 20 ms | idle+3 | GNSS 到 Navigation domain，IMU FIFO 到姿态解算 |
| `health` | 100 ms | idle+2 | 超时检测、OFFLINE 判定、健康快照、看门狗喂狗门控 |
| `comm` | 10 ms | idle+2 | LoRa RX，MAVLink TX 调度，通信类模块服务 |
| `biz_system` | 1000 ms | idle+2 | 启动日志、注册表轮询、系统业务状态 |
| `biz_acq` | 200 ms | idle+2 | Navigation 快照复制和 EventBus 分发 |
| `biz_display` | 10 ms | idle+1 | 触摸优先，预算化 LCD 刷新，单步预算 2 ms |
| `debug` | 100 ms | idle+1 | 周期诊断和任务监控，不纳入 watchdog 集合 |
| `storage` | 50 ms | idle | 注册式 SD CSV 日志服务，低优先级阻塞 I/O，不纳入 watchdog 集合 |

新增任务必须说明为什么不能挂到已有 service/work 中，并提交周期、优先级、栈预算、最长执行时间、heartbeat 和 DebugTaskMonitor 注册结果。

## 7. 注释与文档同步

- 新增或重构源码必须使用 Doxygen 风格中文注释。
- 每个 `.c` / `.h` 文件开头说明文件职责、所属层级、主要依赖和禁止事项。
- 每个公开函数、重要内部函数、公开结构体、配置结构、跨层消息结构必须有说明。
- 结构体成员涉及物理量、时间、长度、计数和状态值时，必须写清单位或取值范围。
- 修改函数行为、参数含义、结构体字段、模块边界或任务归属时，必须同步更新对应注释和本手册。

## 8. 提交和记录

提交信息统一使用 `<type>: <简短中文说明>`，常用类型为 `feat`、`fix`、`docs`、`refactor`、`chore`、`build`、`test`。

架构、协议、日志、存储、显示、任务边界、模块状态或外设接入方式发生变化时，必须同步更新：

1. 本编号手册中的长期规则。
2. `05_完成度与后续清单.md` 中的完成度、验证结果和后续入口。
3. `Change_History/` 中的一次性变更记录。
