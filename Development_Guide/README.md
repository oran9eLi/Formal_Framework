# 开发文档说明

## 本轮 V1.0 工作入口

- [里程碑计划](../Release/V1.0_里程碑计划.md)：V1-M0—V1-M8 的交付、依赖及通过条件。
- [执行台账](../Release/V1.0_执行台账.md)：任务、决策、问题关闭、证据和候选状态的唯一维护入口。
- [预发布改动文档](2026-09-28_V1.0稳定版预发布改动文档.md)：本轮产品范围与行为要求。
- [M3 页面与日志变更](Change_History/2026-10-03_V1-M3_页面与日志收敛.md)：本机页面、固定控件、事件职责及兼容边界；实际验证见对应阶段记录。

旧模块清单和旧里程碑保留历史上下文，不沿用其中的完成标记判断本轮进度。

## 规范与资料

本目录包括开发规范、架构图、模板和版本设计资料：

1. `01_强制开发规范.md`
2. `02_总体架构图.md`
3. `03_数据完整性流程图.mmd`
4. `04_代码架构与功能标注.md`
5. `05_项目缺失内容清单.md`
6. `06_应用层数据接口.md`
7. `07_移植进度与功能清单.md`
8. `08_架构设计与后续开发汇报.md`
9. `09_框架V2第一阶段与任务栈监控.md`
10. `15_模块数据契约与评审门禁应答.md`
11. `16_模块接入标准与评审清单.md`（新模块接入与合入门禁,以 GNSS/LoRa 为样板）
12. `Example_Template/`
13. `Business_Layer_Template/`

历次架构整改和问题处理记录统一放入 `Change_History/`，文件名必须包含
日期，不再散落在当前规范目录。

最新验证通过的固件和构建记录统一放在项目根目录的 `Release/Latest/`。
历史发布版本放在 `Release/Archive/YYYY-MM-DD_version/`，不得覆盖。

规则优先级：

```text
数据正确性 > 故障可检测性 > 实时性 > 功能数量 > 开发便利性
```

任何模块若不能证明“不读半包、不发布半包、不发送半帧”，不得合入正式
版本。

`07_移植进度与功能清单.md` 保留历史移植、模块与占位接口记录；
本轮计划和完成度以顶部 V1.0 入口为准。

需要进行组内汇报、架构评审或新成员宣贯时，使用
`08_架构设计与后续开发汇报.md`。
