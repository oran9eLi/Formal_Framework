# 调试验证与发布门禁

## 1. Debug 开关规则

Debug 使用独立 per-module switch，不设置总开关。关闭 Debug 开关不得改变生产数据路径。

`Debug/Inc/debug_config.h` 是唯一调试配置入口。底部派生宏由 per-module switch 自动计算，不得手动编辑。

常用开关：

```c
#define DEBUG_BOOT_LOG_ENABLE              1U
#define DEBUG_BUSINESS_LOG_ENABLE          0U
#define DEBUG_STACK_MONITOR_ENABLE         1U
#define DEBUG_GNSS_MONITOR_ENABLE          1U
#define DEBUG_IMU_MONITOR_ENABLE           1U
#define DEBUG_BARO_MONITOR_ENABLE          1U
#define DEBUG_POWER_MONITOR_ENABLE         1U
#define DEBUG_LORA_MONITOR_ENABLE          1U
#define DEBUG_ALARM_MONITOR_ENABLE         1U
#define DEBUG_STORAGE_MONITOR_ENABLE       0U
```

## 2. Debug 输出约束

- 原始流打印只能由独立 RAW 宏开启。
- 正式耐久测试禁止逐字节、逐帧打印。
- 周期调试输出不得快于 1 Hz，除非专项测试有明确要求。
- ISR 内禁止 `printf`。
- DebugTask 运行在 idle+1，是最低业务优先级，不纳入 watchdog heartbeat。
- 长稳测试时不得开启 raw NMEA 打印，避免串口格式化改变任务时序。

必须能观察以下指标：

- 每个任务最小剩余栈。
- FreeRTOS 最小剩余堆。
- FIFO 峰值与溢出数。
- DMA/协议丢包数。
- CRC 错误数。
- 模块最后接收和最后有效时间。
- 恢复请求、恢复次数和最近恢复结果。

## 3. 构建验证

修改 STM32 固件源码、Keil 工程或外设配置后，必须运行 Keil build verification。

目标：

```text
0 Error(s), 0 Warning(s)
```

验证记录至少包含：

1. Keil 版本和编译器：MDK-ARM v5 + ARMCC 5.06，C 标准 `--c99`。
2. 构建入口：`MDK-ARM/formal_framework.uvprojx`。
3. Build 或 Rebuild All 的实际结果。
4. 新增模块的栈水位、heap 峰值、错误计数、恢复次数。
5. 无法执行 Keil build 时的原因和未验证风险。

文档或仓库规则修改不需要强制跑 Keil build，但必须说明未跑 build 的原因。

## 4. 必测项目

新增或调整模块必须按风险选择测试项：

| 测试项 | 目的 |
|---|---|
| DMA 缓冲区回绕 | 验证读写位置和丢弃策略 |
| 半帧、粘包、乱序、CRC 错误 | 验证解析器不发布半包 |
| 部分发送 | 验证发送接口语义和重试 |
| 结构体复制中任务切换 | 验证 snapshot 一致性 |
| 队列、FIFO、内存池满 | 验证背压和丢弃计数 |
| 传感器拔出、恢复和抖动 | 验证 Health 与 recovery |
| GNSS 有数据无定位 | 验证 ONLINE 与 DEGRADED 区分 |
| SD 卡拔出和写入超时 | 验证低优先级阻塞 I/O 不影响采集 |
| LoRa/5G-A 断链重连 | 验证通信状态和恢复 |
| Debug 关闭长稳运行 | 验证调试不改变生产路径 |

通过异常注入和至少 24 小时运行测试后，模块才可标记为正式完成。

## 5. 发布门禁

发布构建必须满足：

1. Rebuild All 达到 `0 Error(s), 0 Warning(s)`。
2. 发布包包含固件、构建日志、版本信息、map/axf/hex 和校验值。
3. `05_完成度与后续清单.md` 已记录完成度、验证结果、未完成项和下一步入口。
4. `Change_History/` 已记录本次架构、协议、任务、显示、日志、存储或外设边界变化。
5. 代码框架有变化时，本编号手册已同步更新。

## 6. 专项说明

### ATK-MD0700 / GT911

- 显示硬件初始化和触摸读写归 Display/BSP 边界。
- 页面刷新归 `biz_display`，触摸优先，单步预算 2 ms。
- 显示业务数据来自 `app_data_api.h`，不得直读 Framework topic 或传感器驱动。

### I2C 共享总线

- I2C 设备恢复必须由资源所属任务执行。
- ISR、Health 和 Debug 不得直接执行总线 reinit。
- 共享总线设备需要退避，避免显示、IMU、Baro 等模块互相放大阻塞。

### SD CSV 日志

- Storage 使用注册式 SD CSV 日志服务，读取 Framework topic。
- 低优先级阻塞 I/O 不纳入 watchdog 集合。
- 小规模嵌入式数据存储优先采用 filesystem-based storage，除非有明确理由才引入数据库。
