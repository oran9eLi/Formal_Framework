# 调试验证与发布门禁

## 2026-07-01 SRAM 门禁补充
- Keil Rebuild All 后必须检查 `.map` 中 `Execution Region RW_IRAM1` 和 `Total RW Size`。STM32F407 主 SRAM1 只有 128KB，发布构建不能只看 Error/Warning。
- LVGL draw buffer、FreeRTOS heap、LoRa/MAVLink 远端缓存和任务栈必须共同留下可解释的 SRAM1 余量。当前门禁参考值：`RW_IRAM1` 剩余量不低于 20KB；低于该值时必须先收缩静态缓冲或任务栈，再进入实机长稳。
- 本次验证基线：`build_2026-07-01_slave_sram_fix.log`，`Code=270316 RO-data=91608 RW-data=1392 ZI-data=103096`，`0 Error(s), 0 Warning(s)`；`RW_IRAM1 Size=0x19828`，剩余约 26.0KB。

## 2026-07-01 实时闭环验证补充
- 主从显示闭环测试必须同时观察：远端节点列表是否在 1 s 内出现新 heartbeat 节点，选中节点后是否收到 `COMMAND_ACK`，远端页左上角 `DCDW-%03u` 是否匹配当前选中 node_id。
- 告警和消息日志同步测试不能只等 8 s 周期；制造模块 OFFLINE/恢复或业务日志变化后，应在选中远端视图的 comm 周期内看到 `REMOTE_ALARM`/`REMOTE_LOG` 调度计数增长，Display 日志版本同步变化。
- LoRa 丢包率测试要覆盖长断链：断开超过 128 个 MAVLink seq 间隔后恢复，`sequence_lost_count` 必须继续增长，不允许归零或静默忽略。
- 本机消息日志压力测试要覆盖 Business 写入同时 Display/Comm 读取，日志条目 sequence、message_id、time_hhmmss 不得出现撕裂组合。
- Display 刷新验证以 100 ms 聚合快照和 2 ms LVGL budget 为门槛，`budget_busy_count` 可以增长但不得导致 sensor/comm 心跳超时。

## 2026-07-01 稳定性验证补充

- Rebuild All 通过后，还需要用 Debug 分项逐项观察：BME280 采样不阻塞 sensor 周期、LoRa 拔插时 comm 周期不出现 500 ms 级停顿、LCD 断开再接回后 Display facade ready 能恢复。
- LoRa 测试必须同时观察 TX/RX 计数、parser error、RX drop、sequence lost 和 loss rate；高丢包率不能只靠调低显示刷新解释。
- Fatal path 验证时，`Error_Handler()` 只允许停 DMA/异步发送并关中断，不允许做 SD 写入、协议发送或页面刷新。
- 启动 heap 水位必须大于 `PX4LITE_HEAP_MIN_FREE_BYTES`。低于阈值应视为启动失败，不得只打印日志。
- 硬件 watchdog 当前仍保持关闭，原因是 BSP watchdog init/feed 尚未实现。发布前必须补齐 BSP 实现后再开启，并重新验证 watchdog 喂狗门控。

## 1. Debug 开关规则

Debug 使用独立 per-module switch，不设置总开关。关闭 Debug 开关不得改变生产数据路径。

`Debug/Inc/debug_config.h` 是唯一调试配置入口。底部派生宏由 per-module switch 自动计算，不得手动编辑。

常用开关：

```c
#define DEBUG_BOOT_LOG_ENABLE              1U
#define DEBUG_BUSINESS_LOG_ENABLE          0U
#define DEBUG_STACK_MONITOR_ENABLE         1U
#define DEBUG_GNSS_MONITOR_ENABLE          1U
#define DEBUG_IMU_MONITOR_ENABLE           1U
#define DEBUG_BARO_MONITOR_ENABLE          1U
#define DEBUG_POWER_MONITOR_ENABLE         1U
#define DEBUG_LORA_MONITOR_ENABLE          1U
#define DEBUG_ALARM_MONITOR_ENABLE         1U
#define DEBUG_STORAGE_MONITOR_ENABLE       0U
```

Debug 分项自测统一由 `DEBUG_SELFTEST_ENABLE` 加单项开关控制，默认必须全部关闭：

```c
#define DEBUG_SELFTEST_ENABLE                0U
#define DEBUG_SELFTEST_IMU_SNAPSHOT_ENABLE   0U
#define DEBUG_SELFTEST_BSP_INIT_ENABLE       0U
#define DEBUG_SELFTEST_DISPLAY_BUDGET_ENABLE 0U
#define DEBUG_SELFTEST_REMOTE_VIEW_ENABLE    0U
#define DEBUG_SELFTEST_GT911_ENABLE          0U
#define DEBUG_SELFTEST_GNSS_ENABLE           0U
#define DEBUG_SELFTEST_LORA_ENABLE           0U
```

使用规则：

1. 每次只开启一个自测项，便于隔离 IMU snapshot、BSP 初始化、LVGL 预算、远端视图、GT911 触摸、GNSS 或 LoRa 问题。
2. 自测代码只能复制现有只读快照并通过 DebugConsole 打印，不得执行外设重新初始化、协议发送、SD 写入或 UI 渲染。
3. Debug 自测属于跨层诊断特例；Business、Display 和 Framework 的正式代码不得照搬 Debug 中的 BSP/Driver 直接读取方式。
4. 关闭 `DEBUG_SELFTEST_ENABLE` 后，`DebugSelfTest_Run()` 不改变生产数据路径，也不应引入额外任务负载。

## 2. Debug 输出约束

- 原始流打印只能由独立 RAW 宏开启。
- 正式耐久测试禁止逐字节、逐帧打印。
- 周期调试输出不得快于 1 Hz，除非专项测试有明确要求。
- ISR 内禁止 `printf`。
- DebugTask 运行在 idle+1，是最低业务优先级，不纳入 watchdog heartbeat。
- 长稳测试时不得开启 raw NMEA 打印，避免串口格式化改变任务时序。
- GNSS/LoRa selftest 只能通过 App/Framework 只读快照和统计接口观察，不得直接读取 DMA buffer、Driver 私有变量或执行协议发送。

必须能观察以下指标：

- 每个任务最小剩余栈。
- FreeRTOS 最小剩余堆。
- FIFO 峰值与溢出数。
- DMA/协议丢包数。
- CRC 错误数。
- 模块最后接收和最后有效时间。
- 恢复请求、恢复次数和最近恢复结果。

## 3. Fatal 现场保存

- HardFault、MemManage、BusFault 和 UsageFault 必须在停机前保存 fault snapshot。
- fault snapshot 至少包含 fault 类型、EXC_RETURN、MSP、PSP、active SP、stacked PC/LR/xPSR、CFSR、HFSR、BFAR 和 MMFAR。
- Fault Handler 内禁止 `printf`、SD 写入、总线访问、协议发送和页面渲染，只允许保存寄存器现场后进入死循环。
- FreeRTOS stack overflow hook 必须保存 task handle 和短 task name 副本；不在溢出现场打印。

## 4. 构建验证

修改 STM32 固件源码、Keil 工程或外设配置后，必须运行 Keil build verification。

目标：

```text
0 Error(s), 0 Warning(s)
```

验证记录至少包含：

1. Keil 版本和编译器：MDK-ARM v5 + ARMCC 5.06，C 标准 `--c99`。
2. 构建入口：`MDK-ARM/formal_framework.uvprojx`。
3. Build 或 Rebuild All 的实际结果。
4. 新增模块的栈水位、heap 峰值、错误计数、恢复次数。
5. 无法执行 Keil build 时的原因和未验证风险。

文档或仓库规则修改不需要强制跑 Keil build，但必须说明未跑 build 的原因。

## 5. 必测项目

新增或调整模块必须按风险选择测试项：

| 测试项 | 目的 |
|---|---|
| DMA 缓冲区回绕 | 验证读写位置和丢弃策略 |
| 半帧、粘包、乱序、CRC 错误 | 验证解析器不发布半包 |
| 部分发送 | 验证发送接口语义和重试 |
| 结构体复制中任务切换 | 验证 snapshot 一致性 |
| 队列、FIFO、内存池满 | 验证背压和丢弃计数 |
| 传感器拔出、恢复和抖动 | 验证 Health 与 recovery |
| GNSS 有数据无定位 | 验证 ONLINE 与 DEGRADED 区分 |
| SD 卡拔出和写入超时 | 验证低优先级阻塞 I/O 不影响采集 |
| LoRa/5G-A 断链重连 | 验证通信状态和恢复 |
| Debug 关闭长稳运行 | 验证调试不改变生产路径 |

通过异常注入和至少 24 小时运行测试后，模块才可标记为正式完成。

## 6. 发布门禁

发布构建必须满足：

1. Rebuild All 达到 `0 Error(s), 0 Warning(s)`。
2. 发布包包含固件、构建日志、版本信息、map/axf/hex 和校验值。
3. `05_完成度与后续清单.md` 已记录完成度、验证结果、未完成项和下一步入口。
4. `Change_History/` 已记录本次架构、协议、任务、显示、日志、存储或外设边界变化。
5. 代码框架有变化时，本编号手册已同步更新。

## 7. 专项说明

### ATK-MD0700 / GT911

- 显示硬件初始化和触摸读写归 Display/BSP 边界。
- 页面刷新归 `biz_display`，触摸优先，单步预算 2 ms。
- 显示业务数据来自 `app_data_api.h`，不得直读 Framework topic 或传感器驱动。

### I2C 共享总线

- I2C 设备恢复必须由资源所属任务执行。
- ISR、Health 和 Debug 不得直接执行总线 reinit。
- 共享总线设备需要退避，避免显示、IMU、Baro 等模块互相放大阻塞。

### SD CSV 日志

- Storage 使用注册式 SD CSV 日志服务，读取 Framework topic。
- 低优先级阻塞 I/O 不纳入 watchdog 集合。
- 小规模嵌入式数据存储优先采用 filesystem-based storage，除非有明确理由才引入数据库。
