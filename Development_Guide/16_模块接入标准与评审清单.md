# 模块接入标准与评审清单

> 本文把已跑通并对齐的 **GNSS(接收/传感器类样板)** 和 **LoRa(通信类样板)** 提炼为统一接入标准。
> 后续传感器或外设(IMU、气压、电源、5G、CAN、SD…)一律照此执行。
> 规范母本见 [01_强制开发规范.md](01_强制开发规范.md);本文是其落地形态与评审勾选表。
> 凡标 **【需构建确认】/【需运行确认】** 的项,以 Keil/ARMCC5 构建与实机为准。

---

## 0. 两类样板

| 范式 | 样板模块 | 数据方向 | 数据模型 |
|---|---|---|---|
| 接收/传感器类 | **GNSS(ATGM336H)** | 只收 | Latest Snapshot(低频)/ FIFO(高频) |
| 通信类 | **LoRa(E22 + MAVLink)** | 收发 | RX Snapshot + TX 异步复制单帧 |

新模块先归类,再对照对应样板。两类共享 §3 的统一规则。

---

## 1. 分层与依赖(强制)

```
Business  ── 只经 app_data_api.h 读快照,禁止 include BSP/Sensor
Framework ── 平台适配(px4lite_platform_f407.c)是唯一可调 BSP 的框架文件
Sensor    ── 芯片协议/解析/设备私有状态;可 include BSP 头,禁止直接 include stm32f4xx_hal.h、禁止调 HAL_*
BSP       ── 唯一持有 HAL 与硬件;句柄私有 static + 访问器
```

铁律:
- **HAL 只出现在 BSP 层。** Sensor 驱动用 CMSIS(`stm32f4xx.h`)拿内联函数,时间用入参 `now_ms` 或 `BSP_Time_GetTickMs()`,**绝不调 `HAL_GetTick()`**。
- 上层禁止跨过数据交换层直接读 DMA 缓冲。
- 业务/显示只经 `app_data_api.h`(`App_Copy*`),不直读 Framework topic。
- 依赖单向:`Business → Framework → (platform adapter) → BSP`;`Sensor → BSP`。

## 2. 样板 A:接收/传感器类(以 GNSS 为准)

逐层职责与对应实现:

| 层 | 文件 | 职责 | 关键点 |
|---|---|---|---|
| BSP | [bsp_gnss.c](../Bsp/Src/bsp_gnss.c) | USART+循环 DMA 接收 | 私有 `s_rx_buf`;句柄 `s_gnss_uart` static + `BSP_GNSS_GetUartHandle()`;IDLE/DMA ISR 只推进写指针;丢最旧 + `drop_count`;`DeInit`/`RecoverRx` |
| Sensor | [sensor_gnss.c](../Sensor/Src/sensor_gnss.c) | 取字节、组帧、解析、维护私有快照 | NMEA 状态机:`$`→体→`*`校验→`\r\n`,**校验失败丢整帧、不刷新 `last_fix_ms`**;`rx_sequence` 判新数据;`data_state` 只表硬件事实 |
| 适配 | [px4lite_platform_f407.c](../Framework/Src/px4lite_platform_f407.c) | 驱动快照→框架测量 | `Px4Lite_GnssRead` 用 `last_rx_sequence` 去重,`rx_sequence==0/未变` 返回 `IDLE` |
| 框架 | [px4lite_modules.c](../Framework/Src/px4lite_modules.c) | 发布测量、升状态、健康超时 | `SensorWorkRun` 仅在拿到数据时升 ONLINE/DEGRADED + 写 `last_rx_ms`/计数;`HealthRun` 判 OFFLINE |
| Topic | [px4lite_topics.c](../Framework/Src/px4lite_topics.c) | Latest Snapshot 发布/拷贝 | 短临界区整体复制 + ready 标志 |

驱动接口目标形态(§4):

```c
Result_t  Device_Init(void);                 /* 只初始化本设备资源 */
Result_t  Device_Service(uint32_t now_ms);   /* 统一采集任务调用,不永久阻塞 */
Result_t  Device_CopySnapshot(Snapshot_t*);  /* 只复制已发布的完整数据 */
Result_t  Device_GetStatus(Status_t*);       /* 不访问慢速总线 */
```

> GNSS、IMU、BARO、BATTERY 已对齐目标形态:`Service(now_ms)` + `CopySnapshot` + `GetStatus`。
> 热插拔恢复见 §4.5:模块注册 `recover` 钩子,Health 侧监视器判定、驱动 `Service` 执行重初始化。
> BME280 额外保留自身的连错重初始化兜底(已验证),与监视器并存。

## 3. 样板 B:通信类(以 LoRa 为准)

在样板 A 的接收链基础上,增加发送链:

| 层 | 文件 | 发送职责 | 关键点 |
|---|---|---|---|
| BSP | [bsp_lora.c](../Bsp/Src/bsp_lora.c) | USART TX DMA(整帧) | 私有 `s_tx_buf`;`StartSend` 复制后启 DMA;`HAL_UART_TxCpltCallback`(TC)置 `s_tx_busy=0` = **空口发完**;`AbortTx` 兜底 |
| Sensor | [lora_e22.c](../Sensor/Src/lora_e22.c) | 非阻塞 TX 状态机 | IDLE→WAIT_AUX→SENDING,**单帧在飞**,忙则 `BUSY`;AUX 超时按 E22 空中速率计算，UART DMA 超时按串口波特率计算;`Lora_E22_Send` = 异步复制语义 |
| 框架 | [px4lite_mavlink_tx.c](../Framework/Src/px4lite_mavlink_tx.c) | topic→MAVLink 帧、轮询调度 | 经 `Copy*`+`IsFresh`+`sequence` 去重;失败按 `RETRY_PERIOD` 重试;`s_frame` comm 任务单一所有者 |
| 框架 | [px4lite_modules.c](../Framework/Src/px4lite_modules.c) `CommWorkRun` | 记录收发活动、升状态 | 只写 `last_rx_ms`/`last_valid_ms`(=max rx/tx)/计数,升 ONLINE/DEGRADED;**OFFLINE 交 Health** |

发送语义(§9.2,必须在接口处注明):
- **异步复制**:`Send` 返回 OK = 已复制并暂存一帧,调用者可立即复用缓冲;OK **不代表已空口发出**。
- "发送成功"(`tx_frame_count`/`last_tx_ms`)只在 TC 完成回调记。
- 帧格式用 **MAVLink**(magic+版本+长度+序号+CRC,字段级编码),**禁止直接发结构体内存**。
- 新增上行命令/参数/控制消息**必须有端到端 ACK**(§9.5);当前只有遥测下行,无需 ACK。

## 4. 统一规则(两类共用,从样板提炼)

1. **句柄私有**:BSP 外设句柄 `static`,对 ISR/MSP 只暴露 `*_GetUartHandle()` 访问器。禁止全局可写句柄与跨文件 `extern`。
2. **时间源**:名以 `_ms` 结尾存真实毫秒;框架用 `Px4Lite_PlatformGetMs()`,Sensor 用入参 `now_ms` 或 `BSP_Time_GetTickMs()`。周期任务用 `vTaskDelayUntil`。时间差一律无符号回绕减法 `(int32_t)(now-deadline)>=0`。
3. **DMA 接收**:专属私有缓冲;ISR 只更新写位置;消费者独立读位置;满了"丢最旧 + `drop_count`",禁止静默覆盖;`__get_PRIMASK` 保存/恢复,**禁止无条件 `__enable_irq()`**;USART 错误中断触发 `*_RecoverRx`。
4. **防半包/半段**:流式协议必须 头→体→校验→完整 才交付;校验失败丢整帧、不刷新 `last_valid`。
5. **发布**:采集→校验→单位换算→质量→填完整临时结构→**一次性发布**;Latest Snapshot 用短临界区整体复制 + `sequence` + 时间戳;读侧 `IsFresh` + `sequence` 去重。临界区内禁止解析/打印/访问外设。
6. **状态单写者(§13.5)**:驱动/采集只表"硬件事实 + 升 ONLINE/DEGRADED";**OFFLINE/FAILED/降级一律 Health 判定**;新数据检测用独立 `sequence`,不得用时间戳是否变化代替。
7. **发送缓冲区所有权(§13.2)**:文件级发送缓冲在声明处标注唯一拥有任务;在飞期间不得重编码。
8. **调试(§12)**:原始流用独立 RAW 宏;周期输出 ≤1Hz;ISR 内不 `printf`;关调试不改采集/解析/状态机/发布逻辑。
9. **启用开关**:`PX4LITE_ENABLE_*=0` / `BSP_ENABLE_*=0` 时不建任务、不注册模块、不初始化外设、不占队列与缓冲。
10. **不靠加栈/加堆掩盖设计**;大数据传索引/指针,不复制整块;每任务定期记录最小剩余栈与堆水位。

## 4.5 热插拔恢复(模块化,注册表驱动)

每个可恢复模块在注册时填一个 `recover` 回调即自动纳管;恢复引擎 [px4lite_recovery.c](../Framework/Src/px4lite_recovery.c) 遍历所有已注册模块,**新增模块零改动**。

职责分层(安全要点):
- **判定在 Health**:`Px4Lite_RecoveryMonitorRun`(HealthRun 调)遍历已注册模块,谁 `OFFLINE/FAILED` 或连错 ≥ `PX4LITE_RECOVERY_ERROR_THRESHOLD`、且距上次尝试 ≥ `PX4LITE_RECOVERY_DELAY_MS`,就调它的 `recover`。重试只限速、**不封顶** → 拔走任意时长再插回都恢复(热插拔)。
- **`recover` 回调必须廉价**:只置一个"请求重初始化"标志(`Sensor_X_RequestReinit`),**禁止在此做阻塞总线 I/O**——否则会在 Health 任务里与采集/通信任务争用同一外设(I2C/UART)。
- **重初始化在驱动 `Service` 执行**:`Service` 顶部见到标志 → 调 `Sensor_X_Init()`(在拥有该总线的任务里,安全);失败则保持未就绪、返回 `NO_DATA`,等下次置位。

为什么不是"每个驱动各自定时重试":那样阈值/退避要在每个驱动里重复、策略分散。注册表驱动把**策略集中一处**,模块只贡献"重初始化动作"。

开关 `PX4LITE_RECOVERY_ENABLE`:仅当所有 `recover` 回调都是廉价置位形态后才可开(否则监视器会在 Health 里触发阻塞 init)。

## 5. 新模块接入步骤

1. **归类**:接收类(样板 A)还是通信类(样板 B)。
2. **BSP**:在 `Bsp/` 加寄存器/总线/DMA 处理,句柄私有 + 访问器,加 `*_RecoverRx`;在 [bsp_config.h](../Bsp/Inc/bsp_config.h) 配引脚/DMA/中断,中断在 [stm32f4xx_it.c](../Core/Src/stm32f4xx_it.c) 路由(经访问器,勿 `extern` 句柄)。
3. **Sensor**:在 `Sensor/` 加芯片解析与私有快照,按 §4 目标接口;时间走 `now_ms`/`BSP_Time`,不碰 HAL。
4. **适配**:在 [px4lite_platform_f407.c](../Framework/Src/px4lite_platform_f407.c) 加 HAL-free 适配,驱动快照→框架测量,`sequence` 去重。
5. **类型/Topic**:在 [px4lite_types.h](../Framework/Inc/px4lite_types.h) 加带 `Px4Lite_TopicHeader_t` 的测量类型;在 [px4lite_topics.*](../Framework/Src/px4lite_topics.c) 加发布/拷贝(低频 Snapshot,高频 FIFO,大帧内存池)。
6. **调度**:只挂进已有任务的周期表(`SensorWorkRun`/`CommWorkRun`),**不要一外设一任务**;新建任务须满足 [02_总体架构图.md](02_总体架构图.md) 的 4 个准入条件并附栈预算与运行监控。
7. **配置**:在 [px4lite_config.h](../Framework/Inc/px4lite_config.h) 加 `ENABLE`、采集周期、`OFFLINE_MS`、`MAX_AGE_MS`、启动宽限。
8. **健康/恢复**:在 `HealthRun` 加该模块的超时→OFFLINE 分支(单写者);注册 descriptor 时填 `recover` 钩子(廉价置位)+ 驱动 `Service` 执行重初始化,即获得热插拔恢复(§4.5)。
9. **消费**:业务/显示经 `app_data_api.h` 读;需要的话在 `App_Copy*` 加字段。
10. **调试**:加独立 RAW 宏与 ≤1Hz 周期报告。
11. **填表**:填本文 §6 评审清单 + 在 [15_模块数据契约与评审门禁应答.md](15_模块数据契约与评审门禁应答.md) 增该模块条目。

## 6. 评审清单(合入前逐项勾选)

合入前每项必须可回答(对应 [01_强制开发规范.md](01_强制开发规范.md) §13):

- [ ] 接收缓冲区唯一所有者是谁?句柄是否 `static` + 访问器(无全局 `extern`)?
- [ ] 谁写谁读?是否有 所有权/长度/序号/时间戳/有效标志?
- [ ] 读不到半写数据:Snapshot 短临界区复制 / FIFO / 序号一致性,哪一种?
- [ ] 如何识别完整帧?校验失败是否丢整帧、不刷新 `last_valid`?
- [ ] 发送:同步 / 异步复制 / 异步零拷贝?接口是否注明?部分发送如何处理?
- [ ] "发送成功"的定义是否=完整帧已交付(非"开始发送")?
- [ ] 超时与恢复策略?`RecoverRx` 是否重启 DMA 并清读写位置?
- [ ] 数据失效后旧值如何处理(`MAX_AGE`→STALE)?
- [ ] 时间字段 `_ms` 是否真毫秒?是否经 `now_ms`/`BSP_Time`/`PlatformGetMs`(未直调 HAL)?
- [ ] 公开状态是否单写者?OFFLINE/FAILED 是否由 Health 判定?
- [ ] 该模块是否未一外设一任务?新增任务是否附栈预算/优先级/周期/WCET?
- [ ] 功能关闭时是否释放对应任务/队列/缓冲?
- [ ] Sensor 层是否未直接 include `stm32f4xx_hal.h`、未调 `HAL_*`?
- [ ] 调试关闭是否不改采集/解析/状态机/发布?周期输出 ≤1Hz?ISR 无 `printf`?
- [ ] **【需构建确认】** ARMCC5 是否 0 Error / 0 Warning?
- [ ] **【需运行确认】** 最小剩余栈 >25% 且 ≥100 word?堆峰值 ≤75%?FIFO 峰值/溢出?
- [ ] **【需运行确认】** §14 异常注入(半帧/粘包/乱序/CRC 错/缓冲满/拔出抖动/断链重连)+ ≥24h?

任一项无法回答,不得合入。
