# Pi命令结果提示：F407接入说明

2026-11-16适用边界：默认已启用[CNS V0.1六动作接口](CNS控制接口_F407端_V0.1.md)。这六类动作接受后的声光由F407自行编排，Pi仅在拒绝后发`01 00`失败通知，不追加通用成功提示。下文原Pi终态提示策略适用于其他保留业务或关闭CNS的兼容构建。

本说明面向树莓派对接和固件维护者。依据用户提供的《Pi命令结果提示与F407接口.md》，本仓库实现F407接收端；Pi的MQTT终态汇总、128条请求级去重及身份绑定等由Pi程序负责，不在此固件内模拟。

## 发送格式

| 字段 | 值 |
|---|---|
| 链路 | 现有Pi→F407 UART6，MAVLink2 |
| 消息／payload_type | TUNNEL，ID385／0x8040（32832） |
| 源system／目标system | 两者均为当前F407非零动态system ID，不固定编号、不接受广播 |
| 源component／目标component | Pi 191／F407 193 |
| payload_length | 2字节 |
| payload[0] | version=1 |
| payload[1] | 1成功、0失败；其他值忽略，不能直接套用MAV_RESULT_ACCEPTED=0 |
| 校验／应答 | 标准MAVLink CRC；该通知不返回COMMAND_ACK |

成功数据区为`01 01`，失败为`01 00`。MAVLink2裁掉消息尾零后，成功外层len7、失败len6均合法；两者内层声明长度仍为2。完整133字节TUNNEL也接受，声明区之外填充不属于这两个协议字节。F407复用既有消息重建清零及标准解码，保证被省略的失败result恢复为0，ARMCC未对齐getter分支也已验证。

通知只能播放对应结果声光，不执行电机控制、不修改控制状态、不产生ACK。合法连续两条成功／失败会分别入队，因为两字节没有请求ID，F407不能按结果值去重。队列仍为既有有界8项，满时仅丢提示并累计软件计数，不保证实物一定发声。

## 提示来源

默认配置`PX4LITE_RPI_RESULT_SOURCE_PI=1`：Pi形成最终结果后发送0x8040，F407统一触发原高音／绿青快闪或低音／暗红慢闪。原Control、COMMAND_LONG和波特率配置的本地自动声光来源关闭，避免同一个命令双响；业务执行、原ACK、原配置重试保留。模块插拔提示、启动音和渐变独立保持。

需要回退原本地执行结果提示时，配置`PX4LITE_RPI_RESULT_SOURCE_PI=0`重新构建；此时0x8040静默，本地结果提示恢复。总开关`PX4LITE_ENABLE_RPI_COMMAND_FEEDBACK=0`会关闭命令结果提示，不关闭模块插拔提示。来源派生宏无需手改，两种来源互斥。

## 联调与职责边界

1. Pi完成身份／端点核验后，用当前动态ID发送成功`01 01`，应听到原成功旋律及对应灯效；发送失败`01 00`，应得到失败效果。
2. 错误source／target、广播system、错误组件、长度、版本或结果应静默；心跳和普通遥测不提示。通知没有ACK，不应等待F407对此包应答。
3. 下发原业务命令，F407仍执行并返回原ACK，但默认不会在本地自行提示；待Pi发送0x8040后提示一次。连续不同请求同结果应在Pi按请求标识去重后分别发送。
4. 核对模块连接提示仍正常；本地回退模式不要同时再依赖Pi结果通知。

原业务控制ACK含义没有改变：例如当前AUTO起降的ACCEPTED表示斜坡已接受，不代表到达终点。本次未新增“IN_PROGRESS→终态ACK”控制协议；若Pi所选动作需要过程完成语义，应使用可信的终态来源，不能把原启动ACK当实际完成。本接口只播放Pi提供的终态结果，不补造任务完成事实。

Pi端负责文档中的终态时机、非法请求处理、128条请求级去重、离线／身份冲突时丢弃、恢复不补发历史、写失败不重试及MQTT回执独立性。当前仓库不含对应Pi命令服务，未新增或声称这些Pi能力已由F407实现。
