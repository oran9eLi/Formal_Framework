## 3. P1：优先修复

### A01：远端查看模式会停止维护本机低压闭锁

- 位置：`Display/Src/display.c:889–900`，关键为 893 行；`Framework/Src/px4lite_control.c:619–628`。
- 根因：唯一实际调用 `App_SetMotorPowerInhibit()` 的周期入口属于 Display，REMOTE 模式直接返回。本机电机已运行时切到远端视图，本机电池随后低压，Control 中闭锁值仍保持先前的“允许”，旧目标也不会因该低压变化清除。反向情况下，旧闭锁也不能随本机电池恢复及时解除。
- 复现：`repro_product.c` 调用真实 `Display_ApplyMotorPowerInhibit()`：本地健康 `calls=1/inhibit=0`；远端模式低电档仍 `calls=1/inhibit=0`；回到本地才 `calls=2/inhibit=1`。
- 修复方向：让 Control/Health 的固定周期入口按本机 Battery2 的有效性、年龄和电压独立维护闭锁，显示只呈现结果。禁止使用当前查看节点的电池值控制本机。
- 验收：本机输出非零→切换远端查看→本机电池低压/断采/恢复，均按本机状态撤收/闭锁；恢复后不能自动恢复旧油门。默认 `PX4LITE_ENABLE_COMMAND=0`，不要把默认关闭的命令路径当作本次复现证据。

### A02：致命异常后 PWM 保持旧输出，直到 IWDG 复位

- 位置：`Core/Src/stm32f4xx_it.c:59–61` 及 93–95；`Core/Src/main.c:93–97`；`Core/Inc/FreeRTOSConfig.h` 的 `configASSERT`。
- 根因：Fault 入口关中断后保存现场并死循环；Error_Handler 只清理 UART DMA；断言也直接关中断死循环。均未撤收 TIM3/TIM4 电机 PWM。定时器硬件仍运行，200 ms 软件失效保护此时无法执行。
- 影响：电机已有非零输出时发生 HardFault、栈溢出或断言，输出可能保持到看门狗复位。当前 IWDG 配置标称约 2.5 秒，具体时延随 LSI 频率变化；本轮未实测波形。
- 修复方向：在这些终止入口最前面调用不依赖调度、互斥锁、HAL tick 或完整句柄的 BSP 紧急输出撤收入口，然后保存现场。明确采用最小油门还是禁用通道，并按实物 ESC 行为验证。
- 验收：示波器监测四路 PWM，分别注入 HardFault、栈溢出、断言；证明输出在规定时间内撤收，且不依赖 IWDG 最终复位。

## 4. P2：稳定版应处理

### A03：LoRa 半帧超时没有重置真正的 MAVLink 解析器

- 位置：`Sensor/Src/lora_e22.c:288–292`，调用点 498–503；库实际状态见 `Third_Party/mavlink/mavlink_helpers.h:926–931`。
- 根因：只清空 `mavlink_parse_char()` 的输出 message/status；实际解析状态保存在该翻译单元的 channel 内部对象。旧半帧继续影响超时后的数据，错误恢复/重新初始化同样调用这个无效重置。
- 复现：`repro_comms.c` 输入 heartbeat 头和一字节载荷，静默 500 ms，再输入完整 heartbeat，实际驱动接受帧数为 **0，预期 1**。
- 修复/验收：重置实际 channel，或改用显式持有状态的 `mavlink_frame_char_buffer()`；验证半帧→超时→完整帧、UART 错误和重新初始化。RPi 侧有相同输出对象清零写法，修复时同步审视；普通切速率请求刚好在完整帧后处理，不能据此宣称每次切换都失败。

### A04：一次 CRC 错误导致 LoRa 丢包计数增加 65536

- 位置：`Sensor/Src/lora_e22.c:535–540`；库返回语义见 `Third_Party/mavlink/mavlink_helpers.h:858–865`。
- 根因：把返回的本次错误数当作累计计数作差；其值从 0→1→0 时，无符号差值累加为 65536。输出结构的 `parse_error` 又没有被库更新，CRC/解析错误计数保持零。
- 复现：同一 `repro_comms.c` 实际输出 `drops=65536 crc_errors=0 parse_errors=0`。
- 修复/验收：按库实际语义统计错误，区分队列溢出、序号缺失、CRC 与解析错误；单错帧、连续错帧、重新初始化后统计均应可解释。

### A05：RTC 时间帧替旧远端定位刷新了有效期

- 位置：`Framework/Src/px4lite_mavlink_rx.c:532–543`；发送端 `px4lite_mavlink_tx.c:981–1002`。
- 根因：GNSSUTC 仅包含时间，却更新整个 NAVIGATION 的有效位和时间；BAROALT 也扩大为整个导航域有效。对端 GNSS 拔出后，发送端继续发送 RTC 时间，旧坐标、fix 和卫星数因此不会按位置更新时刻过期。
- 修复/验收：分开维护位置、速度、时间、气压高度的有效性和时间戳。先定位再拔掉 GNSS，同时保留 RTC/IMU/气压通信，位置必须按阈值失效，时间仍正常显示。证据为静态完整调用链。

### A06：显示组合快照忽略其中一个域已经过期

- 位置：`Business/Src/app_display_model.c:100–125`；环境/电池同类组合在 138–153。
- 根因：导航和姿态任一域新鲜就返回 OK，但输出有效位只判断 `valid_mask`，忽略相应 `stale_mask`；一个域持续更新会掩盖另一个域断流。
- 复现：`repro_product_remote.c` 明确输入 stale GNSS + fresh ATTITUDE，真实 API 仍返回 OK、`latitude=123456789, fix=3, position_valid=1`。
- 修复/验收：逐域按有效且未过期决定复制和有效位，消费者清除无效字段。分别停止导航、姿态、环境、电池流，其他流继续；过期域不得借其他域刷新。此项与 A05 独立，即使通信层正确标记 stale，显示仍有问题。

### A07：非定位 NMEA 语句为旧 GNSS 测量更新时间

- 位置：`Sensor/Src/sensor_gnss.c:259–265`、300–328；适配器 `Framework/Src/px4lite_platform_f407.c:351–363`。
- 根因：任何校验有效的 NMEA 都更新同一 `rx_sequence/last_rx_ms`；适配器将后者作为测量时间。GGA/有效定位停止，但 GSV/GSA 等持续到来时，旧 fix/坐标没有独立的年龄约束，可反复发布为新测量。
- 修复/验收：分别记录链路活动与位置/速度等测量的更新；有效 GGA 后只发送 GSV/GSA，并注入持续坏校验 GGA，链路可在线而位置必须按时过期。证据为静态数据流。

### A08：横滚滤波在 ±180° 处跨界跳变

- 位置：`Framework/Src/px4lite_attitude.c:356–362`。
- 根因：陀螺预测角和 `atan2f` 加速度角直接线性插值，把约 +181° 和 −179° 当作相差 360°。
- 复现：`repro_product_attitude.c` 链接真实算法，两帧横滚 **179.03°→166.86°**，实际应接近 **−179.03° / +180.97°**。
- 修复/验收：对角度残差做归一化，再沿最短角差滤波并归一化输出。覆盖双向跨界、倒置附近静止噪声、慢转和连续多圈；显示相对基准的既有修复不能替代算法本体修复。

### A09：SD 文件准备失败绕过降级和恢复

- 位置：`Storage/Src/storage_sd.c:226–235`，准备逻辑 119–156，服务提前返回 180 行。
- 根因：打开文件、写表头或 seek 失败时直接返回 IO_ERROR，没有进入正常写失败的关闭文件、错误计数和 DEGRADED 路径。首次挂载成功但首个文件打开失败时，可保持 ONLINE；服务不重挂载，没有打开文件时 Sync 又返回成功，上层已弹出的记录被丢弃。
- 修复/验收：文件准备失败统一进入清理/降级/恢复，并保留真实错误与丢弃计数。注入 f_open、header write、seek、sync 的失败，覆盖首次建文件及跨日换文件，不能报在线成功。现有 storage 单测未覆盖真实文件状态机。

### A10：触摸首次初始化失败后不会自动恢复

- 位置：`Display/Src/display_lvgl.c:2526–2534`；`Display/Src/lv_port_indev.c:49–63`。
- 根因：忽略 `LvPortIndev_Init()` 失败并报告 Display 初始化成功。若 GT911 启动时通信失败，输入设备没有注册，后续也没有输入读取回调；自检只看显示 ready，恢复监督无法发现。
- 修复/验收：独立记录触摸就绪/故障，并由显示任务限速重试初始化，覆盖首次缺席、短时通信故障、恢复后重新注册，避免重复注册输入设备。此项为静态调用链确认，未操作实屏。

### A11：电流检测开关关闭后仍主动驱动模拟输入

- 位置：`Bsp/Src/bsp_adc_current.c:200–204`；推挽配置 62–70，每次平均采样前的预置在 122 行。
- 根因：`BSP_ADC_CURRENT_FLOAT_CHECK_ENABLE=0` 仅改变结果清零策略，未关闭 `PinFloating()` 的高/低推挽探测；正常采样也每次先推挽拉低，随即采样。代码注释已经记录 CURR 输出下沉能力弱，仍主动扰动被测信号。
- 修复/验收：开关门控完整探测流程，正常测量保持模拟输入；如需断线检测，结合电路验证限流、弱拉及稳定时间。用示波器和已知电流验证误差；具体电气负荷取决于输出阻抗和 RC，本轮不断言硬件已受损。

### A12：BME280 两阶段状态机被整段节流到 1 秒

- 位置：`Framework/Src/px4lite_modules.c:427–433`；`Sensor/Src/sensor_bme280.c:352–365`、398。
- 根因：外层每 1000 ms 才调用一次 Service。一次触发 forced conversion，下一秒才读取，随后再等一秒触发下一次，因此有效发布约 0.5 Hz；读取时把 `now_ms` 写成采样时间，将约一秒前的测量标新。
- 修复/验收：启动采样周期和推进已有测量分开，等待阶段每个 sensor 周期服务；采样时刻按实际转换记录。检查连续序列、触发/完成时刻、环境新鲜度和高度融合时间对齐。

### A13：临时电流打印占用最高优先级采集任务

- 位置：`Framework/Src/px4lite_app.c:309–311`、340–341；`Debug/Src/debug_console.c:58`。
- 根因：只受派生 `DEBUG_CONSOLE_ENABLE` 控制，默认其他日志开启使该条件成立；关闭 POWER_MONITOR 仍每秒输出整行电流日志。阻塞式 115200 串口发送在 sensor 优先级运行，一行百余字节已接近 10 ms 采集周期，还可能等待 console 互斥量。
- 修复/验收：迁回低优先级 DebugService，用模块开关控制并读取快照；消除 Framework app 直接包含 BSP 诊断头的越层依赖。比较开/关日志的 sensor 最坏周期、IMU 时间间隔及 FIFO 丢弃。

### A14：RTC 保留 LSI 选择时没有保证振荡器已开启

- 位置：`Bsp/Src/bsp_rtc.c:138–139`；后续 `HAL_RTC_Init()` 调用在 178 行附近。
- 根因：首次 LSE 不可用后可回退到 LSI；后续启动看到备份域 RTCSEL=LSI 时，仅更新变量，未重新开启/等待 LSI。若本轮上电/复位已清除 LSION，而备份域仍保留选择，RTC 初始化可能超时，BSP_Init 失败并在调度器启动前停机，此时软件尚未启动 IWDG。
- 修复/验收：保留时钟选择时仍确认该振荡器开启且就绪。重点在无 LSE、VBAT 保留备份域、VDD 断电再上电条件下验证，并分别测试普通复位与 IWDG 复位；不能假定所有复位类型对 LSI 的效果相同。此项为条件性启动缺陷，未进行硬件复现。

### A15：RemoteID 两种时间戳的基准不符合消息定义

- 位置：`Framework/Src/px4lite_remoteid_tx.c:305–307`、337。
- 根因：LOCATION 使用 UTC 当天秒数 `%86400`，捆绑消息头要求当前 UTC 小时内秒数；SYSTEM 使用开机秒数，消息头要求自 2019-01-01 起的秒数。
- 直接依据：`Third_Party/mavlink/common/mavlink_msg_open_drone_id_location.h:13` 和 `mavlink_msg_open_drone_id_system.h:13`。
- 修复/验收：分别转换小时内秒数和 2019 纪元时间，未知值遵循协议。构造跨小时、跨日、无 GNSS/RTC 的向量；实际抓取发往 ESP32 及 RPi 镜像的报文。尚未验证 ESP32 最终广播行为。

### A16：RemoteID 水平速度和方向含义错误

- 位置：`Framework/Src/px4lite_remoteid_tx.c:143–146`、167–174。
- 根因：地速取 `abs(vN)+abs(vE)`，北/东各 100 cm/s 时编码为 200，正确模长约 141；运动方向取相对 IMU yaw，而消息头要求地面航迹方向。
- 修复/验收：从北/东速度或有效 GNSS COG 计算地速模长和航迹角，使用协议规定的未知/饱和值。覆盖对角运动、机头朝向不同于运动方向、静止和无速度输入。

### A17：远端槽查找和复制不原子，可能返回另一节点数据

- 位置：`Framework/Src/px4lite_remote_telemetry.c:173–184`；替换槽位 46–71。
- 根因：读者在临界区外查找槽，进入复制临界区前可被 CommTask 抢占；八槽已满时新节点淘汰该槽并重绑定。读者恢复只检查 valid，可将节点 B 快照作为请求节点 A 的结果返回。节点状态列表另读槽绑定也有类似窗口。
- 修复/验收：在同一临界区内完成槽查找、身份核验及复制，分配/替换也保持一致保护。用第九节点触发淘汰，并在查找后注入一次写者运行，证明请求身份与返回快照一致。此项为可构造的调度交错，未做 RTOS 抢占复现。

## 5. 保留的验证项与未重复报告的问题

- **GNSS DMA 位置更新并发：** `Sensor/Src/sensor_gnss.c:212` 与 USART2 IDLE ISR 均调用 `BSP_GNSS_RxIdleCallback()`，后者 `263–284` 没有任务/ISR 互斥。任务读到旧 pos 后被 ISR 更新 head，再恢复可能把旧位置当作一次回绕，回退 head/tail 或虚增丢弃。已确认共享写者；本轮未执行中断插入点复现，应在收发修复批次补充。
- **心跳门限和启动保护：** biz_system 周期为 1000 ms，统一心跳门限为 500 ms；正常运行中部分时刻会停止喂狗。IWDG 要到所有必要心跳首次健康后才启动，此前的启动卡死没有这层硬件恢复。需定义按任务周期的期限与启动超时，并进行故障注入，不根据现有静态结果断言当前必然复位。
- **comm 栈不能直接判为已溢出：** 调用图给出含 SHA256 的深路径，但当前签名未启用。无签名 H1 路径连同周期包装约 880 B，考虑完整 M4F 上下文约 1084 B，相对 1536 B 栈仍有约 452 B。此为静态估算，不替代最大 RX/TX/中断组合下的实测高水位。
- **波特率 B1 负载：** H1/切速率单测通过；仍需在 57600 下同时开启最大日志、告警、周期遥测及接收压力，记录 20 ms TX timeout、128 B RX 环和任务抢占下的真实收发结果。
- **未重复旧问题：** 已核对四路命令事务、远端操作入口隔离、CSV v2 新鲜度修复；不能照抄 9 月 15 日旧审查。当前节点表已采用动态槽位，sysid 大于 7 本身不会被拒绝，配置中的旧注释需同步，但不是“只支持编号 0–7”的运行缺陷。
- **不提升功能完成度：** 本报告未把任何模块标为正式完成。功能台账继续以 `07_移植进度与功能清单.md` 为事实入口。
