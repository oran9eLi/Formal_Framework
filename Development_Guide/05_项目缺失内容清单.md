# Formal Framework 项目缺失内容清单

## 1. 当前可用能力

以下内容已有真实实现，不属于纯占位：

- STM32F407 系统时钟、HAL、FreeRTOS 启动。
- USART1 调试输出及任务间互斥。
- ATGM336H USART2 + DMA + IDLE 接收链路。
- GNSS NMEA GGA、RMC、GSA、GSV 解析。
- GPS、北斗可见星数和参与定位星数。
- GNSS 原始快照、Framework 类型转换及最新值 topic。
- GNSS 在线、无定位、离线和初始化失败状态。
- GNSS 到导航 topic 的基础转换。
- latest-value 快照保护、IMU FIFO 骨架、告警/命令队列骨架。
- 六个周期任务、任务心跳门控和 FreeRTOS 异常 hooks。
- 非阻塞 Business EventBus 及逐订阅者统计。
- ARMCC5 独立工程及 `Release/Latest` 发布目录。

## 2. P0：形成最小闭环前必须补齐

### 2.1 应用层真实业务

当前 `Business_RegistryPoll()` 是空函数，应用层尚未形成业务闭环。缺失：

- 应用初始化、启动阶段和运行阶段状态机。
- 模块注册表及统一 init/self-check/start/stop/recover 调度。
- 业务状态快照，供显示、LoRa、5G、日志共同读取。
- `App_CopyNavigation()`、`App_CopySystem()` 和
  `App_GetModuleStatus()` 已建立；活动告警读取 API 尚未实现。
- 调用返回值、数据新鲜度、无效原因和版本兼容规则。
- 模块启停、降级运行和恢复重试策略。

### 2.2 告警系统

当前只有 `Px4Lite_AlarmEvent_t` 和队列接口，没有任何生产者、消费者或
告警任务。缺失：

- 全局故障码表及故障码所有权。
- 活动告警表，而非只保存瞬时事件。
- 告警产生、去重、升级、降级、锁存、确认、清除。
- 同一故障重复上报的抑制和计数。
- 恢复事件及恢复时间记录。
- 告警严重度到蜂鸣器、LED、显示、LoRa、5G、日志的动作映射。
- 多告警同时存在时的最高严重度仲裁。
- 告警队列满、活动表满时的保底策略。
- 栈溢出、malloc 失败、任务超时、传感器离线的告警接入。
- 关键告警掉电保存和重启原因读取。

### 2.3 上电初始化与自检

当前只调用 GNSS init，没有完整 POST。缺失：

- 板级资源初始化结果汇总。
- 传感器 `self_check()` 的统一调用。
- RAM、Flash 配置、时钟、通信接口、存储和看门狗检查。
- 必选模块与可选模块区分。
- 启动超时和启动降级策略。
- 自检进度、结果和错误原因提供给显示层。
- 启动失败后的安全状态，而不是直接永久停在 `Error_Handler()`。

### 2.4 真实传感器驱动

目前只有 GNSS 真实实现。缺失：

- MPU6050/后续 IMU 的 BSP、驱动、标定、自检、FIFO 和 topic 发布。
- BME280/气压计的 BSP、驱动、补偿计算、垂直速度和 topic 发布。
- 电池电压、电流、电量估算和低电量判断。
- 其他计划传感器的设备 ID、引脚、总线和 DMA 资源定义。
- 每个传感器的启动宽限、数据超时、最大数据年龄和恢复策略。
- 总线故障恢复，例如 I2C BUSY、SPI 超时、DMA 卡死。

### 2.5 数据模型统一

旧的 `Sensor_Sample_t/Sensor_Status_t` GNSS 兼容模型已经删除。当前唯一
链路为“设备强类型快照 -> Platform Adapter -> Framework Measurement”。
仍缺失：

- 后续各传感器强类型快照和 Framework Measurement 的字段规范。
- 原始值、标定值、工程值、融合值的分层定义。
- 单位、缩放、坐标系、符号方向和有效范围规范。
- `sample_time_ms` 与 `publish_time_ms` 已进入公共数据头；
  `receive_time` 是否需要独立保留仍待各总线评审。
- 数据质量计算规则，不能只用固定的 100/30。
- `valid`、`stale`、`degraded`、`offline` 已形成第一版语义，
  仍需在新增传感器接入时验证一致性。
- 每类 topic 的更新频率、最大年龄和消费者规则。

### 2.6 运算后数据

当前 Estimator 基本是 GNSS 字段复制，不是真正融合。缺失：

- IMU 零偏、比例、安装方向和温漂补偿。
- 姿态解算及 roll、pitch、yaw。
- GNSS 速度分解为 NED/ENU 分量。
- 气压高度、垂直速度和滤波。
- GNSS、IMU、气压计时间对齐。
- 异常值、跳变、范围和变化率过滤。
- 数据源切换、降级和恢复。
- 融合算法状态、置信度和有效位。
- 地理坐标到本地坐标转换及原点管理。

## 3. P1：系统联调前必须补齐

### 3.1 EventBus 消费者

当前没有任何 `Business_EventBusSubscribe()` 调用，所有 EventBus 队列均
没有正式消费者。缺失：

- Alarm、Logger、State、Protocol、Comm 的订阅注册。
- 每个 topic 的生产者和消费者表。
- 消费任务及单次最大处理条数。
- 队列拥塞后的降采样、覆盖或丢弃策略。
- EventBus 统计进入 SystemHealth 和调试输出。
- 没有订阅者时是否允许发布成功的明确规则。

### 3.2 Display

Display 任务已创建，但驱动全部返回 `NOT_READY`。缺失：

- ATK-MD0700 的 FSMC 16位 BSP 和 SSD1963 类控制器驱动。
- GT911 软件 I2C 触摸驱动及触摸事件输入。
- LCD 背光 GPIO/PWM 控制。
- 屏幕初始化、自检、在线检测和重连。
- 页面数据模型和变量映射。
- 导航、传感器、健康、告警和启动进度页面。
- 触摸事件转应用命令。
- 非阻塞或分步刷新状态机。
- 局部刷新、刷新预算、最长刷新耗时和错误统计。
- `bsp_config.h -> MSP -> BSP Init -> SSD1963/GT911 Driver` 配置边界。

FSMC 屏幕不是串口通信设备，不使用分包、CRC、ACK 或通信重连语义。
显示风险主要是长时间同步写 GRAM、刷新阻塞、数据版本切换和任务栈占用。

### 3.3 LoRa、5G 与 Remote ID

配置均为关闭，没有驱动或任务。缺失：

- BSP、模块驱动、初始化、自检和链路状态。
- 统一通信帧头、版本、长度、序号、时间戳、CRC。
- 序列化和反序列化，禁止直接发送 C 结构体内存。
- 分包、重组、ACK、重发、超时和重复包处理。
- 不同链路的速率、优先级和带宽调度。
- 告警、导航、健康数据的发送策略。
- Remote ID 数据内容、刷新周期和法规接口。
- 5G 与未来 Linux A 核之间的通信边界。

### 3.4 日志与 SD 卡

`px4lite_log_pool.h` 只有声明，没有 `.c` 实现。缺失：

- 固定内存池、记录格式、提交和释放实现。
- Logger 消费任务。
- SDIO/SPI SD BSP、FatFs 和挂载状态。
- 文件轮转、容量上限、写入批处理和 flush 策略。
- CRC、序号和掉电时不完整记录识别。
- 存储满、拔卡、写失败和恢复处理。
- 黑匣子关键事件和高频数据降采样。
- 日志读取、导出和版本兼容。

### 3.5 命令链

当前只有 command/ack 队列，没有处理者。缺失：

- 命令 ID、权限、参数范围和来源定义。
- 命令解析、执行、超时和 ACK。
- 重复命令幂等处理。
- Display、LoRa、5G 命令统一入口。
- 危险命令的状态条件和二次确认。
- 命令执行日志和故障反馈。

### 3.6 健康监控

当前 Health 主要检查 GNSS 超时。缺失：

- 所有模块统一超时和恢复检查。
- `severity`、`recovery_count`、`drop_count` 的真实维护。
- IMU FIFO、Alarm queue、EventBus、Log pool 峰值统计。
- FreeRTOS stack high-water、最小剩余 heap、CPU 占用。
- 任务周期超时、deadline miss、最长执行时间。
- 中断计数、DMA 停滞和通信错误率。
- 状态变化事件和告警事件发布。
- 禁用模块与故障模块的状态区分。

### 3.7 看门狗与致命异常

当前硬件看门狗关闭，hooks 只进入死循环。缺失：

- IWDG 初始化和刷新 BSP。
- 必要任务心跳集合的配置化。
- 任务失联后停止喂狗并记录复位原因。
- HardFault、BusFault、UsageFault、MemManageFault 捕获。
- 异常寄存器、任务名、栈水位和最后事件保存。
- 重启次数限制和安全模式。

## 4. P2：产品化和扩展阶段补齐

### 4.1 参数与标定

- 参数表、默认值、范围和版本。
- Flash 双备份、CRC 和掉电安全更新。
- IMU、气压计、电池和安装方向标定数据。
- 参数从 Display/LoRa/5G 修改后的确认和持久化。

### 4.2 时间系统

- 单调时间与 UTC 时间分离。
- GNSS UTC 同步、有效标志和失锁保持。
- 跨传感器采样时间对齐。
- Linux A 核加入后的时钟同步协议。

### 4.3 Linux A 核预留

- MCU 与 Linux 的 IPC 物理链路选择。
- 共享消息格式、版本、字节序和 CRC。
- 心跳、启动握手、断链重连。
- Linux 不在线时 MCU 独立运行能力。
- 数据所有权和控制权仲裁。

### 4.4 测试体系

- NMEA 单元测试和历史数据回放。
- 每种传感器驱动的假设备/模拟输入。
- topic、FIFO、EventBus、Alarm 的并发测试。
- 丢字节、半帧、CRC 错、DMA 卡死、队列满故障注入。
- 24/72 小时稳定性测试。
- 栈水位、heap、CPU 和最大任务执行时间报告。
- 硬件在环、通信互通和掉电恢复测试。

### 4.5 工程与发布

- 自动化全量编译脚本。
- 编码规范检查和静态分析。
- 模块接口评审清单。
- 版本号、Git 提交号和构建时间写入固件。
- Release Archive 正式版本归档。
- 配置、固件和通信协议版本兼容矩阵。
- Bootloader、升级包校验、回滚和 OTA 方案。

## 5. 当前主要风险

1. 目前能编译并不代表业务闭环完成，真实闭环只有 GNSS。
2. Display 任务每 10 ms 运行但始终返回 `NOT_READY`，会消耗少量 CPU 和
   栈，尚无实际显示能力。
3. EventBus 创建了五个队列但没有订阅者，当前占用 heap 而不传递业务。
4. Alarm、Command、LogPool 均有接口外形但没有完整实现，容易被误判为
   已完成模块。
5. Health 只对 GNSS 有真实检测，其他模块状态长期保持
   `UNINITIALIZED`。
6. 硬件看门狗关闭，任务或系统死锁后不能自动复位。
7. 栈溢出和 malloc 失败不能在复位前保存诊断信息。
8. Estimator 目前是字段搬运，不能称为多传感器融合。

## 6. 补充缺失功能审计

以下内容不重复“GNSS 之外的设备尚未实现、告警/通信/日志等模块缺失”，
而是当前框架还没有形成的横向系统能力。

### 6.1 启动、生命周期与资源管理

- 没有统一模块生命周期管理：
  `init -> self_check -> start -> run -> stop -> recover`。
- 没有启动依赖排序，例如存储、通信和 Display 是否允许在时间或导航
  未就绪时启动。
- 没有启动阶段、进度、失败原因和降级启动结果快照。
- 创建部分任务或队列失败后，没有统一回滚和资源清理。
- 没有设备注册表记录模块版本、实例数量、能力和启用状态。
- 没有 BSP 资源管理器检查引脚、DMA Stream、UART、定时器和中断冲突。
- 没有必选模块、可选模块和条件启用模块的统一策略。
- 没有运行中模块重启、热插拔或重新初始化流程。

### 6.2 数据定义和契约完整性

- 原始值、标定值、工程值和融合值的边界尚未完全固定。
- 各数据字段的单位、量程、精度、坐标系、正方向和无效值缺少完整表格。
- `receive_time`、`sample_time`、`publish_time` 和 UTC 时间的关系尚未定版。
- 数据质量 `quality` 的统一计算标准没有完成，目前主要只有 GNSS 简化规则。
- 缺少数据来源、估算、饱和、越界、时间未对齐等完整 flags 定义。
- Topic 和 Event payload 没有独立的数据结构版本及兼容转换机制。
- 大型或高频快照尚未实现双缓冲、版本校验或零拷贝发布。
- 没有统一定义消费者遇到 `NOT_READY`、`STALE`、`DEGRADED` 时的行为。
- 没有数据有效范围、变化率、跳变和物理一致性检查框架。
- 没有多实例设备标识规则，例如双 IMU、双 GNSS 和主备数据源。

### 6.3 时间系统

- 没有单调运行时间与 GNSS UTC/RTC 时间的统一时间服务。
- 没有解析并发布完整 UTC 日期、时区无关时间和时间有效状态。
- 没有 GNSS 失锁后的 UTC 保持、漂移估计和重新同步策略。
- 没有跨 GNSS、IMU、气压计和外部 A 核的采样时间对齐机制。
- 没有 PPS 输入、硬件时间戳或高精度同步接口预留的真实实现。
- 没有统一验证 32 位毫秒时间回绕行为。

### 6.4 GNSS 完整设备能力

- 当前主要解析 GGA、RMC、GSA、GSV，尚未形成 ZDA、VTG、GLL、TXT 等
  语句的正式数据接口。
- 没有完整发布天线开路、短路和模块自检状态。
- 没有 GNSS 配置命令流程，例如波特率、输出语句、输出频率和星座配置。
- 没有冷启动、热启动、恢复出厂设置和配置应答确认。
- 没有 PPS、授时质量、定位模式和差分状态接口。
- 没有位置跳变、速度异常、漂移和静止检测过滤。
- 没有 GNSS 数据回放接口，用于脱离硬件验证解析和异常数据。

### 6.5 任务实时性和资源监控

- 没有周期统计任务实际执行时间、最大执行时间和 deadline miss。
- 没有把任务栈高水位写入 SystemHealth 或日志。
- 没有持续记录当前/最小剩余 heap 和启动阶段内存峰值。
- 没有 CPU 占用、空闲任务比例和中断负载统计。
- 没有队列使用峰值、等待时间和连续满次数的统一监控。
- `imu_fifo_peak`、`alarm_queue_peak`、`log_pool_free_min` 等健康字段尚未
  由真实统计填充。
- 心跳目前主要用于未来看门狗门控，没有形成任务超时状态和告警。
- 没有检测互斥锁长时间占用、优先级反转和潜在死锁。
- 没有为每个周期任务定义并验证最坏执行时间预算。

### 6.6 总线、DMA 和设备恢复

- 没有 UART、I2C、SPI、CAN 和 SDIO 的统一错误统计及恢复接口。
- GNSS UART 错误后的 DMA 重启、软件读写位置复位和恢复验证尚未系统化。
- 没有 DMA 长时间不推进、环形缓冲区覆盖和数据洪泛检测。
- 没有 I2C BUSY、从机无应答、总线被拉低后的时钟恢复流程。
- 没有 SPI 超时、片选异常和连续错误后的设备复位策略。
- 没有通信设备上电时序、硬复位 GPIO 和重连退避机制。
- 没有掉电、电压跌落和 Brown-out 场景下的安全处理。

### 6.7 应用接口和业务快照

- 应用 API 目前主要提供 Navigation、System 和单模块状态。
- 没有 IMU、气压、电源、链路、存储和时间等正式应用快照 API。
- 没有活动告警列表、告警历史和最高严重度读取 API。
- 没有命令提交、查询执行状态和读取 ACK 的应用接口。
- 没有配置/参数读取、修改、确认和持久化接口。
- 没有统一业务快照把导航、健康、告警和链路状态绑定到同一版本。
- 没有消费者能力声明和接口版本协商机制。

### 6.8 通信协议的通用基础

- 没有统一字节序、对齐、编码、版本、长度、序号、时间戳和 CRC 实现。
- 没有流式解帧器处理半包、粘包、错位、超长和 CRC 错误。
- 没有部分发送状态机，无法证明一次逻辑发送对应完整帧交付。
- 没有分包重组、重复包、乱序、ACK、超时重发和流量控制。
- 没有链路优先级和带宽预算，不能保证告警优先于普通遥测。
- 没有通信离线缓存、恢复补发和过期数据丢弃策略。
- 没有协议兼容矩阵、能力协商和远端版本不匹配处理。
- 没有命令鉴权、来源校验、重放保护和危险命令权限控制。
- 没有加密、密钥更新和安全启动相关设计。

### 6.9 故障安全和飞控场景

- 没有系统级安全状态和 failsafe 状态机。
- 没有定义关键传感器失效后继续运行、降级还是停止输出。
- 没有主备传感器选择、故障隔离和恢复切回策略。
- 没有控制输出、执行器状态和紧急停机接口。
- 没有飞行阶段状态，无法按地面、起飞、飞行和降落改变故障策略。
- 没有复位次数限制、反复崩溃检测和安全模式。
- `Error_Handler()` 当前只是关闭中断后死循环，没有最后告警、诊断保存
  或受控复位。

### 6.10 配置、标定和持久化

- 没有参数元数据：类型、默认值、范围、单位、版本和只读属性。
- 没有 Flash 双备份、CRC、原子更新和掉电恢复。
- 没有设备序列号、硬件版本、板卡版本和传感器实例绑定。
- 没有标定流程、标定状态、标定结果验证和标定时间记录。
- 没有工厂参数与用户参数分区。
- 没有复位原因、运行小时数、启动次数和关键故障计数持久化。

### 6.11 调试、诊断和维护

- 没有统一运行时诊断命令，例如查看 topic、状态、队列、栈和 heap。
- 没有调试输出限流、分类级别和模块级过滤。
- 没有二进制 trace 或关键事件环形记录，串口关闭后难以定位瞬时故障。
- 没有在线查看 DMA、中断计数、解析错误和状态变化的统一接口。
- 没有现场导出版本、配置、故障和运行统计的一键诊断包。
- 没有明确的生产调试接口关闭和权限策略。

### 6.12 测试、构建与发布

- 没有自动单元测试运行框架和覆盖率统计。
- 没有 GNSS 历史数据、IMU 波形和通信帧的自动回放测试。
- 没有驱动 mock/fake 平台，算法和业务仍依赖真实硬件联调。
- 没有静态分析、编码规则和接口依赖的自动门禁。
- 没有自动全量编译、尺寸比较和 RAM/Flash 超预算阻止机制。
- 没有固件内嵌语义版本、Git 提交号、构建时间和配置 ID。
- 没有 Bootloader、升级包签名、完整性校验、回滚和 OTA。
- 没有板级生产测试、烧录校验和出厂自检工具。
- 没有温度、振动、电源波动、EMI 和通信干扰环境测试。
- 没有正式需求到接口、测试和发布记录的追踪矩阵。

## 7. 推荐开发顺序

1. 统一数据模型、模块状态和故障码规则。
2. 完成 POST、模块注册表、Alarm Manager 和 Health Monitor。
3. 接入 IMU，完成标定、FIFO、姿态解算和时间对齐。
4. 接入气压计和电池，形成导航与健康完整快照。
5. 完成 Display 真实适配和应用层稳定读取接口。
6. 完成日志池、Logger 和 SD 卡。
7. 完成 LoRa，再复用协议层接入 5G 和 Remote ID。
8. 启用硬件看门狗、异常记录和长时间稳定性测试。
9. 最后定义 MCU 与 Linux A 核 IPC，保证 MCU 可独立运行。
