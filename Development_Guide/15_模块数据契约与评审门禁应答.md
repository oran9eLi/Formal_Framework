## 2. 谁是硬件唯一所有者?

**BSP 层是所有硬件的唯一所有者**(P1 重构后):
- 句柄全部私有化为 `static`(如 [bsp_gnss.c](../Bsp/Src/bsp_gnss.c) 的 `s_gnss_uart`),ISR/MSP 通过 `BSP_GNSS_GetUartHandle()` 访问器使用,无全局可写句柄。
- 初始化集中在 [bsp.c](../Bsp/Src/bsp.c) 的 `BSP_Init()`(按 `BSP_ENABLE_*` 开关),Sensor 驱动与平台适配层不再调用 `BSP_*_Init()`。
- 依赖单向:`Platform Adapter → BSP → Sensor`;`HAL_*` 只允许出现在 BSP 层。
- DMA 接收缓冲 `s_rx_buf` 归 `bsp_gnss.c` 私有;消费者用独立读位置 `s_rx_tail` 取数据。

## 3. 数据模型(Snapshot / FIFO / Event / Pool)

| 模块 | 模型 | 实现 |
|---|---|---|
| GNSS | **Latest Snapshot** | `Px4Lite_CopyGnss` 短临界区复制 |
| IMU | **固定 FIFO** | `Px4Lite_PushImu/PopImu`,容量 `PX4LITE_IMU_FIFO_CAPACITY=32`,满时丢最旧并计 overflow |
| BARO/BATTERY/导航/健康 | **Latest Snapshot** | 临界区复制 + 版本号 |
| 业务事件 | **Event Bus** | 非阻塞事件总线,逐订阅者投递统计 |
| 报警/命令 | Queue(已定义未启用) | `ALARM_QUEUE_LENGTH=16`、`COMMAND_QUEUE_LENGTH=8` |
| Memory Pool | **未使用** | `LOG_POOL` 关闭;LoRa/SD 大帧无实现 |

## 5. 状态、故障码、超时、恢复条件

**状态**(`Px4Lite_State_t`):UNINITIALIZED/STARTING/ONLINE/DEGRADED/OFFLINE/FAILED/DISABLED。
**单一写入者 = Health 层**(§13.5,P4 已修):驱动只输出 `last_rx_ms`/`last_valid_ms`/错误计数,
不再在采集路径强制 OFFLINE。

**实际会被设置的故障码**(`px4lite_faults.h` 定义 23 个,代码只用 5 个):

| 码 | 名称 | 触发 |
|---|---|---|
| 0x0000 | NONE | 正常 |
| 0x0201 | SENSOR_INIT | 初始化失败 → FAILED |
| 0x0202 | SENSOR_OFFLINE | 超时无数据 → OFFLINE |
| 0x0203 | SENSOR_INVALID | 电池数据无效 |
| 0x0204 | SENSOR_NO_FIX | GNSS 有 NMEA 无定位 |

> 其余 18 个码(SYSTEM/COMM/STORAGE/PROTOCOL/ESTIMATOR 等)定义了但无代码触发,详见
> 本轮排查结论:多数对应不存在的子系统或会挂死的钩子。

**超时阈值 / 启动宽限**:

| 模块 | OFFLINE_MS | 启动宽限 |
|---|---|---|
| GNSS | 2000 | 5000 |
| IMU | 500 | 2000 |
| BARO | 3000 | 5000 |
| BATTERY | 3000 | 5000 |

**恢复**:`Px4Lite_RecoveryMonitorRun()` 已接入 HealthRun,但**仅实现 GNSS 策略**且
`PX4LITE_GNSS_RECOVERY_ENABLE=0`(默认关)。IMU/BARO/BATTERY 暂无恢复路径——目前靠
Service 内懒初始化兜底(待 P2a 改为 Recovery 层接管)。

## 7. 消费者通过哪个 API 获取数据?

唯一只读 API:[app_data_api.h](../Business/Inc/app_data_api.h)
- `App_CopyNavigation(out, now_ms)` — 导航(位置+姿态+角速度,屏幕/PID/MAVLink共用)
- `App_CopySystem(out, now_ms)` — 系统健康+各模块状态+告警摘要
- `App_CopyAlarm(out, now_ms)` — 活动告警表,供屏幕/Debug/Logger只读
- `App_CopyEnvironment(out, now_ms)` — 气压/温湿度/电池
- `App_GetCommStats(out)` — LoRa/MAVLink统计
- `App_GetModuleStatus(id, out)` — 单模块状态

业务/显示**禁止**直接读 Framework topic 或 BSP DMA 缓冲;均经此 API 取版本一致的副本。
Display 后续接入姿态和告警时也只能走这些 App 接口,不得直接读取 MPU6050
驱动、Health 内部数组或 Alarm Queue。

## 8. 半包、撕裂、队列满、缓冲覆盖风险?

| 风险 | 处理 | 位置 |
|---|---|---|
| 半包 | NMEA 状态机,必须完整 `\r\n` + 校验通过才更新;校验失败不刷新 `last_valid_ms` | [sensor_nmea.c](../Sensor/Src/sensor_nmea.c) |
| 撕裂(读到半写) | Snapshot 短临界区整体复制 + 版本号一致性 | `Px4Lite_Copy*` |
| 队列/FIFO 满 | IMU FIFO 满丢最旧并计 overflow_count | `Px4Lite_PushImu` |
| DMA 缓冲覆盖 | **P1 已修**:IDLE 回调检测写指针越过 tail,累计 `drop_count` 并丢最旧 | [bsp_gnss.c](../Bsp/Src/bsp_gnss.c) `BSP_GNSS_RxIdleCallback` |
| 中断状态破坏 | 取数用 `__get_PRIMASK()` 保存/恢复,不无条件 `__enable_irq()` | `BSP_GNSS_GetRxData` |

## 9. Debug 宏是什么?关闭后是否影响正式逻辑?

来源 [Debug/Inc/debug_config.h](../Debug/Inc/debug_config.h)

- 控制台/周期服务由 `DEBUG_*_MONITOR_ENABLE`、`DEBUG_BOOT_LOG_ENABLE` 等独立开关推导
  (`DEBUG_CONSOLE_ENABLE`、`DEBUG_PERIODIC_SERVICE_ENABLE` 为派生宏,不可手改)。
- 全部关闭时,`DBG_PRINT` 等编译为空宏,不创建 DebugTask,**不改变采集/解析/状态机/发布逻辑**(§12)。
- 原始流输出由独立 RAW 宏(`DEBUG_GNSS_BSP_MONITOR_ENABLE`)控制;ISR 内不调用 printf。
- 周期输出已修正为 ≤1Hz(GNSS/IMU/BARO/POWER/LORA/ALARM 均 1000ms)。
- Debug 只观察正式链路已生成的可视化数据,不替正式链路采集或更新状态。

## 13. 通信类问题(发送/分包/帧/确认)

LoRa(USART3 + E22-400T30D + MAVLink)已实现并启用,逐条作答:

| 门禁问题 | LoRa 现状 |
|---|---|
| 谁拥有接收缓冲区 | `bsp_lora.c` 私有 `s_rx_buf`(USART3 循环 DMA),唯一所有者 BSP;句柄 `s_lora_uart` 已私有化,ISR/MSP 经 `BSP_LoRa_GetUartHandle()` 访问(本轮 A1) |
| 谁写谁读 | 写:DMA(硬件)+ IDLE/DMA ISR 经 `BSP_LoRa_UpdateRxPosition` 更新写位置;读:comm 任务经 `BSP_LoRa_GetRxData` → `Lora_E22_Service` 解析 |
| 如何识别完整帧 | RX:`mavlink_parse_char` 状态机,仅完整帧(头+长度+CRC)置 `s_rx_ready`;字段级编码(`MAVLINK_ALIGNED_FIELDS 0`),不依赖结构体内存布局 |
| 如何处理部分发送 | TX 经 USART3 DMA 整帧搬运(`DMA_NORMAL`),非"返回已发字节"模型;`Lora_E22_TxStep` 非阻塞状态机 IDLE→WAIT_AUX→SENDING,单帧在飞 |
| 发送完成定义 | **空口发完** = `HAL_UART_TxCpltCallback`(TC)置 `s_tx_busy=0` → `tx_frame_count++`、`last_tx_ms`;`Lora_E22_Send` 返回 OK 仅表示**已复制并暂存**(异步复制语义,已在 `lora_e22.h`/`px4lite_platform.h` 注明,本轮 B3) |
| 超时与恢复 | USART3 错误中断触发 `BSP_LoRa_RecoverRx()`(重启 DMA+清读写);TX 卡死 `LORA_E22_TX_DMA_TIMEOUT_MS=500` 兜底 `BSP_LoRa_AbortTx` |
| 数据失效后旧值 | 经 framework `Copy*` + `IsFresh`;MAVLink 发送侧按 `sequence` 去重,`PX4LITE_GNSS_MAX_AGE_MS` 判 STALE 后不发 |
| 公开状态写入者 | **本轮 A3:OFFLINE 移交 Health 统一判定(§13.5)**;comm 任务只记录 `last_rx_ms`/`last_valid_ms`(=max rx/tx)/错误/丢包并升 ONLINE/DEGRADED |
| 端到端 ACK(§9.5) | 当前仅遥测下行(heartbeat / GPS_RAW / GNSS_SAT),无需 ACK 的关键命令;**新增上行命令时必须补 ACK** |
| 发送缓冲区所有权(§13.2) | `s_tx_pending`(驱动)、`s_frame`(MAVLink TX)均 comm 任务单一所有者,声明处已标注(本轮 B2) |
| 最坏栈/堆/执行时间 | **【需运行确认】** |
| 功能关闭释放 | `PX4LITE_ENABLE_LORA=0` 时不创建 comm 任务、不注册 LoRa 模块、不初始化 USART3 DMA |

> GNSS(接收类)门禁应答见 §1–§9;5G/SD 仍不存在。

## 附:门禁项处理状态

**本轮已修(GNSS/LoRa/IMU/BARO/BATTERY 对齐,Keil 构建已确认):**

- A1 LoRa UART 句柄私有化 `s_lora_uart` + `BSP_LoRa_GetUartHandle()`,删除全局可写句柄与 it.c 的 `extern`。
- A2 LoRa 驱动去 HAL:不再直接 `#include stm32f4xx_hal.h` / 调 `HAL_GetTick()`,时间统一经入参 `now_ms` 与 `BSP_Time_GetTickMs()`;`sensor_gnss.c` 同步去掉冗余 HAL include。
- A3 通信类 OFFLINE 移交 Health 统一判定(§13.5),comm 任务不再自行写 OFFLINE。
- B2 发送缓冲区(`s_tx_pending`/`s_frame`)声明处补所有者标注;B3 `Lora_E22_Send`/`Px4Lite_LoRaSend` 注明异步复制语义。
- P2(GNSS)§4 模板落地:`Sensor_GNSS_Service(out)` → `Service(now_ms)` + `CopySnapshot` + `GetStatus`,时间戳改由入参贯穿(去驱动内 `BSP_Time` 调用)。
- P2(IMU/BARO/BATTERY)§4 模板落地:`Sensor_*_Service(out)` → `Service(now_ms)` + `CopySnapshot` + 紧凑 `GetStatus`;平台适配层改为先推进采集,再复制驱动缓存快照。
- 优化:GNSS/IMU 的 I/O 错误改用 `Px4Lite_RecordSensorIoError` helper;LoRa 补 `STARTUP_GRACE_MS`;`BSP_GNSS_Init` 检查 HAL 返回值;§13.5 改为"按转移类别单一归属"消除矛盾。
