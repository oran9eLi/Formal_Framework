# 架构边界与数据流

## 2026-07-01 从机 SRAM 余量收口
- LVGL SSD1963 draw buffer 是 Display 层私有静态缓冲，当前固定为 `800x16x2` 字节，约 25KB，位于 `0x20000000` 主 SRAM；不得放入 CCM，避免未来引入 DMA/FSMC 搬运时访问非法内存。
- Display 页面、LoRa/MAVLink 远端槽位、FreeRTOS heap 和各任务栈共享 STM32F407 的 128KB SRAM1；新增远端字段、页面对象或静态缓存时，必须同步检查 Keil map 的 `RW_IRAM1`，不能只以 `0 Error(s)` 判断可发布。
- 显示缓冲条带行数属于实时性和 SRAM 余量的折中项。若后续提高行数或新增大数组，必须先说明目标刷新收益、SRAM1 剩余量和从机/主机双角色运行风险。

## 2026-07-01 实时闭环与消息同步收口
- 本机结构化消息日志是 Framework 固定环形缓冲，Business 单写，Display/Comm 多读；读写必须在临界区内复制完整条目和序号，禁止跨任务无保护读取日志元数据。
- LoRa/MAVLink 告警表和消息日志仍走 catalog 分项调度，但当 Alarm snapshot sequence 或本机日志 sequence 变化时，TX 调度器必须把 `STATUSTEXT`、`REMOTE_ALARM`、`REMOTE_LOG` 的下一次发送提前到当前 comm 周期；周期全量/空闲发送只作为兜底。
- 远端选择页由 LVGL 通过 `App_CopyRemoteNodeStatuses()` 周期刷新列表，页面层不得直接读取 LoRa driver 或 MAVLink RX 私有状态；主机发现新从机只依赖远端 heartbeat/ACK 更新后的 RemoteTelemetry 节点表。
- 丢包率统一按 MAVLink `seq` 的 8 bit 回绕差值估算，长时间断链后的大 delta 也计入丢包，不再把 `delta >= 128` 静默忽略。
- Display 聚合快照周期为 100 ms，LVGL 刷新仍保持 10 ms service 和 2 ms budget；UI 变快不改变 sensor/comm 的任务所有权和优先级边界。
- BME280 探测使用短 probe timeout，正常寄存器读写仍使用总线读写 timeout；未插或热插拔时不得因探测阻塞拖垮 10 ms sensor 周期。

## 2026-07-01 稳定性边界收口

- `sensor` 任务不得在 BME280 forced measurement 后忙等测量完成。BME280 service 必须分周期触发和读取；Baro 重初始化前应请求 I2C 总线恢复。
- GNSS 和 LoRa parser 在 re-init 或 RX recovery 时必须清除半包状态，半句 NMEA 或半帧 MAVLink 不得跨热插拔恢复残留。
- LoRa E22 re-init 在 `comm` 任务内必须非阻塞。AUX 未就绪时返回 `BUSY` 并保留 re-init 请求，禁止在任务里自旋等待数百毫秒。
- Display 热插拔恢复分为 LVGL backend 探活和 Display facade ready 同步。底层探活成功后必须恢复 facade ready 并通过 Display API 重建当前页面。
- `Error_Handler()` 只能在关中断前调用 BSP emergency stop helper，Core 不得直接了解单个 UART/DMA 细节。
- Control 等资源拥有者可以发布 STARTING/ONLINE/DEGRADED 事实，最终 OFFLINE/FAILED 策略仍由 Health 统一裁决，启动门禁失败由 Registry 记录。
- Alarm 对新激活故障做消抖；已激活告警继续保留，模块恢复健康时立即清除。
- 硬件 watchdog 仍是发布要求，但必须先补齐真实 BSP watchdog init/feed 链路。未实现 `BSP_WatchdogRefresh()` 前，不得把 `PX4LITE_ENABLE_HARDWARE_WATCHDOG` 改成 1 伪闭环。

| `Control/` | 电机/PWM/控制输出的业务入口和框架适配 |

## 2. 数据读取边界

Business、Display、LoRa、Logger、Storage 和未来业务消费者只能通过 `Business/Inc/app_data_api.h` 读取数据。

正式读取入口：

```c
App_CopyNavigation(&nav, now_ms);
App_CopySystem(&sys, now_ms);
App_CopyEnvironment(&env, now_ms);
App_CopyAlarm(&alarm, now_ms);
App_CopyDateTime(&date_time, now_ms);
App_CopyRemoteDisplaySnapshot(&remote_view, now_ms);
App_GetModuleStatus(id, &status);
App_GetCommStats(&comm);
```

不同业务快照使用独立新鲜度阈值，不得为了省配置复用不相干模块的超时宏。例如 DateTime 使用 `APP_DATETIME_MAX_AGE_MS`，不跟随 Health/System 的 500 ms 阈值。

禁止行为：

- Business 和 Display 页面/业务适配代码直接包含 BSP、Sensor 或 Driver 头文件。
- Business 和 Display 页面/业务适配代码直接读取 Framework topic。
- 任意业务代码直接读取 DMA buffer、驱动私有变量或 BSP 私有句柄。
- 为了显示一个在线灯新增空 topic；状态型外设应使用 `App_GetModuleStatus()`。

以下文件属于边界适配器或底层介质适配器，是当前工程允许的明确特例。特例只对表中列出的文件生效，不扩展到整个目录。

新增特例必须同时满足：

1. 文件职责是边界适配、介质适配或唯一传输出口，而不是普通业务逻辑。
2. 文件名、所属层级、允许调用范围和禁止事项必须写入本白名单。
3. 不能扩大为目录级特权。
4. 不能破坏 `Core -> Business -> Framework -> Platform Adapter -> Driver -> BSP -> HAL` 的单向依赖。
5. 必须同步更新 `03_模块接入手册.md` 的评审清单和 `Change_History/`。

## 4. Snapshot 发布模式

低频或中等大小数据使用 latest snapshot：

```c
/* Writer: owner task */
taskENTER_CRITICAL();
g_topic = *source;
g_topic_ready = 1U;
taskEXIT_CRITICAL();

/* Reader */
taskENTER_CRITICAL();
if (g_topic_ready)
{
    *dest = g_topic;
}
taskEXIT_CRITICAL();
```

临界区内只允许复制快照和设置标志，不得解析、计算、打印或执行阻塞 I/O。

高频连续数据使用固定 FIFO。大帧或可变长数据使用固定块内存池，传递索引或句柄，避免在任务栈中复制整块。

## 5. 协议和转换边界

| 内容 | 所属层级 |
|---|---|
| UART/SPI/I2C/CAN 原始收发 | BSP |
| DMA 环形缓冲、写位置、硬件错误标志 | BSP |
| NMEA、AT、MAVLink RX 等协议解析 | Driver 或协议模块 |
| 单位转换、校准、质量字段 | Driver |
| Driver 类型到 Framework 类型 | Platform Adapter |
| Topic 发布、模块状态、恢复调度 | Framework |
| 展示、日志、业务决策 | Business / Display / Storage |

除 `Framework/Src/px4lite_platform_f407.c` 这个唯一平台适配文件，以及 BSP 内部封装如 `Bsp/Inc/bsp_critical.h` 外，非 BSP/Core 文件不得直接包含 `stm32f4xx_hal.h`。需要时间延时走 `BSP_Time_DelayMs()`，需要硬件访问或短临界区保护走 BSP 或平台适配层。

5G-A 可发送 AT 指令做连接管理、附着查询、恢复配置和状态确认。AT 指令收发属于 5G-A 所属 service/driver 的控制面，不向 Business 暴露原始 AT 命令或响应。除非后续明确有业务数据消费，否则 5G-A 只上报模块状态。

RemoteID 当前与 LoRa 同时启用，但二者链路职责独立：LoRa 负责板间 MAVLink 主从遥测、远端选择和显示数据闭环；RemoteID 由 STM32 通过 UART4 TX DMA 向 ESP32-S3 提交 MAVLink/OpenDroneID 消息，ESP32-S3 负责 BLE/Wi-Fi 广播和监管格式适配。RemoteID 的 ONLINE 只表示 STM32 本地 UART4/DMA 发送通道近期成功提交帧，不证明 ESP32-S3 已完成广播；若需要判断 ESP32 实际在线，必须后续增加 GPIO presence、UART RX ACK 或 ESP32 心跳。

命令执行统一收口在 `Framework/Src/px4lite_command.c`。MAVLink RX 只负责逐字段解码 `COMMAND_LONG` / `COMMAND_ACK`，MAVLink TX 只负责排队发送 ACK、发送本机控制帧和维护通信统计；命令目标校验、支持列表、执行分发和 ACK 结果选择不得散落在 RX/TX 文件中。后续 5G-A 或 Remote ID 控制面命令必须先接入 Command 执行器，再由所属模块 service 执行。

显示界面所展示的外设状态和值，是 LoRa/MAVLink 对外传输的数据视图。发送侧不得从 Display 反读，也不得为通信单独维护一套影子数据；必须从 Framework topic、Health 状态或其 App API 映射出的同源数据生成 MAVLink 帧。Display 页面层不得直接包含 Framework 故障头文件或模块枚举；模块状态灯、告警原因、离线清屏策略和日志状态由 `App_CopyDisplaySnapshot()`、`App_GetModuleDisplayName()` 和 `App_GetFaultReasonText()` 统一输出。后续新增外设时，先明确是状态类还是数据类：状态类进入模块状态和 Health，再映射到 App Display 视图；数据类先建立 topic/App_Copy* 快照，再由显示和通信共同消费。

周期任务不得在栈上放完整系统快照、完整告警表、全量显示视图或大 payload。需要聚合显示、调试或遥测数据时，使用文件级静态 scratch、轻量 summary 接口或固定块缓存；新增外设接入前必须评估其对 `biz_display`、`comm`、`health` 和 `debug` 栈水位的影响。

统一的是数据入口和快照来源，不是统一大包。LoRa/MAVLink 外发必须通过 Telemetry Catalog 分项调度：每个数据项独立配置 enable、周期、message id、编码函数和统计入口；单周期最多提交一帧。不得在 `comm` 任务栈上拼接全量显示数据、完整告警表或全量外设数据。大 payload、分段重传、主从从机表和 LoRa 收发重组缓存必须使用静态缓存、固定块池或固定队列。

接收侧分两层：LoRa Driver 使用静态有界 FIFO 队列向上暴露已解析的 MAVLink 协议帧事实，队列满时丢弃最旧帧并累加 RX drop 计数；`Framework/Src/px4lite_mavlink_rx.c` 在 comm task 中按标准 MAVLink message id 解码为 `Px4Lite_RemoteTelemetry_t` 远端遥测快照；Business 再通过 `App_CopyRemoteDisplaySnapshot()` 映射为 Display 专用 App 视图。LoRa 驱动不得解释从机业务字段，Display 页面不得直接读取 LoRa RX 帧。

LoRa 收发统计属于通信事实：TX 计数以本机 UART DMA TC 且 E22 AUX 回到空闲后的完成帧为准，RX 计数以接收侧成功解析的合法 MAVLink 帧为准。接收侧丢包率由 LoRa Driver 按 MAVLink `system_id` 分组跟踪 `seq` 跳号估算，单位为 0.1%；序号跳变超过半圈时按断链后重同步处理，不累加大额丢帧。该值只能说明本机收到的对端帧是否连续，不能证明对端是否收到本机发送帧。Display 本机视图显示本机总链路统计；Display 对端视图显示本机 TX 总数和当前选中远端槽位的 RX/丢包率。ACK 计数在未定义真实 ACK/重传协议前固定为 0，仅作为后续命令确认或分段重传协议入口。

节点身份只允许通过 `PX4LITE_BOARD_UNIT_ID` 选择：`PX4LITE_PAIR_MASTER_ID` 固定表示配对主机，默认 1；`PX4LITE_BOARD_UNIT_ID=1` 自动派生为主机，`2/3/4...` 自动派生为从机。LoRa `node_id`、MAVLink `system_id` 和 RemoteID `DCDW-%03u` 身份均等于该 unit id，禁止再分别手改 `PX4LITE_MASTER_NODE_ID`、`PX4LITE_NODE_ROLE` 或 `PX4LITE_MAVLINK_SYSTEM_ID`。远端接收按 system id 写入远端槽位表；主机查看从机 1/2/3 时，只切换选中远端槽位，不新增 LoRa 驱动或 Display 页面底层特例。

LoRa 半双工链路必须按最慢环节做预算，不能只看 USART DMA 是否搬完。当前 E22 走 USART3 9600 bps，本机串口到 E22 和 E22 空中速率均按 9600 bps 记录；`Bsp/Inc/bsp_config.h` 中的 `BSP_LORA_UART_BAUD` 和 `BSP_LORA_AIR_BPS` 是驱动计算 UART DMA、AUX 等待和空中发送超时的配置事实。默认单端可用发送预算按 40% 计算，即 3840 bps，用于预留对端发送、E22 包开销、纠错、AUX 空闲等待和避让余量。默认 MAVLink 周期按 E22 9600 bps 半双工保守配置：心跳和 LoRa 摘要保持 1 s，姿态 2 s，定位 4 s，状态/环境/电源 8 s 级，日志/告警 8 s 级，告警文本 15 s 级；互看时主数据目录项按 `PX4LITE_MAVLINK_MUTUAL_STREAM_THROTTLE` 继续降频。后续主从时隙、节点 ID、空口速率和功率确定后，必须统一调整 `bsp_config.h` 的速率事实和 `px4lite_config.h` 的周期/链路预算宏，不得在业务层临时加快发送。

本机/对端显示数据源切换已迁入 LVGL 屏幕交互：Display facade 只暴露 `Display_SetDataSource()` / `Display_GetDataSource()` / `Display_ToggleDataSource()`，LVGL 通信页通过 `app_data_api.h` 选择远端节点、开启主数据查看租约并切换到对端 App 数据视图。主机只允许选择从机节点，选择框按心跳新鲜度显示绿色状态灯并对当前选中节点加高亮；从机只允许选择主机节点，从机查看主机时 180 s 无触摸操作自动退回本机视图。点击返回必须关闭远端查看并发送 stream stop，使本机计时清零、对端停止主数据流。Display 页眉显示当前查看对象 `DCDW-%03u` 临时身份，后续 Remote ID 接入后只替换身份显示来源，不改变远端槽位和 MAVLink `system_id` 规则。KEY0 不再作为产品交互入口；BSP/Platform 仍可保留板载按键原始能力，但不得再承载本机/对端切换策略。KEY1 保持电机急停输入。

## 6. 状态边界

公开模块状态使用统一语义：

| 状态 | 含义 | 写入者 |
|---|---|---|
| UNINITIALIZED | 尚未初始化 | 注册/初始化流程 |
| STARTING | 初始化完成，等待首个有效数据 | 资源所属任务 |
| ONLINE | 通信和数据均正常 | 资源所属任务 |
| DEGRADED | 有通信或本机驱动可运行，但数据质量不足、对端超时或链路降级 | 资源所属任务 |
| OFFLINE | 超过超时阈值无新数据 | Health |
| FAILED | 初始化失败或不可恢复故障 | Health 或启动门禁 |

驱动和采集任务只记录硬件事实、错误计数、最近接收时间和最近有效时间。OFFLINE、FAILED、恢复触发和系统降级由 Health 统一判定。

## 7. 恢复边界

`Px4Lite_RecoveryMonitorRun()` 遍历所有带 `recover` 回调的注册模块。

- 恢复限速为 2 s backoff，允许无限重试，支持热插拔。
- `recover` 回调只能设置请求标志，不得在 Health task 中执行总线 I/O。
- 实际重新初始化必须由资源所属 service task 执行。
- IMU 保留 driver-level auto-reinit：连续 5 次读取失败后调度 `Init()`，前 5 次 100 ms 快速重试，之后 500 ms backoff。
- IMU 重初始化后，Platform Adapter 至少等待 3 帧连续有效数据后才允许发布到 Framework。
- LoRa E22 本机热插拔以 AUX 长期不可用作为本地模块离线事实；半双工发送期间 AUX 短暂拉低不判离线。对端合法 MAVLink RX 超时只表示链路降级，不触发本机模块红灯。
- Display 热插拔由 DisplayTask 执行：SSD1963 通过周期 PID 探测清除 ready 并进入通用恢复链；GT911 触摸在 LVGL 输入回调中限频重探测，触摸缺失不得让页面层绕过 Display facade 或直接访问 BSP。
- RemoteID 恢复挂入 registry recovery：recover 回调只置位重新初始化请求，真正 UART4/DMA abort、BSP init 和发送调度复位由 `comm` task 执行。RemoteID 发送忙超过 `PX4LITE_REMOTEID_TX_BUSY_TIMEOUT_MS` 或底层提交失败时进入 OFFLINE 并请求恢复；缺少 GNSS 位置只影响 Location 消息，不等价于 RemoteID 本地发送通道离线。

## 8. 总体数据流

```text
Device
  -> BSP raw rx/tx
  -> Driver protocol/state/snapshot
  -> Platform Adapter type conversion
  -> Framework topic/status/registry
  -> app_data_api.h
  -> Business / Display / Comm / Storage
```

通信发送链路必须逐字段编码：

```text
App snapshot
  -> Comm scheduler
  -> MAVLink or protocol frame
  -> Driver async copy
  -> BSP DMA tx
  -> DMA TC callback confirms completion
```

`Lora_E22_Send()` 是异步 copy 语义，返回 `OK` 只表示帧已入发送流程，不代表已经发到空中。LoRa TX 本机发送完成必须同时满足 UART DMA TC 完成和 E22 AUX 回到空闲；该完成只作为本机 TX 统计，不证明对端在线。LoRa 绿色只由最近收到对端合法 MAVLink 帧证明；本机 LoRa 初始化失败或 AUX 长期不可用才进入红色离线故障，对端超时显示黄色降级。

`Px4Lite_RemoteIdSend()` 同样是异步 copy 语义，返回 `OK` 只表示 MAVLink/OpenDroneID 帧已提交给 UART4 DMA。RemoteID 绿色表示 STM32 本地 RemoteID 发送通道健康；红色/离线表示 UART4/DMA 未初始化、提交失败或 DMA 忙超时。该状态不替代 ESP32-S3 广播状态，ESP32 真实广播确认必须由后续回传协议补齐。

模块状态外发使用原生 MAVLink `NAMED_VALUE_INT`：`MODSTAT0` 和 `MODSTAT1` 每帧打包 8 个模块状态，每个状态占 4 bit，模块顺序与 `Px4Lite_ModuleId_t` 一致。该机制只承载模块状态，不替代具体外设数值消息。

## 2026-06-30 LoRa / RemoteID 身份和数据流收口

- 统一身份源为 `PX4LITE_ORG_PREFIX + PX4LITE_UNIT_ID`：RemoteID 显示为 `DCDW-%03u`，LoRa `node_id = UNIT_ID`，MAVLink `system_id = UNIT_ID`。主机固定 `DCDW-001 / node_id=1 / system_id=1`，从机从 `DCDW-002` 开始递增。
- 角色和身份分离：`PX4LITE_NODE_ROLE_MASTER/SLAVE` 只决定查看权限、poll 行为和 stream 控制策略，不再改变身份编号算法。
- LoRa 物理层仍为广播，协议层必须过滤完整数据：`HEARTBEAT`、`COMMAND_LONG`、`COMMAND_ACK` 和 `LORASUM` 摘要允许所有节点处理；导航、姿态、电源、告警、日志等完整数据只有本机正在查看对应节点时才能写入远端快照。
- 从机查看主机采用“最后一个查看者为准”：主机收到新的 stream start 后记录 `active_viewer_node_id`、`lease_id` 和 180 s 截止时间；同一查看者续约只刷新短传输窗口，不延长 180 s 上限；其他从机通过 `LORASUM` 看到占用者和倒计时后提示/退出。
- 主机查看从机时只选择一个从机完整数据流；未选中的节点只保留心跳和摘要。主机处于远程查看时后台 poll 自动退让。
- LoRa 在线判定不再把 3 s 心跳和 3 s 离线阈值贴边使用：当前心跳为 1000 ms，LoRa offline 窗口为 8000 ms，用于降低黄绿反复闪烁。
- 以上实现不新增任务、不扩大 `PX4LITE_STACK_COMM`，新增状态均为文件级静态变量或远端快照内标量字段。
