# 2026-07-10_04 修复 RemoteID 自检灯在兜底刷新路径不更新(表现为"只上电检测一次")

## 问题现象

硬件已正确:ESP 插上 PC8=3.3V(高)、拔掉=0.x V(低),电平切换正常。但屏上 **RemoteID 自检灯拔插不变**(LoRa 灯却会变)。表现像"上电检测一次、之后不再检测"。

## 根因

显示周期刷新 `Display_Refresh` 取系统快照有两条路径([display.c](../../Display/Src/display.c) 约 1169-1177):

- `App_GetDisplaySystem()==OK` → `Display_LoadSystemSnapshot()`:刷**全部**自检灯,含 RemoteID(经 `Display_MapCommStateValue`)。
- `App_GetDisplaySystem()!=OK`(本地模式,系统快照未就绪) → `Display_LoadModuleStatusFallback()` 兜底。

而 `Display_LoadModuleStatusFallback()` 只刷了 **GNSS/IMU/BARO/LoRa/SD** 五个灯,**漏了 RemoteID**(以及 5G)。该兜底函数写于 RemoteID(PC8 在位检测,2026-07-09_25)接入之前,一直未补。

当板子长期走兜底路径时,CommWorkRun 每周期仍按 PC8 正确更新 REMOTE_ID 模块状态(ONLINE/FAILED),但显示层兜底不把该状态刷到灯 → **RemoteID 灯冻结在启动时的值**,拔插不动;LoRa 因兜底里有,所以会变。

## 修改

- `Display/Src/display.c` `Display_LoadModuleStatusFallback()`:在 LoRa 之后补上 RemoteID 灯刷新,与 `Display_LoadSystemSnapshot()` 一致:
  ```c
  if (App_GetModuleStatus(PX4LITE_MODULE_REMOTE_ID, &status) == PX4LITE_OK) {
    (void)Display_SetHmiValueU16(DISPLAY_HMI_VAR_SELF_CHECK_REMOTEID, Display_MapCommStateValue(status.state));
    loaded = 1U;
  }
  ```

## 行为变化

- RemoteID 自检灯在**全量快照路径与兜底路径都刷新**:拔掉 → 约一个显示周期内转红;插回 → 转绿。不再"只上电检测一次"。
- 判据仍是 PC8 硬件电平(CommWorkRun 每周期读),本次只是把已正确的模块状态补进兜底显示路径。

## 验证方法和结果

- **未运行 Keil build**:本机无 Keil MDK-ARM 环境,未执行 `0 Error/0 Warning`。改动为单个 if 块,与同函数既有 LoRa/SD 块同构,人工核对通过。**须 Keil Rebuild All + 重新烧录后实测。**
- **上屏实测**:拔 ESP → RemoteID 灯变红;插回 → 变绿;反复热插拔灯跟随 PC8。

## 尚未解决或后续替换项

- Keil 编译验证 + 重新烧录(之前烧的固件也可能不含该修复)。
- 兜底路径同样漏了 **5G(`SELF_CHECK_5GA`)** 灯;若启用 5G 模块需按同法补上(本次只修 RemoteID)。
- 电机 4 灯由环境/电池路径驱动,不在本函数范围,无需补。
