# 单路主回路供电监测与统一显示

日期：2026-11-04。当前为本地软件候选，实板验收待执行；进度以 `Release/V1.0_执行台账.md` 为准。

## 需求与测量来源

用户确认一个电流计位于整机主回路，要求停用第一组电压、电流，只保留第二组，屏幕使用统一的电压、电流和功率名称。当前不识别输入来自电池还是外接电源，因此不向消费者声明有效电池电量或充电状态。

| 路径 | 默认配置 | 结果 |
|---|---|---|
| PA5 / ADC1_IN5 电压1 | 停用 | 不初始化外部引脚、不预充、不采集、不发布 |
| PC0 / ADC3_IN10 电流1 | 停用 | 不初始化外部引脚，禁用接口在惰性初始化前拒绝 |
| PA4 / ADC2_IN4 电压2 | 启用 | 主回路输入电压 |
| PC1 / ADC3_IN11 电流2 | 启用 | 主回路总电流，测量范围由实际电流计安装位置决定 |
| ADC1 内部 VREFINT | 保留 | ADC2 与 ADC3 继续使用公共 VDDA 修正 |

第二组分压比例、电流标定、滤波和采样周期保持。功率使用同组电压、电流计算，既不是电机单独功率，也不是实测转速或推力。

## 配置与层次边界

- BSP 使用 `BSP_ENABLE_POWER1/2` 管理外部硬件输入，当前为 `0/1`。ADC总开关按组使能派生，ADC1可仅用于内部参考，不占用PA5。
- Framework 使用 `PX4LITE_ENABLE_BATTERY1/2` 管理生产路径，当前为 `0/1`；电源模块总开关按OR派生。两层分别管理自己的配置，Platform Adapter只初始化、读取及请求恢复已启用的驱动。
- 原第一/第二组topic、结构字段、模块编号和HMI编号继续保留。第二组没有被复制进第一组充当主电池；消费者保持真实数据来源。
- `sensor`继续是采集所有者，Health负责最终超时判定，恢复回调只设置请求。未新增任务、动态内存或ISR业务处理。

## 健康与控制

唯一电源模块依据已启用组汇总新样本、错误和低压事实。默认仅第二组时，第二组成功维护Power在线及心跳；禁用第一组不会引起假离线、恢复循环或不断重置第二组滤波。

电流失败时仍保留有效电压供Control判定，同时电源服务降级并记录错误。电机控制仍读取Battery2，保留既有低压闭锁、恢复滞回、最高电压、有效性、过期与急停策略；本轮未调整保护阈值。

新增回归覆盖开机0 ms即取得样本的情况：该样本合法，断流应按运行离线门限判断；真正未取得样本时才使用启动宽限。使用显式sample_seen/work_started事实区分0时间与未开始。

## 显示与业务

Flight、Power/Environment详情及Remote使用统一的 `Voltage / Current / Power`，不再分Main/Motor两组。默认读取第二组真实字段；缺测或过期显示N/A，不把低压或超范围有效读数人为改为零。功率来源无效时也显示N/A。

Observe保留38个字段的原编号，停用组元数据标为不可选，UI跳过空组，请求与采样入口均拒绝禁用字段。Debug只读取启用组；关闭Debug不会改变生产路径。本机事件文本改为Supply，事件编号、严重度及目录顺序保持。

供电类型未确定时，App不置电量百分比有效位。原驱动中的电压估算算法保留为内部历史能力，不用它自动判断供电类型。

## 通信与CSV兼容

- MAVLink第二组继续使用 `BATTERY_STATUS.id=1`；停发禁用第一组的 `id=0`。上位机应读取id=1，不能只等待id=0。
- `SYS_STATUS`原第一组电池字段使用协议未知值，不静默取第二组替代。第二组 `battery_remaining=-1`、`charge_state=UNDEFINED`，电压和有效电流继续逐字段编码。
- LoRa POWER实验组只冻结并发送已启用组，单路第二组也会正确结束一次发送。
- CSV仍为schema2、49列，列名与顺序保持。第一组数据域为Missing，占位数值不得当作有效0V/0A；不为该禁用组产生缺测或低压故障。
- 百分比输入的 `UINT8_MAX` 表示未提供，序列化为空列；`0..100`仍正常输出。默认通用供电的 `battery2_pct`为空，而不是255%或伪造0%。解析端需保留空列并按未知处理。
