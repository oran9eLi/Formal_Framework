# LoRa心跳发现与选中数据流统一

## 背景

实际产品交互要求在线发现和数据查看分层：所有节点先用轻量心跳判断在线；用户在主机选择从机，或在从机选择主机后，目标节点才开始发送自己的屏幕同源数据。单纯依赖心跳会有空口碰撞漏包概率，单纯依赖学生手动打开 poll 兜底也不适合教学使用，因此本次改为默认自动兜底。

## 变更

- 所有节点在产品模式下低频发送 `HEARTBEAT`，用于在线发现和远端节点列表显示。
- 从机空闲时不再屏蔽 `HEARTBEAT`；只屏蔽 GPS、姿态、位置、气压、电池、模块状态、告警等主数据。
- 心跳周期调整为 3000 ms，并按 `node_id * PX4LITE_MAVLINK_HEARTBEAT_SLOT_MS` 做启动错峰，降低多节点同时上电时的碰撞概率。
- `MAV_CMD_USER_1` stream start/stop 继续作为选中数据链路：主机选从机、从机选主机都走同一套租约续期。
- 主机默认开启 `MAV_CMD_USER_2` 慢速 poll 兜底，按 node id 自动轮询在线状态，学生无需改代码。
- 主机选中某个从机查看数据时，后台 poll 自动退让，避免和屏幕数据抢 LoRa 空口。
- 主机和从机同时互相查看时，双方 stream 保持打开，主数据目录项按 `PX4LITE_MAVLINK_MUTUAL_STREAM_THROTTLE` 自动降频；`HEARTBEAT`、COMMAND 和 ACK 不降频。
- 更新 `03_模块接入手册.md` 和 `05_完成度与后续清单.md`，明确“心跳发现 + 选中租约数据流”的统一规则。

## 栈与任务

- 未新增 FreeRTOS 任务。
- 未新增周期栈大对象。
- 仅调整 MAVLink TX 调度策略和配置宏，仍由原 `comm` 任务单所有者发送。
