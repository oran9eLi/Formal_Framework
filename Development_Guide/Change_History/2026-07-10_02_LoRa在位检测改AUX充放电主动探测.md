# 2026-07-10_02 LoRa 在位检测改 AUX 充放电主动探测(修复拔出不变红)

## 修改原因和风险

- **原因**:实测 LoRa 上电不插=红(对)、插上=绿(对)、但**运行中拔出不会变回红**。定位为在位判据 `Lora_E22_IsPresent()` 直接活读 AUX(PF0)静态电平:模块在位时 E22 用推挽把 AUX 拉高,拔出后那条走线只靠 STM32 内部弱下拉(~40kΩ),被残留电荷/走线电容钉在高电平,固件读到高 → 仍判在位 → 灯不翻红。静态读电平无法区分"在位空闲高"与"拔出悬空高"。
- **方案**:改用**充放电主动探测**——先把 AUX 临时配成推挽输出拉低,排空悬空走线上的电容;再切回下拉输入采样。E22 的 AUX 是推挽强驱输出,在位时会立即把线重新拉回高(读 1);拔出后悬空线被放电+下拉维持低(读 0)。探测结果经去抖后作为在位标志。这样在位判定不再依赖引脚静态电平,纯软件即可在拔出后翻红,**无需改动硬件**。
- **对比冷启动为何原本正确**:冷启动 AUX 自复位起一直被下拉在低、且模块从未推挽拉高过,读到稳定低 → 红正确;运行中拔出是从"曾被推挽拉高"跌落,才出现悬空钉高。这解释了"开机对、运行拔出错"的不对称。
- **风险**:
  - 探测拉低的瞬间会和在位模块的推挽高**短暂顶牛**(推挽对推挽)。已把放电脉冲压到微秒级(≈4µs)、探测低频(默认 300ms 一次),电流与时长都很小,可接受。
  - 若在模块**正忙**(发送空口/接收空口,AUX 本就被拉低)时探测会误读低。已用两道闸门规避:①TX 状态机非空闲或占空静默期内不探测;②近期收到过对端帧(< 探测周期)直接判在位并跳过探测。
  - 探测期间 AUX 短暂变输出,只允许在 comm 任务上下文调用(单写者),不得在 ISR 内调用。

## 涉及文件

- `Bsp/Src/bsp_lora.c`、`Bsp/Inc/bsp_lora.h`:新增 `BSP_LoRa_ProbeAuxPresent()`(推挽拉低放电→切下拉输入→settle→采样,返回后 AUX 恢复输入+下拉);新增微秒级忙等 `BSP_LoRa_ProbeSpin` 与常数 `BSP_LORA_AUX_PROBE_DISCHARGE_ITERS/SETTLE_ITERS`。
- `Sensor/Src/lora_e22.c`:
  - 新增去抖在位状态 `s_present_state / s_present_pending_streak / s_present_next_probe_ms` 与常数 `LORA_E22_AUX_PROBE_PERIOD_MS(300) / LORA_E22_AUX_PROBE_DEBOUNCE(3)`。
  - 新增 `Lora_E22_UpdatePresence()`:近期有 RX 直接判在位;否则仅在 TX 空闲+过静默期时按周期探测,连续 3 次反向才翻转在位态;由 `Lora_E22_Service()` 每周期调用。
  - `Lora_E22_Init()` 成功路径以在位起步(`s_present_state=1`),首探测推迟一周期。
  - **重写 `Lora_E22_IsPresent()`**:改为返回去抖后的 `s_present_state`(未初始化仍返回 0),不再活读 AUX 静态电平。原 `Lora_E22_LocalUnavailable`/`s_last_aux_ready_ms` 超时逻辑保留,仍供 `Lora_E22_GetState` 使用。
- `Sensor/Inc/lora_e22.h`:更新 `Lora_E22_IsPresent` 注释说明改为探测去抖判据。

上层无需改动:`Px4Lite_CommWorkRun` 仍按 `Px4Lite_LoRaIsPresent()`(转调本接口)发布 LoRa 灯色(在位=ONLINE 绿,拔出=FAILED 红),显示层映射不变。

## 行为变化

- **拔出翻红**:运行中拔掉 E22,约 `300ms × 3 ≈ 0.9s` 内 LoRa 自检灯由绿转红(FAILED + COMM_OFFLINE),不再长期卡绿。
- **插回转绿**:插回后恢复监视器(约 2s 退避)重初始化成功,`s_present_state` 复位为在位 → 转绿;若在重初始化前探测先命中,亦会自恢复。
- **冷启动不插**:仍稳定红(未初始化直接返回不在位),行为不变。
- **正常收发**:近期 RX 或 TX 忙时不探测,不影响链路吞吐;探测仅在空闲缝隙以 300ms 低频进行,单次 comm 周期额外阻塞约十几微秒。
