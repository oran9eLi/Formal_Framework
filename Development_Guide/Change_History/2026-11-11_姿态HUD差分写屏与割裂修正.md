# 姿态HUD差分写屏与割裂修正

日期：2026-11-11。任务V1-HUD-T01，证据V1-E65；软件检查通过，实屏待验证。本文面向固件维护与验收人员，依据当前绘制/提交代码、主机GRAM比较、Keil构建和用户现场反馈记录实际改动。

## 原因与范围

用户再次反馈姿态页中间圆圈像整页刷新一样割裂，并提供照片。照片能说明页面与读数，不能独立证明动态帧率或所烧录固件身份。代码核查发现：E62虽然将HUD取数请求改成50ms并固定一批条带的姿态，像素仍通过800×16行局部缓冲直接写入可见SSD1963 GRAM；2ms软预算用完后，下一个显示节拍才继续，所以画面变化可能逐条带出现。上次软件优化不等于此次实屏问题已经解决。

本次仅处理姿态HUD圆圈的像素提交，沿用10ms显示调度、触摸优先、2ms软预算、16行LVGL缓冲、50ms HUD请求和整批固定快照。未修改传感器采集、姿态解算、控制、MAVLink协议与速率、RGB灯效、其他页面或FSMC硬件时序。

## 实际改动

1. 新增Display层`display_hud_present`：比较最终RGB565像素与上次真正同步写入的颜色，跳过完全相同的像素，仅提交变化区间。允许桥接最多4个相同像素，减少短区间设置窗口的开销。
2. 258×258 HUD内半径126px的实心圆采用4bit索引精确缓存。11种已知颜色保存完整RGB565对应关系；未知色索引15，每次都写，不近似抗锯齿色，不采用有碰撞风险的哈希。圆外和非HUD区域保守使用原写屏；整块不与HUD相交时维持一次原批量调用。
3. 配色/位置/尺寸身份变化、切页、布局重建或LCD恢复时撤销缓存。首块全部未知时原样批量提交后建立缓存；提交后确认LCD就绪才记录已写入的事实。Freeze、ZERO、无效灰盘和其他显示行为沿用原入口。
4. 缓存总计25057B：CCM尾24KB＋主SRAM481B。ARMCC将整个64KB CCM明确保留为UNINIT区域，前40KB仍供原LVGL裸地址内存池；本模块只读写尾24KB，绝不整体清空CCM。主机测试以A5哨兵检查前40KB未被修改。该区只供CPU访问，绝不用于DMA。
5. 仅新提交单元使用ARMCC局部O2/Otime和逐像素小函数强制内联，避免每像素Changed/Get/Byte多层调用抵消总线收益；不改变全工程优化或外设时序。反汇编确认Byte/Get/Set/Changed/Find无逐像素BL调用。
6. `DISPLAY_HUD_DIFF_ENABLE=0`可回退原批量提交并不分配缓存；已单独全量构建和主机检查。

局部优化语法核对：[Arm Compiler 5用户手册](https://www.keil.com/support/man/docs/armcc/)的`#pragma Onum`、`#pragma Otime`及`__forceinline`章节。

## 验证与资源

最终14组选定host全部通过：hud_present、hud_present_off、hud_refresh、gnss_clean_display、display_gnss_status_utc、display_motor_lock、display_field_validity、bmi088_platform、attitude、attitude_ops、attitude_roll_wrap、bmi088_uplink、gnss_sat_stream、startup_rgb。新增提交测试使用-Werror；不将未指定-Werror的其他组描述成同一编译设置。

GRAM比较覆盖160组确定性随机partial、跨HUD/边界裁剪/源行跨度、未知颜色、半字节相邻值、主SRAM尾、切页/位置/配色/恢复及关闭路径。每次提交后与旧全量路径整个800×480 GRAM逐像素一致。缓慢12步、每步地平线移动1px的模拟中，写入24096/494508像素，约减少95.1%；完整重复圆块写入17361/66564像素。这是模拟像素流量，不能换算成实际帧率或完成时间，快速大幅动作不保证同样收益。

Keil唯一工程、Target 1、ARMCC5.06/C99：run1启用/关闭均Rebuild All 0 Error(s), 0 Warning(s)；随后为避免逐像素调用开销补充局部优化，run2最终关闭/启用再次全量0/0，构建日志各15s，进程退出0。最终构建时间2026-11-11 10:29:29—10:30:04（UTC+8），默认启用版本最后构建。没有沿用历史构建冒充本次结果。

普通执行环境初次启动fromelf失败，系统报告DLL重定位错误；不修改生产代码来规避环境问题。在允许的本机环境启动后成功生成反汇编，并核对热点无BL调用。其后一条检索因没有匹配行而返回1，不是反汇编失败；以实际58548B输出文件及内容核验为准。两轮Keil构建均无失败/警告；最终14组host无失败。
