# 2026-07-07_13_远端遥测漏收修复与电机滑块保活

## 背景

两个现场问题：
1. **本地读数正常，但远端（LoRa 接收方/远端显示）收不到 电流 / BME280 / MPU6050，其他数据都能收到。**
2. **电机滑块滑上去后，约 200ms 又自己掉回 0。**

排查后确认都在接收端/UI 逻辑，不是传感器或发送层。本次修 3 处确定 bug，姿态/压力那条另议（见文末）。

---

## 一、远端漏收：确定的接收端 bug

### 1.1 电流——接收端根本没解（端到端修）

`SendBatteryStatus` 发送端已带 `current_battery`（单位 cA=10mA），但远端 `MavRx_DecodeBattery` / `MavRx_DecodeSysStatus` 只取了电压/电量/充电态，**从不读 `current_battery`**；`Px4Lite_RemoteTelemetry_t` 也没有电流字段、远端显示没有消费点（`app_data_api.c` 读的是本地电流）。→ 电流发得出去、进 LoRa 后被丢。

**修改**：
- `px4lite_types.h`：`Px4Lite_RemoteTelemetry_t` 新增 `uint32_t current_ma`。
- `px4lite_mavlink_rx.c`：`MavRx_DecodeBattery` 与 `MavRx_DecodeSysStatus` 解 `current_battery`（`>=0` 时 `current_ma = current_battery * 10`，cA→mA；-1 视为未测量保持 0）。
- `app_display_model.c`：`App_GetDisplayEnvironment`（远端模式）补 `out->current_ma = remote.current_ma`，与本机路径对齐。

### 1.2 BME280 湿度——被压力帧覆盖成 0（修）

湿度经独立的 `HUMIDITY` NAMED_VALUE 帧送到，但 `MavRx_DecodePressure` 里写死了 `remote->relative_humidity_pct = 0.0f;`——每收到一帧 SCALED_PRESSURE 就把湿度清零。

**修改**：`px4lite_mavlink_rx.c` 删除该清零语句（湿度只由 HUMIDITY 帧维护）。

### 1.3 BME280 压力/温度 + MPU6050 姿态——本次不改（待确认）

接收 handler（`DecodeAttitude`/`DecodePressure`）与显示消费（`app_display_model` roll/pressure/temperature）链路**本身正确**。若这两个仍收不到，不是解码缺失，而是 **LoRa 带宽/占空过载**（9600bps + 40% 占空，当前周期激进：姿态 500ms、压力 1000ms…）。建议先在收端看接收计数确认，再决定是否放宽这几条的发送周期，**不盲目改周期**。

## 二、电机滑块"自己掉下来"：200ms 指令看门狗未被喂狗

**根因**：`px4lite_control.c` 控制任务对每路电机有 200ms 指令失效保护
（`PX4LITE_CONTROL_FAILSAFE_TIMEOUT_MS`）：
```c
if (estop || target_update_ms==0 || (now - target_update_ms) > 200ms) { 该路油门 = 0; }
```
即油门目标必须每 200ms 至少刷新一次，否则判"指令失联"归零。而屏幕滑块**只在拖动事件下发一次**（`App_SetMotorThrottlePercent`），松手后无任何周期性重发 → 约 200ms 后失效保护清零 → 电机状态回 0 → 滑块随刷新拉回 0。

**修改**（全部在 `Display/Src/display.c`，不动控制层，保留失效保护语义）：
- 新增 `s_motor_cmd_percent[4]` 缓存本机滑块最新油门意图；在滑块下发（`Display_SetMotorThrottleCommand`）、急停（`Display_MotorEmergencyStop`）、低压强停（`Display_ForceMotorsOff`）三处同步更新（下发写值/清零写 0）。
- 新增 `Display_ServiceMotorKeepAlive()`：把非零油门重发一次喂狗；**仅本机模式且非低压锁定**时驱动。
- 在每 10ms 的显示服务节拍 `Display_PollTouch()`（由 Business 显示任务 `BUSINESS_DISPLAY_SERVICE_PERIOD_MS=10` 调用）里调用它。

**安全性保持**：保活的源头是显示任务本身——只要显示/通信任务挂死，保活停止，控制层 200ms 失效保护照样安全停机；`px4lite_control.c` 的按键急停、控制任务自身 200ms 看门狗、2500ms ESC 解锁延时均不变。**不建议直接调大 200ms 超时**（削弱安全）。
