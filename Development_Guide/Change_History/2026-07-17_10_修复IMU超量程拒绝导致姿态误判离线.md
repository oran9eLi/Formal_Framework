# 2026-07-17_10 修复 IMU 超量程拒绝导致姿态误判离线

## 现象

姿态运行一段时间后自行掉线，硬件正常。与 [2026-06-17_31](2026-06-17_31_I2C共享总线与MPU6050退避说明.md) 记录的"MPU6050 上电运行一段时间后离线、BME280 短暂离线又恢复"属同一症状族。

## 根因链

三个缺陷叠加，任何一次剧烈机动都会把 IMU 打成"永久离线"。

### 1. 量程过小，正常机动即削顶

芯片原配置为最小量程 `MPU6050_ACCEL_RANGE_2G`(±2g) 与 `MPU6050_GYRO_RANGE_250DPS`(±250dps)。而控制层允许 ±45° 横滚/俯仰目标（`PX4LITE_CONTROL_ATTITUDE_TARGET_LIMIT_DEG100 = 4500`）并支持自动起降。手上快速转动、磕碰、电机振动都会超过该量程，传感器输出的是限幅后的假数据。

### 2. 超量程拒绝阈值在旧量程下等于"普通动作"

`Mpu6050_IsOutOfRange()` 以原始值 29500 为界。旧量程下换算为：

- 加速度：29500 ÷ 16384 LSB/g = **1.80 g**
- 角速度：29500 ÷ 131 LSB/dps = **225 °/s**

该检查的本意是拦截贴轨的垃圾帧，但在 ±2g/±250dps 满量程下，90% 满量程就是普通动作。且 `RANGE_REJECT` 被计入 `Mpu6050_ShouldCountForReinit()`，连续 5 次即触发 `BSP_I2C_Recover()` + 整片重初始化——重初始化并不能让机体慢下来，只会让 IMU 停摆更久，并连带干扰同 I2C 总线的 BME280。

### 3. 稳定计数被瞬时失败清零，导致永久锁死

`Px4Lite_ImuRead()` 中：

```c
result = Sensor_MPU6050_Service(now_ms);
if (result != MPU6050_RESULT_OK) {
    stable_valid_count = 0U;        /* ← 任何一次拒绝都清零 */
    return ...PX4LITE_IO_ERROR;
}
...
if (stable_valid_count < PX4LITE_IMU_STABLE_VALID_MIN) {   /* 需要 3 */
    stable_valid_count++;
    return PX4LITE_IDLE;            /* ← 爬坡期间不发布 */
}
```

需连续 **4 次** Service 成功才发布一帧（3 次爬坡 + 第 4 次发布），按 10 ms 采样周期即需 **40 ms 干净数据**。只要拒绝出现得比每 40 ms 一次更密，`stable_valid_count` 就在 0..2 之间反复横跳而永远到不了门限，`Px4Lite_ImuRead()` 永不返回 OK，`s_status[IMU].last_rx_ms` 就此冻结，2000 ms 后 Health 判定 OFFLINE（`px4lite_modules.c:701`），姿态位随之消失。

该清零**超出了 AGENTS.md 的规定**。规范只要求"IMU 重初始化后，Platform Adapter 至少等待 3 帧连续有效数据后才允许发布"，而该语义已由下方 `reinit_count` 判定正确实现。第 395 行的清零是额外多出来的，它把"刚重初始化过"与"这一帧数据不好"混为一谈。

## 修复

### 量程改为 ±8g / ±1000dps

`sensor_mpu6050.c`：`AFS_SEL=2` / `FS_SEL=2`（寄存器 bit[4:3]，值 `0x10`），换算系数同步改为 4096 LSB/g 与 32.8 LSB/dps。宏一并改名为 `MPU6050_ACCEL_RANGE_8G` / `MPU6050_GYRO_RANGE_1000DPS` / `MPU6050_ACCEL_SCALE_8G` / `MPU6050_GYRO_SCALE_1000DPS`——改名而非改值，是为了让任何漏改的使用点在编译期暴露，避免出现"能编译但数值错"的静默故障。已核对全仓库无旧宏残留。

改后关键数值：

| 项 | 旧(±2g/±250dps) | 新(±8g/±1000dps) |
|---|---:|---:|
| 满量程 | 2.00 g / 250 dps | 8.00 g / 999 dps |
| 29500 拒绝阈值 | **1.80 g / 225 dps** | **7.20 g / 899 dps** |
| 量化步长 | 0.061 mg/LSB / 0.0076 dps/LSB | 0.244 mg/LSB / 0.031 dps/LSB |

29500 这个阈值本身未改：在新量程下它对应 7.20 g / 899 dps，回归了"贴轨垃圾帧"的本意。

### `RANGE_REJECT` / `SPIKE_REJECT` 不再计入重初始化门限

`Mpu6050_ShouldCountForReinit()` 只保留 `DATA_READ`(I2C 不通) 与 `ZERO_FRAME`(芯片掉配置或掉电)——这两者才说明采样链路本身不可用。超范围帧与尖峰帧是机体动得快导致的真实数据，链路是好的。

### 删除稳定计数的额外清零

`px4lite_platform_f407.c`：单帧采样失败只代表"本轮没有新样本"，不再重置 `stable_valid_count`。清零的唯一来源恢复为 `reinit_count` 变化，与 AGENTS.md 一致。启动路径不受影响：`Px4Lite_ImuInit()` → `Sensor_MPU6050_Init()` 使 `s_reinit_count` 由 0 变 1，首次读取时 `reinit_count != last_reinit_count` 成立，仍会正常执行 3 帧爬坡后再发布。

## 未改动项与理由

- **量化对姿态估计器的影响**：已核对 `px4lite_attitude.c` 全部阈值均以物理单位表达，与量程解耦。新量化步长下余量充足——`STATIC_ACCEL_DELTA` 0.03 g = 123 LSB，`STATIC_GYRO_DELTA` 2.0 dps = 66 LSB，`YAW_DEADBAND` 0.75 dps = 25 LSB，均远高于 1 LSB。陀螺量化噪声约 0.0088 dps RMS，仍低于 MPU6050 自身约 0.05 dps RMS 的噪声底。**无需重新整定。**
- **`PX4LITE_IMU_CALIB_ACCEL_MIN_MG` / `MAX_MG` / `GYRO_MAX_MDPS`**：以物理单位表达，不受量程变更影响。但已核对这三个宏**全仓库无任何引用**，属死配置，本次不动，建议后续单独清理。
- **`navigation` 快照的姿态瞬时闪断**（次要缺陷，本次不修）：`px4lite_modules.c:554` 的 `navigation` 为每轮 memset 的局部快照，`PX4LITE_NAV_VALID_ATTITUDE` 仅在本轮取到 IMU 样本时置位，而 `publish_navigation` 在 GNSS 序号变化时也会置 1。故某轮 GNSS 更新而 IMU FIFO 恰好为空时，会发布一份无姿态位、且 roll/pitch/yaw 全为 0 的快照。GNSS 约 1 Hz，表现为低频闪断而非持续掉线，与本次根因无关，留待单独评估。

## 现场验证方法

固件已有诊断打印（`debug_service.c:99`）：

```
IMU: state=%u err=%lu age=%lu fresh=%u drv_stage=%u drv_rc=%u reinit=%lu ...
```

`drv_stage` 枚举见 `sensor_mpu6050.h:31`：`NONE=0, PROBE=1, WHO_AM_I=2, CONFIG=3, DATA_READ=4, ZERO_FRAME=5, SPIKE_REJECT=6, RANGE_REJECT=7`。

修复前预期：掉线时 `drv_stage=7`、`err` 与 `reinit` 持续增长、`age` 冻结。
修复后预期：剧烈机动下 `drv_stage` 不再频繁为 7（阈值提高到 7.2g/899dps），即使偶发也不再触发 `reinit`，`age` 保持在 `PX4LITE_IMU_MAX_AGE_MS` 内，`state` 稳定为 ONLINE。

回归重点：静置时姿态零漂与 yaw 稳定性应与改动前一致（阈值余量分析见上）。
