# 2026-07-07_11_树莓派专属扩展遥测

## 背景与原因

三链路架构中，树莓派链路(USART1 / compid 193)应作为"全量数据出口"，即树莓派收到的数据是
**LoRa 遥测的超集**：除镜像 LoRa 的全部标准遥测外，还应额外携带树莓派本身拿不到的信息 ——
**LoRa 链路状态、RemoteID 广播状态、节点 ID、身份哈希摘要**。

改动前，RPi 链路只是把每帧 LoRa MAVLink 改写 compid=193 后镜像到 USART1(`MavTx_SendRpiCopy`)，
字段集与 LoRa **完全相同**，没有任何 RPi 专属内容。本次按计划书补齐 RPi 专属扩展消息，
标准消息没有的一律用 `NAMED_VALUE_INT` / `STATUSTEXT` 承载，只发 USART1、**不上 LoRa 空口**。

本次不新增文件、不新增任务，仍由 CommTask 以静态缓冲逐帧调度，不扩大任务栈。

## 一、新增 RPi 专属消息(仅发 USART1)

在 `px4lite_mavlink_tx.c` 发送目录尾部新增 3 项(仅 `PX4LITE_ENABLE_RPI_MAVLINK` 时编译)：

| 名称 | MAVLink 消息 | 周期 | 内容 |
|---|---|---|---|
| `RPILORA` | `NAMED_VALUE_INT("LORASTAT")` | 1000ms | LoRa 链路状态 |
| `RPIRID` | `NAMED_VALUE_INT("RIDSTAT")` | 1000ms | RemoteID 广播状态 |
| `RPIIDENT`| `STATUSTEXT` | 5000ms | 节点 ID + 完整身份串 + 身份哈希摘要 |

三者 `scope = MAV_TX_SCOPE_ALWAYS`，不受 LoRa 的 `NAMED_VALUE` 扩展策略约束，因为它们是
独立于 LoRa 的 RPi 出口数据。编码时直接用 `PX4LITE_RPI_MAVLINK_COMPONENT_ID(193)` 打包。

### `LORASTAT`(value 位布局)
- `[0:15]` 接收侧估算丢包率，单位 0.1%(0..1000)
- `[16:23]` LoRa 节点 ID
- `[24]` LoRa 模块在位标志
- `[25:27]` LoRa 链路状态枚举(`Px4Lite_State_t`)

数据源：`Px4Lite_LoRaGetDebugInfo` / `Px4Lite_LoRaGetState` / `Px4Lite_LoRaIsPresent` /
`Px4Lite_IdentityGetNodeId`。`time_boot_ms = now_ms`。

### `RIDSTAT`(value 位布局)
- `[0:15]` 位置广播成功计数低 16 位(`location_count`)
- `[16:31]` 编码/提交错误计数低 16 位(`error_count`)

数据源：`Px4Lite_RemoteIdTxGetStats`。`time_boot_ms = last_success_ms`，
树莓派据此判断 RemoteID 是否仍在推进广播(结合本机 RemoteID 自检状态)。

### `RPIIDENT`(STATUSTEXT 文本)
形如 `ID=DCDW-160 NODE=160 HASH=1A2B3C4D`，与 RemoteID `self_id`/`uas_id` 同源。
`severity = MAV_SEVERITY_INFO`。用轻量定长追加器(`MavTx_TextAppend*`)构造，不引入 stdio。

## 二、身份哈希摘要对外暴露

`px4lite_identity.{h,c}`：新增 `uint32_t Px4Lite_IdentityGetUidHash(void)`，
返回由 STM32 硬件 UID 派生的 32 位 FNV-1a 摘要(按需缓存)。原 `Identity_BuildUidHash`
为私有；`Px4Lite_IdentityGetNumericId` 改为复用该 getter，行为不变。

## 三、双链路序号正确性(关键)

RPi 是一条独立 MAVLink 链路，其序号必须自成连续序列，才能让树莓派侧正确统计丢包；
同时**不能污染 LoRa 的通道序号**，否则远端 LoRa 接收方会把空洞误判为丢包
(见 `Px4Lite_MavlinkTxRun` 原有注释)。为此：

- 新增 `s_rpi_tx_seq`：RPi 链路独立发送序号，**镜像帧 + RPi 专属扩展帧共用**该计数器，
  保证树莓派收到的是一条连续序列。
- `MavTx_SendRpiCopy` 重构：镜像帧改写 compid=193 的同时，用 `s_rpi_tx_seq++` 重新编号，
  发送后恢复原 `compid/seq/checksum`(原实现保留 LoRa 原始 seq)。
- 新增 `MavTx_SendRpiExclusive`：RPi 专属帧经 `encode_chan(COMM_0)` 编码时占用了一个 LoRa
  发送序号，但该帧不经 LoRa。发送前把 `MAVLINK_COMM_0` 的 `current_tx_seq` **回退**到该帧
  借用的值(库实现为 `msg->seq = current_tx_seq; current_tx_seq++`，故回退为
  `current_tx_seq = s_message.seq`)，再用 `s_rpi_tx_seq++` 重编号，只写 USART1。
- 新增 `MavTx_RecomputeChecksum`：从原 `SendRpiCopy` 提取的 CRC 重算逻辑(按 MAVLink1/2 头
  布局)，供镜像帧与专属帧复用；改写 compid/seq 后必须重算校验和。

净效果：
- **LoRa 链路(COMM_0)**：序号连续，只被真正经 LoRa 发出的帧递增，RPi 专属帧不留空洞。
- **RPi 链路(USART1)**：镜像帧 + 专属帧统一由 `s_rpi_tx_seq` 连续编号，树莓派丢包统计正确。

## 四、配置项

`px4lite_config.h` 新增周期：
```
PX4LITE_MAVLINK_RPI_LORASTAT_PERIOD_MS = 1000U
PX4LITE_MAVLINK_RPI_RIDSTAT_PERIOD_MS  = 1000U
PX4LITE_MAVLINK_RPI_IDENT_PERIOD_MS    = 5000U
```

## 构建

无新增文件，Keil 工程无需改动 `.uvprojx`。需 Keil 重新编译。全部 RPi 相关代码由
`PX4LITE_ENABLE_RPI_MAVLINK` 守卫，关掉该宏时不参与编译。
