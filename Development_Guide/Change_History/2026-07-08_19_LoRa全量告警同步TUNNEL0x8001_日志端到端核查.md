# 2026-07-08_19_LoRa全量告警同步TUNNEL0x8001_日志端到端核查

## 背景

需求:本机有什么告警,远端(LoRa 对端屏幕)就要收到什么告警——逐条完整,不是只有摘要。消息日志同理。

## 诊断:告警只同步了摘要(问题),日志是全量的(无 bug)

**告警(修前)**:LoRa 只发 `ALRMHI`(最高一条) + `ALRMMSK`(活动模块位图)。远端遥测结构体只有 `alarm_active_mask` + `highest_*`,**没有 per-module 记录**;屏幕 RX **不解 TUNNEL**。显示层 `App_GetDisplayAlarm` 从位图硬凑记录:除最高一条外,其它活动模块的 `fault_code`/`severity` 全填 0(`app_display_model.c`)。→ 远端拿不到每条告警的真实详情。

**日志**:端到端机制**完整**(本次核查,无 bug):本机 `Px4Lite_LocalMsgLogPush`(app_message_log)→ `MavTx_SendMessageLog` 增量 LOGSYNC + 每 20s 全量重播 → `MavRx_AppendRemoteLog` 按 sequence 去重进环 → 显示层 `App_*`(valid_mask & VALID_LOG)读 `remote_log_entries`。只要本机有日志事件,远端就能全量拿到。

## 修改:告警改走 TUNNEL 0x8001 全量表(复用 RPi 打包器)

**决策**:LoRa 上把 `ALRMHI/ALRMMSK` 摘要**替换**为 `TUNNEL 0x8001` 完整告警表,与 RPi 侧同构、复用同一打包器。两块板同程序一起重编译即自洽。

**类型**(`px4lite_types.h`):`Px4Lite_RemoteTelemetry_t` 加紧凑 per-module 数组(省 SRAM,不用整套 record):
```c
uint16_t alarm_fault_code[PX4LITE_MODULE_COUNT];
uint8_t  alarm_severity[PX4LITE_MODULE_COUNT];
```
(约 +42B/节点 × 8 节点 ≈ +336B SRAM。)

**TX**(`px4lite_mavlink_tx.c`):
- `MavTx_TunPutU16` + `MavTx_PackAlarmTable` 移出 `#if PX4LITE_ENABLE_RPI_MAVLINK`(LoRa/RPi 共用)。
- 新增 `MavTx_SendAlarmTable`:packs 0x8001 表 → `mavlink_msg_tunnel_encode_chan(compid 191)` → `MavTx_SendToLora()`。无告警时 count=0(小帧,远端感知清空)。
- LoRa 目录项 `ALARM`(NAMED_VALUE/SendAlarmStatus)换成 `ALRMTBL`(TUNNEL/SendAlarmTable,scope=STANDARD)。
- 删 `MavTx_SendAlarmStatus` 摘要编码器 + 分片游标 `s_alarm_status_part`(及 init)。

**RX**(`px4lite_mavlink_rx.c`):
- 新增 `MavRx_DecodeTunnel`:解 0x8001,逐行填 `alarm_fault_code[src]`/`alarm_severity[src]`、重建 `alarm_active_mask`、算 `highest_*`;每帧全量重建,故清空可感知。分发加 `case MAVLINK_MSG_ID_TUNNEL`。
- 删 `ALRMHI`/`ALRMMSK` name 分支(发送端不再发)。
- `MavRx_DecodeStatusText`:**不再改写 `alarm_active_mask`**(只留 `highest_*` 横幅),否则会把全量表的完整位图覆盖成"仅最高一条"。

**显示**(`app_display_model.c`):远端告警逐来源展开时,`fault_code`/`severity` 用 `remote.alarm_fault_code[source]`/`alarm_severity[source]` 真实值,不再只有最高一条有详情。

## 效果

远端现在收到并显示**每一条**活动告警的真实 source/fault_code/severity(全量),而非"最高一条 + 位图"。日志维持既有全量同步。

## 影响面

- LoRa 占空:告警帧由"每 700ms 一条 NAMED_VALUE"变为"每 700ms 一个 TUNNEL 表"。无告警时是 2 字节 payload 小帧(v2 零截断);告警多时一帧带全表(≤100B payload)。周期未变,总体可控;必要时上调 `PX4LITE_MAVLINK_ALARM_STATUS_PERIOD_MS`。
- 契约:LoRa 上 `ALRMHI/ALRMMSK` 弃用(两板一起重编译自洽)。RPi 侧不受影响(本就走 RPIALRM TUNNEL)。
- `STATUSTEXT` 仍发(最高告警文本),但 RX 不再用它写活动位图。

## 改动文件

- `Framework/Inc/px4lite_types.h`:远端结构体加 alarm_fault_code[]/alarm_severity[]。
- `Framework/Src/px4lite_mavlink_tx.c`:TunPutU16/PackAlarmTable 移出 RPi 守卫;加 SendAlarmTable;目录换 ALRMTBL;删摘要编码器+游标。
- `Framework/Src/px4lite_mavlink_rx.c`:加 MavRx_DecodeTunnel + TUNNEL case;删 ALRMHI/ALRMMSK 分支;StatusText 不写位图。
- `Business/Src/app_display_model.c`:远端告警用逐来源真实 fault/severity。
