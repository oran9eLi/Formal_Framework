# 修复电机电池门槛静默拒绝、一键降落姿态门控，并上屏姿态校正量

## 1. 问题

用户现象为三条：滑块拖上去"有时候自己就掉下来"、一键起飞没反应、一键降落没反应。定位后前两条同源，第三条是独立的设计缺陷。

### 1.1 滑块自己回落

`Display_SetMotorThrottleCommand()` 在电机电池档位不足时对非零油门返回 `DISPLAY_NOT_READY`，`Display_LvglMotorSliderEventCb()` 收到失败后执行 `lv_slider_set_value(slider, s_values[id])` 把滑块弹回旧值。整条路径不产生任何日志，因此用户只看到滑块自己掉下来，无从判断是电池门槛还是控制链路故障。

门槛为 `Display_MotorPowerAllowsOutput()`，要求 `s_motor_band > DISPLAY_MOTOR_BAND_LOWPOWER`，即电机电池必须落在 9.9V ~ 13.5V。档位在 9.9V 附近按滞回来回跳时，表现为"有时候"回落。

### 1.2 一键起飞无反应

`Display_RequestMotorAutoTakeoff()` 先过同一道电池门槛并提前 `return`，此路径不推日志；原有的 `姿态或环境异常 一键起飞失败` 日志只在传感器检查失败时才推。电池不足时按钮完全静默。

### 1.3 一键降落无反应

`Px4Lite_ControlStartAutoLanding()` 要求 `Px4Lite_ControlAutoAttitudeReady()` 通过，否则返回 `PX4LITE_NOT_READY`；`Display_RequestMotorAutoLanding()` 对失败不推日志。姿态过期或 IMU 离线时，降落按钮静默失效——而这恰恰是最需要把油门收回 0 的时刻。

姿态修正本身不是滑块回落的原因：`PX4LITE_CONTROL_ATTITUDE_KP_X100 = 30` 对应 10° 误差仅 3% 修正，与现有单元测试 `TestAttitudeAssistPreservesUnequalBaseThrottle`（base 20/30/40/50 + roll 10° → duty 17/33/37/53）一致。

## 2. 修复

### 2.1 拒绝路径全部可见

新增三条 append-only 日志 ID（`px4lite_log_message_ids.h`，同步镜像到 `App_LogMessageId_t` 与 `Display_LogMsg_t`）：

| ID | 文案 | 触发点 |
|---:|---|---|
| 33 | 电机供电不足 一键起飞失败 | `Display_RequestMotorAutoTakeoff()` 电池门槛 |
| 34 | 电机供电不足 油门失败 | `Display_SetMotorThrottleCommand()` 拒绝非零油门 |
| 35 | 一键降落失败 | `Display_RequestMotorAutoLanding()` 未被 Control 接受 |

滑块一次拖动会连续产生多个 `LV_EVENT_VALUE_CHANGED`，每次被拒都推日志会瞬间冲掉整屏历史，因此 `AppLog_PushActionFail()` 对同一原因按 `APP_MSGLOG_ACTION_FAIL_MIN_GAP_MS = 3000` 限流，只保留窗口内第一条。既有的起飞传感器失败日志一并纳入该限流。

三条新日志与原 `TAKEOFF_SENSOR_FAIL` 统一走 `Display_LvglLogMessageIsAction()` 判定，红色 + 循环滚动显示，与周期状态日志区分。

### 2.2 一键降落去掉姿态准入

`Px4Lite_ControlStartAutoLanding()` 移除 `Px4Lite_ControlAutoAttitudeReady()` 检查。撤收动作不应被传感器状态阻止。三条降落入口的口径统一为：

- 自动起飞过程中姿态丢失 → `Px4Lite_ControlMonitorAutoTakeoff()` 自动转入降落斜坡（原有实现不变）。
- 手动油门下按一键降落 → 直接启动降落斜坡。
- 姿态过期 / IMU 离线 / IMU 失败 → 仍然允许降落。

急停锁存时按降落维持返回 `PX4LITE_OK`：此时四路目标已被急停清零，语义上已达成降落终点。

一键起飞门槛保持不变，仍要求姿态与环境模块同时可用。

### 2.3 断开滑轨的输入/输出反馈环（油门自己掉下来的真因）

滑轨原本跟随 Control 发布的 `duty_percent`，而 `duty_percent` 已叠加姿态修正。滑轨同时是输入（拖动写基础油门）和输出（显示发布值），于是构成正反馈环：

```text
拖到 30%      -> 基础油门 = 30%
                 姿态修正 -3%
发布 duty=27% -> 滑轨跳到 27%
再次触摸滑轨  -> LVGL 把旋钮跳到按下位置并发 VALUE_CHANGED，提交 27%
基础油门 = 27% -> 发布 24% -> 滑轨 24% -> ... 逐次棘轮到 0
```

每触摸一次，修正量就被当作新目标吃进基础油门一次。叠加偏航陀螺积分漂移（无磁力计约束，修正量随时间增大），即使不触摸滑轨也会缓慢下滑。这就是用户报告的"手动油门滑杆自己掉下来"。

参考工程 `C:\Users\admin\Desktop\项目\Formal_Framework` 的 `Display_LvglApplyValue()` 与本工程同源，存在同样的环。

修复：`Px4Lite_MotorOutputs_t` 增加 `base_percent[4]`（姿态修正前的基础油门），Control 在混控前锁存并单独发布；`Display_LoadMotorSnapshot()` 改为用 `base_percent` 驱动四个滑轨。

| 显示元素 | 数据源 | 含义 |
|---|---|---|
| 滑轨 | `base_percent[i]` | 用户/下行锁存的目标，拖到哪停在哪 |
| `PWM` 百分比 | `base_percent[i]` | 同滑轨，整数百分比 |
| `us` 脉宽 | `pulse_us[i]` | 姿态修正后的真实硬件输出 |

姿态修正照常生效，只是不再回推滑轨；修正量通过 `us` 观察（整数百分比会把 3% 以下的修正取整抹掉，脉宽不会）。远端模式 `base_percent` 退化为 `duty_percent`——远端遥测帧不携带基础油门，且 `Display_SetMotorThrottleCommand()` 在 REMOTE 模式直接返回、滑轨本就不可写，不存在成环风险。

`duty_percent` 保持为实际输出，MAVLink 遥测与 SD 日志口径不变。

曾一并加过每路"校正"列与电机页姿态行（`attitude_correction_x10[4]` / `attitude_assist_active` 字段 + 滑轨缩短 138→110 让位），**已按用户要求全部回退**，电机页布局恢复原状（滑轨 138、表头 234、数值 250）。`Px4Lite_ControlApplyAttitudeAssist()` 的返回值随之退回 `void`。横滚/俯仰/偏航仍在姿态页正常显示。

## 3. 字库

新增文案全部命中现有 `display_lvgl_font_zh_16` 子集，未新增字形，`glyphs=206` / `bitmap_bytes=26368` 不变。已逐字核对：`电机供电不足`、`油门`、`一键起飞失败`、`一键降落失败` 取自既有字符串；`校正`(U+6821/U+6B63)、`横滚`(U+6A2A/U+6EDA)、`俯仰`(U+4FEF/U+4EF0)、`偏航`(U+504F/U+822A) 均已在子集码点表中。

定点数格式化未使用 `%+.1f`：ARMCC 的浮点 printf 会显著增大镜像，`Display_LvglFormatSignedX10()` 按定点手工拆分符号与小数位。

## 4. 验证

### 4.1 单元测试

`Tests/Unit/test_control_motor_logic.c`：

- 新增 `TestAttitudeAssistKeepsBaseThrottleStable()`：在持续 10° 横滚偏差下跑 50 个控制周期，断言四路 `base_percent` 恒为 30% 不被修正污染，同时 `duty_percent` 确实带上 ∓3% 修正；并覆盖 ESC 预解锁期间 `base_percent` 保留已接受目标而 `pulse_us` 停在 1000us。这是滑轨反馈环的回归锁。
- 改写 `landing attitude not fresh` 用例：原断言 `PX4LITE_NOT_READY` 编码的是被修复掉的错误行为，改为断言无姿态 / IMU 离线 / IMU 失败三种情况下降落均返回 `PX4LITE_OK`，并跑完整条降落斜坡到 0%。

### 4.3 根因修正：电池档位不是滑块回落的原因

实机照片已推翻 1.1 / 1.2 的电池假设：电机一~四自检灯全绿、消息日志为"电机正常"，即 `s_motor_band` 高于 LOWPOWER，该门槛根本没触发。**滑块回落的实际原因是姿态零点偏差。**

实机 `俯仰 +27.0` / `横滚 +10.1`（板子平放时本应接近 0），说明 IMU 未做水平校准。姿态辅助按该假偏差持续"纠正"，各路修正量为：

| 电机 | 机位 | roll 混控 | pitch 混控 | 修正量 |
|---|---|---:|---:|---:|
| 一号 | 前左 | +1 | -1 | **+5.0%** |
| 二号 | 前右 | -1 | -1 | **+11.2%** |
| 三号 | 后左 | +1 | +1 | **-11.1%** |
| 四号 | 后右 | -1 | +1 | **-5.1%** |

（KP=30：roll 误差 -1010 → -3.03%；pitch 误差 -2700 → -8.1%）

三号负修正最大，滑到 11% 以下即被压到 0%；滑轨显示的正是修正后的值，因此表现为"自己掉下来"。**处置方式是把板子放平后在姿态页按"校准"**（`Display_LvglAttitudeCalEventCb` → `Px4Lite_RequestAttitudeLevelCalibration()` → `Px4Lite_EstimatorRun()` 把当前姿态记为零位），而非改代码。

### 4.4 仍未解释的现象

用户报告"滑动两条上去后，滑动第三条，**全部**掉下来"。上表只能解释三号/四号（负修正）下沉，无法解释一号/二号（正修正）同时归零：每路修正量与"有几路在跑"无关，`has_active_output` 只是总开关，不改变各路修正值。

能让四路同时归零的代码路径只有 `Px4Lite_ControlClearTargets()`，其调用点为任务饥饿 failsafe(>200ms)、KEY1 急停边沿、`Px4Lite_ControlEmergencyStop()`、`Px4Lite_ControlReset()`。已排除：

- 恢复模块：只在 OFFLINE/FAILED 触发，Control 发布的是 ONLINE/DEGRADED。
- 显示任务饿死 Control：`BUSINESS_PRIORITY_DISPLAY`(+1) 低于 `PX4LITE_PRIORITY_CONTROL`(+2)。
- 低压强制停机：参考工程有 `Display_ForceMotorsOff()`，本工程没有该路径。

待水平校准后复测，确认到底是四路全掉还是仅三号/四号下沉，再定位剩余路径。

## 5. 边界

本次不改变姿态算法、混控符号、PD 增益与限幅，不改变一键起飞的传感器准入，不引入高度闭环或落地判定。`ATTITUDE_MAX_CORRECTION_PERCENT = 20` 的单轴限幅与三轴叠加最大 ±60% 的既有边界保持不变。

普通单向 ESC 的 1000~2000us 只表示油门，软件不能改变电机转向；M1/M4 顺时针、M2/M3 逆时针仍须由电调配置或交换三相线实现，并在拆除桨叶后验证。姿态辅助油门混控不等同于完整飞控闭环。
