# 2026-06-17 27 RTC 时间持久化与 GNSS 自动校时

## 背景与原因

此前显示页的日期时间直接来自 GNSS 主题，并在 Display 层做 UTC+8 转换。
这种方式在 GNSS 尚未定位、室内无星或短时丢星时无法持续显示有效日期时间，
也把时间转换逻辑放在了界面层。

本轮增加 RTC 持久化时间链路：系统启动后优先读取 RTC，GNSS 获得有效定位后
校准 RTC，之后按固定周期再次校准。即使后续 GNSS 没有定位，显示页仍可从 RTC
得到一个持续递增的大致日期时间。

## 设计要点

- **BSP 管 RTC 硬件**：新增 `bsp_rtc`，负责 RTC 外设初始化、LSE/LSI 时钟源选择、
  备份寄存器有效标记、UTC 日期时间读写和基础合法性检查。
- **Framework 管时间策略**：新增 `px4lite_time`，读取 RTC 和 GNSS 主题，判断是否需要
  校时，并发布统一的本地显示时间快照。
- **GNSS 只做校准源**：校时要求 GNSS 主题新鲜、已有定位、UTC 日期时间字段合法；
  默认每 10 分钟检查一次，RTC 与 GNSS 差值超过 1 秒才写入 RTC。
- **Display 不再做时区转换**：UTC+8 转换移动到 Framework 时间服务，
  Display 只通过 `App_CopyDateTime()` 读取本地日期时间快照。
- **层边界保持不变**：Business/Display 不直接访问 Framework 主题或 BSP；
  Framework 内只有 `px4lite_platform_f407.c` 通过平台适配层调用 BSP RTC。

## 行为变化

- 上电后如果 RTC 备份域存在有效标记，系统可在 GNSS 未定位前显示 RTC 日期时间。
- GNSS 首次有效定位后会校准 RTC；后续按 `PX4LITE_TIME_GNSS_SYNC_INTERVAL_MS`
  周期重新比较并校准。
- RTC 保存的是 UTC 日期时间，显示层读取的是已按
  `PX4LITE_TIME_LOCAL_OFFSET_S = 28800` 转换后的本地日期时间。
- Display 页面不再依赖 GNSS 快照中的时间字段，导航数据和日期时间快照分开读取。
- RTC 时钟源优先使用 LSE；若 LSE 无法就绪，则降级使用 LSI，保证功能可用。

## 风险与边界

- F407 RTC 本身可以保存日期和时间，但断电保持依赖 VBAT/备份域供电。
  若无 VBAT 或备份域被复位，RTC 会丢失，需要等待 GNSS 重新校时。
- LSI 精度低于 LSE；若板级没有可用 LSE，长时间无 GNSS 时日期时间会逐步漂移。
- 当前只使用 GNSS 作为权威校时源，未接入手动设置、网络时间或 SD 记录中的时间恢复。
