# I2C 阻塞导致显示卡死的修复

## 现象

接入 I2C 传感器后，屏幕刷新卡住（不接传感器时正常）。

## 根因

1. `sensor` 任务优先级最高（`PX4LITE_PRIORITY_SENSOR = idle+4`，
   见 `Framework/Inc/px4lite_config.h`），`biz_display` 最低
   （`BUSINESS_PRIORITY_DISPLAY = idle+1`）。
2. 传感器读取走 `HAL_I2C_*` 轮询接口（`Bsp/Src/bsp_i2c.c`），HAL 轮询版
   I2C 是忙等，不让出 CPU。
3. 传感器驱动在未初始化成功时，每个 10ms 服务周期都重新探测 + 阻塞 I2C
   （`Sensor_MPU6050_Service` / `Sensor_BME280_Service`）。
4. `bsp_i2c.c` 没有任何总线恢复逻辑。器件接入后一旦总线被钳死或时钟拉伸
   （`NoStretchMode = I2C_NOSTRETCH_DISABLE`），最高优先级的 `sensor`
   任务长时间忙等在 I2C 上，把最低优先级的显示任务饿死，表现为屏幕卡死。

不接传感器时 I2C 线空闲，探测快速 NACK 返回，`sensor` 任务很快让出
CPU，所以显示正常——这解释了“插上才卡”。

> 注：本问题与任务栈溢出无关，栈溢出检测开关
> （`configCHECK_FOR_STACK_OVERFLOW=2`）未被触发。

## 修改

### 1. `Bsp/Src/bsp_i2c.c` —— I2C 卡死检测与总线恢复

- 新增 `BSP_I2C_BusRecover()`：将 SCL/SDA（PB6/PB7）切为开漏 GPIO，输出
  9 个时钟脉冲冲掉从机残留位，补一个 STOP，再 `BSP_I2C_Init()` 重初始化
  （MspInit 会把引脚切回 AF）。
- 新增 `BSP_I2C_Finish()`：仅在 HAL 返回 `HAL_TIMEOUT/HAL_BUSY`（真正的
  总线卡死）时调用 `BSP_I2C_BusRecover()`，避免一次卡死变永久卡死。
  **不对 `HAL_ERROR`（NACK / 应答失败）触发恢复**——NACK 是共享总线上的
  正常瞬态，整条总线 DeInit/Init 反而会打断另一个传感器、造成不稳定。
- `BSP_I2C_IsDeviceReady/MemRead/MemWrite` 三个传输函数的返回改为走
  `BSP_I2C_Finish()`。

### 2. 缩短传感器 I2C 超时

- `Sensor/Src/sensor_mpu6050.c`：`MPU6050_I2C_TIMEOUT_MS` 20 → 4。
- `Sensor/Src/sensor_bme280.c`：`BME280_I2C_TIMEOUT_MS` 20 → 4。

I2C 速率为 400kHz（`BSP_I2C_SPEED`），最长一次多字节读（26B 标定）约
0.6ms，4ms 超时足够，同时把单次最坏忙等时间限定住。

### 3. 失败退避（关键）

- `sensor_mpu6050.c` / `sensor_bme280.c` 各新增 `s_next_init_ms`，并在
  `*_Service()` 的初始化分支加入退避：初始化失败后 `*_INIT_RETRY_MS`
  （1000ms）内不再触碰 I2C，直接返回 `NO_DATA`。

效果：器件缺失或异常时，最高优先级任务每秒最多碰一次 I2C，其余周期立刻
让出 CPU，显示任务不再被饿死。

### 4. 初始化成功后掉线的自愈

原实现一旦 `s_initialized=1`，之后读失败只累加 `error_count`，永远不再
重新初始化。若器件因供电抖动复位（MPU6050 复位后回到 sleep、BME280 丢失
forced 配置），就会一直读一个不再采样的芯片，表现为“连接不稳定”。

- `sensor_mpu6050.c` / `sensor_bme280.c` 各新增 `s_read_fail_count` 与
  `*_REINIT_FAIL_LIMIT`（连续 5 次）。初始化后连续读失败达到阈值即把
  `s_initialized` 清 0，触发（带退避的）重新初始化；任一次成功读即清零
  计数。BME280 的三个读失败出口统一走 `Bme280_NoteReadFailure()`。

## 修订记录

- 本文档 §1 的恢复触发条件由 `TIMEOUT/ERROR/BUSY` 收窄为 `TIMEOUT/BUSY`，
  原因见 §1 说明（NACK 不应触发整条总线恢复）。
- 新增 §4 掉线自愈，解决“接入后连接不稳定”。

## 对照规范

- 满足 §6「I2C 卡死必须有明确恢复策略」。
- 缓解 §4「`Service()` 不得永久阻塞」与 §3.1「禁止周期任务无界阻塞轮询」。
- 未盲目扩栈、未改任务优先级（符合 §2.1）。

## 验证清单（烧录后）

- [ ] 不接传感器：屏幕正常刷新、触摸正常。
- [ ] 接入 MPU6050 / BME280：屏幕不再卡死，数据正常更新。
- [ ] 运行中热插拔传感器、短时间拉低 SDA：总线能自动恢复，显示不卡死。
- [ ] USART1 周期 `STACK:` 报告持续输出，无 WARN 上升趋势。
- [ ] ARMCC 5.06 编译 0 Error / 0 Warning。
