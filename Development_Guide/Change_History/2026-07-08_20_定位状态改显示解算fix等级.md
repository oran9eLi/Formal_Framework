# 2026-07-08_20_定位状态改显示解算fix等级

## 背景与问题

定位页"定位状态"字段原来取的是 **GNSS 模块健康态**(ONLINE/DEGRADED/…)经 `Display_GnssSignalValue` 映射:ONLINE→1、其余→0;再经通用状态文字 `Display_LvglStatusText` 渲染(2 正常/1 警告/0 未就绪/其它 故障)。

结果**映射错位**:GPS 已锁星(模块 ONLINE)→ 值 1 →显示 **"警告"**;未锁星→值 0 →"未就绪"。**永远不会显示"正常"**。同页"自检-定位模块"用的却是 `Display_MapStateValue`(ONLINE→2 正常),两处对 ONLINE 的取值不一致——是个显示 bug。

而更细的**解算 fix 等级**(`Px4Lite_GnssDisplayFixState`,值 0 无/2 2D/3 3D/4 差分)其实早已算好并放进导航快照 `gnss_fix_type`,却没被"定位状态"使用。

## 修改:定位状态改显示解算 fix 等级

**数据来源**(`Display/Src/display.c`):
- `Display_LoadNavigationSnapshot` 新增 `GNSS_FIX = navigation->gnss_fix_type`(解算 fix 等级)。本地来自 `Px4Lite_GnssDisplayFixState`(0/2/3/4);远端来自 GPS_RAW 的 MAVLink `fix_type`(0..6)。
- 删去 `Display_LoadSystemSnapshot` 与 `Display_LoadModuleStatusFallback` 里用模块态写 `GNSS_FIX` 的两处(改由导航快照单一驱动)。
- 删除不再使用的 `Display_GnssSignalValue`。
- 导航不可用时 `Display_ClearNavigationSnapshot` 已把 `GNSS_FIX` 清 0(无定位)。
- 预览示例数据默认值 2→3(3D定位)。

**文字渲染**(`Display/Src/display_lvgl.c`):
- `DISPLAY_HMI_VAR_GNSS_FIX` 从通用状态文字组拆出,单列一个 case,用新 `Display_LvglGnssFixText`。
- 映射:0/1→无定位、2→2D定位、3→3D定位、4→DGPS、5→RTK-F、6→RTK-X、其余→3D定位。

## 字库限制(重要)

字库 `display_lvgl_font_zh.c` 现有 **无/定/位/分/动**,但**缺 差/浮/固**三字(已核实 glyph 表)。因此:
- "无定位/2D定位/3D定位" 可正常显示中文(2D/3D 走 montserrat 回退)。
- **差分/RTK 暂用 ASCII 词 `DGPS`/`RTK-F`/`RTK-X`**,避免缺字显示为空框。
- 若要中文"差分/RTK浮动/RTK固定",需按 `lvgl-font-add-glyph`(GDI/msyh 16px 4bpp)给字库补 差/浮/固 再改 `Display_LvglGnssFixText`。
- 实际上 ATGM336H 常见只有 0/2/3(无/2D/3D),DGPS 偶发(SBAS),RTK 基本不出现,故 ASCII 兜底影响很小。

## 效果

定位状态现按真实解算等级显示:**无定位 / 2D定位 / 3D定位 / DGPS**(而非之前只会出现的"警告/未就绪")。远端模式同样按对端 GPS_RAW fix_type 显示。

## 改动文件

- `Display/Src/display.c`:GNSS_FIX 改由导航快照 gnss_fix_type 驱动;删模块态两处写入与 Display_GnssSignalValue;示例默认值改 3。
- `Display/Src/display_lvgl.c`:新增 Display_LvglGnssFixText;GNSS_FIX 单列渲染。

## 构建与验证

- 需重新编译。
- 验证:① 未锁星→"无定位";锁到 2D→"2D定位";3D→"3D定位";SBAS 差分→"DGPS"。② 自检-定位模块指示(SELF_CHECK_GNSS)不受影响,仍反映模块在线态。③ 远端模式下按对端 fix_type 显示。
