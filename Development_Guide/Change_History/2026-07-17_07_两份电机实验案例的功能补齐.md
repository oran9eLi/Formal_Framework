# 补齐《动力系统安全控制》与《姿态数据反馈的电机输出辅助校准》两份实验案例的功能

## 1. 背景

对照两份实验案例逐条核对现有实现。绝大部分能力和参数已经存在且与文档一致，无需改动：

| 文档要求 | 现状 |
|---|---|
| 0%-100% ↔ 1000-2000us，5%≈1050us，60%≈1600us | `Px4Lite_ControlThrottleToPulseUs()` / `AppDisplay_MotorPulseUs()` 一致 |
| 自动起飞约 6 秒爬升至约 60% | `AUTO_TAKEOFF_RAMP_MS=6000`、`AUTO_TAKEOFF_TARGET_PERCENT=60` |
| 自动降落约 8 秒回 0% | `AUTO_LANDING_RAMP_MS=8000` |
| 电池五档 5.0 / 9.0 / 9.9 / 10.5 / 13.5V | `DISPLAY_MOTOR_BAT_*_MV` 完全一致（带 200mV 滞回） |
| 姿态辅助不让 0% 通道意外启动 | `ATTITUDE_MIN_BASE_PERCENT=1` 的逐路门控 |
| 急停四路立即清零 | `Px4Lite_ControlEmergencyStop()` |
| 失效保护超时回最小脉宽 | `FAILSAFE_TIMEOUT_MS=200` |
| 远端查看时本地滑条无效 | `Display_SetMotorThrottleCommand()` 在 REMOTE 直接返回 |
| 姿态零位校准按钮 | `Display_LvglAttitudeCalEventCb()` |

真正缺的是三条，本次补齐。

## 2. 修复

### 2.1 低压强制清零（实验一 4.3 表 / 步骤 9）

文档要求断开、没电、供电不足三档"四路油门清零"。原实现只有 `Display_MotorPowerAllowsOutput()` 在输入口拒绝**新的**非零命令——这挡不住"电机已经转起来之后电压才跌破门限"：Control 锁存的旧目标不会自己消失，滑条停在原处，PWM 继续输出。

新增动力电池闭锁，与急停分开：

- `Px4Lite_ControlSetPowerInhibit(uint8_t)` / `Px4Lite_ControlIsPowerInhibited()`，经 `App_SetMotorPowerInhibit()` / `App_IsMotorPowerInhibited()` 暴露给 Display。
- 置位沿清零四路目标并撤销自动油门；置位期间 `Px4Lite_ControlRun()` 恒按 0 输出，拒绝一切非零油门/脉宽命令与一键起飞；**一键降落不受限制**（撤收永远允许）。
- 解除时不自动恢复任何油门，必须用户重新拖滑条——避免电压在门限附近跳动时电机自己转起来。
- `Display_ApplyMotorPowerInhibit()` 每个显示周期按 `s_motor_band` **无条件**下发（Control 侧只在 0→1 沿动作，重复下发幂等）。不按边沿下发是有意的：若 Control 被重新初始化丢掉闭锁，边沿式下发会因为"以为已经发过了"而永不补发。同理 `Px4Lite_ControlReset()` 故意不复位该标志——闭锁是外部供电事实，不是 Control 的内部状态。
- 只在本机模式维护：远端查看时 `s_motor_band` 反映的是远端机电池，不能用来闭锁本机电机。

拒绝判断放在解除急停和撤销自动油门**之前**：否则一条被拒的滑条命令会顺带把急停解锁、把降落斜坡撤掉。该口径由单元测试锁住。

### 2.2 一键降落进行中拒绝非零手动油门（实验一 4.4.2 / 步骤 7）

原实现中 `Px4Lite_ControlSetMotorThrottlePercent()` 无条件调用 `Px4Lite_ControlClearAutoThrottle()`，手动输入会直接**取消**降落并生效，与文档"降落过程中不应接受新的非零手动油门"相反。

改为：一键降落进行中，非零手动油门/脉宽返回 `PX4LITE_NOT_READY` 且不打断斜坡；0 与降落终点一致，接受但同样不打断。

**只对用户按下的一键降落生效**，新增 `s_auto_landing_user` 区分。姿态丢失触发的强制降落（`Px4Lite_ControlForceAutoLanding()`）不设限制：那是内部保护，锁住手动接管会让 IMU 掉线时操作员失去出口。该口径原本就由 `TestAutoTakeoffDropsToLandingOnAttitudeLoss()` 锁住（"manual override during forced landing"），不能为了满足文档而破坏它——文档步骤 7 描述的是按降落按钮后的行为，两者不矛盾。一键起飞同样不设限制，手动接管随时可以打断上升。

### 2.3 滑轨改回跟随姿态修正后的输出（实验二 步骤 5 / 6）

实验二要求倾斜时"四路电机显示出现小幅差异"、回平后"差异减小或恢复一致"，并在记录表里逐路填写。因此 `Display_LoadMotorSnapshot()` 改回用 `duty_percent`（含姿态修正）驱动四条滑轨与 PWM 百分比，`base_percent` 保留为遥测里"用户锁存目标"的真值。

`2026-07-17_05` 曾因棘轮效应把滑轨改成跟随 `base_percent`。棘轮的真实成因不是"显示了修正值"，而是 `2026-07-17_04` 引入的松手重发：滑轨同时是输入和输出，松手时无条件重发 `lv_slider_get_value()`，于是把**显示值**当成了新目标。

本次改为触摸锁存，从根上断开回灌，而不是靠隐藏修正量：

- `LV_EVENT_VALUE_CHANGED` 只在 LVGL 因手指移动旋钮时才发出。仅此时记录 `s_motor_touch_value[]` 并置 `s_motor_touch_valid[]`。
- 松手（`RELEASED`/`PRESS_LOST`）重发的是 `s_motor_touch_value[]`，不是滑轨当前值——保留了电阻触摸快速松手漏掉最后一次 `VALUE_CHANGED` 的补偿。
- 手指按下但没移动旋钮的点按不产生 `touch_valid`，因此**什么都不提交**，显示值不会变成新目标。

于是"滑轨显示修正后的值"与"永不回灌"同时成立。`Display_LoadMotorSnapshot()` 的 `duty_percent` 口径与 `Display_LvglMotorSliderEventCb()` 的触摸锁存成对存在，两处注释互相指向，改一处必须同时改另一处。

`Px4Lite_ControlApplyAttitudeAssist()` 不修正基础油门为 0 的通道这一既有门控保持不变，因此实验一步骤 5"其他三路保持 0%"仍然成立。

### 2.4 新增两条日志

append-only ID，四处镜像（`px4lite_log_message_ids.h` → `App_LogMessageId_t` → `Display_LogMsg_t` → LVGL 文案表）已同步：

| ID | 文案 | 触发点 |

| 36 | 电机供电不足 自动停机 | `Display_ApplyMotorPowerInhibit()` 闭锁生效沿（只推生效沿，解除沿不推，否则用户会误以为油门被自动恢复） |
| 37 | 降落中 油门失败 | 一键降落进行中非零手动油门被 Control 拒绝 |

## 5. 验证

### 5.1 单元测试

`Tests/Unit/test_control_motor_logic.c` 新增两个用例：

- `TestPowerInhibitClearsAndRefusesThrottle()`：闭锁沿必须清零已锁存的 30% 目标（这是"只在输入口拒绝"挡不住的那条路径）、四路 duty/base 归零、脉宽回 1000us；闭锁期间拒绝油门/脉宽/一键起飞、接受 0、允许一键降落；被拒的油门不得顺带解锁急停；解除后不自动恢复、需重新下发才生效。
- `TestLandingRefusesNonZeroManualThrottle()`：一键降落中非零油门与非零脉宽均被拒且斜坡不断，0 被接受且斜坡不断，斜坡跑完落到 0 并自行结束；一键起飞与强制降落两条路径相反，手动接管仍可打断。

`ResetHarness()` 增加 `Px4Lite_ControlSetPowerInhibit(0U)`：闭锁被 `Px4Lite_ControlReset()` 故意跳过，必须由测试夹具显式复位，否则用例之间互相污染。

`TestAttitudeAssistKeepsBaseThrottleStable()` 的断言不变（base/duty 分离仍是遥测口径），只更新了注释——棘轮防护已移到 Display 层的触摸锁存，不再由该字段承担。

### 5.2 未完成的验证

**本机没有安装任何 C 编译器（已逐一确认 gcc / clang / cl / tcc / Keil / LLVM 均不存在），本次改动未经过任何编译或测试执行，全部为源码级人工审查。** 合入前必须执行：

1. `MDK-ARM/formal_framework.uvprojx` Target 1 Rebuild All，确认 `0 Error(s), 0 Warning(s)`。
2. 执行 `Tests/Unit/test_control_motor_logic.c`，确认含两个新用例在内全部通过。
3. 实机按实验一步骤 9 复测低压闭锁：在 5% 油门下把电机电池降到 9.9V 以下，确认四路滑条自动回 0、脉宽回 1000us、日志出现"电机供电不足 自动停机"，且此时拖滑条被拒并出现"电机供电不足 油门失败"。
4. 实机按实验一步骤 7 复测降落拒绝：降落斜坡中拖滑条，确认滑条弹回且日志出现"降落中 油门失败"，斜坡不被打断、8 秒内回 0。
5. 实机按实验二步骤 5/6 复测：四路 5% 基础油门下倾斜，确认四条滑条出现小幅差异、回平后收敛。
6. 实机确认点按滑条旋钮但不移动时，基础油门不发生任何变化（棘轮回归锁）。

## 6. 边界与已知影响

**姿态辅助默认开启（`ATTITUDE_ASSIST_DEFAULT=1`），滑轨现在跟随修正后的输出，因此姿态零位未校准时滑轨会自己动。** 这是实验二步骤 5 要观察的现象，但对实验一步骤 5 有直接影响：若姿态零点存在明显偏差（如 `2026-07-17_05` 第 4.3 节实测的俯仰 +27°），单路 5% 的基础油门会被修正吃掉，滑条掉回 0、脉宽停在 1000us，读不到文档预期的 1050us。

**因此实验一步骤 5 之前必须先按实验二步骤 3 完成水平姿态校准。** 这是两份实验案例的隐含依赖，建议在实验一步骤 1 的安全确认里补一句。本次不改姿态算法、混控符号、PD 增益与限幅，也不改姿态辅助的默认开关。

本次不改变电池档位门限与滞回、不改变一键起飞的传感器准入、不改变告警与自检灯口径、不改变 MAVLink 与 SD 日志的 `duty_percent` 语义。
