# 2026-06-29 51 LoRa收发队列与超时收口

## 背景

对比 `LLLLLL/Formal_Framework` 中的 LoRa 收发实现后，当前工程继续保持一主多从、Command 控制、远端节点表和 App API 显示边界，不整包迁入旧工程的 RemoteTelemetry/RemoteTunnel 模块。

## 已完成

1. `Driver/Comm/Src/lora_e22.c` 的 RX 缓存由单帧覆盖改为静态 8 帧 FIFO 队列，一个 comm 周期内解析出多帧时按顺序供 Framework 消费。
2. RX 队列满时丢弃最旧帧并累加 `rx_drop_count`，避免旧积压挡住最新状态。
3. `Lora_E22_Service()` 单次 RX 处理预算保持 128 byte，不扩大 comm 任务栈。
4. `Bsp/Inc/bsp_config.h` 新增 `BSP_LORA_AIR_BPS`，BSP 暴露 `BSP_LoRa_GetUartBaud()` 和 `BSP_LoRa_GetAirBps()`。
5. LoRa TX AUX 等待、UART DMA 和空中完成超时改为按 UART/空中速率计算，不再依赖固定魔数。
6. `Development_Guide/02_架构边界与数据流.md` 和 `03_模块接入手册.md` 已同步 LoRa RX 队列和速率配置规则。

## 栈和内存

本次没有扩大 `PX4LITE_STACK_COMM`。新增 RX 队列为文件级静态缓冲，消耗 BSS，不占用任务栈。Keil Rebuild All 后 `ZI-data=120596`。

## 后续要求

后续 5G、RemoteID 或其它通信模块接入时，接收侧大 payload、分段重组和批量状态都必须使用静态有界队列、固定块池或 summary 接口，并保留 service 预算上限；不得通过扩大任务栈掩盖协议缓存设计问题。
