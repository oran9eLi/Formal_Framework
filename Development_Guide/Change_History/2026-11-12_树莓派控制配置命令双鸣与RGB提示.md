# 树莓派控制、配置请求双鸣与RGB提示

日期：2026-11-12。执行台账R79 / V1-E75，新增V1-RPI-T01，状态：待验证（软件验证通过，实板待验）。

## 修改原因与范围

用户要求树莓派下发指令时蜂鸣器两声、RGB闪烁，并进一步明确“只对控制和配置命令提示”。基于真实UART6 MAVLink接收、Command地址门禁、波特率配置状态机与sensor现有声光owner实现；不新增任务，不改串口协议或业务执行结果。

## 实际行为

| 收到的报文 | 提示条件 |
|---|---|
| COMMAND_LONG | 仅RPi物理链路，沿用本机或广播的system/component门禁；通过地址门禁即提示，执行DENIED/UNSUPPORTED也提示收到 |
| TUNNEL 0x8003 type3配置 | 来源ID非零，本机system/component193，version1、声明14字节、实际12～14字节且省略尾字节均为零，nonce非零，目标57600；完整校验后提示 |
| 配置重复、配置事务忙或H1占用发送口 | 结构有效仍提示；原有仲裁保留，不提前切速率/不覆盖待发槽 |
| 心跳、RPICELL网络状态、普通遥测、COMMAND_ACK、H1回显、错误目标、CRC错误或不完整数据 | 静默；不把普通非心跳报文当控制命令 |
| LoRa收到同类请求 | 静默，此功能只针对树莓派UART6 |

提示为2400Hz蜂鸣器与白灯(48,48,48)同步双闪：100ms响/白、100ms停/黑、100ms响/白、100ms停/黑；结束恢复此时的环境渐变相位。sensor每10ms推进，每轮最多一相位，迟到会延长槽时而不会跳过第二声，实物时长仍须测量。启动旋律优先，期间收到请求排队；待播上限8项（不含正在播放1项），溢出只丢提示并累计dropped，指令处理保持原路径。提示表示收包，不表示命令执行成功，执行结果仍由原ACK给出。

Comm只在短临界区登记计数，sensor通过Platform驱动现有蜂鸣器/RGB。无动态分配、无阻塞等待、无ISR声光操作。蜂鸣器和RGB故障隔离，沿用RGB退避并为提示蜂鸣器提供2s重试；故障时可能缺声/缺光，不补播过期灯色。状态快照增加received/started/finished/dropped/pending/active/错误事实，不新增MAVLink消息，finished不等于实物验收通过。
