# 开发日志索引与归档规则

开发日志统一放在本目录 `Development_Guide/Change_History/`。这里记录实际实现、排查、回滚与验证事实；有日志不等于已经通过实板验收。任务状态以[执行台账](../../Release/V1.0_执行台账.md)为唯一维护入口。

每次修改均须同步记录，包括源码、配置、测试、界面、协议、文档与规则。记录至少包含日期、原因、涉及文件、实际改动、验证证据、未完成项和下一步；失败、回滚及未执行检查也如实说明。固件修改记录Keil实际结果，纯文档修改说明不运行构建的原因。

## 归档规则

文件通常命名为 `YYYY-MM-DD_主题.md`；同日需要区分多项时可加入序号。每份记录至少包含修改原因、涉及文件、行为变化、验证方法与实际结果，以及尚未解决项。

历史日志描述当时版本。后续变更通过新记录和台账关联，不将旧记录中的当时行为误当成当前配置；软件测试和Keil通过不能替代实板结果。当前有效架构规则应同步到上一级开发规范，不能只存在历史记录中。
