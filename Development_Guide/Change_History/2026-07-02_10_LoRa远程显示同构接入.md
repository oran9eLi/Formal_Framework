# 2026-07-02_10_LoRa远程显示同构接入

## 背景与原因

从 `oran9eLi/Formal_Framework` 的 **lvgl** 分支移植整套"远程显示同构"能力:让远端(对端设备)的
**消息日志**与**完整告警表**也能通过 LoRa MAVLink TUNNEL 同步到本机,并在远端模式下与本机显示同构。

移植前本分支(`feat/nw4.1-voltage-attitude`)只同步遥测(电压/电流/姿态/GNSS 等),远端模式下:
消息日志被清空、告警表只显示最高项摘要。本分支与 lvgl 共同祖先 `50a763f`,lvgl 在远程显示方向
领先约 29 个提交;本分支这 9 个提交未动过 LoRa 框架文件,故 `mavlink_tx/rx`、`remote_telemetry`
可整取 lvgl 版,其余外科式合并。

## 一、协议层(P1)

- 整取 lvgl 版:`Framework/Src/px4lite_mavlink_tx.c`、`px4lite_mavlink_rx.c`、
  `px4lite_remote_telemetry.c`、`Framework/Inc/px4lite_remote_telemetry.h`、`px4lite_mavlink_tx.h`、
  `px4lite_mavlink_rx.h`(本分支未改过,安全)。`remote_telemetry` 结构为超集,不丢本机读用点。
- 新增:`Framework/Inc+Src/px4lite_local_msglog.{h,c}`(本机日志池,单一真值源)、
  `px4lite_remote_tunnel.{h,c}`(告警表/消息日志 TUNNEL 打包解包;`Px4Lite_Pack/UnpackAlarmTable`、
  `Px4Lite_Pack/UnpackMessageLog`、`Px4Lite_AlarmTableSignature`)。
- `Framework/Inc/px4lite_config.h`:**新增** `PX4LITE_MAVLINK_ENABLE_REMOTE_ALARM/LOG` 与
  `REMOTE_ALARM/LOG/LOG_FULL_PERIOD_MS`;**保留**本分支的 `LORA_OFFLINE_MS=800`、`MAVLINK_SYSTEM_ID=1`
  (lvgl 为 3000/2,是不同选择,不覆盖)。

## 二、业务生产者(P2)

- 新增 `Business/Inc+Src/app_message_log.{h,c}`(含 `App_LogMessageId_t`/`APP_LOGMSG_*` 枚举):
  从本机 `App_*` 接口按去抖生成结构化日志,推入 Framework `local_msglog`;`mavlink_tx` 据此发送。
- `Display/Src/display.c`:`Display_Init` 一次性 `App_MessageLogInit`,`Display_PrepareSnapshot`
  每周期 `App_MessageLogUpdate(now_ms)` 驱动生产。
- `app_data_api.*` 未改(本分支已是超集,含 current_ma)。

## 三、显示同构(P3)

- `Business/Src/app_display_model.c`:
  - `App_GetDisplayMessageLog` 桩函数填实:LOCAL 返回本机业务日志(`App_MessageLogCopy`),
    REMOTE 返回远端同步日志(`remote_telemetry.log_entries`,新鲜度判定)。
  - `App_GetDisplayAlarm` 远端分支升级:从"仅最高项摘要"改为**逐行填满完整告警表**
    (`remote.alarm_records[]`),整表未到时退回摘要单行。
- `Display/Src/display.c`:消息日志渲染改为**统一桥接** —— 从 `App_GetDisplayMessageLog`
  按 `sequence` 增量推进既有渲染环(`Display_PagesPushLogMessage`),切换本地/远端时清环重建。
  枚举 `Display_LogMsg_t` 与 `APP_LOGMSG_*` 数值一致(均 `SYSTEM_START=0`),直接转换无需映射。
  告警表沿用既有 `App_GetDisplayAlarm`→`Display_LoadAlarmSnapshot` 渲染,无需改动。
- **删除**已被业务层取代的旧显示内部日志生成器:`Display_UpdateMessageLog` 及其
  `Display_*Log*` 辅助函数、`DISPLAY_MSGLOG_DEBOUNCE_MS`、`Display_LogDebounce_t`。

## 构建

新增 3 个 `.c` 需入工程(Keil GUI 加,uVision 会覆盖外部对 `.uvprojx` 的改动):
`px4lite_local_msglog.c`、`px4lite_remote_tunnel.c`(Framework 组)、`app_message_log.c`(Business 组);
`.eide/eide.yml` 已同步。`mavlink_tx/rx`、`remote_telemetry`、`app_display_model`、`display` 为同名
已在工程文件,内容更新自动重编。

## 行为变化

- 远端模式下**消息日志**与**完整告警表**随对端同步显示,与本机同构。
- 本机日志改由业务层 `app_message_log` 统一生产(与旧显示内部日志同源同算),顺带修复远端切换后
  本地日志显示路径。
- 新增 `local_msglog`(9 条)、`remote_telemetry` 的 `log_entries[9]`/`alarm_records[]` 静态占用,
  RAM 略增。

## 验证

- **构建**:Keil ARMCC5(V5.06 u7)Rebuild 通过,0 error;清理死代码后 0 warning。
  (过程中经历过 3 个新 `.c` 未入工程的 undefined、以及旧 unity-include 与工程双编译的 multiply-defined,均已解决。)
- **待上板**:远端模式消息日志/告警表同步显示;本地模式日志正常;本地/远端切换无残留。

## 边界与后续

- `SYSTEM_ID` 保留本分支的 1;若遥控端按 sysid=2 过滤需另配。
- 远端日志/告警表断链时由新鲜度判 STALE 保留旧值。
- LoRa 在位判定保留本分支较新的"物理在位检测"(未采用 lvgl 的 AUX-ready+超时,见 lora 分支比对)。
