# 屏幕模块技术文档

描述 Display 模块的硬件接口、驱动分层、数据结构、刷新机制和调度模型。
面向需要理解内部实现或排查显示问题的成员。二次开发操作步骤见
`18_屏幕模块开发文档.md`。

## 1. 硬件

```text
MCU:        STM32F407ZGT6
Display:    正点原子 ATK-MD0700  7 寸 TFTLCD
Resolution: 800 x 480
Controller: SSD1963 类控制器，期望 PID = 0x61
LCD bus:    FSMC 8080 并口，16-bit 数据宽度
Pixel:      RGB565
Touch:      GT911 电容触摸，软件 I2C
```

全屏 RGB565 数据量 `800 x 480 x 2 = 768000 字节`，超出 F407 内部 SRAM，
因此**不使用全屏帧缓冲，也不使用 DMA2D**，统一采用 LCD 内部 GRAM + 局部刷新 +
脏矩形 + 小型固定行缓冲。

### 1.1 FSMC 地址映射（bsp_config.h）

```text
Bank:        FSMC Bank1 NOR/SRAM4，基址 0x6C000000
命令/数据选择: NE4 + 地址线 A6 (REG_SEL = 6)
  CMD 地址:  0x6C000000 | (((1<<6)-1)<<1)
  DATA 地址: 0x6C000000 | ((1<<6)<<1)
时序:        AddressSetup / DataSetup(读/写) 分开配置
控制线:      CS=PG12, RS(A6)=PF12, RD=PD4, WR=PD5  (AF12_FSMC)
数据线:      D0..D15 分布于 GPIOD/E (AF12_FSMC)
```

读写时序参数（`ADDRESS_SETUP`、`DATA_SETUP_READ/WRITE` 等）全部集中在
`bsp_config.h`，BSP Init 时填入 HAL FSMC 结构，驱动层不重复设置。

## 2. 驱动分层

```text
bsp_config.h            是否启用、控制器型号、引脚、FSMC Bank/时序、地址映射
  -> HAL MSP            开 FSMC/GPIO 时钟、配置 AF 复用、触摸/背光 GPIO
  -> BSP Init           填 FSMC 16-bit 数据宽度与读写时序、软 I2C 延时
  -> display_ssd1963.c  读校验 PID、PLL/时序/像素接口、写窗口、像素/矩形/清屏
  -> display_gt911.c    复位与地址选择、读 ID/分辨率/触摸点、坐标转换
  -> display_gfx.c      像素图元：点、线、矩形、填充、状态点
  -> display_text.c     字体、字符串、标签、单位渲染
  -> display_logo.c     位图资源
  -> display_pages.c    页面骨架与字段绘制（页面级渲染）
  -> display.c          配置表、变量缓存、快照装配、刷新调度、触摸导航
  -> DisplayTask        Business 层周期任务，唯一 FSMC 写入者
```

`display_ssd1963.h` 对外只暴露 `Init / ReadId / DrawPixel / FillRect / Clear /
IsReady`；`display_gt911.h` 暴露 `Init / Scan / GetDebug`。上层只依赖这些接口，
不触碰 FSMC 寄存器。

## 3. 显示对象模型（display.c）

### 3.1 页面表

```c
static const Display_HmiPageConfig_t s_hmi_pages[] = {
  {DISPLAY_HMI_PAGE_SELF_CHECK, 0x0000, "self_check", 200},
  {DISPLAY_HMI_PAGE_FLIGHT,     0x0004, "flight",     500},
  {DISPLAY_HMI_PAGE_AIRCRAFT,   0x0005, "aircraft",   500},
  {DISPLAY_HMI_PAGE_DATA,       0x0001, "data",       500},
  {DISPLAY_HMI_PAGE_MOTOR,      0x0006, "motor",      500},
  {DISPLAY_HMI_PAGE_ALARM,      0x0002, "alarm",      200},
};
```

`DISPLAY_HMI_PAGE_LOGO` 已废弃，仅保留枚举值以维持路由 ID 稳定。翻页由
`Display_PagesGetPrev/NextPage()` 按枚举顺序在 SELF_CHECK..ALARM 之间循环。

### 3.2 变量表

每个显示量是一条 `Display_HmiVariableConfig_t`：

```text
id          内部变量 ID
page        所属页面
var_addr    固件内部虚拟变量地址 (非 LCD 寄存器地址)，用于 App/Display/调试路由
data_type   U16 / I16 / U32 / I32
access      RO(主控刷新) / RW(参数或命令入口)
refresh_ms  0=事件触发，非0=最快重绘周期
x,y,w,h     横屏显示区域 (0 表示不占绘制区，仅参与逻辑/日志)
name/unit/source  调试与文档元数据
```

同一个 `var_addr` 可在不同页复用（例如各模块自检状态同时出现在自检页和数据页）。

### 3.3 变量缓存与脏标记

```c
typedef struct {
  uint32_t value;            /* 当前缓存原始值 */
  uint32_t drawn_value;      /* 上次已绘制到屏幕的值 */
  uint32_t last_refresh_ms;  /* 上次重绘时间 */
  uint8_t  valid;            /* 缓存是否可用 */
  uint8_t  drawn_valid;      /* 当前页是否已绘制过该字段 */
  uint8_t  dirty;            /* 下次刷新是否强制重绘 */
} Display_ValueCache_t;
```

`Display_Refresh()` 的跳过条件（满足任一即不重绘，省 FSMC 带宽）：

- 缓存无效，或变量不属于当前页；
- 非脏、已画过、且值未变化；
- 非脏、周期型且距上次重绘未到 `refresh_ms`；
- 非脏、事件型 (`refresh_ms==0`) 且已画过。

即只有“变了 / 被置脏 / 到周期”才会真正写屏，这是显示稳定与低抖动的基础。

## 4. 数据装配：Display_PrepareSnapshot

每个刷新节拍从 App 只读快照拉一版完整数据，写入变量缓存：

```text
App_CopyNavigation  -> 姿态/GNSS/位置
App_CopyDateTime    -> 日期/时间
App_CopySystem      -> 系统状态/自检结果/最高故障码
App_CopyEnvironment -> 温湿压/电源 (含电机电池告警评估 Display_EvalMotorFault)
App_CopyAlarm       -> 告警码/激活位图
App_CopyMotor       -> 四路油门
```

设计约束：

- 任一快照拉取失败 → 走 fallback（`Display_LoadModuleStatusFallback`）或清空对应区，
  **绝不显示半截数据**（对应门禁“不读半包、不发布半包”）。
- 一次刷新使用同一版本快照；刷新期间到达的新数据留到下一版本。
- 消息日志与自检灯/告警表同源（模块状态 + 告警码），无论完整 system 快照是否可用
  都更新，避免日志长期空白。

## 5. 刷新预算与调度

### 5.1 DisplayTask 主循环（business_task_template.c）

```text
每 10ms:
  1. Display_PollTouch()            输入永远先服务，刷新失败不得抑制触摸
  2. 到 200ms 节拍 -> PrepareSnapshot() 取一版数据，置 refresh_pending
  3. 切页等需要整页重绘 -> 立即置 refresh_pending（不等 200ms）
  4. refresh_pending -> RefreshStep(now, 2000us) 按预算画一步
       OK   -> 清 pending
       BUSY -> 保持 pending，下个 10ms 接着画
  5. StatusHeartbeat -> vTaskDelayUntil(10ms)
```

`Display_RefreshStep()` 是有时间预算的分步刷新：用游标 `s_refresh_cursor` 记录进度，
单次只画 2ms 能完成的字段，剩余工作返回 `DISPLAY_NOT_READY/BUSY`，下一个 10ms tick
继续，从而把一帧重绘摊到多个节拍，避免长时间占用 CPU/总线。

### 5.2 切页立即刷新

切页后不等常规 200ms 节拍：`Display_HasPendingRedraw()`（`s_static_redraw_pending`）
置位，下一个 10ms tick 立即用现有缓存值重绘整页静态骨架；动态数据仍由常规节拍的
快照更新，故无需在切页时重取快照。（见 `Change_History/2026-06-22_29` 与
`2026-06-23_30`。）

## 6. 状态灯配色

```c
static uint16_t Display_PagesGetStatusColor(uint32_t value) {
  if (value == 0) return GRAY;    /* 未就绪 */
  if (value == 1) return YELLOW;  /* 降级/警告 */
  if (value == 2) return GREEN;   /* 在线/正常 */
  return RED;                     /* 失败/离线 */
}
```

各模块状态（如 LoRa：ONLINE→绿、STARTING→灰、OFFLINE/DEGRADED→黄、FAILED→红）
统一映射成 0/1/2/3 后由该函数着色，保证全屏配色一致。

## 7. 初始化与自检流程

```text
Display_Init():
  清空全部变量缓存
  AtkMd0700_PortInit()   FSMC + SSD1963 (校验 PID 0x61) + GT911
    失败 -> ready=0, 返回 DISPLAY_ERROR
  ready=1, 当前页=SELF_CHECK
  Display_InitSelfCheckValues()
  Display_PagesDrawStatic(SELF_CHECK)   首屏静态骨架

Display_SelfCheck():
  ready==0 -> DISPLAY_NOT_READY, error_code=1
  否则      -> DISPLAY_OK

恢复:
  Display_RequestRecover() 置 s_recover_requested
  下一轮 Display_EnsureInit() 重新 Display_Init()
```

模块通过 `s_display_descriptor`（`PX4LITE_MODULE_DISPLAY`）注册到 Framework
注册表，由 Business 适配层（`business_display_placeholder.c`）把
`PollTouch / HasPendingRedraw / PrepareSnapshot / RefreshStep` 映射成统一服务返回码。

## 8. 触摸链路

```text
GT911 (软 I2C) -> Display_Gt911_Scan(x,y) -> 横屏坐标
  -> Display_PollTouch():
       命中导航按钮 (prev: x∈[8,258], next: x∈[542,792], y∈[426,474]) -> 翻页 + 整页重绘
       命中变量触摸区 (s_hmi_touch_regions) -> 相对增量/绝对写入 RW 变量
```

按下/抬起带 latch（`s_touch_down` / `s_touch_nav_latched` / `s_touch_slider_latched`），
避免单次触摸被多次判定；导航判定只命中按钮矩形本身，不覆盖中间页码圆点区域，
防止误翻页。

## 9. 关键不变量

1. FSMC LCD 只有 DisplayTask 一个写入者。
2. 不分配 768000 字节全屏帧缓冲，不使用 DMA2D。
3. 上屏数据来自统一版本的 App 只读快照，半包数据不上屏。
4. 单帧重绘可被 2ms 预算切片，跨多个 10ms tick 完成。
5. 状态配色统一走 `Display_PagesGetStatusColor`。
6. `var_addr` 是固件内部虚拟地址，与 LCD 控制器寄存器地址无关。
