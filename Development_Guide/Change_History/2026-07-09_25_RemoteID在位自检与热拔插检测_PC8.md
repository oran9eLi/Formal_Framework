# 2026-07-09_25 RemoteID(ESP32)在位自检与热拔插检测(PC8)

## 修改原因和风险

- **原因**:RemoteID(UART4→ESP32-S3)是只发不收的盲发通道,原自检灯以 `Px4Lite_RemoteIdTxRun` 发送是否成功为判据。DMA 往 UART 盲发必然"成功",导致 ESP32 拔掉/断电时 RemoteID 自检仍显示 ONLINE(绿),自检结果失真。新增 PC8 硬件在位检测作真实判据,对齐 LoRa 的 `IsPresent` 模式。
- **风险**:
  - PC8 电平检测只反映"ESP32 的 3.3V 是否加在该脚上",不能反映固件是否在运行;若 ESP32 与主板共用常供 3.3V,该路电平不随 ESP 工作状态变化,检测退化为"接线/模块物理在位"。
  - 悬空输入问题:内部下拉约 40kΩ 偏弱,长跳线拔出后可能悬在高电平,需外部下拉电阻(建议 10kΩ 对地)保证拔出判低。
  - 两板必须共地,否则电平读数无参考。

## 涉及文件

- `Bsp/Inc/bsp_config.h`:新增 `BSP_ESP_DETECT_PORT/PIN`(GPIOC / GPIO_PIN_8)。
- `Bsp/Inc/bsp_remoteid.h`、`Bsp/Src/bsp_remoteid.c`:`BSP_RemoteId_Init` 内配置 PC8 下拉输入;新增 `BSP_RemoteId_IsPresent()`(读 PC8),模块关闭时 `#else` 返回 0。
- `Framework/Inc/px4lite_platform.h`、`Framework/Src/px4lite_platform_f407.c`:新增 `Px4Lite_RemoteIdIsPresent()`,转调 BSP。
- `Framework/Src/px4lite_modules.c`:`Px4Lite_CommWorkRun` 的 RemoteID 分支灯色只按 PC8(插=ONLINE 绿,拔=FAILED 红);保留 TX 泵帧、reinit 自愈、stats 记录;删除基于 TX 结果的 busy/timeout 判定与 `s_remoteid_busy_since_ms`。新增 `s_remoteid_present_prev` 轮询边沿检测:插入(低→高)置位 reinit 请求当拍重初始化 UART4/DMA,拔出(高→低)`AbortTx`。
- `Business/Inc/app_message_log.h`、`Business/Src/app_message_log.c`:`App_LogMessageId_t` 尾部追加 `APP_LOGMSG_REMOTEID_OK/LOST`;新增 `s_db_remoteid` 去抖 + boot 跟踪 + 稳态推送。
- `Display/Inc/display_pages.h`、`Display/Src/display_lvgl.c`:`Display_LogMsg_t` 镜像追加两枚举;日志文本 "RemoteID正常/断开"(拉丁走 montserrat fallback,中文走 zh 点阵)。
- `Display/Src/display_pages.c`、`Display/Src/display.c`:清理旧点阵残留死代码(空壳 LoRa 直绘接口、只写不读的 selfcheck_faults 数组),与本次自检改动同批。

## 行为变化

- RemoteID 自检灯:插着并上电(PC8 高)=ONLINE 绿,未插/未上电(PC8 低)=FAILED 红,不再受盲发 TX 结果影响。
- 消息日志:新增 "RemoteID正常" / "RemoteID断开" 两条,走既有 1.5s 去抖。
- 告警汇总:RemoteID 置 FAILED + `PX4LITE_FAULT_COMM_OFFLINE` 后自动进告警表,显示 "REMOTE ID / COMM OFFLINE"(告警侧无需改动)。
- 热拔插:运行中插/拔在下一个通信周期反映;插入触发 UART4/DMA 重初始化以干净恢复广播。
