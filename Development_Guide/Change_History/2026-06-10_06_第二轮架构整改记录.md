# 第二轮架构整改记录

## 1. 微秒时间源

原实现：

```c
return HAL_GetTick() * 1000U;
```

该实现数值单位虽然是微秒，但精度只有 1 ms，已经移除。

当前实现使用 HAL 时间基准定时器 TIM6：

- TIM6 计数频率：1 MHz
- TIM6 自动重装：999
- `HAL_GetTick()` 提供毫秒部分
- `TIM6->CNT` 提供 0~999 微秒部分
- 读取期间保存并恢复 PRIMASK
- 若 TIM6 更新中断待处理，主动补偿 1 ms

`Px4Lite_PlatformGetUs()` 现在具有约 1 us 计数分辨率。返回值为
`uint32_t`，约 71 分钟自然回绕，调用方必须使用无符号差值计算。

## 2. 看门狗任务心跳门控

增加三个必需心跳：

```text
SENSOR
ESTIMATOR
HEALTH
```

每个任务完成本周期主要工作后更新自己的心跳。Health 调用喂狗函数时，
平台层必须确认：

1. 三个任务都至少运行过一次。
2. 每个任务心跳年龄不超过 500 ms。
3. 所有条件满足后才允许刷新硬件看门狗。

硬件看门狗默认关闭：

```c
#define PX4LITE_ENABLE_HARDWARE_WATCHDOG 0U
```

启用后必须实现：

```c
void BSP_WatchdogRefresh(void);
```

否则链接失败。这是故意设置的集成门禁，防止启用 IWDG 后仍使用空喂狗
函数。

## 3. GNSS 单一状态职责

GNSS 驱动不再判断超时、离线和失联。驱动只提供事实：

```text
GNSS_DATA_NONE
GNSS_DATA_NO_FIX
GNSS_DATA_FIX_OK
```

以及：

- 最近有效 NMEA 时间
- 最近定位时间
- 接收序号
- GPS/北斗可见与参与定位卫星数
- 经纬度、高度、速度和航向

Framework Health 是唯一负责组件公开状态的模块：

```text
STARTING / ONLINE / DEGRADED / OFFLINE / FAILED
```

因此不会再出现驱动状态和框架状态使用不同超时阈值的问题。

## 4. GNSS 新数据判定

原实现用 `last_rx_ms` 是否变化判断是否有新数据。当前改为：

```c
snapshot.rx_sequence != last_rx_sequence
```

每收到一条校验正确的完整 NMEA 语句，驱动递增 `rx_sequence`。

序号回绕规则：

- 0 保留为“尚未收到数据”。
- 自增回绕到 0 时立即跳到 1。
- 消费者只比较是否相等，不比较大小。

这消除了时间戳相同或毫秒回绕导致漏判新数据的风险。
