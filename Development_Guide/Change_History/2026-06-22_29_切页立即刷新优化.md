# 2026-06-22_29 切页立即刷新优化

## 一、背景与现象

切换 HMI 页面时，画面有时会有明显的卡顿/延迟，且**时快时慢**——有时几乎瞬间切换，有时要停顿一下才重画。属于手感问题，不影响数据正确性。

## 二、根因分析

显示任务的调度与刷新是两套独立节奏（[business_template_config.h](../../Business/Inc/business_template_config.h)）：

| 参数 | 值 | 含义 |
|------|----|------|
| `BUSINESS_DISPLAY_SERVICE_PERIOD_MS` | 10ms | FreeRTOS 任务唤醒周期（`vTaskDelayUntil`），真正的任务调度 |
| `BUSINESS_DISPLAY_REFRESH_PERIOD_MS` | 200ms | **软件刷新间隔**，决定多久启动一轮刷新，非 RTOS 调度 |
| `BUSINESS_DISPLAY_REFRESH_BUDGET_US` | 2000us | 每步预算（当前 `Display_RefreshStep` 未使用） |

显示任务循环（[business_task_template.c](../../Business/Src/business_task_template.c)）：

```
每 10ms 唤醒：
  1. 轮询触摸（切页就发生在这里：nav 触摸 -> Display_SetHmiPage）
  2. if (到 200ms 节拍) 取快照、置 refresh_pending=1
  3. if (refresh_pending) 执行一步刷新（一次整页骨架 或 画一个字段）
```

`Display_SetHmiPage` 只是把显示层的 `s_static_redraw_pending=1`，**并不通知任务**。因此整页重绘必须等到下一个 200ms 节拍 `refresh_pending` 被置位后才开始。

**卡顿与“时快时慢”的来源**：

1. **0~200ms 的随机等待**：触摸切页的时刻与 200ms 节拍之间相位随机，刚好赶上节拍则几乎不卡，刚错过则要等近 200ms 才开始重画——这就是“有时候卡”的根源。
2. **逐字段填充**：骨架画完后，每个 10ms tick 只画一个字段，字段多的页（告警表、消息日志、电机滑条）要十几帧才填满，内容是“一格一格冒出来”。
3. **整页静态重绘是一次性重活**：清整屏 800×480 + 表头 + 中文标签/边框，多为逐像素绘制（Logo 64×64、公司名位图、中文字模），会把该 tick 堵住一小会儿。

其中第 1 点（200ms 门槛）是主要可感知因素，也是本次优化目标。

## 三、优化方案（切页立即刷新）

不改动常规 200ms 刷新节奏，仅对“切页等需要整页重绘的事件”增加一条立即触发通路：让显示任务每个 10ms tick 检查显示层是否有待重绘，有则当拍立即置位 `refresh_pending` 并执行刷新。

由于切页发生在循环开头的触摸轮询中，且立即刷新检查在同一 tick 内进行，**整页重绘与触摸落在同一个 10ms tick**，切页延迟从 0~200ms 降到约 0~10ms。

静态骨架使用现有缓存值绘制，业务数据仍由常规 200ms 节拍的快照更新，故立即刷新通路**无需重取快照**，不增加额外开销。

## 四、改动清单

| 文件 | 改动 |
|------|------|
| [display.c](../../Display/Src/display.c) | 新增 `Display_HasPendingRedraw()`，返回 `s_static_redraw_pending`（切页待重绘标志） |
| [display.h](../../Display/Inc/display.h) | 声明 `Display_HasPendingRedraw()` |
| [business_display_placeholder.c](../../Business/Src/business_display_placeholder.c) | 新增适配封装 `Business_DisplayNeedsImmediateRefresh()` -> `Display_HasPendingRedraw()` |
| [business_task_template.h](../../Business/Inc/business_task_template.h) | 声明 `Business_DisplayNeedsImmediateRefresh()` |
| [business_task_template.c](../../Business/Src/business_task_template.c) | 显示任务循环在 200ms 节拍判断之后，新增立即刷新检查：`if (Business_DisplayNeedsImmediateRefresh()) refresh_pending = 1U;` |

核心循环（改动后）：

```c
result = Business_DisplayPollTouch(now_ms);          /* 切页在此触发 s_static_redraw_pending */
...
if (Business_TimeReached(now_ms, next_refresh_ms)) { /* 常规 200ms 节拍，取快照 */
    ...; refresh_pending = 1U; next_refresh_ms = now_ms + 200ms;
}
if (Business_DisplayNeedsImmediateRefresh()) {       /* 新增：切页立即刷新 */
    refresh_pending = 1U;
}
if (refresh_pending) {
    Business_DisplayRefreshStep(now_ms, ...);        /* 本拍即执行整页骨架重绘 */
}
```

## 五、时序对比

```
旧：触摸切页 ──(等 0~200ms 节拍)── 整页骨架 ──(每 10ms 一个字段)── 填满
新：触摸切页 ──(同一 10ms tick)── 整页骨架 ──(每 10ms 一个字段)── 填满
```

- 切页“开始重画”的延迟：0~200ms → ≈0~10ms。
- `s_static_redraw_pending` 在 `Display_RefreshStep` 执行完整页骨架后立即清零，立即刷新检查随之停止，后续逐字段填充由 `refresh_pending` 维持，不会反复触发。

## 六、影响与边界

- **不改 200ms 常规节奏**：周期性传感器字段刷新频率不变，CPU 占用基本不变；立即刷新仅在切页瞬间多触发一拍。
- **数据新鲜度不变**：立即刷新用缓存值绘制骨架，业务数据仍按 200ms 更新；切页瞬间字段为上一次快照值（≤200ms），随后正常刷新。
- **线程安全**：`s_static_redraw_pending` 为单字节标志，写在显示任务（`Display_SetHmiPage`/`Display_RefreshStep`）、读在同一显示任务，无跨任务竞争。
- **可达性**：任何置位 `s_static_redraw_pending` 的事件（当前为切页）都会被立即刷新覆盖，后续若新增“强制整页重绘”需求亦可复用。

## 七、后续可继续优化（本次未做）

1. **拆分整页静态重绘**：把清屏/表头/各面板分到多帧，避免单帧堵塞过久（第 3 点）。
2. **加速逐像素绘制**：Logo、标题位图、中文字模改为按行/块写（FSMC 块写），或表头不变时不重画 Logo。
3. **逐字段填充加速**：切页后的字段填充仍是每 10ms 一个，可在切页突发期内一拍多画几个字段（受 `BUSINESS_DISPLAY_REFRESH_BUDGET_US` 预算约束）。

## 八、验证建议

- 连续快速切页，观察是否每次都近乎即时开始重画、无 0~200ms 抖动。
- 切到重内容页（告警页中文表、消息日志页、电机滑条页），确认骨架立即出现、字段随后填充。
- 确认常规运行时 CPU/任务栈无异常（显示任务优先级 `tskIDLE_PRIORITY + 1`，低于采集/系统任务）。
