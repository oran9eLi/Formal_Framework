# Serial 通用串口监视页

日期：2026-10-23。分支：`codex/serial-monitor`；生产提交：`d6515d7551ae7600e23b17da7320c0c54b4ca45a`；基线：`5e1b2e266f899de5f4915615bf9f41a5c30d7edc`（develop）。

## 范围与当前状态

用户确认F407提供可复用的串口能力、平台组织实验；授权独立分支实现，左上角名称继续使用 `Serial`。本分支实现和Keil构建已完成，实屏、实际收发及性能待验证；未合入develop、未推送或建立tag。V1.0已有验收状态不扩大。

Serial取消H1/B1专用实验计数/nonce/阶段面板，统一观察UART6。现有H1 Echo和B1临时波特率切换处理、TUNNEL编码、路由、重试、先发旧速率确认再切速率和复位语义保留。这里完整显示五项配置，不增加配置修改入口，也不实现后续UART1 CLI。

## 屏幕内容

主内容区沿用800×480屏幕的(8,62,784,272)，八行14 px文字，200 ms更新、文字变化才刷新。页头Serial、公共返回、最近三条Event Log、History和底部导航保留；数字沿用已有等宽代理，普通英文字母度量不变。

| 行 | 字段 | 含义 |
|---|---|---|
| 1 | Baud rate / Data bits / Stop bits | 当前实际配置；默认115200 bps、8、1，现有B1成功后baud显示57600 |
| 2 | Parity / Flow control | 校验和硬件流控；当前均None，未提供改参入口 |
| 3 | RX bytes / Valid frames | 接收回调交付字节数 / MAVLink解析器返回FRAMING_OK的帧数；不是业务命令接受数，签名按现有解析器配置处理 |
| 4 | TX complete bytes / Frames | 完整发送成功的字节 / 帧；不证明树莓派在线或收到 |
| 5 | TX failures / RX frame errors | 非OK发送结果次数 / MAVLink BAD_CRC、BAD_SIGNATURE次数 |
| 6 | RX errors / Drops / Rearm | 带UART硬件错误标志的IRQ次数 / 接收环满舍弃字节 / 回调重新挂接接收失败次数 |
| 7 | Last RX / Last TX complete | 距最近收到字节 / 完整发送成功的毫秒数，基于同份快照时间计算；从未发生为N/A |
| 8 | Counts / Snapshot age | 当前计数范围since boot或since clear，以及Comm快照年龄；超过1000 ms标STALE |

配置尚不可用或快照超过1000 ms时五项配置显示N/A，避免把旧配置显示为当前生效值。未发布监视快照时统计/活动也显示N/A。时间0 ms合法，由rx_seen/tx_seen表示事件是否发生。

## 操作

| 操作 | 行为 |
|---|---|
| Clear stats | 为九项显示计数记录同份快照基线，按uint32_t差值显示此后的变化；不清设备累计计数、最近活动、协议请求、波特率或捕获会话；切页回来保留基线，重启恢复 |
| Frames > | 进入已有报文观察页，默认RPi RX；学生手动Start，再选择Messages/Raw/Decoded，TX另手动选向 |
| History / Back / 主导航 | 沿用已有页面与导航行为 |

端口统计独立于捕获。未开始/暂停捕获、进入其他页面时，UART6累计统计仍随真实通信推进。RX bytes包含后续因环满未入环的已交付字节，不包括硬件过载后从未交付给软件的字节。有效帧不保证目标/命令被接受。TX超时可能已有部分字节出线，这部分不计入“完整发送字节”；失败包含BUSY/超时/错误，非法空参数在发送前拒绝不计数。

普通遥测仍按既有调度发送，因此没有树莓派时TX统计可以增长，RX可以保持0、Last RX为N/A。计数为32位自然回绕；清基线后的差值支持一次回绕，不承诺超过2^32次事件的完整总数。完整端口初始化会复位底层统计，页面清零、切速率、失败回滚或半帧解析重置均不清统计。

## 分层与资源

- BSP：配置句柄与原始RX计数/时间；ISR仍只做接收环操作和有限计数，不解析/格式化。硬件错误在IRQ入口计一次，回调中重新挂接失败单列，不把同次错误回调再计为硬件错误；硬件恢复调用保持原样。
- 平台适配：转换HAL配置（字长扣除校验位得到数据位），在原MAVLink校验/发送完成位置累计协议事实。通用计数不接入实验事务决策。
- Framework：由现有Comm循环发布60 B通用快照，与原实验快照API并存；不让显示任务消费串口接收环。
- Business / Display：只通过App_CopySerialMonitor读取已发布副本；九项显示基线36 B由显示任务独占。

没有新增FreeRTOS任务、业务动态分配、队列或大缓存，没有修改任务优先级、周期、栈或任何协议配置。页面对象继续使用既有固定LVGL内存池；本页新增一个端口标题标签，其池内运行占用待实屏采样。静态空间以实际链接结果为准；本次不以编译结果宣称运行耗时改善。
