# 2026-07-17_08 COMMAND_ACK 按接收链路原路返回

## 背景

树莓派侧反馈：下发 `COMMAND_LONG` 后收不到 `COMMAND_ACK`，并把 STM32 判为 `stm32_identity_unknown`。

排查后确认是两个独立问题。

## 问题一：ACK 出口按 `target_component` 反推，会静默走错链路

原实现按 ACK 的 `target_component` 是否等于 `193` 决定走 USART6 还是 LoRa：

```c
static uint8_t MavTx_PendingAckTargetsRpi(void)
{
  return ((s_pending_ack.valid != 0U) &&
          (s_pending_ack.target_component == PX4LITE_RPI_MAVLINK_COMPONENT_ID)) ? 1U : 0U;
}
```

而 `target_component` 是原样回填的命令来源 compid，由对端自选。树莓派若用 `MAV_COMP_ID_ONBOARD_COMPUTER`(=191) 而非 `MAV_COMP_ID_ONBOARD_COMPUTER3`(=193) 发命令，就会出现：

- 命令正常执行（`Command_IsForThisSystem` 只校验 target，不校验 source）；
- ACK 的 `target_component`=191 ≠ 193，被判为"不发往 RPi"，从 LoRa 空口发走；
- USART6 上什么都没有，树莓派看起来像命令石沉大海。

即"命令生效但没有回执"这一最难排查的症状。

### 修复

应答原路返回：ACK 出口由**收到命令的链路**决定，不再从 sysid/compid 反推。

- `px4lite_types.h` 新增 `Px4Lite_MavlinkLink_t`(`PX4LITE_MAVLINK_LINK_LORA` / `PX4LITE_MAVLINK_LINK_RPI`)。
- `Px4Lite_CommandHandleMavlinkLong()` 增加 `link` 入参，`Px4Lite_MavlinkQueueCommandAck()` 随之透传。
- `px4lite_mavlink_rx.c` 两个接收入口各自标注链路：`Px4Lite_MavlinkRxRun` 传 `LORA`，`Px4Lite_MavlinkRxRunRpi` 传 `RPI`。
- `MavTx_PendingAckTargetsRpi()` 删除。

`COMMAND_ACK.target_system`/`target_component` 仍原样回填命令来源，供对端做请求-应答配对——这部分行为不变，符合 MAVLink 语义。

## 问题二：待发 ACK 单槽被两条链路共用

`s_pending_ack` 只有一个槽。LoRa 忙或 `s_tx_enabled==0` 时挂起的 ACK 不会被排空，会被另一条链路的下一条命令覆盖，症状同样是应答丢失。

### 修复

按链路拆槽：`s_pending_ack[MAV_TX_ACK_SLOT_COUNT]`，`MAV_TX_ACK_SLOT_LORA` / `MAV_TX_ACK_SLOT_RPI` 各持一条待发应答。`MavTx_SendPendingAck()` 改为按槽位发送，两条发送趟各取自己的槽，互不覆盖也互不阻塞。RAM 增加 6 byte。

RPi 趟的 ACK 仍排在 `s_rpi_uplink_enabled` 判定之前：应答是命令的必然回执，不随遥测上行开关关断。

## 关于 `stm32_identity_unknown`（未改固件）

树莓派用 `autopilot != MAV_AUTOPILOT_INVALID` 判定飞控端点，而固件 HEARTBEAT 填的是 `MAV_AUTOPILOT_INVALID`(=8) + `MAV_TYPE_ONBOARD_CONTROLLER`(=18)。

本机是机载控制器而非 autopilot，按 MAVLink 语义填 `INVALID` 是正确的，不应为迁就该判据而谎报 autopilot——这会同时影响 LoRa/GCS/RemoteID 侧的语义。判据应改在树莓派侧：按 `type == MAV_TYPE_ONBOARD_CONTROLLER` 且 `compid == 193` 识别端点。已在 `树莓派下行MAVLink电机控制帧格式.md` 补充 HEARTBEAT 字段实测值表说明。

若后续决定把 STM32 正式声明为 autopilot（它确实承担姿态解算、电机输出、自动起降），应作为独立变更评估，并同步 LoRa 与 RemoteID 侧影响。
