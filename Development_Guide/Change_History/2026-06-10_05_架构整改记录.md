# 架构整改记录

## 已落实项目

### 1. 通信缓冲区所有权

- `s_lora_frame` 明确归 `Px4Lite_LoRaTask` 独占。
- `s_fiveg_frame` 明确归 `Px4Lite_FiveGTask` 独占。
- 日志编码缓冲区明确归 `Px4Lite_LoggerTask` 独占。
- 平台发送接口补充契约：返回 `OK` 后调用者才可复用缓冲区。
- 异步零拷贝发送必须使用内存池，完成回调后释放。

### 2. 周期任务累计漂移

以下周期任务统一使用 `vTaskDelayUntil()`：

- Sensor
- Estimator
- Health
- Display扩展任务
- LoRa扩展任务
- 5G扩展任务
- Logger扩展任务
- Control

`vTaskDelay()` 只允许用于退避、重试和无固定频率的等待。

### 3. 报警覆盖问题

健康任务不再由队列最后一条事件直接控制蜂鸣器。

当前逻辑：

1. 使用 `source_id + fault_code` 维护活动报警表。
2. 激活事件新增或更新对应报警。
3. 恢复事件只清除精确匹配的报警。
4. 每个周期计算全部活动报警中的最高等级。
5. 只要仍有 ERROR 及以上报警，低等级事件就不能关闭蜂鸣器。

### 4. 调试宏解耦

- `DEBUG_ENABLE`：仅启用调试串口基础设施。
- `DEBUG_PERIODIC_ENABLE`：单独启用周期状态输出。
- GNSS RAW、BSP状态等继续使用各自独立宏。
- 周期调试关闭后，对应局部变量和打印代码不参与编译。

### 5. Tick与毫秒语义

- GNSS `_ms` 字段统一使用 `HAL_GetTick()`。
- GNSS超时常量直接以毫秒比较。
- RTOS Tick只用于 `vTaskDelayUntil()` 调度。
- `Px4Lite_PlatformGetMs()` 明确依赖TIM6提供的1 ms HAL时间基准。

### 6. 工程独立化

以下依赖已经复制到 `Formal_Framework/Third_Party`：

- CMSIS
- STM32F4xx HAL
- FreeRTOS内核
- ARM Cortex-M4F移植层
- STM32F407启动文件

Keil工程所有源码和包含路径均位于 `Formal_Framework` 内部。
