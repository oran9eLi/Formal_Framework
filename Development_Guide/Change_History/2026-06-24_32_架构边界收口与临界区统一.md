# 2026-06-24 32 架构边界收口与临界区统一

## 背景

当前编号开发手册已经合并 6.24 接入指南，但代码中仍有两类边界容易被后续开发者误扩散：

- 普通 Business 任务文件直接访问 Framework Registry，容易让业务代码绕过边界适配器。
- GNSS 和 LoRa Driver 直接包含 CMSIS 头并散落 PRIMASK 关中断细节，后续复制时容易出现无条件开中断或长临界区。

## 变更内容

- 新增 `Bsp/Inc/bsp_critical.h`，统一提供 `BSP_Critical_Enter()` / `BSP_Critical_Exit()`。
- `Sensor/Src/sensor_gnss.c` 改为使用 BSP 临界区接口，不再直接包含 `stm32f4xx.h`。
- `Sensor/Src/lora_e22.c` 改为使用 BSP 临界区接口，不再直接包含 `stm32f4xx.h`。
- 将 Display 模块注册表 descriptor、init/self_check/recover 回调和 `Px4Lite_RegistryStart()` 调用收口到 `Business/Src/business_platform_adapter.c`。
- `Business/Src/business_task_registry.c` 只保留 Business 服务初始化和任务创建，不再直接包含 Display 或 Framework Registry 头文件。
- `Business/Src/business_task_template.c` 通过 `Business_DisplayStatusStart()` 启动 Display 模块状态，不再直接调用 Framework Registry。
- 更新 `01_统一开发手册.md`、`02_架构边界与数据流.md`、`03_模块接入手册.md` 的边界规则和评审清单。

## 边界说明

本次不物理移动 `Sensor/Src/lora_e22.c`，避免扩大 Keil source list 和 include path 变更面。当前先完成语义收口：LoRa 仍作为通信类模块由 `comm` 任务服务，后续如新增 `Driver/Comm` 目录，可单独做路径迁移。
