# 屏幕模块开发文档

面向在 Display 模块上做二次开发的成员：新增页面、新增显示变量、新增触摸区域、
接入新数据源时应该改哪里、不准改哪里。内部实现原理见
`19_屏幕模块技术文档.md`。

## 1. 模块边界

```text
Bsp           FSMC/GT911 引脚、时序、地址映射          bsp_config.h / MSP / BSP Init
Display 驱动   SSD1963 像素读写、GT911 触摸扫描         display_ssd1963.* / display_gt911.*
Display 渲染   像素图元、字体、页面绘制、刷新调度        display_gfx.* / display_text.* / display_pages.* / display.c
Business      DisplayTask、模块注册、快照拉取            business_task_template.c / business_task_registry.c
```

强制分层规则（与 `11_ATK-MD0700配置与驱动分层方案.md` 一致）：

1. `bsp_config.h` 只声明引脚/时序/地址，**不得**执行初始化、**不得**包含 SSD1963 命令序列。
2. 设备驱动通过 BSP 接口访问硬件，**不得**重复配置 GPIO/FSMC。
3. **DisplayTask 是 FSMC LCD 的唯一写入者。** GNSS、Alarm、Health、电源等任务
   一律不得直接调用任何 `Display_Pages*` / `Display_Gfx*` 绘图函数。
4. 上层只能通过 `Display_SetHmiValue*` 写入变量缓存，或由 `Display_PrepareSnapshot`
   统一从 App 只读快照拉取。
5. 禁止在任务栈或静态区分配 768000 字节全屏帧缓冲（F407 SRAM 放不下）。

## 2. 数据怎么上屏

```text
传感器/通信任务
  -> 发布到 Framework topic
  -> App 只读快照 (App_CopyNavigation/System/Environment/Alarm/DateTime/Motor)
  -> Display_PrepareSnapshot() 写入 HMI 变量缓存
  -> Display_RefreshStep() 按脏标记+预算绘制变化字段
  -> SSD1963 局部写 GRAM
```

业务侧**不直接画屏**，只要保证数据进了对应的 App 快照字段，Display 会在下一个
刷新节拍自动取走并显示。

## 3. 常见开发任务

### 3.1 新增一个显示变量

1. 在 `Display/Inc/display.h` 的 `Display_HmiVariableId_t` 枚举里加一个 ID
   （加在 `DISPLAY_HMI_VAR_COUNT` 之前，**不要插在中间打乱已有顺序**）。
2. 在 `Display/Src/display.c` 的 `s_hmi_variables[]` 增加一条配置：

   ```c
   {DISPLAY_HMI_VAR_新ID, 所属页面, 0x虚拟地址, 数据类型, 读写属性,
    刷新周期ms, x, y, width, height, "name", "unit", "source"},
   ```

   - `var_addr` 是固件内部虚拟变量地址，**不是 LCD 寄存器地址**，全表唯一即可。
   - `refresh_ms = 0` 表示事件触发（值变了才画），非 0 表示最快多久重绘一次。
   - `x/y/w/h = 0` 表示该变量只参与逻辑/日志，不在当前页占绘制区。
3. 在 `Display_PrepareSnapshot()` 里把数据源写进缓存：
   `Display_SetHmiValueU16/I16/U32/I32(DISPLAY_HMI_VAR_新ID, value);`
4. 字段绘制样式（颜色、单位、格式）在 `display_pages.c` 的 `Display_PagesDrawField`
   分支里处理。

### 3.2 新增一个页面

1. 在 `Display_HmiPage_t` 枚举加页面 ID（`DISPLAY_HMI_PAGE_COUNT` 之前）。
2. 在 `s_hmi_pages[]` 加一条 `{页面ID, 0x页面号, "name", 刷新周期ms}`。
3. 在 `display_pages.c`：
   - `Display_PagesDrawStatic()` 加该页固定骨架（边框、标题、静态标签）。
   - `Display_PagesDrawHeader()` / 翻页逻辑 `Display_PagesGetPrev/NextPage()` 自动按
     枚举顺序串联，一般无需改。
4. 把要显示的变量在 `s_hmi_variables[]` 里 `page` 字段指向新页面。

### 3.3 新增一个触摸区域（按钮 / 滑条 / 参数写入）

1. 在 `s_hmi_touch_regions[]`（display.c）加一条 `Display_HmiTouchRegionConfig_t`：
   矩形 `x1,y1,x2,y2`、命中的变量 ID、相对增量 `delta` 或绝对值 `absolute_value`、
   `set_absolute` 选其一。
2. 写入型变量 `access` 要设成 `DISPLAY_HMI_ACCESS_RW`。
3. 命中后的命令分发（例如把电机 PWM 写回控制层）在 `Display_HandleTouch()` /
   `Display_PollTouch()` 里处理，不要在绘图函数里改状态。

### 3.4 状态灯配色

所有“在线/正常/告警”类状态点统一走 `Display_PagesGetStatusColor(value)`：

| value | 颜色 | 语义 |
|-------|------|------|
| 0 | 灰 | 未初始化 / 未就绪 |
| 1 | 黄 | 降级 / 警告 |
| 2 | 绿 | 在线 / 正常 |
| 其他 | 红 | 失败 / 离线 |

新模块状态灯只要把状态映射成 0/1/2/3 写入对应变量即可，**不要自己另写一套配色**。

## 4. 任务与调度约束

DisplayTask（`Business_DisplayServiceTask`）参数（`business_template_config.h`）：

| 参数 | 值 | 说明 |
|------|----|------|
| `BUSINESS_DISPLAY_SERVICE_PERIOD_MS` | 10 | 任务节拍，每 10ms 跑一轮 |
| `BUSINESS_DISPLAY_REFRESH_PERIOD_MS` | 200 | 常规数据刷新节拍 |
| `BUSINESS_DISPLAY_REFRESH_BUDGET_US` | 2000 | 单次刷新时间预算 |
| `BUSINESS_DISPLAY_TASK_STACK_WORDS` | 768 | 任务栈 |
| `BUSINESS_PRIORITY_DISPLAY` | idle+1 | 低优先级，不得抢占数据正确性相关任务 |

每轮固定顺序：**先轮询触摸 → 到节拍取快照 → 切页则立即整页重绘 → 按预算画一步 → 心跳 → 延时**。
开发时不要在这条循环里加阻塞调用或长耗时绘制，单步必须能被 2ms 预算切片。

## 5. 自检与恢复

- 模块注册描述符 `s_display_descriptor`（business_task_registry.c）挂了
  `init / self_check / recover` 三个回调，由 Framework 注册表统一调度。
- `Display_SelfCheck()`：链路就绪返回 `DISPLAY_OK`；未就绪返回 `DISPLAY_NOT_READY`
  且错误码置 1。
- 屏幕异常时调用 `Display_RequestRecover()` 置位，下一轮 `Display_EnsureInit()`
  重新初始化 FSMC/SSD1963/GT911，**不在中断或其他任务里直接重init**。

## 6. 调试开关

```c
#define DEBUG_DISPLAY_MONITOR_ENABLE  0U   /* 默认关闭 */
```

可输出：LCD ID 与初始化结果、单次局部刷新耗时及峰值、刷新/超预算/丢版本计数、
GT911 触摸中断与 I2C 错误计数、DisplayTask 栈峰值。`DEBUG_ENABLE` 下
`Display_LoadMockValues()` 可灌入模拟值用于离线联调。

## 7. 合入门禁（对照 `16_模块接入标准与评审清单.md`）

- [ ] 没有任何非 DisplayTask 路径写 FSMC LCD。
- [ ] 新变量/页面/触摸区都进了对应配置表，`var_addr` 不冲突。
- [ ] 数据只读半包不上屏：快照拉取失败时走 fallback / 清空，不显示半截数据。
- [ ] 单次刷新可被预算切片，不阻塞、不超时。
- [ ] 状态灯走统一配色函数。
- [ ] 改动记录写入 `Change_History/YYYY-MM-DD_序号_标题.md`。
