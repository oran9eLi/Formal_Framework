# 2026-06-27_45_LoRa多从机轮询与点名数据流

## 背景

多从机场景下，若所有从机独立周期发送心跳和完整遥测，LoRa 半双工空口容易发生碰撞，也会让后续从机扩容不可控。因此本次将多从机在线发现统一收口为主机轮询，完整数据统一收口为显示选中后的租约式点名发送。

## 代码调整

- `Framework/Inc/px4lite_config.h`
  - `PX4LITE_REMOTE_NODE_MAX` 调整为 17，预留主机 0 和从机 1~16。
  - 新增 `PX4LITE_REMOTE_HEARTBEAT_STALE_MS`，将在线响应超时与主数据 stale 分离。
  - 新增 `PX4LITE_MAVLINK_NODE_POLL_PERIOD_MS`，主机按 node id 轮询从机在线状态。
- `Framework/Src/px4lite_mavlink_tx.c`
  - 新增 `MAV_CMD_USER_2` node poll 命令调度。
  - 主机产品模式下按 node id 轮询从机，轮询命令优先级低于远端数据流续租。
  - 从机空闲时不主动周期发送 HEARTBEAT；被主机打开主数据流后才随数据流发送 HEARTBEAT 和完整遥测。
- `Framework/Src/px4lite_command.c`
  - 新增 node poll 命令处理。
  - 从机只接受主机 node 0 的 poll 和 stream 控制命令。
  - 保留 stream start/stop 的 COMMAND_ACK 回执。
- `Framework/Src/px4lite_mavlink_rx.c`
  - 将 poll/stream 的 accepted `COMMAND_ACK` 作为远端在线响应更新到远端节点心跳口径。
  - 主数据 stale 仍按 3 s 判定，在线响应 stale 按独立心跳超时判定。
- `Display/Src/display_lvgl.c`
  - 远端节点选择页扩展为 16 行静态缓存和右侧滚动列表，避免后端支持 16 个从机但界面只能选择前 5 个节点。
  - 远端列表缓存仍为文件静态数组，不进入 `biz_display` 任务栈。

## 外设数据链路复查

当前选中从机打开主数据流后，发送侧已覆盖：

- GNSS：`GPS_RAW_INT` + `GNSS_SAT` 扩展。
- 姿态：`ATTITUDE`。
- 位置/速度：`GLOBAL_POSITION_INT`。
- 电源：`SYS_STATUS` + `BATTERY_STATUS`。
- 环境：`SCALED_PRESSURE`。
- 模块状态：`MODSTAT0/1`。
- 告警：`STATUSTEXT`。

接收侧已逐字段解码到远端遥测快照，并由 `App_CopyRemoteDisplaySnapshot()` 映射给 Display。新增外设数据后仍按 Telemetry Catalog -> MAVLink RX -> App 远端视图的链路接入，不得绕到 Display 或 LoRa Driver。
