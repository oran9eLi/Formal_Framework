# MPU6050 强类型迁移执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use inline execution with test-first checkpoints. Steps use checkbox syntax for tracking.

**Goal:** 将 `projext` 的 MPU6050 6 轴采集能力迁移到 N1，并符合 N1 强类型、Topic/FIFO、Health 和 App API 规范。

**Architecture:** MPU6050 继续挂在 I2C1 PB6/PB7，与 BME280 共用 `BSP_I2C`。Sensor 层只输出强类型 6 轴真实值；Framework 层把样本转换为 `Px4Lite_SensorImu_t` 并推入已有 IMU FIFO；Estimator 层消费 FIFO，用一阶互补滤波生成 `roll_deg100` 和 `pitch_deg100`。

**Tech Stack:** STM32F407、FreeRTOS、HAL I2C、N1 BSP/Sensor/Framework/Business/Debug 分层、C99 单元测试。

## 关键约束

- 不迁移 `Sensor_Driver_t`、`Sensor_Sample_t`、`channel + unit` 弱类型模型。
- 不新增 MPU6050 永久任务；默认复用 `sensor` 任务。
- 不输出 yaw。MPU6050 没有磁力计，yaw 无法长期稳定。
- 底层数据使用真实数值，不带单位字符串：`accel_g`、`gyro_dps`、`temperature_c`。
- Framework IMU FIFO 仍使用现有正式单位：`accel_mg`、`gyro_mdps`、`temperature_cdeg`。
