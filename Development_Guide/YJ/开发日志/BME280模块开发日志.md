# BME280 模块开发日志

## 1. 开发目标

将 BME280 环境传感器接入 NW3 工程，提供温度、气压、湿度三类环境数据，并符合工程强类型、单 owner、统一 Health 管理的架构要求。

## 2. 开发过程

### 2.1 BSP I2C 基础能力

先补齐 I2C1 的 BSP 封装，统一提供：

- `BSP_I2C_Init()`
- `BSP_I2C_MemRead()`
- `BSP_I2C_MemWrite()`
- `BSP_I2C_IsDeviceReady()`
- `BSP_I2C_Recover()`

后续 BME280 和 MPU6050 共用该总线，避免每个驱动直接操作 HAL。

### 2.2 Sensor 强类型驱动

新增 `sensor_bme280.h/.c`，不沿用旧工程的弱类型通道模型。驱动内部完成：

- 地址探测：0x76 / 0x77；
- 芯片 ID 校验；
- 软复位；
- 校准参数读取；
- forced mode 单次测量；
- 温度、气压、湿度补偿计算；
- 快照缓存和状态复制。

### 2.3 Framework 接入

BME280 接入 `sensor` 任务的周期调度，不新增独立任务。采样成功后由 Platform Adapter 转换成 `Px4Lite_SensorBaro_t` 并发布到 Baro Topic。

Health 通过模块状态、超时和错误计数判断 BME280 是否离线，驱动本身不直接发布 OFFLINE。

## 3. 调试记录

调试重点主要集中在 I2C 共享总线和缺失设备时的阻塞问题。

已做处理：

- 初始化失败后增加 1000 ms 退避，避免每个采样周期都阻塞 I2C。
- 读失败计数达到阈值后清除初始化状态，后续自动重新初始化。
- BSP I2C 对 timeout/busy 情况执行总线恢复。
- `GetStatus()` 只复制轻量状态，不触碰 I2C 总线。

## 4. 当前结果

当前 BME280 模块已完成：

- Sensor 驱动；
- I2C BSP 支持；
- Platform Adapter 转换；
- Baro Topic 发布；
- Business 环境快照读取；
- Storage CSV 数据来源接入；
- Health 超时管理。

模块状态可按“基础完成”理解：主链路已接入，仍需结合真实硬件做长时间稳定性验证。

## 5. 后续注意

- BME280 和 MPU6050 共用 I2C1，调试一个模块时不要破坏另一个模块的总线时序。
- 如果出现偶发无数据，优先查看 I2C timeout、busy 和总线恢复次数。
- 若环境数据长期为 0 或异常，应先检查芯片 ID、地址焊接选择和校准参数读取。
- 长时间测试时观察 Display 是否被 I2C 重试拖慢。
