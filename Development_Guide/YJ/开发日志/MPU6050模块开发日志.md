# MPU6050 模块开发日志

## 1. 开发目标

将 MPU6050 六轴 IMU 接入 NW3 工程，为姿态估计提供加速度和角速度数据，并保持 Sensor、Framework、Estimator 的职责边界清晰。

## 2. 开发过程

### 2.1 Sensor 驱动

新增 `sensor_mpu6050.h/.c`，驱动负责硬件事实和原始物理量换算：

- 探测 0x68 / 0x69 地址；
- 校验 `WHO_AM_I = 0x68`；
- 唤醒芯片；
- 配置采样分频、DLPF、陀螺仪量程和加速度量程；
- 读取 14 字节连续数据；
- 换算为 g、dps 和摄氏度；
- 记录 last stage、last result、chip id 和 BSP status。

### 2.2 Framework 接入

MPU6050 不创建独立任务，而是接入统一 `sensor` 任务。Platform Adapter 将 Sensor 层单位转换为 Framework 单位：

```text
g      -> mg
dps    -> mdps
C      -> cdeg
```

转换后的样本推入 IMU FIFO，由 `estimator` 任务消费。

### 2.3 姿态估计

Estimator 从 IMU FIFO 中读取样本并调用 `Px4Lite_AttitudeUpdate()`。当前主要输出：

- roll；
- pitch；
- yaw_rel；
- 三轴角速度。

MPU6050 不提供磁力计，因此不能依赖它得到长期稳定的绝对航向。

## 3. 调试记录

调试中重点处理以下问题：

- I2C 总线偶发 busy 或 timeout；
- 设备未接入时不能持续阻塞总线；
- 全 0 帧不能作为有效 IMU 数据；
- 原始值明显越界时需要拒绝；
- 初始化失败后要退避重试。

2026-06-18 轴向实测记录：

- 以模块红圈排针侧作为机头方向；
- 抬头时 pitch 上升，说明机头方向和 pitch 符号正确；
- 右倾时 roll 减小，roll 符号反向；
- 左转时 yaw 增大，若按右转为正，则 yaw 符号反向；
- 最终在平台适配层增加 IMU 机体坐标映射：`accel_y`、`gyro_x`、`gyro_z` 取反。

当前策略：

- 初始化失败先 100 ms 快速重试，超过阈值后 500 ms 慢速重试；
- 连续读失败达到阈值后请求重新初始化；
- 采样失败只记录硬件事实，不直接把模块写成 OFFLINE；
- Health 统一根据 age 和状态判断离线。

## 4. 当前结果

当前 MPU6050 模块已完成：

- Sensor 强类型驱动；
- I2C BSP 共用；
- Platform Adapter 单位转换；
- IMU FIFO；
- Estimator 姿态更新；
- Debug 状态输出；
- Health 超时管理；
- Storage CSV 姿态字段接入。

模块状态可按“基础完成”理解：采集、FIFO 和姿态输出链路已经闭合，仍需结合真实飞行姿态和长时间漂移做进一步验证。

## 5. 后续注意

- 调试 yaw 时要注意 MPU6050 没有磁力计，绝对航向漂移属于硬件能力限制。
- 如果姿态显示不动，先看 IMU FIFO 是否有数据，再看 Estimator 是否消费。
- 如果 I2C 设备同时异常，要先排查 I2C1 总线而不是单独怀疑 MPU6050。
- 长时间运行时观察 `reinit_count`，如果持续增加，需要检查供电、焊接和 I2C 上拉。

## 6. 2026-06-24 姿态估计算法优化

根据 JY-61/MPU6050 模块资料与本工程现状对比，本次优先优化裸 MPU6050 软件姿态估计中的三个薄弱点：

- 在 `Px4Lite_AttitudeState_t` 中增加三轴陀螺零偏、累加值、样本计数和零偏有效标志。
- 在 `Px4Lite_AttitudeUpdate()` 内增加静止零偏校准。上电静止且加速度模长接近 1g 时累计 128 帧估计 bias，校准前冻结静止样本的陀螺积分，减少 yaw 初始漂移。
- 增加加速度可信度门控和动态互补系数。线加速度或冲击导致加速度模长明显偏离 1g 时，不再用该帧加速度强行修正 roll/pitch；采样周期变化时互补权重同步调整。

已完成验证：

- ARMCC 5.06 单独编译 `Framework/Src/px4lite_attitude.c` 通过。
- ARMCC 5.06 单独编译 `Tests/Unit/test_attitude_filter.c` 通过。
- Keil `MDK-ARM/formal_framework.uvprojx` / `Target 1` 构建通过，结果为 `0 Error(s), 0 Warning(s)`。

后续实测时重点观察：上电静止 1.5 s 内 yaw 是否明显收敛、持续机动时 roll/pitch 是否减少线加速度误修正，以及静止阈值是否会误判低速真实转动。
