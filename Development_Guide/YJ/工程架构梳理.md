# NW3 项目工程架构梳理

## 1. 工程定位

NW3 为外部分支快照，目标平台为 STM32F407ZG，使用 Keil MDK-ARM v5 和 ARMCC 5.06 构建。工程已从单一传感器采集框架，扩展为包含 GNSS、IMU、Baro、Battery、LoRa/MAVLink、Display、Alarm、Storage 的低空 CNS 综合框架。

工程入口为：

```text
Core/Src/main.c
```

启动流程为：

```text
HAL_Init
  -> SystemClock_Config 168MHz
  -> DebugConsole_Init
  -> BSP_Init
  -> Px4Lite_PlatformInit
  -> Px4Lite_AppInit
  -> Business_AppInit
  -> vTaskStartScheduler
```

## 2. 总体分层

NW3 采用单向依赖架构：

```text
Core
  -> Business
  -> Framework
  -> Platform Adapter
  -> Sensor Driver / Storage Driver / Display Driver
  -> BSP
  -> HAL / FreeRTOS / Third_Party
```

核心约束：

- `main.c` 是组合根，只负责初始化和启动调度器。
- `Framework/Src/px4lite_platform_f407.c` 是 Framework 唯一允许包含 BSP/Sensor 头文件的适配层。
- Business 层只能通过 `app_data_api.h` 读取数据，不能直接访问 BSP、Sensor 或 Framework 私有 Topic。
- Sensor Driver 只处理芯片协议、寄存器和原始数据转换，不直接管理系统状态。
- OFFLINE、FAILED 等系统级状态由 Health/Registry 统一管理。

## 3. 目录职责

| 目录 | 职责 |
|---|---|
| `Core` | HAL 启动、系统时钟、FreeRTOS Hook、中断入口 |
| `Bsp` | 板级外设封装：UART、I2C、SPI、ADC、LCD FSMC、Touch Port、LoRa、GNSS DMA |
| `Sensor` | 具体设备驱动：GNSS/NMEA、BME280、MPU6050、Power ADC、LoRa E22 |
| `Framework` | Topic、模块状态、任务调度、Health、Recovery、Alarm、MAVLink、Storage 适配 |
| `Business` | 应用层任务、事件总线、只读数据 API、显示业务调度 |
| `Display` | SSD1963 LCD、GT911 触摸、页面、字体/绘图、Logo |
| `Debug` | 串口调试、模块监控、任务栈和 heap 监控 |
| `Storage` | SD SPI、FatFS diskio、CSV 格式、日志队列、SD 状态机 |
| `Third_Party` | FreeRTOS、FatFS、MAVLink、STM32 HAL/CMSIS 等第三方组件 |
| `Development_Guide` | 工程规范、开发记录、团队手册、YJ 个人汇报文档 |
| `MDK-ARM` | Keil 工程文件和构建输出配置 |
| `Release` | 发布清单和交付说明 |

## 4. 任务架构

当前 Framework 和 Business 组合后，主要任务如下：

| 任务 | 周期 | 优先级 | 主要职责 |
|---|---:|---:|---|
| `sensor` | 10 ms | idle+4 | 唯一硬件采集所有者，采集 GNSS、IMU、Baro、Battery |
| `estimator` | 20 ms | idle+3 | GNSS/IMU 数据转换为 Navigation，姿态估计 |
| `health` | 100 ms | idle+2 | 模块超时、状态机、Health 快照、恢复监控、看门狗门控 |
| `comm` | 10 ms | idle+2 | LoRa 服务、MAVLink 遥测发送调度 |
| `biz_system` | 1000 ms | idle+2 | 系统业务轮询、启动日志、注册信息维护 |
| `biz_acq` | 200 ms | idle+2 | 读取应用数据快照，分发到业务事件总线 |
| `biz_display` | 10 ms | idle+1 | 显示刷新和触摸处理，2ms 步进预算 |
| `debug` | 100 ms | idle+1 | 周期调试打印，栈和 heap 监控，不参与看门狗集合 |
| `storage` | 50 ms | idle | SD CSV 日志写入，执行阻塞 SD/FatFS 操作，优先级最低 |

设计原则：

- 一个硬件资源只能有一个任务所有者。
- 普通传感器不允许每个模块单独建任务，统一归 `sensor` 调度。
- SD 卡写入可能阻塞，因此独立 `storage` 任务并保持最低优先级。
- `debug` 和 `storage` 不进入看门狗必需心跳集合，避免调试或 SD 慢操作误触发系统异常。

## 5. 数据流架构

### 5.1 传感器采集链路

```text
BSP 外设
  -> Sensor Driver
  -> px4lite_platform_f407.c
  -> Framework Topic / FIFO
  -> Estimator / Health / Storage / Business
```

具体链路：

| 模块 | 硬件/接口 | Sensor 输出 | Framework Topic |
|---|---|---|---|
| GNSS | USART2 + DMA + IDLE | NMEA 解析快照 | `Px4Lite_SensorGnss_t` |
| MPU6050 | I2C1 | accel/gyro/temp | `Px4Lite_SensorImu_t` + IMU FIFO |
| BME280 | I2C1 | temp/pressure/humidity | `Px4Lite_SensorBaro_t` |
| Power ADC | ADC1 IN5 / PA5 | voltage/percent/low | `Px4Lite_BatteryStatus_t` |
| LoRa E22 | UART + AUX/M0/M1 | 通信帧与调试计数 | Comm Debug + MAVLink TX |
| SD Card | SPI3 + PA15 CS | CSV 日志写入状态 | Storage Module Status |
| Display/Touch | FSMC + GT911 | 页面和触摸状态 | Business Display 服务 |

### 5.2 Navigation 链路

```text
GNSS Topic
IMU FIFO
  -> estimator task
  -> Px4Lite_VehicleNavigation_t
  -> Business / Display / MAVLink / Storage
```

Navigation 当前包含：

- 经纬度、海拔、GNSS 时间；
- roll、pitch、yaw_rel；
- roll/pitch/yaw 角速度；
- GNSS fix、HDOP、卫星数；
- `valid_mask` 标记哪些字段有效。

### 5.3 Storage 链路

```text
Framework Topics
  -> px4lite_storage.c
  -> storage_csv.c
  -> storage_queue.c
  -> storage_sd.c
  -> diskio_sd_spi.c
  -> bsp_spi.c
  -> SD Card
```

CSV 文件：

```text
YYMMDD_D.CSV  DATA 周期数据
YYMMDD_E.CSV  EVENT 事件数据
```

Storage 只读取 Framework Topic，不读取 Business API，也不访问 Sensor 私有变量。

### 5.4 Comm/MAVLink 链路

```text
Framework Topics / Alarm / Comm Stats
  -> px4lite_mavlink_tx.c
  -> Px4Lite_LoRaSend
  -> lora_e22.c
  -> BSP LoRa UART
```

MAVLink 采用字段级编码，禁止直接发送 C 结构体内存。

## 6. 模块状态与恢复机制

NW3 使用注册表管理模块生命周期：

```text
Px4Lite_RegistryRegister
  -> RegistryStart
  -> init callback
  -> Health 监控
  -> RecoveryMonitorRun
  -> recover callback
```

恢复规则：

- Health 负责判断模块错误和超时。
- Recovery 只调用轻量级 recover 回调。
- recover 回调只设置“请求重新初始化”标志，不能在 Health 任务里做阻塞 I/O。
- 实际重新初始化由资源所属任务完成，例如 sensor、comm 或 storage。

当前 IMU 还有驱动级自动恢复：连续读失败后自动请求重新初始化，并在重新初始化后通过稳定样本门控再发布。

## 7. 硬件资源分配

| 功能 | 外设/引脚 |
|---|---|
| Debug UART | USART1 PA9/PA10 |
| GNSS | USART2 PA2/PA3 + DMA1 Stream5 Channel4 |
| I2C 传感器 | I2C1 PB6/PB7，BME280 + MPU6050 |
| Power ADC | ADC1 IN5，PA5，分压比例 4:1 |
| SD Card | SPI3 PB3/PB4/PB5，PA15 CS |
| Display | FSMC + SSD1963 |
| Touch | GT911 触摸接口，经 `bsp_touch_port` 适配 |
| LoRa | LoRa BSP + E22 驱动 |

注意：PB3、PB4、PA15 与 JTAG 复用相关，调试时应使用 SWD，避免 JTAG 占用 SD 引脚。

## 8. 第三方组件

| 组件 | 用途 |
|---|---|
| STM32 HAL/CMSIS | 芯片外设和启动支持 |
| FreeRTOS | 任务、队列、临界区、heap 管理 |
| FatFS | SD 卡文件系统 |
| MAVLink | LoRa 遥测消息编码 |

## 9. 当前架构重点

NW3 当前已经具备以下完整能力：

- 多传感器强类型采集；
- GNSS/NMEA 解析和导航快照；
- MPU6050 姿态估计；
- BME280 环境监测；
- ADC 电源监测；
- LoRa + MAVLink 遥测；
- Display/Touch 显示服务；
- Alarm 告警快照；
- SD CSV 数据和错误日志；
- Debug 独立监控；
- 注册式模块恢复；
- 任务栈与 heap 运行观测。

后续开发应继续保持“单向依赖、单资源单 owner、强类型 Topic、低优先级隔离阻塞外设”的架构原则。
