## 2. MPU6050 姿态估计优化

### 2.1 问题背景

原姿态估计器使用固定 `0.98` 互补滤波系数，roll/pitch 由陀螺积分和加速度角融合，yaw 由 Z 轴陀螺积分得到。实际使用中存在几个问题：

- 陀螺零偏会导致静止时 yaw 持续漂移。
- 加速度计在机动、冲击或线加速度较大时，不一定能代表真实重力方向。
- 固定互补系数没有根据采样周期和加速度可信度动态调整。

### 2.2 解决方案

本次在 `Framework/Src/px4lite_attitude.c` 中补充了以下策略：

- 静止零偏校准：当加速度模长接近 1g 且三轴角速度较小时，累计 128 帧估计三轴陀螺 bias。
- 静止校准期间冻结陀螺积分，避免上电静止阶段直接积累 yaw 漂移。
- 加速度可信度门控：加速度模长在 `0.95g ~ 1.05g` 内完全可信，`0.85g ~ 1.15g` 之间线性过渡，超出范围关闭加速度修正。
- 动态互补系数：根据采样周期和加速度可信度计算 alpha，加速度不可信时更依赖陀螺预测。

同时在 `Framework/Inc/px4lite_attitude.h` 中扩展了姿态估计状态，增加陀螺零偏、累计值、校准样本数和零偏有效标志。

### 2.3 验证

- 1.41g 线加速度不应把 roll 强行拉向错误角度。

## 3. SD-CSV 日志命名方案

### 3.1 文件命名调整

今日确认采用以下文件命名：

```text
YYMMDD_D.CSV  DATA 数据日志
YYMMDD_E.CSV  EVENT 事件日志
```

示例：

```text
260624_D.CSV
260624_E.CSV
```

实现位置：

- `Storage/Src/storage_file.c`
- `Storage/Inc/storage_config.h`
- `Storage/Src/storage_sd.c`

原先的前缀式命名 `DYYMMDD.CSV` / `EYYMMDD.CSV` 已改为后缀式命名，方便按日期排序并保持 DATA/EVENT 类型清晰。

### 3.2 时间无效兜底策略

讨论中确认：如果 RTC/GNSS 日期尚未有效，日志不能直接丢弃，否则上电早期异常和未同步阶段的数据无法追溯。

因此新增兜底文件：

```text
UNSYNC_D.CSV
UNSYNC_E.CSV
```

行为规则：

- 时间无效时，DATA 写入 `UNSYNC_D.CSV`。
- 时间无效时，EVENT 写入 `UNSYNC_E.CSV`。
- 行内 `local_date` 和 `local_time` 记录为 `0`。
- 时间有效后，自动切换到当日 `YYMMDD_D.CSV` / `YYMMDD_E.CSV`。
- 不自动重命名 `UNSYNC` 文件，避免嵌入式侧增加目录扫描和重命名复杂度。

## 5. Git 分支推送

### 5.1 目标

用户要求将当前工程推送到：

```text
https://github.com/oran9eLi/Formal_Framework.git
```

并创建新分支：

```text
NW3.1
```

### 5.2 遇到的问题

#### 问题 1：本地无法创建分支

执行：

```text
git switch -c NW3.1
```

失败，报错：

```text
cannot lock ref 'refs/heads/NW3.1'
Permission denied
```

检查发现 `.git/refs/heads` 目录 ACL 中存在显式 Deny 权限，导致 Git 无法创建本地分支引用。

#### 问题 2：无法写入 index.lock

执行 `git add` 时也出现：

```text
Unable to create '.git/index.lock': Permission denied
```

说明 `.git` 写操作受到本机权限限制。

#### 问题 3：首次推送 TLS 失败

首次 `git push` 报错：

```text
schannel: failed to receive handshake, SSL/TLS connection failed
```

随后通过 `git ls-remote` 验证 GitHub 远端可访问，判断为 TLS 瞬时握手失败或 Windows Git schannel 后端偶发问题。

### 5.3 解决方案

由于无法创建本地 `NW3.1` 分支，采用绕过本地分支引用的方式：

1. 将当前工程状态加入索引。
2. 使用 `git write-tree` 和 `git commit-tree` 直接创建提交对象。
3. 将该提交对象直接推送到远端分支：

```text
refs/heads/NW3.1
```

推送成功后的远端提交：

```text
9902ce5 feat: snapshot NW3.1 project state
```

远端分支确认：

```text
origin/NW3.1 -> 9902ce53b922c73c76e92f450194ade5bf4928d4
```

GitHub 返回 PR 地址：

```text
https://github.com/oran9eLi/Formal_Framework/pull/new/NW3.1
```

### 5.4 后续注意

本地当前仍停留在 `NW3` 分支，工作区文件内容未回滚。本地 `.git` 权限问题仍然存在，后续如果要正常创建、切换、提交分支，建议修复 `.git` 目录 ACL，或者重新 clone 一份干净工作区。

## 6. 5G 与 Remote ID 日志规划

今天讨论了后续 5G 和 Remote ID 接入时日志模块是否需要调整。

### 6.1 5G 当前定位

用户明确：当前 5G 模块只需要显示是否接入 5G 网络，不做数据收发。

因此当前阶段不需要：

- 5G TX/RX 字节数。
- 5G 服务器连接状态。
- 5G 大帧队列。
- 单独的 5G CSV 文件。
- 复杂通信统计。

建议当前只保留最小状态：

```text
fiveg_registered
fiveg_signal_level  // 可选
fiveg_state         // 可选
```

EVENT 中只记录状态变化：

```text
fiveg_registered
fiveg_unregistered
fiveg_offline
fiveg_recovered
```

### 6.2 Remote ID 后续方向

Remote ID 后续接入时，应重点记录“是否按要求发出、发出的数据是否有效、失败原因是什么”。

建议后续预留：

```text
rid_state
rid_mode
rid_uas_id_valid
rid_position_valid
rid_operator_valid
rid_tx_count
rid_fail_count
rid_last_error
```

当前不急于新增 `YYMMDD_R.CSV`，等 Remote ID 数据内容和协议确定后再决定是否单独成文件。

## 7. 电源管理模块优化建议

今天基于当前 `sensor_power.c`、`sensor_power_config.h`、Battery Topic、Display、Storage 和 MAVLink 链路，梳理了电源管理模块的后续优化方向。

当前已有能力：

- ADC1_IN5 / PA5 电压采样。
- 电压二次校准。
- 电量百分比曲线。
- 电压低通滤波。
- 电量百分比迟滞和连续确认。
- Battery Topic 发布。
- Display 显示电压和电量。
- Storage 记录 `voltage_v` 和 `battery_pct`。

建议后续优先优化：

1. 低电压判断增加迟滞和连续确认。
2. 区分 `low_battery` 和 `critical_voltage`。
3. Storage DATA 增加 `low_voltage`、`power_quality`、`battery_state`。
4. EVENT 中记录 `low_voltage`、`low_voltage_recovered`、`critical_voltage`、`critical_voltage_recovered`。
5. 后续如果接入电流计 `CURR`，增加 `current_ma`、`power_w`、`consumed_mah`。
6. 未来将固定负载补偿升级为基于电流的动态补偿。

其中短期最值得先做的是：

- 低电压迟滞。
- 低电量/危险电压分级。
