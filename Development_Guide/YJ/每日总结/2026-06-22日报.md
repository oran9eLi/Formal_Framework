## 2. 日志模块工作内容

### 2.1 数据日志与事件日志分离

今天对 SD-CSV 日志模块做了进一步梳理，将原先偏单一的数据记录方式扩展为两类日志：

- 数据日志：记录周期性传感器与系统运行数据。
- 事件日志：记录告警、恢复、模块状态变化、存储异常等非周期事件。

文件命名采用按日期分文件的方式：

```text
YYMMDD_D.CSV  数据日志
YYMMDD_E.CSV  事件日志
```

这样做的作用是把“连续采样数据”和“系统发生了什么事”分开。后续排查问题时，可以先看事件日志定位异常发生时间，再回到数据日志查看对应时间附近的传感器数据。

### 2.2 补充 RTC 时间与文件滚动

日志模块加入了 RTC 时间缓存与文件日期滚动能力。SD 卡日志记录中同时保留：

- `time_ms`：系统启动后的毫秒时间，用于判断任务运行相对时间和事件先后顺序。
- `local_date`：RTC 日期，格式如 `20260622`。
- `local_time`：RTC 时间，格式如 `154727`。

今天也明确了这三个字段的含义：`time_ms` 是运行时相对时间，`local_date/local_time` 是 RTC 提供的真实日期时间。因为板子上有 RTC 纽扣电池，所以方案中不再额外设计“时间未同步”状态。

### 2.3 事件日志字段说明

今天根据实际 CSV 截图解释了事件日志字段含义，并补充了 `Development_Guide/YJ/日志字段说明.md`。

事件日志主要字段包括：

| 字段 | 含义 |
|---|---|
| `time_ms` | 系统启动后的毫秒时间 |
| `local_date` | RTC 日期 |
| `local_time` | RTC 时间 |
| `event_type` | 事件类型，如告警激活、状态恢复 |
| `source` | 事件来源模块 |
| `state` | 模块状态 |
| `fault` | 故障码 |
| `severity` | 严重等级 |
| `active` | 是否为当前激活事件 |
| `count` | 同类事件累计次数 |
| `message` | 事件文本 |

这部分工作的作用是让 SD 卡中的告警信息可以被解释，而不是只有一串数字。后续查看 CSV 时，可以快速判断是 SD 卡异常、IMU 离线、LoRa 离线还是模块恢复。

### 2.4 模块状态变化记录

今天重点处理了一个实际问题：拔掉姿态传感器后，屏幕显示“姿态不在线”，但是 SD 卡没有记录。

分析后判断原因是：屏幕显示使用的是业务层或状态快照，而 SD 卡事件日志原先没有完整订阅并记录模块状态变化。也就是说，“状态已经变化”并不等于“事件日志已经写入”。

改进方向是：

- 当模块从正常状态进入异常状态时，写入告警事件。
- 当模块恢复正常时，写入状态恢复事件。
- 恢复事件文本按用户要求使用“状态恢复”，不写“清除”这类容易误解的描述。

今天实现后，事件日志中可以看到类似：

```text
imu_offline
imu_recovered
baro_offline
baro_recovered
lora_offline
lora_recovered
storage_degraded
storage_recovered
```

这解决了“屏幕能看到异常，但 SD 卡追溯不到异常”的问题。

### 2.5 SD-CSV 数据字段补充偏航角

今天确认 SD 卡记录的数据中缺少偏航角。根据现有姿态解算结果，补充了 `yaw_deg` 字段，使 SD 卡数据记录包含完整的姿态角：

- 横滚角 `roll_deg`
- 俯仰角 `pitch_deg`
- 偏航角 `yaw_deg`

这项改动的作用是让飞行姿态数据在离线分析时完整可用。此前只有横滚、俯仰时，无法分析航向变化；补充偏航角后，可以结合 IMU 姿态和后续 GNSS/LoRa 数据做更完整的过程分析。

## 3. 电池 ADC 模块工作内容

### 3.1 新增电压校准配置文件

今天新增了 `Sensor/Inc/sensor_power_config.h`，用于集中管理电池 ADC 的现场校准参数。

主要配置项包括：

```c
POWER_CAL_GAIN_NUM
POWER_CAL_GAIN_DEN
POWER_CAL_OFFSET_MV
POWER_LOAD_COMPENSATION_ENABLE
POWER_LOAD_COMPENSATION_MV
```

这些参数的作用是把“电压校准”从算法代码中拿出来，后续如果现场测量发现 ADC 与万用表存在稳定偏差，可以通过配置修正，而不需要修改 `sensor_power.c` 的主逻辑。

当前默认配置为：

- 增益为 `1000 / 1000`，即 1.000 倍。
- 固定偏移为 `0mV`。
- 负载补偿默认关闭。
- 负载补偿值预留为 `200mV`。

也就是说，默认情况下不会额外给测得电压加 0.2V。

### 3.2 明确负载补偿的使用边界

今天讨论了一个关键点：负载补偿参数是否就是在测得数据上加 0.2V，以及它是否能区分空载电池和负载电池。

结论是：

- 如果开启负载补偿，本质上就是在校准后的电压上增加固定值，例如 `+200mV`。
- 当前 ADC 只测电压，没有测电流，也没有输入电源状态判断，因此不能自动区分空载电池和负载电池。
- 目前建议先不开启负载补偿，优先以设备实际运行时的负载电压作为电量判断依据。

如果后续想开启，只需要修改：

```c
#define POWER_LOAD_COMPENSATION_ENABLE 1U
```

如果想调整补偿值，则修改：

```c
#define POWER_LOAD_COMPENSATION_MV 200U
```

单位是 mV。

### 3.3 优化电量百分比曲线

今天将电池电量计算从简单低电量分段加线性换算，改为表驱动曲线。当前曲线为：

| 电压点 | 电量 |
|---|---|
| 9.90V | 0% |
| 10.20V | 5% |
| 10.50V | 10% |
| 10.80V | 20% |
| 11.10V | 30% |
| 11.40V | 40% |
| 11.70V | 50% |
| 11.95V | 60% |
| 12.15V | 70% |
| 12.30V | 80% |
| 12.45V | 90% |
| 12.55V | 100% |

曲线点之间仍使用线性插值，最后按 5% 档位显示。

这样做的作用是让电量显示更贴近实测电池特性。低电压区保留更细的判断点，避免 9.9V 到 10.5V 之间电量显示过于粗糙；高电压区也保留多个曲线点，使满电附近显示更自然。

### 3.4 保留防跳变机制

今天继续保留原有的电量稳定策略：

- 电压使用一阶滤波：`3/4` 旧值 + `1/4` 新值。
- 电量只按 5% 档位显示。
- 新档位必须连续 10 次进入后才更新。
- 档位切换保留 200mV 滞回。

这部分的作用是防止 ADC 抖动导致电量在两个档位之间来回跳变。测试中也确认了：当电压从 50% 对应区间跳到高电压区时，前 9 次不会立即更新，连续第 10 次确认后才切换。

## 4. 今日遇到的问题与解决过程

### 4.1 SD 卡事件日志中出现 `sd_write_failed`、`sd_sync_failed`

问题现象：

用户查看 SD 卡 CSV 时，看到事件日志中出现：

```text
sd_write_failed
sd_sync_failed
storage_degraded
storage_recovered
```

分析过程：

- `sd_write_failed` 表示 SD 写入失败。
- `sd_sync_failed` 表示 FatFs 同步或刷盘失败。
- `storage_degraded` 表示存储服务进入降级状态。
- `storage_recovered` 表示后续存储服务恢复。

解决方式：

- 补充事件字段解释文档。
- 将存储异常作为事件日志记录，而不是只在内部计数。
- 保留恢复事件，便于判断异常是持续存在还是短暂抖动。

作用：

后续如果 SD 卡偶发接触不良、SPI 写入失败或文件同步失败，可以在事件日志中看到发生时间、恢复时间和累计次数。

### 4.2 姿态传感器离线没有写入 SD 卡

问题现象：

拔掉姿态传感器后，屏幕显示姿态不在线，但 SD 卡没有对应记录。

原因分析：

显示和日志是两个消费路径。屏幕显示可以直接反映当前状态，但事件日志必须显式记录状态变化。如果日志模块没有订阅或比较模块状态变化，就不会自动写入 SD 卡。

解决方式：

- 增加模块状态事件记录机制。
- 对 IMU、BARO、GNSS、LoRa 等模块状态变化进行事件化。
- 异常进入时写告警事件，恢复时写状态恢复事件。

作用：

屏幕看到的模块异常，现在可以在 SD 卡事件日志中留下追溯记录。

### 4.3 数据日志缺少偏航角

问题现象：

SD 卡数据记录中有姿态相关数据，但没有偏航角。

原因分析：

姿态估计模块已经具备横滚、俯仰、偏航数据，但 Storage CSV 字段没有把 `yaw_deg` 纳入输出。

解决方式：

- 扩展数据日志字段。
- 增加 `yaw_deg` 写入。
- 更新相关测试，覆盖扩展字段。

作用：

SD 卡数据可以完整记录三轴姿态角，便于后续离线分析。

### 4.4 电池同时给电流计和开发板供电时 ADC 偏低约 0.2V

问题现象：

电流计单独测试电压准确，但同一个电源同时接电流计和开发板供电时，ADC 测得电压比实际电压低约 0.2V。

原因分析：

这个偏差更接近负载状态下的实际压降，可能来自线材、接头、开发板负载、共地路径等因素。由于电流计分压比例约 10 倍，PA5 上约 20mV 的差异会被还原成约 0.2V 的电池电压差异。

解决方式：

- 不直接默认加 0.2V。
- 新增负载补偿参数，但默认关闭。
- 建议以设备实际工作状态电压作为电量判断基准。

作用：

既保留了后续补偿能力，又避免现在把负载电压强行修正为空载电压，导致低电压判断偏乐观。
