## 2. 需求背景

在前一阶段工作中，第二电池作为动力电池已经具备：

- 独立采样链路：PA4 / ADC2。
- 独立电量曲线：10.50V 为 0%，12.60V 为 100%。
- 低压告警阈值：低于 10.80V 连续确认后置位。
- 低压恢复阈值：高于 11.00V 连续确认后清除。
- 防跳变机制：滤波电压、连续确认、恢复回差。

今天检查第一电池时发现，第一电池虽然已有电量百分比滤波和档位防跳变，但低压标志仍然偏向瞬时判断。原逻辑近似为：

```c
s_snapshot.low_voltage = (voltage_mv < POWER_PERCENT_TABLE_EMPTY_MV) ? 1U : 0U;
```

该逻辑存在两个问题：

- 低压状态直接受单次采样影响，容易被 ADC 抖动或瞬时负载压降触发。
- 低压进入和恢复没有回差，临界电压附近可能反复跳变。

因此决定给第一电池补齐低压确认机制。

## 3. 方案设计

第一电池仍然保持现有电量百分比曲线不变：

| 电压点 | 电量显示 |
|---:|---:|
| 9.90V | 0% |
| 10.20V | 5% |
| 10.50V | 10% |
| 12.55V | 100% |

低压告警策略调整为：

| 项目 | 当前配置 |
|---|---:|
| 低压进入阈值 | 10.30V |
| 低压恢复阈值 | 10.50V |
| 恢复回差 | 200mV |
| 判断依据 | 滤波后的电池电压 |
| 连续确认次数 | 复用 `POWER_PERCENT_CONFIRM_COUNT` |

状态机规则：

```text
未告警状态：
  filtered_voltage_mv < 10.30V 连续确认
  -> low_voltage = 1

已告警状态：
  filtered_voltage_mv > 10.50V 连续确认
  -> low_voltage = 0

中间区间：
  10.30V <= filtered_voltage_mv <= 10.50V
  -> 保持当前 low_voltage 状态
```

这样可以避免第一电池在临界电压附近反复触发和解除告警。

## 4. 代码修改

### 4.1 配置文件修改

修改文件：

- `Sensor/Inc/sensor_power_config.h`

新增第一电池低压确认相关宏：

```c
#define POWER_LOW_WARNING_MV 10300U
#define POWER_LOW_RECOVER_MV 10500U
#define POWER_LOW_CONFIRM_COUNT POWER_PERCENT_CONFIRM_COUNT
```

含义：

- `POWER_LOW_WARNING_MV`：第一电池低压预警进入阈值，单位 mV。
- `POWER_LOW_RECOVER_MV`：第一电池低压预警恢复阈值，单位 mV。
- `POWER_LOW_CONFIRM_COUNT`：第一电池低压连续确认次数。

### 4.2 Sensor Driver 修改

修改文件：

- `Sensor/Src/sensor_power.c`

新增静态计数器：

```c
static uint8_t s_pending_low_voltage_count;
```

新增内部函数：

```c
static uint8_t Power_ApplyLowVoltageConfirm(uint8_t previous,
                                            uint32_t filtered_voltage_mv);
```

该函数负责根据当前低压状态、滤波电压和连续确认次数决定是否切换 `low_voltage`。

原来的瞬时低压判断：

```c
s_snapshot.low_voltage = (voltage_mv < POWER_PERCENT_TABLE_EMPTY_MV) ? 1U : 0U;
```

修改为：

```c
s_snapshot.low_voltage =
    Power_ApplyLowVoltageConfirm(s_snapshot.low_voltage, filtered_voltage_mv);
```

同时在 `Sensor_Power_Init()` 中清零低压确认计数，保证模块初始化或重初始化后状态干净：

```c
s_pending_low_voltage_count = 0U;
```

### 4.3 单元测试修改

修改文件：

- `Tests/Unit/test_power_adc_calibration.c`

新增测试辅助函数：

```c
static uint8_t SnapshotLowVoltage(void);
```

替换旧的“低压跟随 0% 档位”测试，新增两个行为测试：

1. `TestBatteryLowVoltageRequiresConsecutiveWarningSamples`
   - 初始电压高于恢复阈值时，`low_voltage = 0`。
   - 电压跌破 10.3V 但未达到连续确认次数时，`low_voltage` 保持 0。
   - 连续确认达到阈值后，`low_voltage` 置 1。

2. `TestBatteryLowVoltageUsesRecoverHysteresis`
   - 先让第一电池进入低压状态。
   - 电压回到 10.3V 到 10.5V 中间区间时，保持低压状态。
   - 电压高于 10.5V 且连续确认后，`low_voltage` 清 0。

由于第一电池电压滤波采用一阶低通，测试输入特意使用较明确的低压和恢复电压，避免测试结果依赖滤波边界过渡样本数。

## 7. 遇到的问题、错误与解决方法

### 7.1 旧逻辑缺少低压防跳变

问题：

第一电池原低压判断使用未滤波或瞬时电压直接判断，低于旧的 0% 电量点附近就置位，缺少连续确认和恢复回差。

影响：

- ADC 毛刺可能触发误告警。
- 负载瞬态压降可能导致日志中 `low_voltage` 频繁变化。
- 第一电池和第二电池的低压告警机制不一致。

解决：

- 新增 `Power_ApplyLowVoltageConfirm()`。
- 使用滤波电压 `filtered_voltage_mv` 判断。
- 新增 10.3V 进入阈值和 10.5V 恢复阈值。
- 引入连续确认计数器。

### 7.2 低压测试需要考虑滤波过渡

问题：

第一电池电压经过一阶滤波，如果测试输入只略低于阈值，滤波值可能需要较多样本才真正越过阈值，测试容易和滤波过渡过程绑定。

解决：

- 测试中使用更明确的低压输入：`POWER_LOW_WARNING_MV - 2500U`。
- 测试中使用更明确的恢复输入：`POWER_LOW_RECOVER_MV + 2000U`。
- 测试目标聚焦低压确认状态机，不让测试依赖边界滤波细节。
