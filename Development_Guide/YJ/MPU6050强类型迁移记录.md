# MPU6050 强类型迁移记录

## 1. 迁移目标

将 `原始参考工程` 的 MPU6050 模块迁入 Formal_Framework1，但不迁移旧工程的 `Sensor_Driver_t`、`Sensor_Sample_t` 和 `channel + unit` 弱类型接口。迁移后按 Formal_Framework1 正式链路运行：

```text
I2C1 PB6/PB7
  -> BSP_I2C
  -> Sensor_MPU6050
  -> Platform Adapter
  -> sensor task
  -> IMU FIFO
  -> estimator task
  -> Navigation roll/pitch
  -> Business / Debug
```

## 4. 数据模型

Sensor 层保存真实浮点数据，不带单位字符串：

```text
accel_g[3]       // g
gyro_dps[3]      // deg/s
temperature_c    // C
sample_time_ms   // 采样时间戳
rx_sequence      // 成功采样序号
error_count      // 驱动错误计数
```

Platform Adapter 转换到 Formal_Framework1 现有 IMU Topic 单位：

```text
accel_mg[3]          // mg
gyro_mdps[3]         // mdps
temperature_cdeg     // 0.01 C
sample_period_us     // 10000 us
```

Estimator 输出：

```text
roll_deg100
pitch_deg100
valid_mask |= PX4LITE_NAV_VALID_ATTITUDE
```

`yaw` 暂不输出有效值，因为 MPU6050 没有磁力计，航向角无法长期稳定。

## 5. 任务和优先级

| 模块 | 所属任务 | 周期 | 优先级 |
|---|---|---:|---:|
| MPU6050 采集 | `sensor` | 10 ms | `idle+4` |
| roll/pitch 估计 | `estimator` | 20 ms | `idle+3` |
| 状态超时判断 | `health` | 100 ms | `idle+2` |

没有新增 MPU6050 独立任务，符合 Formal_Framework1 “新外设默认加入已有 sensor 任务周期表”的规范。

## 6. Debug 输出

开启 `DEBUG_IMU_MONITOR_ENABLE` 后，串口会输出类似：

```text
[DBG] IMU: state=2 roll=+0.00deg pitch=+0.00deg fifo=0 peak=2 ovf=0 age=5
```

字段含义：

| 字段 | 含义 |
|---|---|
| `state` | IMU 模块状态 |
| `roll/pitch` | Estimator 输出的姿态角 |
| `fifo` | 当前 IMU FIFO 样本数 |
| `peak` | FIFO 历史峰值 |
| `ovf` | FIFO 溢出次数 |
| `age` | 当前姿态输出距离采样时间过去的毫秒数 |
