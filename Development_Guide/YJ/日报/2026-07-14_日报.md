## 二、发现的错误与问题排查（重点）

### 问题 1：四个模块的技术文档与代码多处不符

- **排查手段**：逐个模块把技术文档里的文件名、字段、宏值、状态机等，对着当前源码一条条核。
- **发现与解决**：
  - **SD-CSV**：文档写的是固定文件名 `SENSOR.CSV`/`ERROR.CSV`，实际代码是按日期命名的 `YYMMDD_D.CSV`/`YYMMDD_E.CSV`（未同步时 `UNSYNC_*`）；数据表文档只列 11 列、实际 36 列；行长上限文档写 192、实际 512；文档给的"错误表头"是一段已无调用方的死代码。先按代码修正事实（V1.1），再按 [00 范本](../技术文档/00_模块技术文档范本.md) 重写为 V2.0（补元信息、采样流程、接口清单、配置项、调试、踩坑教学、变更记录）。复核 §6 状态机时又发现"STARTING 时打开文件"表述不准——实际文件是首次写该日期记录时由 `EnsureFileForDate` 按需打开，已改正。
  - **BME280**：查明文档长期悬而未决的"`BME280_I2C_TIMEOUT_MS` 20 vs 4"疑点——源码里其实是两个宏并存：常规读写超时 `BME280_I2C_TIMEOUT_MS=20U`、地址探测超时新增的 `BME280_PROBE_TIMEOUT_MS=4U`，历史那个"4"落在探测路径上，不矛盾；据此把 §4/§7/§11 的"待确认"改为"已查明"。另删除 §2/§7/§9/§10 中"MPU6050 已替换为 AHRS10 / 共用 I2C1"的错误表述（代码中无 AHRS10、MPU6050 仍是在用 IMU，且 AHRS10 是 UART5 设备不共用 I2C1）。升级到 V2.2。
  - **ADC/电源**：这份最过时——文档还停留在"单电池、只测电压、固定 3.3V 参考、5 行电量表"。实际代码已有：双电池（ADC1/ADC2 电压 + ADC3 双路电流）、电流/功率、12 点电量曲线、VREFINT 实测 VDDA、浮空检测、二次校准配置层、平均次数 16（文档写 8）等。按范本重写为 V2.0。
  - **MPU6050**：逐条核对（地址、量程、换算系数、退避阈值、尖峰滤波宏等）全部命中文档，无需改动。
- **教训**："已跑通"的模块文档也会随代码演进而失真；判断口径必须回到当前源码，不能凭文档自证。

### 问题 2：电流读数恒为"幽灵值"，与负载无关

- **现象**：CSV/串口里第二电池电流 `current2_a` 恒定 −2.398A，电机开到 100% 油门也纹丝不动；第一电池电流 `current_a` 在零点附近小幅漂、还出负值。
- **排查手段**：从换算公式反推引脚电压——`电流 =(引脚mV − 零点mV)/ 灵敏度`。
- **发现**：−2.398A 正好等于"零点 240mV ÷ 100mV/A"，即引脚电压 ≈0V。说明那一路**没有活信号进来**，读数纯粹是"0 减零点"的算术产物。负电流同理，是引脚电压略低于零点所致——供电电流物理上不可能为负，恰恰证明"没在测真实电流"。
- **解决方向**：定位为硬件/接线问题（电流计没串进对应回路、或信号没接到对应 ADC 脚），而非算法问题。

### 问题 3：加了串口诊断打印，却"一个字节都收不到"

- **背景**：为在板上直接看原始 `adc_mv` + 浮空标志，给现成的 `DebugConsole` 加了增强版 POWER 打印，并在高优先级 sensor 任务里另挂了一条独立的 `[CUR]` 打印（带心跳计数，绕开可能被饿死的 debug 任务）。
- **现象**：串口助手已连接（115200 8N1），但 RX 恒为 0。
- **排查手段**：先审代码确认调试口在 USART1/PA9、`PX4LITE_DEBUG_USART1_SILENT_FOR_RPI=0`（未静音）、MspInit 已配 PA9/PA10、开机就打 banner——代码侧全部正常。据此判定是设置/接线问题，让对方查设备管理器里 USB 转串口的真实 COM 号。
- **发现**：一直选的 **COM1 是主板传统串口（空口）**，实际适配器是 **COM5（USB-SERIAL CH340）**。换到 COM5 立刻有数据。
- **教训**：USB-TTL 适配器一般枚举成 COM3+，COM1 常是主板空口；排查"无串口数据"要先在设备管理器确认真实 COM 号，别默认 COM1。

### 问题 4：电流计接线反复接反（VOLT/CURR、PC1/PA4）+ 双电池没共地

- **现象**：串口通了之后，第二电池电流仍浮空。
- **排查手段**：给 `[CUR]` 打印补上两路电池电压（`V1(PA5)`/`V2(PA4)`），用"读数特征"反推每根线落在哪个脚——电压分压信号 ≈ 电池电压 ÷10.08（约 1.1V），电流信号空载 ≈ 0.24V。
- **发现并逐一纠正**：
  - 双电池分开供电时一度**没共地**，导致第二电池信号相对 MCU 没有参考——补上共地后电压 `V2` 恢复正常读数；
  - **VOLT 与 CURR 接反**、**PC1 与 PA4 接反**多次：靠打印里"哪一路读出 ≈1.1V（=电压÷10）就是 VOLT、≈0.24V 小值就是 CURR"来定线，并给两根线贴标签固定"CURR→PC1、VOLT→PA4"。
- **教训**：多信号模块接线要靠"读数特征"确认落点，不能靠记忆反复试插；杜邦线反复插拔极易虚接，是"接对了还是不对"的常见隐藏原因。

### 问题 5（根因、最关键）：浮空检测把高阻的 CURR 真实信号误判清零

- **现象**：接线终于都对了（`V2(PA4)≈11000` 正常），万用表量模块 CURR 脚也有 0.25V，但固件仍报第二电池电流浮空 `f=1`、清零成幽灵值。
- **排查手段**：临时改代码，让"判浮空时也采一次真实引脚电压并打印出来"，以分辨"线开路(≈0)"还是"信号到了但高阻"。
- **发现**：打印显示 `I2(PC1) adc_mv≈215mV、f=1`——**真实信号确实到了 PC1（≈215mV），是浮空检测误判把它清零了**。根因：浮空检测靠"把引脚预置拉高到 3.3V、再看信号源能否把它拉回"来判阻抗；这个分流式电流计 CURR 输出**下沉能力弱（高阻）**，小电流（~0.2V）时拉不回来 → 被误判为浮空。而这个检测在此处其实也没挡住幽灵值（清零后照样 0 减零点=−2.4A），纯属帮倒忙。
- **解决**：
  - 关闭电流通道的浮空检测（新增开关 `BSP_ADC_CURRENT_FLOAT_CHECK_ENABLE=0`），`ReadVoltageMv` 改为始终读真实电压、浮空标志仅保留作诊断；
  - 用实测空载值把 `POWER2_CURRENT_ZERO_MV` 从 240 改为 **215mV**。
  - 复位后第二电池电流恢复正常：电机停 ≈0A、单电机空转读出几十~200mA 的真实小电流。
- **教训**：为"未接传感器"设计的防御逻辑（浮空检测），遇到"已接但输出高阻"的真实传感器会变成误杀；防御性检查要考虑真实器件的输出特性，不能只按理想低阻源假设。
