# MPU6050 模块技术文档

## 1. 模块定位

MPU6050 模块用于采集三轴加速度、三轴角速度和芯片温度，是姿态估计链路的 IMU 数据来源。模块接入统一 `sensor` 任务，采样后进入 Framework IMU FIFO，再由 `estimator` 任务计算姿态。

正式数据链路如下：

```text
BSP_I2C
  -> Sensor_MPU6050
  -> px4lite_platform_f407.c
  -> IMU FIFO
  -> estimator task
  -> Navigation Topic
  -> Display / MAVLink / Storage / Business
```

## 2. 硬件与总线

| 项目 | 配置 |
|---|---|
| 传感器 | MPU6050 |
| 总线 | I2C1 |
| 引脚 | PB6/SCL，PB7/SDA |
| I2C 地址 | 自动探测 0x68 或 0x69 |
| 加速度量程 | +/-2g |
| 陀螺仪量程 | +/-250 dps |
| 采集周期 | 10 ms |
| 所属任务 | `sensor` |

MPU6050 与 BME280 共用 I2C1，因此总线异常恢复由 `BSP_I2C` 统一处理。

## 3. 软件分层

| 层 | 文件 | 职责 |
|---|---|---|
| BSP | `Bsp/Src/bsp_i2c.c` | I2C 读写、超时、总线恢复 |
| Sensor | `Sensor/Src/sensor_mpu6050.c` | WHO_AM_I 检查、寄存器配置、14 字节采样、单位换算 |
| Platform Adapter | `Framework/Src/px4lite_platform_f407.c` | 将 g/dps/C 转为 mg/mdps/cdeg |
| Framework | `px4lite_topics.*` / `px4lite_modules.c` | IMU FIFO、状态维护、Health 超时 |
| Estimator | `px4lite_attitude.c` | 姿态更新，输出 roll/pitch/yaw_rel |

## 4. 数据结构

Sensor 层输出 `Mpu6050_Snapshot_t`：

| 字段 | 单位 | 说明 |
|---|---|---|
| `accel_g[3]` | g | 三轴加速度 |
| `gyro_dps[3]` | deg/s | 三轴角速度 |
| `temperature_c` | 摄氏度 | 芯片温度 |
| `sample_time_ms` | ms | 采样时间 |
| `rx_sequence` | 次 | 成功采样序号 |
| `error_count` | 次 | I2C、ID、数据异常计数 |

Platform Adapter 转换为 Framework IMU 单位：

| Framework 字段 | 单位 |
|---|---|
| `accel_mg[3]` | mg |
| `gyro_mdps[3]` | mdps |
| `temperature_cdeg` | 0.01 摄氏度 |
| `sample_period_us` | us |

## 5. 初始化与采样

初始化流程：

1. 探测 `0x68` 和 `0x69` 地址。
2. 读取 `WHO_AM_I`，确认芯片 ID 为 `0x68`。
3. 写 `PWR_MGMT_1` 唤醒芯片。
4. 配置采样分频、DLPF、陀螺仪量程、加速度量程。
5. 等待芯片稳定。

采样流程：

1. 读取 `ACCEL_XOUT_H` 起始的 14 字节连续数据。
2. 解析 accel、temperature、gyro 原始值。
3. 拒绝全 0 帧。
4. 拒绝明显越界帧。
5. 换算为 g、dps、摄氏度并缓存。

## 6. 姿态估计

`sensor` 任务只负责采集和推入 IMU FIFO，不做姿态计算。`estimator` 任务从 FIFO 中弹出样本，通过 `Px4Lite_AttitudeUpdate()` 更新姿态。

当前实物安装以模块红圈标出的排针侧作为机头方向。根据实测：

- 抬头时 pitch 增大，pitch 方向正确；
- 右滚时 roll 减小，roll 方向需要取反；
- 左转时 yaw 增大，若采用右转为正，yaw 方向需要取反。

因此平台适配层在 `px4lite_imu_axis_map.h` 中执行机体坐标映射：

```text
accel_y 取反
gyro_x  取反
gyro_z  取反
```

MPU6050 驱动仍保留芯片原始坐标，坐标映射只在 Framework 平台适配层完成。

当前输出：

| 字段 | 说明 |
|---|---|
| `roll_deg100` | 横滚角，角度乘 100 |
| `pitch_deg100` | 俯仰角，角度乘 100 |
| `yaw_deg100` | 当前作为相对 yaw 输出 |
| `roll_rate_dps100` | 横滚角速度 |
| `pitch_rate_dps100` | 俯仰角速度 |
| `yaw_rate_dps100` | 偏航角速度 |

MPU6050 没有磁力计，绝对航向不能长期稳定，后续如需绝对 yaw 需要接入磁力计或外部航向源。

## 7. 异常与恢复

- 初始化失败后先按 100 ms 快速重试，超过快速重试次数后按 500 ms 退避。
- 连续数据读取失败达到阈值后请求重新初始化。
- Sensor 层记录 `last_stage`、`last_result`、`last_chip_id`、`last_bsp_status`，便于 Debug 定位。
- OFFLINE/FAILED 状态仍由 Health 统一判断，驱动不直接抢写系统状态。

## 8. 验收要点

- 采样周期为 10 ms，不能新增 MPU6050 独立任务。
- IMU 数据必须通过 FIFO 进入 Estimator。
- I2C 异常不能永久卡死总线。
- Debug 能观察 IMU state、FIFO、roll、pitch、age 等信息。
- 姿态字段必须带单位后缀，禁止使用弱类型 `value` 字段。

## 9. 2026-06-24 姿态算法优化记录

`Px4Lite_AttitudeUpdate()` 在保持接口不变的前提下补充了三项滤波策略：

- 静止陀螺零偏估计：加速度模长接近 1g 且三轴角速度小于静止阈值时，累计 128 帧估计三轴 gyro bias。校准完成前的静止阶段冻结陀螺积分，避免上电静止零偏直接积累 yaw 漂移。
- 加速度可信度门控：按加速度模长对重力方向修正赋权，0.95g 到 1.05g 完全可信，0.85g 到 1.15g 之间线性过渡，超出范围时关闭加速度修正，降低线加速度和冲击对 roll/pitch 的误拉偏。
- 动态互补系数：互补滤波的陀螺权重由采样周期和加速度可信度动态计算。10 ms 周期且加速度可信时仍接近原 0.98 策略；加速度不可信时权重提升到 1.0，仅保留陀螺预测。

该优化仍不改变 MPU6050 无磁力计的边界：yaw 只能作为相对航向，长期绝对航向仍需要磁力计、双天线 GNSS 或其他外部航向源约束。
