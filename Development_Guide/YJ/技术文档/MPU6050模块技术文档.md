## 1. 模块定位

MPU6050 模块用于采集三轴加速度、三轴角速度和芯片温度，是姿态估计链路的唯一 IMU 数据来源，模拟无人机的姿态感知能力（设计书 §3.2.5）。模块接入统一 `sensor` 任务，不单独创建 FreeRTOS 任务；采样结果推入 Framework IMU FIFO，由 `estimator` 任务消费并解算 roll/pitch/yaw。

MPU6050 无磁力计，`yaw_deg100` 仅作相对航向输出，不具备长期绝对航向稳定性；后续如需绝对航向需接入磁力计或外部航向源（对应设计书 §1.4 可扩展性）。

正式数据链路如下：

```text
I2C1 (PB6/SCL, PB7/SDA)
  -> BSP_I2C
  -> Sensor_MPU6050
  -> px4lite_platform_f407.c (Px4Lite_ImuRead, 轴向映射)
  -> IMU FIFO
  -> estimator task (Px4Lite_AttitudeUpdate)
  -> Navigation Topic (roll/pitch/yaw_deg100)
  -> Display / Debug / MAVLink / Business
```

## 2. 硬件与总线

| 项目 | 配置 |
|---|---|
| 传感器 | MPU6050 |
| 总线 | I2C1 |
| 引脚 | PB6/SCL，PB7/SDA（见 [bsp_config.h](../../../Bsp/Inc/bsp_config.h)） |
| I2C 速率 | 100 kHz |
| I2C 地址 | 自动探测 `0x68`（主）或 `0x69`（备），单次探测失败重试 3 轮，轮间延时 5 ms |
| 加速度量程 | ±8g（`AFS_SEL=2`，4096 LSB/g）。机体允许 ±45° 姿态目标并支持自动起降，±2g 在正常机动下即削顶 |
| 陀螺仪量程 | ±1000 dps（`FS_SEL=2`，32.8 LSB/dps） |
| DLPF / 采样分频 | `MPU6050_DLPF_CFG=0x03`，`MPU6050_SAMPLE_RATE_DIV=0x09` |
| 采集周期 | 10 ms（`sensor` 任务节拍，与 `PX4LITE_IMU_WORK_PERIOD_MS` 一致） |
| 所属任务 | `sensor` |

MPU6050 与 BME280 共用 I2C1，总线读写、超时与恢复统一由 `BSP_I2C` 处理，Sensor 层不直接操作寄存器以外的总线状态。

## 3. 软件分层与依赖

| 层 | 文件 | 职责 |
|---|---|---|
| BSP | `Bsp/Src/bsp_i2c.c` | I2C 初始化、`MemRead`/`MemWrite`/`IsDeviceReady`、超时、总线恢复 |
| Sensor | `Sensor/Src/sensor_mpu6050.c` | 地址探测、WHO_AM_I 校验、寄存器配置、14 字节连续采样、零帧/越界剔除、单位换算、私有快照与错误计数 |
| Platform Adapter | `Framework/Src/px4lite_platform_f407.c`（`Px4Lite_ImuInit/ImuRead/ImuRequestReinit`） | 驱动快照 → Framework IMU 测量；g/dps/℃ 换算为 mg/mdps/cdeg；调用轴向映射；`rx_sequence` 去重；启动稳定计数过滤 |
| 轴向映射 | `Framework/Inc/px4lite_imu_axis_map.h`（`Px4Lite_MapImuAxes`） | 驱动轴向 → 机体系轴向的符号翻转，只做符号翻转，不做量纲转换 |
| Framework | `px4lite_modules.c` / `px4lite_topics.*` | IMU 模块注册、周期采集、推入 FIFO、状态维护（ONLINE/DEGRADED）、Health 超时判 OFFLINE |
| Estimator | `px4lite_attitude.c`（`Px4Lite_AttitudeUpdate`） | 姿态解算，输出 `roll/pitch/yaw_deg100` 与角速度 |
| Business | `Business/Inc/app_data_api.h`（`App_CopyNavigation`） | 对业务/显示/Debug 提供只读姿态快照 |

依赖单向：`Sensor → BSP`；`Framework(Platform Adapter) → Sensor`；`Estimator/Business` 只经 Framework Topic / `app_data_api.h`，不下探 Sensor 层。

## 4. 数据结构与契约

Sensor 层输出 `Mpu6050_Snapshot_t`（[sensor_mpu6050.h](../../../Sensor/Inc/sensor_mpu6050.h)）：

| 字段 | 单位 | 说明 |
|---|---|---|
| `accel_g[3]` | g | X/Y/Z 加速度（芯片原始轴向） |
| `gyro_dps[3]` | deg/s | X/Y/Z 角速度（芯片原始轴向） |
| `temperature_c` | 摄氏度 | 芯片温度 |
| `sample_time_ms` | ms | 采样完成时间（真实毫秒） |
| `rx_sequence` | 次 | 成功采样递增序号，用于读侧去重 |
| `error_count` | 次 | I2C/ID/零帧/越界等错误累计计数 |

`Mpu6050_Status_t` 为轻量状态查询，不访问 I2C 总线：`last_result`、`last_stage`、`reinit_count`、`last_chip_id`、`i2c_addr_7bit`、`last_bsp_status`，以及与 `Mpu6050_Snapshot_t` 同名的 `rx_sequence`、`sample_time_ms`、`error_count`（供只查状态不复制整个快照的场景使用）。

Platform Adapter 转换为 Framework `Px4Lite_SensorImu_t`：

| Framework 字段 | 单位 | 说明 |
|---|---|---|
| `accel_mg[3]` | mg | 已做轴向映射 |
| `gyro_mdps[3]` | mdps | 已做轴向映射 |
| `temperature_cdeg` | 0.01 摄氏度 | |
| `sample_period_us` | us | 固定为 `PX4LITE_IMU_WORK_PERIOD_MS * 1000` |

**数据契约**：Platform Adapter 用 `rx_sequence` 去重（`rx_sequence==0` 或未变时返回 `PX4LITE_IDLE`，不产出新测量）；驱动 reinit 后前 `PX4LITE_IMU_STABLE_VALID_MIN`（3）个样本仅计数、不对外产出，避免刚复位的瞬态数据进入姿态解算；Estimator 侧用 `Px4Lite_IsFresh` 判 `PX4LITE_IMU_MAX_AGE_MS`（200 ms）过滤陈旧样本。

## 5. 采样 / 处理流程

初始化（`Sensor_MPU6050_Init`）：

1. 探测 `0x68`，失败探测 `0x69`；两者都失败重试，最多 3 轮，轮间延时 5 ms。
2. 读取 `WHO_AM_I`，确认芯片 ID 为 `0x68`。
3. 写 `PWR_MGMT_1=0x00` 唤醒芯片。
4. 依次配置采样分频（`SMPLRT_DIV`）、DLPF（`CONFIG`）、陀螺仪量程（`GYRO_CONFIG`）、加速度量程（`ACCEL_CONFIG`），任一失败即返回 IO 错误。
5. 延时 10 ms 等待芯片稳定。

采样（`Sensor_MPU6050_Service`，`sensor` 任务周期调用）：

1. 若存在重初始化请求且退避时间未到，直接返回 `NO_DATA`；到期则执行 `Init`。
2. 从 `ACCEL_XOUT_H`（0x3B）起连续读取 14 字节（accel×3 + temperature + gyro×3，均为大端 16 位有符号数）。
3. 拒绝全零帧（`Mpu6050_IsAllZeroFrame`）。
4. 拒绝越界帧（原始 ADC 值绝对值 > 29500 视为异常，`Mpu6050_IsOutOfRange`）。
5. 换算为 g（÷16384）、dps（÷131）、摄氏度（÷340 + 36.53）。
6. 一次性写入快照，`rx_sequence++`（回绕时跳过 0），`sample_time_ms=now_ms`；成功后清零的是内部重试计数器，公开的 `error_count` 是累计值，不会被清零。

> 增量尖峰过滤（`MPU6050_DELTA_SPIKE_FILTER_ENABLE`）代码保留但当前宏值为 `0`，处于关闭状态，不在生产路径生效。

Platform Adapter 与 Estimator：

1. `Px4Lite_ImuRead` 调用 `Service` + `CopySnapshot`，按 `rx_sequence` 去重。
2. 换算为 mg/mdps/cdeg 后调用 `Px4Lite_MapImuAxes` 做轴向符号翻转。
3. `estimator` 任务每周期（20 ms）从 IMU FIFO 弹出最多 8 个样本，逐个调用 `Px4Lite_AttitudeUpdate` 更新姿态，仅对 `IsFresh` 且有效的样本参与解算。

## 8. 异常与恢复

- 驱动只上报硬件事实与错误计数（`error_count`/`last_stage`/`last_result`），不在驱动内判定 OFFLINE；OFFLINE/FAILED 统一由 Health 判定（`PX4LITE_IMU_OFFLINE_MS`=2000 ms 无新帧，且过了 `PX4LITE_IMU_STARTUP_GRACE_MS`=2000 ms 启动宽限）。
- 采样阶段异常处理：I2C 读失败、全零帧、越界帧均计入 `error_count` 并记录 `last_stage`，不产出快照。
- 连续数据读失败达到 `MPU6050_REINIT_FAIL_LIMIT`（5 次）后，驱动自身置位 `s_reinit_request` 并进入 100 ms 快速重试；初始化连续失败超过 `MPU6050_INIT_FAST_RETRY_LIMIT`（5 次）后退避到 500 ms 慢速重试。
- 热插拔恢复（注册表驱动）：`Px4Lite_ImuRecover` 只调用 `Sensor_MPU6050_RequestReinit()` 置位标志，真正的重新初始化在 `Service` 顶部执行，不在 Health 任务中做阻塞 I2C 操作。
- 重初始化后前 3 个有效样本仅用于稳定计数，不对外产出测量，避免瞬态数据污染姿态解算。

## 10. 验收要点

对标注 **【需运行确认】** 的项，按下表操作步骤验收，验收结果填入"实际结果"列。

**关键测试用例**：

| 用例 | 操作步骤 | 预期结果 | 实际结果 |
|---|---|---|---|
| I2C 读失败注入 | 运行中断开/短接 I2C1（PB6/PB7）制造总线错误 | `error_count++`，`last_stage` 记录出错阶段，不产出新快照，不影响同总线的 BME280 | |
| 全零帧/越界帧剔除 | 观察上电瞬间或总线抖动时的采样数据 | 全零帧与越界帧（原始 ADC 绝对值 > 29500）被剔除，不写入快照，`error_count++`，`rx_sequence` 不前进 | |
| 连续失败触发重初始化 | 持续制造 I2C 读失败直到达到 `MPU6050_REINIT_FAIL_LIMIT`（5 次） | 驱动自身置位 `s_reinit_request`，进入 100 ms 快速重试，`reinit_count`（经 `GetStatus`）递增 | |

- [ ] 采样周期 10 ms，未新增 MPU6050 独立任务，挂在 `sensor` 任务。
- [ ] IMU 数据必须经 FIFO 进入 Estimator，`estimator` 任务单次最多弹出 8 个样本。
- [ ] I2C 异常（读失败/坏 ID/超时）不会永久阻塞总线，驱动具备自身重试退避 + 注册表热插拔恢复双重路径。

- [ ] **【需构建确认】** Keil ARMCC5 `0 Error / 0 Warning`。
- [ ] **【需运行确认】** IMU FIFO 峰值/溢出计数、最小剩余栈水位符合 [15_模块接入标准与评审清单.md](../../15_模块接入标准与评审清单.md) 要求。

## 11. 开发踩坑与教学案例

> 本节沉淀 MPU6050 接入过程中真实遇到的软硬件问题，作为教材/实验案例素材。每条按
> **现象 → 定位 → 根因 → 解法 → 教学点/学生易错** 组织。

**问题 1：yaw（航向）长期缓慢漂移，转一圈回不到原值**（类别：传感器特性 / 软件）

- **现象**：静止放置时 roll/pitch 稳定，但 yaw 缓慢往一个方向漂；水平转 360° 再转回来，yaw 读数对不上原值。
- **定位**：对比三个角——roll/pitch 不漂而 yaw 漂，说明问题不在解算 bug，而在数据源本身缺一个绝对参考。
- **根因**：MPU6050 是 6 轴（3 轴加速度 + 3 轴陀螺），**没有磁力计**。roll/pitch 有重力向量做绝对参考可以收敛，yaw 只能靠陀螺积分，积分误差必然随时间累积漂移，没有任何绝对航向参考去纠正。
- **解法**：文档与接口明确把 `yaw_deg100` 标注为**相对航向**，不承诺长期绝对精度（见 §1）；需要绝对航向时接磁力计或外部航向源（9 轴方案）。
- **教学点 / 学生易错**：以为"有陀螺就能测航向"。要讲 6 轴 vs 9 轴 IMU 的区别、陀螺积分漂移、以及为什么互补/卡尔曼滤波能压住 roll/pitch（有重力参考）却压不住 yaw（无参考）。

**问题 2：热插拔恢复或上电后，姿态短暂乱跳**（类别：软件 / 传感器时序）

- **现象**：传感器断开再接上（或刚上电）后的头几帧，姿态数值明显抖动、跳变，随后自行稳定。
- **定位**：打印 reinit 后的原始样本，发现刚复位后的前几个样本数值不稳。
- **根因**：芯片刚唤醒/复位，内部滤波器与量程尚未进入稳态，前几个样本是瞬态、不可信。
- **解法**：`PX4LITE_IMU_STABLE_VALID_MIN`（3）——reinit 后前 3 个有效样本**只计数、不对外产出**，等稳定了再进入姿态解算（见 §4 数据契约、§8 异常与恢复）。
- **教学点 / 学生易错**：忽略传感器上电/复位的稳定时间，把启动瞬态数据直接喂给算法。任何传感器复位后都应丢弃开头若干样本。

**问题 3：MPU6050 与 BME280 共用 I2C1，偶发初始化失败 / `WHO_AM_I` 读错**（类别：硬件 / 软硬结合）

- **现象**：单独接 MPU6050 正常；和 BME280 一起挂在 I2C1 上时，偶尔某个器件初始化失败或 `WHO_AM_I` 读回异常值。
- **定位**：示波器看 SCL/SDA 上升沿是否塌软（上拉是否够带两个器件的总线电容）；确认 MPU6050 的 AD0 引脚电平决定地址是 `0x68` 还是 `0x69`，与 BME280 地址不冲突。
- **根因**：多器件共用一条开漏 I2C 总线，上拉负载加重、上升沿变慢；地址由 AD0 决定，接线不清会读错器件。
- **解法**：地址自动探测（`0x68` 主 → `0x69` 备，失败重试 3 轮、轮间 5 ms，见 §2）；总线读写、超时与恢复统一交给 `BSP_I2C`，Sensor 层不各自操作总线。
- **教学点 / 学生易错**：I2C 是开漏、多器件共总线时上拉要按总线电容重算；地址靠 AD0 分配；总线所有权要收敛到一层（BSP），不要每个驱动各管一段。

**问题 4：上电瞬间或总线抖动时，采样出现全零帧或爆表值**（类别：硬件表现 → 软件防御）

- **现象**：上电初期或总线受扰时，偶见 accel/gyro 某几轴读回全 0，或原始 ADC 值接近满量程的离谱大数。
- **定位**：打印 14 字节原始寄存器块，发现整帧为 0，或原始 ADC 绝对值 > 29500（接近 ±32768 满量程）。
- **根因**：芯片尚未就绪、或总线抖动导致一次无效读，寄存器返回 0 或垃圾值。
- **解法**：`Mpu6050_IsAllZeroFrame` 剔除全零帧、`Mpu6050_IsOutOfRange`（`|raw| > 29500`）剔除越界帧，二者都不写快照、`error_count++`、`rx_sequence` 不前进（见 §5）。
- **教学点 / 学生易错**：把传感器原始读数当成一定有效。任何原始数据都要做合理性校验（全零、越界、突变），不合理就丢，别让脏数据进入后级算法。
