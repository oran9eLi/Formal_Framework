# BME280 模块技术文档

## 1. 模块定位

BME280 模块用于采集环境温度、气压和相对湿度，是 NW3 工程中的低频环境传感器模块。模块接入统一的 `sensor` 任务，不单独创建 FreeRTOS 任务。

正式数据链路如下：

```text
BSP_I2C
  -> Sensor_BME280
  -> px4lite_platform_f407.c
  -> Baro Topic
  -> Health / Storage / Business
```

## 2. 硬件与总线

| 项目 | 配置 |
|---|---|
| 传感器 | BME280 |
| 总线 | I2C1 |
| 引脚 | PB6/SCL，PB7/SDA |
| I2C 地址 | 自动探测 0x76 或 0x77 |
| 采集周期 | 1000 ms |
| 所属任务 | `sensor` |

BME280 与 MPU6050 共用 I2C1，因此 BSP 层只负责 I2C 读写和总线恢复，不能在 BSP 内解析传感器数据。

## 3. 软件分层

| 层 | 文件 | 职责 |
|---|---|---|
| BSP | `Bsp/Src/bsp_i2c.c` | I2C 初始化、寄存器读写、超时映射、总线恢复 |
| Sensor | `Sensor/Src/sensor_bme280.c` | 芯片 ID 检查、校准参数读取、强制测量、补偿计算 |
| Platform Adapter | `Framework/Src/px4lite_platform_f407.c` | 将 Sensor 快照转换为 Framework Baro 类型 |
| Framework | `px4lite_topics.*` / `px4lite_modules.c` | 发布 Baro Topic，维护模块状态 |
| Business | `app_data_api.*` | 对业务层提供只读环境快照 |

## 4. 数据结构

Sensor 层输出 `Bme280_Snapshot_t`：

| 字段 | 单位 | 说明 |
|---|---|---|
| `temperature_c` | 摄氏度 | 温度补偿值 |
| `pressure_pa` | Pa | 气压补偿值 |
| `relative_humidity_pct` | % | 相对湿度 |
| `sample_time_ms` | ms | 采样时间 |
| `rx_sequence` | 次 | 成功采样递增序号 |
| `error_count` | 次 | I2C、ID、超时等错误计数 |

Framework 发布 `Px4Lite_SensorBaro_t`，继续保留温度、气压和湿度字段，并通过统一 topic 给 Estimator、Storage、Business 使用。

## 5. 采样流程

1. 初始化时探测 `0x76` 和 `0x77`。
2. 读取 `WHO_AM_I`，确认芯片 ID 为 `0x60`。
3. 软复位后等待校准参数更新完成。
4. 读取温度、气压、湿度校准参数。
5. 每次 Service 使用 forced mode 触发一次测量。
6. 等待 measuring 位清除。
7. 读取 8 字节原始数据并进行补偿计算。
8. 缓存快照，由 Platform Adapter 复制并发布。

## 6. 异常与恢复

模块不在驱动内直接判定 OFFLINE。驱动只记录硬件事实和错误计数，OFFLINE/FAILED 由 Health 统一管理。

当前异常处理：

- I2C 读写失败返回 `BME280_RESULT_IO_ERROR`。
- 芯片 ID 不匹配返回 `BME280_RESULT_BAD_ID`。
- 状态位等待超时返回 `BME280_RESULT_TIMEOUT`。
- 连续读失败达到阈值后清除初始化状态，下一次 Service 重新初始化。
- 初始化失败后使用 1000 ms 退避，避免缺失设备时每个周期阻塞 I2C。

## 7. 验收要点

- BME280 数据由 `sensor` 任务周期采集，不新增独立任务。
- 业务层只能通过 `App_CopyEnvironment()` 读取环境数据。
- BME280 缺失或 I2C 异常不能拖死 Display、Storage 或其他传感器。
- Debug/Storage 读取的是 Framework 快照，不直接访问 BME280 私有变量。
- Keil Rebuild All 最终要求 `0 Error / 0 Warning`。
