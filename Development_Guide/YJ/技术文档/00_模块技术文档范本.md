## 两种样板，一份范本

CNS 平台里的模块协议形态大致分两类，本范本用两个真实模块分别举例，正文每一节都给出两个样板的写法：

| | **样板 A：流式接收 / 寄存器块读类** | **样板 B：命令/应答 + 主动上报类** |
|---|---|---|
| 数据方向 | 单向：模块 → 主控（只收） | 双向：主控发命令，模块也主动推送 |
| 典型总线 | UART 连续文本流（GNSS/NMEA）、I2C/SPI 寄存器块读（BME280/MPU6050） | UART 私有帧协议，帧头/帧 ID 区分命令与上报 |
| 是否需要初始化时序 | 不需要，上电即收；或简单探测地址+校验芯片 ID | 需要：初始化必须发命令查询关键寄存器（量程/算法等） |
| 本范本举例 | **BME280**（I2C 寄存器块读、强制测量模式） | **ATK-MS901M**（UART 私有帧协议、十轴姿态传感器） |
| 参考资料 | 芯片厂商 datasheet（Bosch BME280 Datasheet） | 《ATK-MS901M模块用户手册_V1.0.pdf》§2.3（正点原子权威协议参考） |

> **怎么判断自己的模块属于哪种样板**：看总线交互方式——如果主控只是"发一条读命令、马上拿到应答"这种
> 同步寄存器读写（I2C/SPI 天然如此，UART 也可能这么用），且模块不会未经请求主动推数据，就是样板 A；
> 如果协议里有"模块不问自取地周期性推送数据帧"这个动作、且主控还能发独立的配置命令帧，就是样板 B。
> 两者混合的模块（既有周期性推送又有配置命令，比如 ATK-MS901M）按样板 B 写。
>

## 1. 模块定位

> 一段话说清：这个模块在 CNS 平台里"模拟无人机的什么功能"、采什么数据/发什么指令、挂在哪个周期任务、
> 是否单独建 FreeRTOS 任务。**原则：一个硬件资源只有一个任务所有者，普通传感器统一挂 `sensor` 任务，
> 不要一外设一任务。** 如果模块自己带 MCU 做了传感器融合（样板 B 常见），必须在这里点明本工程只是
> "透传模块算好的结果"，不重新实现融合算法，避免后续维护者误以为融合逻辑在本工程某处。

**样板 A 示例（BME280）**：BME280 用于采集环境温度、气压、相对湿度，是 CNS 平台"电源/环境"能力的
低频传感器载体。模块本身不做任何解算，寄存器里存的是未补偿的 ADC 原始值，补偿计算（把 ADC 值换算成
工程单位）由本工程的 Sensor Driver 完成，不在模块内部。模块接入统一的 `sensor` 采集任务。

正式数据链路：

```text
BME280 (I2C1)
  -> BSP_I2C           (寄存器读写、总线恢复)
  -> Sensor_BME280     (芯片 ID 校验、强制测量触发、补偿计算)
  -> px4lite_platform_f407.c   (驱动快照 -> 框架 Baro 测量, sequence 去重)
  -> Baro Topic                (Latest Snapshot 发布)
  -> Health / Storage / Business / Display
```

**样板 B 示例（ATK-MS901M）**：ATK-MS901M 是十轴姿态传感器模块（陀螺仪+加速度计+磁力计+气压计+
32 位 MCU），**模块内部已完成传感器融合**，直接通过 UART 输出解算好的姿态角。这一点和样板 A 的
BME280 刚好相反——BME280 只出原始 ADC 值靠本工程补偿；ATK-MS901M 出的已经是最终工程量，本工程
**不需要**再实现姿态融合算法，只需要透传。模块接入统一的 `sensor` 采集任务。

正式数据链路：

```text
ATK-MS901M (UART，默认 115200bps)
  -> BSP_AHRS10       (UART + 循环 DMA 接收)
  -> Sensor_AHRS10    (帧头/帧ID/长度/校验和组帧，按帧 ID 分派)
  -> px4lite_platform_f407.c   (驱动快照 -> 框架 IMU 测量, sequence 去重)
  -> IMU Topic                 (FIFO 发布，姿态角字段随附)
  -> Estimator（直通模块融合角度，不重新做互补滤波）
  -> Health / Storage / Business / Display
```

## 3. 软件分层与依赖

> 逐层一行，说明每层的文件和职责。依赖必须单向：`Business → Framework → (platform adapter) → BSP`；
> `Sensor → BSP`。HAL 只允许出现在 BSP 层；Sensor 层禁止 include `stm32f4xx_hal.h`、禁止调 `HAL_*`、
> 禁止调 `HAL_GetTick()`。**两个样板的分层结构完全一样**，唯一区别是样板 B 的 BSP 层要多一个阻塞发送
> 函数（供命令帧使用），Sensor 层要多一段"初始化时发命令查寄存器"的逻辑。

| 层 | 样板 A（BME280） | 样板 B（ATK-MS901M） |
|---|---|---|
| BSP | `Bsp/Src/bsp_i2c.c`：I2C 初始化、寄存器读写、超时映射、总线恢复 | `Bsp/Src/bsp_ahrs10.c`：UART 初始化、循环 DMA 接收、总线恢复，**外加阻塞发送函数**（命令帧用） |
| Sensor | `Sensor/Src/sensor_bme280.c`：芯片 ID 校验、强制测量触发、补偿计算 | `Sensor/Src/sensor_ahrs10.c`：帧解析、**初始化时发命令查询关键寄存器**、按帧 ID 分派 |
| Platform Adapter | `Framework/Src/px4lite_platform_f407.c`：驱动快照 → 框架 Baro 测量 | 同左，驱动快照 → 框架 IMU 测量（含融合角度字段） |
| Framework | `px4lite_topics.*` / `px4lite_modules.c`：发布 Topic，升 ONLINE/DEGRADED，Health 判 OFFLINE | 同左 |
| Business | `app_data_api.*`：对业务/显示提供只读快照 | 同左 |

**样板 B 特有的分层约束**：命令帧的"发送 + 等应答"逻辑只允许在 `Sensor_XXX_Init()` 里同步阻塞调用；

## 4. 协议 / 数据格式（本节是复现本模块的核心，必须给真实可编译代码）

### 4.1 样板 A 示例：BME280 寄存器块读协议

BME280 是标准 I2C 从设备，没有帧头/校验和这类协议包装，交互就是"写寄存器地址 → 读连续字节"。

**关键寄存器地址**（摘自驱动源码 `Sensor/Src/sensor_bme280.c`）：

```c
#define BME280_REG_CALIB_TP   0x88U  /* 温度/气压补偿参数，连续 26 字节 */
#define BME280_REG_CALIB_H1   0xA1U  /* 湿度补偿参数第 1 项，1 字节 */
#define BME280_REG_ID         0xD0U  /* 芯片 ID，期望值 0x60 */
#define BME280_REG_RESET      0xE0U  /* 写 0xB6 触发软复位 */
#define BME280_REG_CALIB_H2   0xE1U  /* 湿度补偿参数第 2~6 项，连续 7 字节 */
#define BME280_REG_CTRL_HUM   0xF2U  /* 湿度过采样配置 */
#define BME280_REG_STATUS     0xF3U  /* bit0=校准参数更新中，bit3=测量中 */
#define BME280_REG_CTRL_MEAS  0xF4U  /* 温度/气压过采样 + 工作模式（强制/正常/休眠） */
#define BME280_REG_CONFIG     0xF5U  /* standby 时间、IIR 滤波系数 */
#define BME280_REG_DATA       0xF7U  /* 测量结果起始地址，连续 8 字节（气压3+温度3+湿度2） */
```

**强制测量触发**（BME280 没有"自动连续采样"这回事，每次要读数据必须先写 `CTRL_MEAS` 触发一次强制
测量，等测量完成再读数据）：

```c
#define BME280_OSRS_X1             0x01U
#define BME280_MODE_FORCED         0x01U
#define BME280_CTRL_MEAS_FORCED_X1 ((BME280_OSRS_X1 << 5) | (BME280_OSRS_X1 << 2) | BME280_MODE_FORCED)

static Bme280_Result_t Bme280_ConfigureForcedMode(void)
{
  /* 顺序不能反：先配湿度过采样，再配 IIR/standby，最后写 CTRL_MEAS 才会真正触发本次测量 */
  Bme280_WriteReg(BME280_REG_CTRL_HUM, BME280_OSRS_X1);
  Bme280_WriteReg(BME280_REG_CONFIG, 0x00U);
  Bme280_WriteReg(BME280_REG_CTRL_MEAS, BME280_CTRL_MEAS_FORCED_X1);
  return BME280_RESULT_OK;
}
```

**等待测量完成 + 读数据**：

```c
static Bme280_Result_t Bme280_WaitStatusClear(uint8_t mask)
{
  uint8_t i;
  for (i = 0U; i < BME280_MAX_WAIT_POLLS; ++i) {
    uint8_t status = 0U;
    Bme280_ReadReg(BME280_REG_STATUS, &status, 1U);
    if ((status & mask) == 0U) { return BME280_RESULT_OK; }  /* bit3 清零表示测量完成 */
    BSP_Time_DelayMs(1U);
  }
  return BME280_RESULT_TIMEOUT;
}

/* 触发测量后：8 字节数据 = 气压(20bit) + 温度(20bit) + 湿度(16bit)，大端拼接、右对齐 */
uint8_t data[8];
Bme280_ReadReg(BME280_REG_DATA, data, sizeof(data));
int32_t adc_P = (int32_t)(((uint32_t)data[0] << 12) | ((uint32_t)data[1] << 4) | ((uint32_t)data[2] >> 4));
int32_t adc_T = (int32_t)(((uint32_t)data[3] << 12) | ((uint32_t)data[4] << 4) | ((uint32_t)data[5] >> 4));
int32_t adc_H = (int32_t)(((uint32_t)data[6] << 8) | data[7]);
```

**补偿计算**：ADC 原始值必须用芯片各自的补偿参数（`dig_T1~T3`/`dig_P1~P9`/`dig_H1~H6`，出厂烧录在
`CALIB_TP`/`CALIB_H1`/`CALIB_H2` 这几个寄存器里，每颗芯片都不同）代入 Bosch 官方补偿公式才能得到
真实温度/气压/湿度，公式本身较长（定点数运算，避免浮点开销），完整实现见
`Sensor/Src/sensor_bme280.c` 里的 `Bme280_CompensateTemperature`/`Bme280_CompensatePressurePa`/
`Bme280_CompensateHumidity` 三个函数，直接照抄 Bosch datasheet 附录的参考实现，不要自己重新推导。

### 4.2 样板 B 示例：ATK-MS901M 私有帧协议

ATK-MS901M 走 UART，协议自己定义了帧格式，比 I2C 复杂：有"模块主动上报"和"主控发命令/模块应答"
两类帧，靠帧头第 2 个字节区分方向。协议细节摘自《ATK-MS901M模块用户手册_V1.0.pdf》§2.3。

**两类帧头**：

| 帧头 1 | 帧头 2 | 含义 |
|---|---|---|
| `0x55` | `0x55` | 模块主动上报帧 |
| `0x55` | `0xAF` | 上位机命令帧 / 模块对命令的应答帧 |

两类帧共用同一个格式：`帧头(2) + 帧ID(1) + 数据长度(1) + 数据(N) + 校验和(1)`。命令帧的帧 ID 读操作
时要把 `bit7` 置 1（`ID | 0x80`），写操作/应答帧不带这一位。**校验和**是帧内除校验和本身外所有字节
相加，`uint8_t` 存储（自然溢出取模 256），不是 CRC。

**主动上报帧的帧 ID 和数据格式**（本工程用到的几种）：

| 帧 ID | 名称 | 数据长度 N | 换算公式 |
|---|---|---|---|
| `0x01` | 姿态角 | 6 | `Roll = int16(RollH<<8\|RollL) / 32768 * 180`（Pitch/Yaw 同理，单位 °） |
| `0x03` | 陀螺仪+加速度计 | 12 | `ACCx = int16 / 32768 * ACC_FSR`（单位 G）；`GYROx = int16 / 32768 * GYRO_FSR`（单位 °/s）——`ACC_FSR`/`GYRO_FSR` 是初始化时查寄存器得到的，不是常量！ |
| `0x04` | 磁力计 | 8 | 原始计数，手册未给标定系数，直接透传 |

**初始化必须先查询量程寄存器**（不能假设默认值，因为这些参数可被上位机改写并持久化到 Flash）：

```c
/* 发一帧读寄存器命令，阻塞等待匹配的应答帧 */
static uint8_t Ahrs10_ReadRegBlocking(uint8_t reg_id, uint8_t *out_value, uint32_t timeout_ms)
{
  uint8_t cmd[6];
  cmd[0] = 0x55; cmd[1] = 0xAF;      /* 命令/应答方向帧头 */
  cmd[2] = reg_id | 0x80;            /* 读操作：帧 ID 的 bit7 置 1 */
  cmd[3] = 1; cmd[4] = 0;            /* 数据长度=1，占位数据 */
  cmd[5] = cmd[0]+cmd[1]+cmd[2]+cmd[3]+cmd[4]; /* 校验和 */
  BSP_AHRS10_Send(cmd, 6, timeout_ms);
  /* 阻塞轮询接收，喂进解析状态机，匹配到帧头 0x55 0xAF 且帧 ID==reg_id 的应答帧即成功 */
}

Ahrs10_Result_t Sensor_AHRS10_Init(void)
{
  uint8_t value;
  BSP_AHRS10_Init();
  Ahrs10_ReadRegBlocking(0x03 /* GYROFSR */, &value, 200);  s_gyro_fsr_index = value;
  Ahrs10_ReadRegBlocking(0x04 /* ACCFSR */,  &value, 200);  s_acc_fsr_index  = value;
  Ahrs10_ReadRegBlocking(0x0B /* ALG，0=六轴/1=九轴 */, &value, 200); s_yaw_absolute = value;
  return AHRS10_RESULT_OK;
}
```

**运行阶段解析状态机骨架**（区分帧方向是第一步）：

```c
switch (parse_state) {
  case WAIT_H1:  if (byte == 0x55) { state = WAIT_H2; }                         break;
  case WAIT_H2:
    if (byte == 0x55)      { is_upload = 1; state = READ_ID; }  /* 上报帧 */
    else if (byte == 0xAF) { is_upload = 0; state = READ_ID; }  /* 命令/应答帧 */
    else                   { state = WAIT_H1; }
    break;
  case READ_ID:  frame_id = byte & ~0x80; state = READ_LEN;                     break;
  case READ_LEN: frame_len = byte; pos = 0; state = (frame_len==0)?READ_CHECKSUM:READ_DATA; break;
  case READ_DATA:
    data[pos++] = byte;
    if (pos >= frame_len) { state = READ_CHECKSUM; }
    break;
  case READ_CHECKSUM:
    /* 校验通过后：is_upload==1 按 frame_id 分派到姿态角/陀螺加速度/磁力计解析分支；
       is_upload==0 是命令应答帧，只在初始化查询流程里被 Ahrs10_ReadRegBlocking() 消费。 */
    state = WAIT_H1;
    break;
}
```

> 完整可编译实现（含循环 DMA 环形缓冲对接、`Ahrs10_Snapshot_t`/`Ahrs10_Status_t` 完整字段、Framework
> 各层接线代码）见 [ahrs10-usart5 执行计划 Task 1-6](../../../docs/superpowers/plans/2026-07-09-ahrs10-usart5.md)，可以直接照抄。本节只保留最核心的协议骨架，方便脱离本工程语境单独理解协议本身。

## 5. 采样 / 处理流程

> 按步骤写清一次完整的采集-解析-发布过程。**样板 A 和样板 B 的流程形状不同**，样板 A 是"触发测量 →
> 等完成 → 一次性块读 → 换算 → 发布"（无命令/应答区分）；样板 B 多一条"初始化查寄存器"支路，运行阶段
> 是"持续解析上报帧"而不是主动触发。

**样板 A 流程（BME280）**：

1. `sensor` 任务周期调用 `Sensor_BME280_Service(now_ms)`。
2. 若未初始化：探测 I2C 地址（`0x76`/`0x77`）→ 校验芯片 ID（期望 `0x60`）→ 软复位 → 等校准参数更新
   完成 → 读校准参数 → 配置强制测量模式。任一步失败，本次 Service 返回错误，退避后下次重试（见 §8）。
3. 若已初始化但本次还未触发测量：调用 `Bme280_ConfigureForcedMode()` 触发一次强制测量，记录起始时间，
   本次 Service 直接返回"无数据"（不阻塞等待）。
4. 后续 Service 调用检查测量是否完成（读 `STATUS` 寄存器 bit3），未完成且未超时则继续返回"无数据"；
   超时则记一次失败。
5. 完成后一次性块读 8 字节数据，代入补偿公式换算成温度/气压/湿度，写入快照，`rx_sequence++`。
6. Platform Adapter 用 `last_rx_sequence` 去重后转成框架 Baro 测量并发布。

> 注意步骤 3-4 是"发起测量 → 下次调用再检查完成"这种跨多次 Service 调用的状态机，不是阻塞等待——这是
> 为了不在 `sensor` 任务里阻塞其他传感器采集（测量典型耗时几毫秒到十几毫秒，够长到不能原地等）。

**样板 B 流程（ATK-MS901M）**：

初始化阶段（只在 `Init()` 跑一次，允许阻塞）：发送命令帧查询 `GYROFSR`/`ACCFSR`/`ALG` 寄存器，任一
查询超时或校验失败则初始化判失败，不进入运行状态（不能假装成功后用默认量程硬算）。

运行阶段（`Service()` 周期调用，只解析不发命令）：

1. `sensor` 任务周期调用 `Sensor_AHRS10_Service(now_ms)`。
2. 从 DMA 环形缓冲取字节，喂进解析状态机（见 §4.2）。
3. 解析出上报帧后按帧 ID 分派：姿态角帧更新 `roll/pitch/yaw` 并递增 `rx_sequence`（姿态角帧是本驱动
   认定的"一次完整测量"心跳）；陀螺仪+加速度计帧、磁力计帧各自更新对应字段，不单独驱动序号前进。
4. 校验和不匹配的帧直接丢弃，`error_count++`，不刷新对应字段。
5. Platform Adapter 用 `last_rx_sequence` 去重后转成框架 IMU 测量并发布。

## 6. 接口清单

> 列出驱动目标接口（四件套）和业务读取接口。样板 B 因为有命令/应答交互，BSP 层要多一个阻塞发送函数。

驱动接口（四件套，两个样板通用）：

```c

Result_t Sensor_XXX_Service(uint32_t now_ms);    /* sensor 任务调用，不永久阻塞 */
Result_t Sensor_XXX_CopySnapshot(XXX_Snapshot_t*); /* 只复制已发布的完整数据 */
Result_t Sensor_XXX_GetStatus(XXX_Status_t*);    /* 不访问慢速总线 */
```

**样板 B 额外需要**（BSP 层）：

```c
BSP_Status_t BSP_XXX_Send(const uint8_t *data, uint16_t len, uint32_t timeout_ms);
/* 阻塞发送，仅供 Sensor 层初始化阶段发命令帧使用，绝不能在周期 Service() 里调用 */
```

业务读取（唯一入口 `app_data_api.h`）：

```c
App_CopyEnvironment(&env, now_ms);   /* 样板 A 示例：只读环境快照 */
App_CopyNavigation(&nav, now_ms);    /* 样板 B 示例：只读姿态/导航快照 */
```

> 通信类模块（对应设计书 §3.2.2 通信、§4.2.4 控制）补充发送接口，并注明：
> "`Send` 返回 OK = 已复制暂存一帧，不代表已空口发出；发送成功只在 TC 完成回调记。"

## 8. 异常与恢复

> 说明驱动只记录硬件事实（ONLINE/DEGRADED + 错误计数），OFFLINE/FAILED 一律由 Health 判定；以及
> 热插拔恢复钩子（廉价置位，重初始化在 Service 执行）。两个样板通用，样板 B 额外多一条"命令帧超时"。

- 驱动只上报硬件事实与错误计数，不在驱动内判 OFFLINE。
- 总线错误触发 `BSP_XXX_RequestRecoverRx`（或 I2C 场景的 `BSP_I2C_Recover`）：重启收发通道。
- 初始化失败使用退避重试（如 BME280 的 1000 ms 退避），避免设备缺失时每周期都去阻塞总线。
- **样板 B 额外**：初始化阶段命令帧超时/校验失败，`Init()` 直接判失败，不进入运行状态，不能"假装成功
  但用默认量程硬算"。
- Health 侧超时（`> OFFLINE_MS` 无新数据）判 OFFLINE，触发对应异常报警。
- 热插拔恢复：注册 `recover` 钩子（只置"请求重初始化"标志），重初始化在 `Service` 顶部执行；重试限速
  不封顶，拔出再插回可自动恢复。

## 9. 调试

- 独立 RAW 宏打印原始数据（寄存器值 / 帧字节），周期输出 ≤ 1 Hz，ISR 内不 `printf`。
- 调试开关关闭后不改采集/解析/状态机/发布逻辑。
- **软硬件两侧的排查手段**：软件侧——串口打印、看 `error_count`/`rx_sequence`/状态机；硬件侧——万用表
  量供电/共地、逻辑分析仪或示波器抓总线波形（I2C 的 SCL/SDA 上升沿与 ACK、UART 电平/波特率/帧字节）。
  **样板 B 的排查顺序建议**：先确认收到的字节流本身对不对（帧头是哪一类、长度字段和实际数据是否
  吻合），再看解析代码——顺序反了容易在解析代码里排查半天，其实是帧同步或波特率就不对；有厂商上位机
  软件的话（如 ATK-MS901M 的 "ATK_IMU"）直接拿来对照更快。

## 11. 开发踩坑与教学案例

> 记录开发、移植、联调中真实遇到的问题——尤其是**软硬件结合**的坑，每条按 **现象 → 定位 → 根因 →
> 解法 → 教学点/学生易错** 写；定位一定要写清用了什么手段。没踩到坑的模块也别留空，至少写清"最容易被
> 新手做错的一两点"。

**问题 1：I2C 传感器多设备共总线导致上升沿变慢、偶发通信失败**（类别：硬件；样板 A 常见）

- **现象**：单独接一个 I2C 设备正常，多个设备同挂一条总线后偶尔某个器件初始化失败或读回异常值。
- **定位**：示波器看 SCL/SDA，上升沿爬升慢、塌软；核对上拉电阻阻值是否够带多个器件的总线电容。
- **根因**：I2C 开漏总线，设备越多总线电容越大，上拉电阻不够会导致上升沿超时。
- **解法**：加合适上拉（典型 4.7 kΩ，多设备/长线再调小）；地址探测兼容多个候选地址。
- **教学点**：I2C 是开漏结构，必须外部上拉；总线波形是判断硬件问题的第一手证据。

**问题 2：把命令帧的"发送+阻塞等应答"逻辑误放进周期 Service() 里**（类别：软硬件结合；样板 B 特有）

- **现象**：`sensor` 任务周期性卡顿，其他传感器采集数据出现周期性延迟。
- **定位**：Debug 打印各传感器 Service 函数执行耗时，发现某次调用耗时远超其他周期，接近命令超时门限。
- **根因**：命令/应答接口天然带阻塞语义，只能在 `Init()` 或明确的一次性配置流程里调用。
- **教学点**：样板 B 和样板 A 根本区别在于前者有"发了要等回应"这个动作，这个动作绝不能混进任何周期
  任务的正常数据路径。

**问题 3：忽略"参数可被上位机改写并持久化"，直接假设出厂默认值硬算**（类别：软件；样板 B 特有）

- **现象**：换算出来的数值长期系统性偏大或偏小一个固定倍数，不报错、不容易被发现。
- **根因**：量程/算法这类参数很多协议允许现场配置并写入 Flash，出厂默认值不保证是当前实际值。
- **教学点**：协议手册写了"默认值"不代表"永远如此"，能现场查询就现场查询，不要硬编码。

**问题 4：偶发数据跳变，复现困难**（类别：软件；两个样板通用）

- **现象**：绝大多数时间正常，偶尔一帧数值明显不自洽。
- **定位**：打印整帧/整包字段，发现同一份数据里的字段来自不同次采样（数据撕裂）。
- **根因**：读侧在写侧更新快照的中途读取，读到"半写"数据；读写之间没有同步保护。
- **解法**：写侧填完整临时结构后**一次性发布**；读侧短临界区整体复制 + `sequence`/`IsFresh` 去重。
- **教学点**：并发下的数据一致性；不能用"时间戳变没变"代替序号判新；临界区要短，里面不解析/不打印。
