# NW3 项目开发指南

## 1. 适用范围

本文档适用于当前最新合并版本工程 NW3。用户前文提到的 NM3 未在桌面目录中发现，当前实际工程路径为：

```text
C:\Users\13377\Desktop\NW3
```

本文档按 NW3 的真实工程结构更新，用于后续新增模块、修改功能、调试问题和提交前自查。

## 2. 基本开发原则

NW3 的核心原则是：

```text
强类型数据
单向依赖
单硬件资源单 owner
周期任务固定调度
阻塞外设低优先级隔离
状态与恢复统一管理
```

必须遵守：

- 不允许业务层直接读取 BSP、Sensor 私有变量或 DMA 缓冲区。
- 不允许在 ISR 中做解析、打印、文件写入或页面渲染。
- 不允许传感器各自创建独立任务，普通传感器统一由 `sensor` 任务调度。
- 不允许在 Sensor Driver 里包含 HAL 头文件或调用 `HAL_*`。
- 不允许在 Sensor/Estimator/Business 任务中直接调用 FatFS。
- 不允许发送 C 结构体原始内存作为通信帧。
- 不允许在启动后随意 `malloc` 大对象，数据结构应静态分配。

## 3. 分层规范

NW3 单向依赖关系：

```text
Core -> Business -> Framework -> Platform Adapter -> Driver -> BSP -> HAL
```

各层职责：

| 层 | 可以做 | 禁止做 |
|---|---|---|
| Core | HAL 初始化、时钟、启动调度器、Hook | 业务逻辑、传感器解析 |
| Business | 通过 `app_data_api.h` 读取快照、处理业务事件 | include BSP/Sensor、读 DMA |
| Framework | Topic、状态、任务、Health、Recovery、MAVLink、Alarm | 直接包含 Business 头文件 |
| Platform Adapter | Sensor/BSP 数据转 Framework 类型 | 写业务逻辑 |
| Sensor Driver | 芯片寄存器、协议解析、物理量换算 | 调 HAL、决定 OFFLINE/FAILED |
| BSP | 引脚、时钟、外设收发、DMA | 解析数据、写业务状态 |
| Storage | SD/FatFS/CSV/队列 | 被高优先级任务直接调用 FatFS |
| Display | LCD、触摸、页面绘制 | 长时间阻塞业务主路径 |

`Framework/Src/px4lite_platform_f407.c` 是 Framework 和 BSP/Sensor 之间唯一正式适配点。

## 4. 关键配置文件

| 文件 | 作用 |
|---|---|
| `Bsp/Inc/bsp_config.h` | 引脚、总线、DMA、板级外设配置 |
| `Framework/Inc/px4lite_config.h` | 模块开关、周期、优先级、栈、超时、MAVLink 开关 |
| `Business/Inc/business_template_config.h` | 业务任务周期、栈、优先级、显示刷新预算 |
| `Debug/Inc/debug_config.h` | 独立调试开关和打印周期 |
| `Storage/Inc/storage_config.h` | SD CSV 文件名、队列、周期、超时、行长 |
| `Framework/Inc/px4lite_types.h` | 全工程强类型数据契约 |
| `Framework/Inc/px4lite_faults.h` | 故障码定义 |

修改功能时，应优先检查是否已有配置宏，避免把周期、阈值、文件名写死在业务逻辑中。

## 5. 任务规范

当前任务表：

| 任务 | 周期 | 优先级 | 栈 | 职责 |
|---|---:|---:|---:|---|
| `sensor` | 10 ms | idle+4 | 512W | 采集 GNSS、IMU、Baro、Battery |
| `estimator` | 20 ms | idle+3 | 512W | 导航和姿态估计 |
| `health` | 100 ms | idle+2 | 768W | 状态、超时、恢复、Health |
| `comm` | 10 ms | idle+2 | 384W | LoRa 服务、MAVLink 发送 |
| `biz_system` | 1000 ms | idle+2 | 384W | 系统业务轮询 |
| `biz_acq` | 200 ms | idle+2 | 512W | 数据快照分发 |
| `biz_display` | 10 ms | idle+1 | 768W | 显示刷新和触摸处理 |
| `debug` | 100 ms | idle+1 | 384W | 调试打印和栈监控 |
| `storage` | 50 ms | idle | 768W | SD CSV 写入 |

任务开发要求：

- 周期任务必须使用 `vTaskDelayUntil()`。
- 所有 `_ms` 字段必须使用真实毫秒时间，不得混用 RTOS tick。
- 高优先级任务不能调用可能长时间阻塞的外设操作。
- Storage 因为 FatFS 和 SD I/O 可能阻塞，必须保持最低优先级。
- 新增任务必须注册到 DebugTaskMonitor，并说明为什么不能复用现有任务。

## 6. 新传感器接入流程

新增传感器时按以下步骤执行：

1. 在 `Bsp` 增加总线或 GPIO 访问能力。
2. 在 `Sensor` 增加强类型驱动和快照结构。
3. 在 `px4lite_types.h` 增加 Framework 数据类型。
4. 在 `px4lite_topics.*` 增加 publish/copy 接口。
5. 在 `px4lite_platform_f407.c` 增加适配函数。
6. 在 `px4lite_config.h` 增加 enable、period、timeout 配置。
7. 在 `px4lite_modules.c` 或对应 WorkRun 中接入调度。
8. 在 Health 中纳入状态和超时判断。
9. 在 Debug 中增加独立开关和状态打印。
10. 增加 PC 单元测试或最小语法检查。

低频传感器使用 Latest Snapshot；高频数据使用 FIFO 或固定内存池。

## 7. 已有传感器规范

| 模块 | 周期 | 数据结构 | 说明 |
|---|---:|---|---|
| GNSS | 10 ms 服务 | `Px4Lite_SensorGnss_t` | USART2 DMA/IDLE，NMEA 解析 |
| MPU6050 | 10 ms | `Px4Lite_SensorImu_t` | I2C1，IMU FIFO，稳定样本门控 |
| BME280 | 1000 ms | `Px4Lite_SensorBaro_t` | I2C1，pressure 使用 Pa 存储 |
| Power ADC | 1000 ms | `Px4Lite_BatteryStatus_t` | ADC1 IN5，电压以 mV 存储 |
| LoRa E22 | 10 ms | `Px4Lite_CommDebugInfo_t` | comm 任务所有，MAVLink 发送通道 |

数据单位要求：

- `_mv` 为毫伏；
- `_pa` 为帕；
- `_deg100` 为角度乘 100；
- `_mdps` 为毫度每秒；
- `_mg` 为毫 g；
- `_ms` 为毫秒；
- `_us` 为微秒。

字段名必须体现单位，不允许只写 `value`、`data` 这类弱类型字段。

## 8. Storage 开发规范

Storage 当前已注册为 `PX4LITE_MODULE_STORAGE`，由 `storage` 任务驱动。

文件：

```text
SENSOR.CSV
ERROR.CSV
```

硬件：

```text
SPI3 PB3/PB4/PB5
PA15 CS
```

开发要求：

- 只有 Storage 任务允许调用 FatFS。
- 数据生产方只投递固定长度记录，不能等待 SD 完成写入。
- 队列满时丢弃并计数，不能阻塞采集任务。
- CSV 单行最大长度由 `STORAGE_CSV_LINE_MAX` 控制。
- SD 初始化、命令、读写、sync 必须有超时或有限重试。
- Storage 异常只能影响日志，不允许拖死 sensor、estimator、display。

## 9. Comm / MAVLink 开发规范

MAVLink 发送由 `comm` 任务统一拥有。

要求：

- 只能在 `px4lite_mavlink_tx.c` 中把 Topic 转为 MAVLink 消息。
- 发送必须字段级编码，不能直接发送结构体内存。
- `Lora_E22_Send()` 返回 OK 只表示数据已 staged，不代表空中发送完成。
- LoRa TX 完成以 DMA 发送完成回调为准。
- 新增 MAVLink 消息必须在 `px4lite_config.h` 增加 enable 和 period 配置。

## 10. Display 开发规范

Display 包含 SSD1963、GT911、页面和绘图模块。

要求：

- `biz_display` 周期为 10 ms。
- 显示刷新必须遵守 `BUSINESS_DISPLAY_REFRESH_BUDGET_US`，当前预算 2000 us。
- 触摸扫描优先于大面积刷新。
- 页面刷新应分步执行，避免一次函数长时间占用 CPU。
- Display 不应直接访问 Sensor/BSP 私有数据，应通过 Business 或 App API 获取状态。

## 11. Debug 开发规范

Debug 开关独立，禁止用一个总开关控制所有调试。

当前开关位于：

```text
Debug/Inc/debug_config.h
```

要求：

- 新模块调试必须增加独立 `DEBUG_xxx_MONITOR_ENABLE`。
- `DEBUG_PERIODIC_SERVICE_ENABLE` 和 `DEBUG_CONSOLE_ENABLE` 是派生宏，不要手工改。
- Debug 任务不能改变生产数据路径。
- 长时间测试不要打开原始 NMEA 连续打印。
- 打印中只读快照，不访问 FatFS 或慢速外设。

## 12. Health 与 Recovery 规范

Health 是 OFFLINE/FAILED 状态的统一管理者。

要求：

- Driver 只能报告硬件事实、错误计数和数据有效性。
- Health 根据 age、error_count、consecutive_errors 判断状态。
- recover 回调必须轻量，只设置 request flag。
- 实际重初始化由拥有该硬件资源的任务执行。
- 恢复逻辑必须有退避，不能高频反复初始化外设。

## 13. 时间与临界区规范

时间规范：

- Framework 使用 `Px4Lite_PlatformGetMs()`。
- BSP/Sensor 可使用 `BSP_Time_GetTickMs()`。
- `_ticks` 字段才允许保存 RTOS tick。
- 不要在 Sensor/Driver 代码中直接使用 `HAL_GetTick()`。

临界区规范：

- 临界区只做快照复制或标志更新。
- 不允许在临界区内解析、格式化字符串、打印、写 SD。
- 使用 `__disable_irq()` 时必须保存 `__get_PRIMASK()`，恢复时只在原来开中断的情况下 `__enable_irq()`。

## 14. 内存与栈规范

要求：

- 启动后不动态申请大对象。
- 大缓冲区放静态区，不放任务栈。
- DMA 缓冲区必须在 0x20000000 SRAM，不可放 CCM。
- heap 峰值使用率建议小于 75%。
- 每个新增任务必须通过 Debug 栈监控确认剩余栈。
- 单函数局部数组超过 128B 要审查；超过 256B 应改为静态或复用缓冲。

- 修改数据结构字段或单位；
- 修改调试输出字段；
- 修改恢复策略。

## 16. 提交前检查清单

每次修改前后至少检查：

1. 是否破坏单向依赖。
2. 是否让多个任务同时访问同一硬件。
3. 是否在高优先级任务中加入阻塞 I/O。
4. 是否混用了 ms 和 tick。
5. 是否新增大栈对象。
6. 是否遗漏 Debug/Health 状态。
7. 是否遗漏超时和错误返回。
8. 是否需要更新 Keil 工程文件。
9. 是否需要更新文档。
10. Keil Rebuild All 是否达到 0 Error / 0 Warning。

## 17. 当前开发建议

基于 NW3 当前状态，后续优先级建议：

1. 完成 SD 卡 CSV 实际文件写入闭环验证。
2. 长时间运行观察 Storage、Display、Comm 是否互相影响。
3. 优化 ADC 电量算法，使用查表和低电压迟滞。
4. 继续验证 MPU6050 自动恢复和 yaw_rel 漂移边界。
5. 接入触摸屏或新增 I2C 设备前，确认地址冲突和总线阻塞风险。
6. LoRa/MAVLink 新消息扩展时，先确认带宽和发送周期。

## 18. 结论

NW3 已经是多模块合并后的正式工程，开发时不能只按单个传感器工程理解。所有新增功能都必须纳入 Framework 的模块注册、状态监控、强类型 Topic、任务优先级和 Debug 体系中。保持这些边界，后续扩展显示、通信、日志和告警功能时，系统才不容易出现卡死、栈溢出或数据链路混乱。
