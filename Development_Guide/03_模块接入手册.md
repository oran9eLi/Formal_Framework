# 模块接入手册

本文档是外设、通信、显示项、状态类模块、5G-A、Remote ID 和后续 LoRa 多从机能力的唯一接入入口。原 `6.24接入指南.md` 的长期有效规则已合并到本手册，后续不得再新增平行接入指南；接入规则变化只维护本文件、`05_完成度与后续清单.md` 和对应 `Change_History/`。

## 1. 接入分类

新增外设先归类，再决定是否需要 topic、App API 和任务。

| 类型 | 示例 | 数据模型 | 业务出口 |
|---|---|---|---|
| 普通传感器 | GNSS、IMU、Baro、Battery | Snapshot 或 FIFO | `App_Copy*` |
| 通信模块 | LoRa、5G-A、CAN、UART modem | RX snapshot + TX 状态机 | `App_GetCommStats()` 或模块状态 |
| 状态/自检外设 | 只判断连接、在线灯、控制面模块 | 模块状态 | `App_GetModuleStatus()` |
| 显示/触摸 | SSD1963/ATK-MD0700、GT911、LVGL | 显示底层驱动 + LVGL 页面模型 | Display 业务入口 |
| 存储 | SD/FatFS/CSV | 队列 + 文件系统 | Storage service |
| 控制输出 | PWM、电机、继电器 | 命令/ACK 或控制快照 | Control service |

连接管理、自检或在线性判断类外设不强制新增 topic；可由所属 service/driver 发送必要控制命令，只上报模块状态。5G-A 的 AT 控制面属于这一类，除非未来明确要在本板承载业务数据。

## 2. 必改文件

新增外设通常至少检查以下文件：

| 文件 | 要求 |
|---|---|
| `Bsp/Inc/bsp_config.h` | 引脚、总线、DMA stream、NVIC、模块 enable 开关 |
| `Bsp/Inc` / `Bsp/Src` | BSP 初始化、原始收发、DMA/IRQ 入口、轻量错误请求；短临界区统一走 `bsp_critical.h` |
| `Sensor/Inc` / `Sensor/Src` 或 `Driver/Comm/Inc` / `Driver/Comm/Src` | 传感器协议解析、通信协议边界、校准、快照、内部状态、reinit 请求 |
| `Framework/Inc/px4lite_config.h` | enable、周期、超时、栈大小、优先级、消息周期 |
| `Framework/Inc/px4lite_types.h` | 模块 ID、状态、必要的数据结构 |
| `Framework/Src/px4lite_platform_f407.c` | 唯一 BSP/Driver 到 Framework 类型转换入口 |
| `Framework/Src/px4lite_app.c` / `px4lite_modules.c` | 注册模块、work/task 接入、heartbeat；Business 拥有的模块通过 Business 平台适配器注册 |
| `Framework/Src/px4lite_health.c` | OFFLINE/FAILED 判定、恢复 backoff、状态上报 |
| `Business/Inc/app_data_api.h` / `Business/Src/app_data_api.c` | 对 Business 暴露快照复制接口或模块状态 |
| `Debug/Inc/debug_config.h` | 独立调试开关，底部派生宏不得手动编辑 |
| `MDK-ARM/formal_framework.uvprojx` | Keil source list 必须包含新增 `.c` |
| `Development_Guide/` | 本手册、完成度、验证结果和变更记录必须同步 |

## 3. 初始化链路

外设接入必须保持完整初始化链路：

1. `bsp_config.h` 定义 enable、GPIO、UART/I2C/SPI/ADC/TIM、DMA stream/channel、NVIC 优先级。
2. MSP 层完成 GPIO/clock/DMA/NVIC 配置。
3. BSP `Init()` 只负责硬件资源和原始收发缓冲。
4. Driver `Init()` 只负责芯片协议状态、校准参数、解析器和快照状态。
5. Platform Adapter 提供 `Px4Lite_XxxInit()`、`Px4Lite_XxxRead()` 或 `Px4Lite_XxxService()`。
6. Framework 注册模块 descriptor，必要时注册 recover 回调；未实现的生命周期回调必须显式写 `NULL`，不得用数字 `0` 混淆普通数值字段和函数指针字段。
7. 模块 `Init()` 回调必须返回底层真实初始化结果。初始化失败时写入模块 `FAILED` 状态并让 Registry 记录失败生命周期；普通非关键外设不得用吞掉错误的方式伪装启动成功。
8. 对外数据通过 topic 和 `app_data_api.h` 输出。
9. Keil 工程 source list 同步新增源文件。

## 4. 接收/传感器类样板

以 GNSS 为样板：

| 层 | 职责 | 关键点 |
|---|---|---|
| BSP | USART + 循环 DMA 接收 | 句柄 `static`，ISR 只推进写指针，满了丢最旧并计数 |
| Driver | 取字节、组帧、解析、维护私有快照 | 校验失败丢整帧，不刷新 `last_valid_ms` |
| Adapter | 驱动快照转 Framework 测量 | 使用 `sequence` 去重，未变返回 idle/no data |
| Framework | 发布测量、升状态、健康超时 | 采集只升 ONLINE/DEGRADED，Health 判 OFFLINE |
| Topic | Snapshot 发布/拷贝 | 短临界区整体复制 + ready 标志 |

目标接口形态：

```c
Result_t Device_Init(void);
Result_t Device_Service(uint32_t now_ms);
Result_t Device_CopySnapshot(Device_Snapshot_t *out);
Result_t Device_GetStatus(Component_Status_t *out);
```

恢复请求必须可重试：ISR 或 BSP 只设置轻量请求标志，实际恢复由所属 service 执行；如果一次恢复 I/O 失败，Driver/Service 必须保留本地 pending 标志并做 backoff，不能消费请求后只尝试一次。

## 5. 通信类样板

以 LoRa 为样板：

| 层 | 职责 | 关键点 |
|---|---|---|
| BSP | USART TX DMA 整帧发送 | 启动前复制完整帧，DMA TC 表示真实发送完成 |
| Driver | 非阻塞 TX/RX 状态机 | 忙则返回 BUSY，接口注明同步/异步复制/零拷贝语义；本机模块状态和对端 RX 新鲜度必须分开 |
| Framework | topic 到协议帧调度 | 逐字段编码，按 sequence 去重和重试 |
| Health | 通信状态超时判定 | Comm 记录活动事实；本机不可用走 OFFLINE，对端超时走 DEGRADED |

5G-A 可按通信类接入，但当前边界为连接管理控制面：AT 指令由 5G-A service/driver 发送和解析，Business 不拿原始 AT，不直接控制 modem。

通信类 Driver 统一放入 `Driver/Comm/`，不得继续放入 `Sensor/`。LoRa E22 的正式位置为 `Driver/Comm/Inc/lora_e22.h` 和 `Driver/Comm/Src/lora_e22.c`。新增通信模块必须同步 Keil include path、source list、Telemetry Catalog、状态统计和恢复入口。

控制命令统一通过 `Framework/Src/px4lite_command.c` 分发。MAVLink RX 只解包，MAVLink TX 只排 ACK 和发送帧；新增 5G-A、Remote ID 或其他控制命令时，必须先登记命令号、目标校验、执行结果和 ACK 规则，不得在 RX/TX/BSP/Display 中直接执行命令。

LoRa/MAVLink 接收必须保持三段边界：Driver 只提供合法帧事实；Framework 协议模块解码为远端遥测快照；Business 通过 `App_CopyRemoteDisplaySnapshot()` 输出远端显示视图。新增对端外设字段时，优先补发送目录项和接收映射，不得在 LoRa Driver、Display 页面或 BSP 中散落业务解析。

LoRa/MAVLink 通信统计必须从 Driver 事实向上透传：TX 完成计数、RX 合法帧计数、MAVLink `seq` 跳号丢帧数和丢包率进入 `Px4Lite_CommDebugInfo_t`，再由 `App_DisplaySnapshot_t` 喂给 Display。远端槽位也要保存当前节点的 RX 计数和丢包率，主机切换从机页面时读取选中槽位，不得只显示全局聚合丢包率。当前 ACK 计数统计 stream 控制和自动 poll 兜底的真实 `COMMAND_ACK`，不得用 RX 计数或发送成功计数伪装确认；数据帧级重传协议后续单独设计。

LoRa/MAVLink RX 不得在 `comm` 任务栈上放完整远端遥测快照、完整 MAVLink 消息或大 payload 临时对象；需要跨调用复用时使用 `comm` 单写者静态 scratch。`HEARTBEAT` 必须解码 `type`、`autopilot`、`base_mode`、`system_status` 和 `mavlink_version` 并透传到远端节点轻量视图；`COMMAND_ACK` 只能作为 stream/poll 控制面确认和在线时间刷新，不得伪造 HEARTBEAT 节点类型。

远端扩展数据统一走两类 MAVLink 容器：小状态使用 `NAMED_VALUE_INT` 固定名称逐字段打包；大表和增量日志使用 MAVLink `TUNNEL`，payload_type 由 `px4lite_remote_tunnel.h` 统一登记。当前基线已包含：

| 数据项 | 容器 | 名称 / payload_type | 接收落点 |
|---|---|---|---|
| 第二电池/外设独立供电 | `NAMED_VALUE_INT` | `BAT2STAT`：voltage2_mv、percent、low_voltage | `Px4Lite_RemoteTelemetry_t.voltage2_mv/battery2_percent/low_voltage2` |
| 电机目标输出 | `NAMED_VALUE_INT` | `MOTORPWM`：4 路 duty_percent | `Px4Lite_RemoteTelemetry_t.motor_duty_percent[]` |
| 活动告警表 | `TUNNEL` | `PX4LITE_TUNNEL_PT_ALARM_TABLE` | 远端告警表缓存和 Display 告警列表 |
| 消息日志增量 | `TUNNEL` | `PX4LITE_TUNNEL_PT_MESSAGE_LOG` | 远端日志最新序号和本地中继状态 |

本机消息日志的 Framework 单一真值源为 `px4lite_local_msglog` 固定环形缓冲；显示层状态日志生成时同步写入该环形缓冲，LoRa `REMOTE_LOG` 只从该缓冲读取增量。后续 5G-A、Remote ID 或业务告警若要产生可远端查看日志，必须调用统一消息日志入口或复用该固定环形缓冲，不得在 Display 页面、LoRa RX/TX 或外设 Driver 内另建日志队列。

双电池/外设独立供电接入规则：底层必须从 BSP ADC、Sensor 驱动、Platform Adapter、Framework topic、App Environment 快照到 Display/LoRa 外发一路闭合；第二电池当前使用 ADC2 IN4/PA4 和 `Px4Lite_PublishBattery2()` / `Px4Lite_CopyBattery2()`，并作为 Battery 模块的一部分参与状态和告警。新增 5G 模块独立供电时优先复用第二电池链路；如硬件改为不同 ADC/PMIC，只替换 BSP/Driver/Adapter，不改变 App 字段命名和 MAVLink `BAT2STAT` 契约。

LoRa 热插拔判断不得把对端收不到数据当成本机模块拔掉：E22 本机存在性当前以 AUX 下拉后的长期不可用判定，进入 OFFLINE/红灯；对端合法 MAVLink RX 超时进入 DEGRADED/黄灯；只有最近收到对端合法帧才进入 ONLINE/绿灯。新增 5G-A、CAN modem 或其他通信模块时也必须区分本机硬件事实、控制面连接事实和对端数据新鲜度。

主从/多从节点统一使用 `PX4LITE_NODE_ID` 和 MAVLink `system_id = node_id + 1`。新增从机时，先分配新的 node id，再让主机远端槽位表接收该 sysid；主机页面选择从机时只切换选中远端槽位，禁止为每个从机复制一套接收解析代码。

多从机在线发现采用“低频错峰 `HEARTBEAT` + 主机自动慢速 poll 兜底”：所有节点发送轻量心跳用于发现和在线判断，心跳按 `node_id` 做启动错峰；主机后台按 node id 低频发送 `MAV_CMD_USER_2` poll，弥补个别心跳碰撞导致的漏发现。未选中节点不主动连续发送完整遥测。远端查看采用租约式点名：选择目标节点后，本机向目标发送 `MAV_CMD_USER_1` stream start/stop，只有被选中的目标节点在租约内发送屏幕同源主数据。主机选择从机、从机选择主机都使用同一条 stream 链路；主机正在查看某个从机时，后台 poll 自动退让，避免和屏幕数据抢 LoRa 空口。若主机和从机同时互相查看，双方 stream 保持打开，主数据目录项按 `PX4LITE_MAVLINK_MUTUAL_STREAM_THROTTLE` 自动降频，`HEARTBEAT`、COMMAND 和 ACK 仍保持优先发送。当前节点表按主机 0 + 从机 1~16 预留，继续扩容时必须同步评估静态 RAM、显示分页、心跳周期、错峰间隔、poll 周期、互看降频倍数和离线超时。

远端节点选择必须按角色收口：主机只允许选择从机节点，通信页选择框通过 `App_CopyRemoteNodeStatuses()` 自动显示收到心跳的从机，并且只消费 App 层 `App_RemoteNodeView_t`，不得直接使用 Framework 远端节点枚举。状态灯表达心跳新鲜度；远端选择页必须提供返回本机入口；正在查看远端数据时，页眉返回入口必须直接回本机同一页面，不得强制再次选择远端节点。从机只允许选择主机节点，从机远端查看 120 s 无触摸操作后自动退回本机视图。远端快照失效或断链时，Display 必须关闭远端查看、切回本机数据源并继续刷新本机页面，避免停留在远端 `DISPLAY_NOT_READY` 状态。当前显示对象身份先使用 `view_node_id/system_id`，Remote ID 后续接入时只替换身份显示来源，不改变 LoRa 槽位、MAVLink system id 或远端快照结构。

## 6. 外发数据目录

LoRa/MAVLink 外发必须按 Telemetry Catalog 管理，不得在 `comm` 任务中拼接全量大包。目录项只描述调度属性，真实数据由编码函数按需读取同源快照。

每个外发数据项必须明确：

1. 数据项名称和 MAVLink message id。
2. 数据来源：Framework topic、Health 状态或 App API 同源快照。
3. enable 开关和发送周期。
4. 编码函数，且必须逐字段编码，不得直接发送 C struct 内存。
5. 成功计数和失败统计入口。
6. 是否需要成功后状态推进，例如 `MODSTAT0/1` 分片。
7. 最大 payload 和是否允许丢弃；大数据必须走静态分段缓存，不得放任务栈。

新增外设数据外发步骤：

1. 若只是在线、自检、连接状态，先接入模块状态和 Health，再通过 `MODSTAT0/1` 自动外发。
2. 若有显示值或业务值，先新增 topic 或 `App_Copy*` 快照，Display 和通信共用同源数据。
3. 在 `Framework/Src/px4lite_mavlink_tx.c` 新增一个编码函数，只读取本项需要的小快照。
4. 在 Telemetry Catalog 中新增一项，配置周期、message id、统计指针和编码函数。
5. 在 `Framework/Inc/px4lite_config.h` 增加 enable 和 period 宏。
6. 更新统计结构、完成度文档和变更记录。
7. Keil build verification 必须达到 `0 Error(s), 0 Warning(s)`。

新增外设数据接收步骤：

1. 确认发送端使用的原生 MAVLink message id 或已有 `NAMED_VALUE_INT` 分片名称。
2. 在 Framework MAVLink RX 解码模块新增逐字段映射，发布到远端遥测快照。
3. 在 `App_CopyRemoteDisplaySnapshot()` 中把远端快照映射到 Display App 视图。
4. 若页面已有对应字段，不改页面底层；若是新字段，先扩展 App 视图，再扩展 Display 变量。
5. 新增大 payload 或分段重组时使用静态缓存、固定块池或固定队列，不占用 comm/display 任务栈。
6. LoRa/E22 接收侧必须保留静态有界 RX 帧队列，不能退回单帧覆盖缓存；队列满时丢弃最旧帧并累加丢弃计数，保证新状态优先进入 Framework 解码。
7. 通信 Driver 的 TX/RX 超时必须来源于 BSP 配置事实，例如 `BSP_LORA_UART_BAUD` 和 `BSP_LORA_AIR_BPS`，不得在业务层或 Framework 层写死与硬件速率相关的魔数。

## 7. 数据契约

正式测量值必须包含采样时间、发布时间、序号、有效标志和质量字段。字段命名必须表达单位，例如 `_ms`、`_mv`、`_deg_c`、`_percent`。

发布顺序固定：

```text
采集完整原始数据
-> 校验
-> 单位转换
-> 校准/过滤
-> 计算质量
-> 填充完整临时结构
-> 一次性发布
```

只有存在真实业务数据消费需求时，才新增 Framework topic 和 `App_Copy*`。只用于在线、自检、连接状态的模块通过 `App_GetModuleStatus()` 输出。

## 8. 调度规则

- 普通传感器挂入 `sensor` 任务。
- 融合与估算挂入 `estimator` 任务。
- 通信 RX/TX 和 modem 控制面挂入 `comm` 任务或其 work。
- 显示刷新归 `biz_display`。
- SD/FatFS 阻塞 I/O 归 `storage`。
- 控制输出归 `control`。

Display 新页面、新控件和触摸交互统一接入 LVGL。`Display/Src/display.c` 只作为 App 数据视图、页面切换和兼容 facade，不得恢复 `display_pages/display_gfx/display_text` 旧手绘页面栈；Logo、字体和图标可作为 `Display/Inc` / `Display/Src` 内只读 LVGL 资源接入，不得携带页面逻辑或跨层依赖；本机显示日志统一由 Business `app_message_log` 写入 Framework 本地消息日志，LVGL 页面只通过 App API 读取本机或远端日志快照。

新建任务必须满足：

1. 现有任务无法承载其实时性或阻塞特征。
2. 有独立资源所有权，且不会与已有任务争抢同一硬件。
3. 有明确周期、优先级、栈预算、最长执行时间和 watchdog 策略。
4. 已加入 DebugTaskMonitor，并记录长稳栈水位。

## 9. 接入评审清单

合入前逐项确认：

- [ ] 没有破坏 `Core -> Business -> Framework -> Platform Adapter -> Driver -> BSP -> HAL` 单向依赖。
- [ ] Framework 中只有 `px4lite_platform_f407.c` 包含 BSP 头文件。
- [ ] Business 和 Display 页面/业务适配代码没有包含 BSP/Sensor 头文件，没有读取驱动私有变量或 DMA buffer。
- [ ] Display 页面层没有直接包含 Framework 故障头文件；模块名和故障原因显示文案通过 App API 获取。
- [ ] Display 页面层没有直接包含 Framework 模块枚举；状态灯、告警列表和离线清屏策略通过 `App_CopyDisplaySnapshot()` 获取。
- [ ] 远端数据显示通过 `App_CopyRemoteDisplaySnapshot()` 进入 Display 视图，没有绕过 App API 直接读 LoRa RX 帧。
- [ ] LoRa 收发计数和丢包率从 Driver 调试事实逐层透传，没有在 Display 或 Business 中重新估算；ACK 未实现前没有伪造确认计数。
- [ ] 本机/对端切换只能通过 LVGL 屏幕交互调用 Display 数据源 API 和 App 远端节点选择 API；KEY0 不作为产品交互入口，KEY1 急停职责没有被复用。
- [ ] 多节点显示选择已按角色过滤：主机只列从机，从机只列主机；远端视图左上角显示当前 `node_id`，Remote ID 后续只替换身份显示字段。
- [ ] Display 芯片驱动只调用显示/触摸 BSP，没有直接包含 `stm32f4xx_hal.h`；需要延时时走 `BSP_Time_DelayMs()`。
- [ ] BSP 没有协议解析和业务逻辑。

## 2026-06-30 远程遥测和页面适配接入补充

- 远端节点数据必须先进入 `px4lite_remote_telemetry` 的静态节点槽位，再由 App/Display/LoRa 读取，不得在 MAVLink RX、Display 或 Business 中各自保存一套远端事实。
- 远端查看模式统一通过 `Px4Lite_MavlinkSetRemoteView()` 切换；该入口负责同步选中节点、模式和 stream request，不得在页面代码中直接拼 COMMAND_LONG。
- REMOTE 日志、告警、电机目标和后续 5G/RemoteID 分片数据必须采用静态 scratch、固定环形缓冲或固定槽位；禁止在 `comm` 或 `biz_display` 栈上放整表、大 payload 或动态数组。
- 页面新增能力只接 LVGL；不得重新引入 `display_pages` / `display_text` 手绘页面或文本枚举适配层，文本、日志和远端状态必须通过 App/Business API 进入页面。
- 新增外设完成收口时，必须同步补齐 `Tests/Unit/` 对应测试源文件或记录没有单元测试执行入口的原因，并继续以 Keil Rebuild All 的 `0 Error(s), 0 Warning(s)` 作为固件发布门禁。

## 2026-06-30 远端显示链路收口补充

- LoRa/MAVLink 远端主数据查看使用 `COMMAND_LONG` stream request，发送端在收到 `COMMAND_ACK` 前按 `PX4LITE_MAVLINK_COMMAND_RETRY_MS` 有限重试，重试上限由 `PX4LITE_MAVLINK_COMMAND_RETRY_MAX` 控制；页面层不得直接拼控制帧。
- 远端普通数据、状态、告警和日志的新鲜度统一按 `PX4LITE_REMOTE_DATA_STALE_MS = 15000 ms` 判定，必须覆盖 5 s 状态帧和 10 s 日志/告警帧周期，避免页面数据周期性消失。
- LoRa/MAVLink 丢包率必须在至少 `PX4LITE_MAVLINK_LOSS_MIN_EXPECTED = 32` 帧样本后显示，启动初期不得用少量帧跳号直接显示高丢包率。
- BME280 湿度通过 `NAMED_VALUE_INT` 的 `ENVHUM` 扩展帧外发，单位为 `relative_humidity_pct * 10`；接收端写回远端环境快照，Display 只通过 App 视图读取。
- 远端消息日志解包后写入 `Px4Lite_RemoteTelemetry_t.log_entries`，每个远端节点固定缓存 `PX4LITE_REMOTE_LOG_ENTRY_MAX = 5` 条，Display 通过 `App_CopyRemoteMessageLog()` 读取；不得在 comm 或 display 任务栈上放全量日志表。
- 本机/远端消息日志显示统一读取 Business/远端结构化日志；LVGL 日志文字使用 ASCII 短码，避免中文字模缺字导致方框。
- 电机状态灯以第二路电池/电机独立供电优先裁决：未接入或严重欠压显示红灯，低压显示黄灯，供电正常时才沿用 control 模块状态。
