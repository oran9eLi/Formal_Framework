# UART1 教学 CLI 一期实施准备

日期：2026-10-15。状态：准备稿 R1，未实施。用户同意先归档优化固件，再开始准备 UART1。

## 1. 目标与版本边界

以 `v1.0.0-pre.opt.20261015` 的生产源码为实现基线，主 SRAM 空余 19384 B。先让学生通过 UART1 手动输入命令，观察回显、设备快照、诊断计数与参数事务。具体发布归属 V1.1 或 V1.2 仍按联合评审确定。

一期只新增 UART1 服务。UART6 的初始化、波特率、MAVLink 调度、H1、B1 及原有实验流程保持现状；不依赖树莓派、服务器或 HTTPS 才能使用本机串口助手。浏览器接入的 HTTPS 条件沿用原评估稿，属于平台联调事项。

现有两份 R0.3 文档描述 CLI 与 UART6 改造的整体候选方案。一期以本文为执行边界：暂不引入新 UART6 HELLO/SESSION/EVENT/筛选发送，也不关闭旧 B1。不得将一期解释为两份总体契约全部实现。

## 2. 拟议首批范围

| 批次 | 能力 | 约束 |
|---|---|---|
| U1 基础闭环 | help、echo、get device_info、get uart_baud、get uart_stats、set uart_baud、get operation_status | 115200/57600、8N1；改参在旧速率整条响应物理发送完成后执行；重启恢复115200 |
| U2 模块只读 | get system_status、module_status、time_utc/time_local、alarm_summary，以及已有 App 快照覆盖的 GNSS/IMU/姿态/环境/双路电源/通信/存储/电机/资源组 | 逐名称接入，数据有效性、年龄、单位明确；大对象用已有字典选择器拆分，每次最多512B；无数据不编造0 |
| U3 有界操作 | 接入已有 App_Request 能提供完整结果关联的实验参数与动作 | 逐项核对R0.3第11章范围；不新增底层硬件能力；普通控制单槽，查询继续；停止/撤收保留优先级 |

U1 完成后先交付可独立联调的候选，再接 U2/U3。80组查询、17组赋值和7组动作是候选目录；没有接入和验收的名称不出现在支持列表。资源或回执条件不足的项明确延期，不能以 ACCEPTED 代替成功。具体 U2/U3 名称清单在实施前逐项冻结，禁止泛化为任意寄存器/内存/参数编辑。

U1的device_info通过Framework正式身份接口聚合，只读取实际身份/能力；不绕过App边界读取业务。U2再接入业务邮箱。UART1自身公布实际能力和字典子集；无 UART6 新握手时，boot_token 保留0并声明跨端启动绑定不可用。本机计数带启动时长；学生/电脑按每次连接及设备复位分段记录，不宣称已有跨端会话关联。

## 4. 所有者、状态和协议

- CommTask 是 UART1 的唯一运行期资源所有者；ISR只更新接收位置、计数和完成标记。硬件重配/恢复在Comm执行，毫秒来源使用PlatformGetMs/BSP_Time_GetTickMs。
- 行协议沿用R0.3：help、echo、get name、set name = value，机器请求可带@request_id；无别名兼容旧草案。CRLF/LF、引号、非法字节及超长行按原规则处理。
- 输入128B不含CRLF，行数组至少129B；响应512B含CRLF；一个响应在途。help用名称或分页查询，不生成全目录长文本，不做自动遥测推送。
- 普通控制一个在途槽，ACCEPTED只表示受理，get operation_status关联原请求号和所有者号；终态需有实际事实。普通set忙时拒绝，不覆盖。急停/撤收优先；普通限流、邮箱忙和旧终态不得挡住必要停止请求，具体优先邮箱在U3冻结。
- UART改参依次为空闲→旧速率响应→等待物理TC→重新初始化→已应用/失败；重新初始化不得影响UART6。失败尝试恢复旧速率，恢复失败保留实际错误；电脑不自动扫描或回退，学生手动恢复。事务有固定超时，超时不伪造成功。
- UART1模块写操作与屏幕复用所属服务的既有互锁、参数范围和异步结果，不新增要求LoRa在线或动力电源在线的全局门禁；各硬件操作的必要条件仍由所属服务检查。
- 共享邮箱由Framework提供类型化请求/结果，Business消费。临界区只复制短结构/标志；解析、格式化、浮点转换和硬件操作均在临界区外。

## 5. 资源与执行预算（设计目标，未测量）

| 项目 | 上限或方法 |
|---|---|
| 新增主 SRAM | 总计≤4096B；RX环256、行129、TX槽512、业务邮箱/响应暂存≤1024、控制/统计/格式化暂存≤768，余量留给DMA句柄、对齐及必须的驱动状态；禁止同一512B响应再层层复制 |
| 集成静态余量 | ≥12288B；当前19384B，若增加4096B则剩15288B，最终以MAP测量 |
| 新增Flash | ≤24576B（24KiB），含help/字典字符串；使用const静态表与公共处理器，不为每个名称建任务或独立大缓冲 |
| 输入/输出 | 普通请求≤5条/s、响应≤2048B/s；错误响应也计预算；持续超限或洪泛不得每字节打印错误 |
| 每轮通信工作 | 建议最多取64原始字节、解析/派发1条、只推进一次非阻塞发送；新增CPU服务目标≤1ms/轮，与现有UART6最坏耗时分别测量 |
| 运行资源 | heap_4峰值<75%；Comm当前栈384 words（1536B），不在栈上放512B响应或大型聚合快照；记录高水位及最重组合 |

512B在115200/8N1线速约44.4ms、57600约88.9ms；这是线上发送时间，不能拿来占住10ms周期的Comm任务。2048B/s约占115200线速17.8%、57600线速35.6%，DMA减少CPU搬运，不缩短线速时间。256B RX环在115200满速约22.2ms可填满，需核对最长调度间隔；溢出后显式计数并丢弃至换行恢复，不悄悄执行残缺命令。

## 6. 实施顺序与完成条件

1. U0：从已归档优化候选建立独立codex功能分支，固定实际命令子集/回执来源、DMA路由、资源表和双口回归基线。更新文档先于编码。
2. U1：完整接入UART1硬件与独占输出，接入平台适配和有界CLI基础闭环；独立构建并记录MAP差额。观察短/长echo、错波特率、改参旧速率响应和复位恢复。
3. U2：通过类型化邮箱接入只读App快照；逐名称核对字段、单位、年龄、失效、超长响应和help能力，避免复制整份历史/原始帧池。
4. U3：逐项接入有完整关联的既有写参数/动作，核对同值、越界、忙、完成、失败、超时、重启生效及与屏幕竞争；缺回执先补正式接口，再暴露命令。
5. U4：独立审查分层/ISR/队列上界/恢复/优先停止；Keil Rebuild All目标0/0，记录源码身份和同次产物；静态预算不达标先缩批次。
6. U5：实板联合验收，UART1单口与UART6遥测/H1/B1并行，叠加显示/LoRa/SD负载，记录数据正确性、误码/丢包、Comm极值、堆栈与保护；通过后再开平台接口迁移阶段。

上述是后续验收计划，本次没有新增/运行主机测试、串口测试或实板操作。若后续需要主机自动化测试，按用户当次授权执行；Keil构建按仓库强制要求执行。

## 7. 准备稿自查与重点验收

已对照R0.3进行覆盖自查：U1覆盖行协议与改参，U2覆盖快照查询，U3覆盖既有有界控制，U4/U5覆盖资源/双口/实板；新UART6协议明确不纳入一期。以下五项列为重点：

| 风险输入/场景 | 归属 | 后续核对的预期 |
|---|---|---|
| 超长行、连续无换行、RX环溢出 | U1/U5 | 计数可见，丢弃到边界，恢复后下一条完整命令执行；不执行截断set |
| UART1改速响应丢失、TX忙/超时或重配失败 | U1/U5 | 旧速率发送完成后才改参，失败结果真实；UART6可继续，学生可手动恢复 |
| 无效/过期快照、超512B、日志/原始帧选择变化 | U2/U5 | 明确无效/过期/长度错误，字段单位和版本正确，无貌似完整的截断结果 |
| 屏幕与CLI同时操作、普通set忙且需要停止 | U3/U5 | 单所有者/既有互锁，普通命令不覆盖，停止优先级与结果关联完整 |
| UART6 H1/B1与UART1突发输入叠加LoRa/SD/显示 | U4/U5 | 原UART6行为不变；记录调度、丢包、栈/堆和显示极值，不仅以编译成功判定 |

上述为后续验收点，本次未新建或运行测试。准备稿未固定的DMA路由及U2/U3逐名称清单是编码前必须完成的设计项，本文不是可直接宣称全部接口已冻结的实施完成记录。
