# 阶段一 H1 UART6 受控回显——箱子端技术文档

日期：2026-09-23

状态：**本地主机单测与 Keil 全量重建通过；跨端字节契约仍为候选，烧录和实板 UART6 验收缺少可核记录。** 本文不把源码默认值或合成向量当作实验箱现场事实。

## 1. 范围和既有事实

- 本轮只改 F407 固件的受控回显接入。UART6 使用既有 `PC6/TX`、`PC7/RX` 配置及 CommTask 收发路径；真实接线、Pi 串口节点、实烧版本和现场基准波特率 B0 均未核验。
- 不更改 UART 参数，不写 Flash，不触发飞控命令，不增加任务或动态分配，不实现后续失配、切换和恢复实验。
- `0x8001/0x8002` 仍属于原业务 `TUNNEL`。H1 仅在 RPi 物理链路识别 `0x8003`，不会进入 LoRa 远端遥测快照。
- 2026-09-22 的 16 字节头、`SET_BAUD` 状态机源码和测试作为旧草案保留于工作区，但当前 Keil 工程不编译其源文件；对应的收发调用已切至 `px4lite_rpi_h1_echo.c`。旧配置开关为 0，不代表旧草案已发布。

## 2. 候选字节布局

承载为 MAVLink 2 `TUNNEL`，`payload_type=0x8003`。TUNNEL 的 `target_system` 必须等于 F407 当前本机 system id，`target_component` 必须等于 UART6 出口组件号 193；广播目标不接受。来源 system/component 不能为 0，来源 system id **可以**与本机相同，响应目标取请求帧真实来源。

| 字节偏移 | 请求（`11+N` 字节） | 响应（`15+N` 字节） |
|---|---|---|
| 0 | 版本 `01` | 版本 `01` |
| 1 | 类型 `01` | 类型 `02` |
| 2—9 | 8 字节 nonce，原样复制 | 与请求逐字节相同 |
| 10 | 文本字节数 `N`，范围 1—48 | 与请求相同 |
| 11—`10+N` | 文本原始字节 | 与请求逐字节相同 |
| `11+N`—`14+N` | 无 | 当前 UART6 已应用波特率 `u32` 小端 |

只比较字节数，不把字符数当长度。F407 不解析或重编码 UTF-8，不裁剪、归一化或写死 `HELLO CNS`。上游对 UTF-8、空白和控制字符的限制不在 F407 重复实现。候选英文例 `HELLO CNS` 的 N=9，请求 20 字节、响应 24 字节；文档内的 57600 仅为合成测试值，不是现场 B0。

MAVLink 2 可以裁剪帧尾零字节。接收端同时检查 TUNNEL 声明的 `payload_length == 11+N`，以及外层帧实际携带的数据区至少覆盖这 `11+N` 字节，避免把解码器补零误认为收到的文本。合法输入的最后一个 UTF-8 文本字节不是零；外层固定数组的零填充不计入 H1 数据区。响应尾部波特率中的零字节允许由 MAVLink 2 裁剪。

## 3. 处理与所有权

1. USART6 中断只收字节，既有 MAVLink 解析器负责完整帧及 CRC；`CommTask` 从 UART6 帧队列取帧。
2. RPi 接收分发器只把 `TUNNEL 0x8003` 交给 H1 模块。模块核对精确目标、版本、请求类型、N、声明长度及真实携带长度；任何不合法请求均不排队成功响应。
3. 合法请求读取 `Px4Lite_RpiMavlinkGetBaudRate()`，最终由 `BSP_RpiUART_GetBaudRate()` 从初始化成功后的 `huart6.Init.BaudRate` 得到已应用配置。读取失败或读到 0 时不使用源码默认值替代，也不发成功响应。
4. H1 模块用 CommTask 独占的静态单槽保存响应。待发期间相同来源、nonce 和文本的重复请求不覆盖响应；不同请求返回忙。响应发送成功后释放单槽。已经发送后的同一请求仍可再次回显；Pi/Server 的动作去重不由 F407 代替。
5. 原 UART6 发送器以较高优先级经 `mavlink_msg_tunnel_encode_chan()` 逐字段编码响应，随后用既有阻塞 UART6 发送接口提交。H1 路径不调用 `Px4Lite_RpiMavlinkSetBaudRate()` 或其他参数/命令接口。

## 4. 本机验证与待验收项

已完成的主机单测 `Tests/Unit/test_rpi_h1_echo.c` 使用 MSVC `/utf-8 /W4 /WX` 编译并运行通过，另用 AddressSanitizer 运行通过；覆盖：候选英文完整 MAVLink 帧解析与 39 字节响应构造、中文与混合 UTF-8 字节、1/48 字节边界、错目标/广播、错来源、错版本/类型、N=0/49、声明长度少/多、实际帧截断、待发重复/忙、波特率读取失败及非旧白名单速率读取。旧草案单测单独运行通过；当前接入的 RX/TX/Comm 源文件另以 MSVC 做语法检查通过，检查时仅屏蔽第三方 MAVLink 和既有无关代码的告警。上述结果仅证明主机侧软件逻辑与语法，完整帧仍为**构造向量**。

Keil MDK-ARM 5.36 / ARMCC5 对当前工程执行 Rebuild All，日志包含 `px4lite_rpi_h1_echo.c`，结果为 0 Error(s)、0 Warning(s)；map 中 `RW_IRAM1` 使用 `0x1d0d0/0x20000` 字节，剩余 `0x2f30`（12080）字节。此为本地构建证据，不是实验箱现场验证。

未核验：实烧固件版本、UART6 实际接线与 B0、真实请求和响应完整抓帧、业务消息并行回归、长稳和任务水位。因此不得标记实板完成或作为可直接部署的正式版本。

正式验收顺序：核对烧录镜像版本/哈希及 UART6 接线与 B0；在 Keil 对当前工程 Rebuild All 并复核 map；烧录候选固件后，用同一真实 UART6 留存至少一组合法英文/中文或混合文本请求响应及一组错误目标/长度拒绝记录；记录完整 TX/RX 帧、字节数和 UART 实测配置；再回归原 `0x8001/0x8002` 业务帧及命令/ACK 不被实验帧误触发。
