# v1.0 发布前审查与教学交互建议

## 1. 产品范围与结论

- 用户确认：课堂实验台，包含传感器、通信、无桨电机实验。
- 产品原则：更多可理解、可操作的交互优于更多自动化；学生应能看见输入、处理过程和输出。
- 审查基线：`651336dd96261cf6be4a75443581db23a6557b3a`。
- 已从 `ldf-new` 签出本地 `release/v1.0`；没有合并 develop、推送、打标签或发布。
- 当前结论：能够全量编译，但存在影响数据真实性、控制一致性和报文健壮性的必修问题，暂不满足正式发布条件。
- 本次交付为审查报告。没有修改固件源码；复现程序位于被忽略的 `Tests/build/`，不是正式回归测试。

## 3. 发布前必须修复

### F1 / P1：远端浏览页面的操作可能作用于本机

**证据：** `Display/Src/display.c:256` 仅对滑块做远端判断，而且直接返回成功；`display.c:305–342` 的自动升速、降速、急停和姿态校准没有同等判断。`Business/Src/app_data_api.c:338–350` 直接调用本机 Control。远端页复用同一套控件，`Display/Src/display_lvgl.c:1154–1187` 没有禁用或改路由。

**触发与影响：** 选择远端节点后进入电机/姿态页，看到远端数据，但按钮可能改变本机输出或本机零位。远端滑块则返回成功但没有执行命令。操作对象和反馈不一致。

**建议：** v1.0 将远端数据页面明确标为“远端只读 + 节点编号”；禁用会改变状态的控件，并在 API 边界拒绝。若保留本机急停，必须独立且明确标为“本机急停”。不必为此次发布新增远端电机控制协议。

**验收：** 双机联调，逐一检查远端模式下滑块、升速、降速、校准及本机急停；本机无意外改变，远端不出现虚假成功；切回本地后正常。

### F2 / P1：匀速转动被当成静止，姿态实验结果错误

**证据：** `Framework/Src/px4lite_attitude.c:166–179` 主要依据相邻帧变化量判静止；`:313–317` 在“静止”时直接冻结姿态。绕重力方向匀速旋转时，加速度方向和角速度都可不变，却不代表没有运动。

**真实算法复现：**

- 静止校准后，输入 Z 轴 30°/s，持续 2 秒（100 帧、20 ms/帧）：输出 **0.60°**，预期约 **60°**。
- 从启动开始保持同样转动：真实零偏为 0，却估出 Z 轴零偏 **30°/s**，偏航输出 **0°**。
- 倾斜 30° 上电并保持静止：输出 roll **0°**，内部 offset **30°**。

**建议：** 区分零偏估计、运动检测和姿态输出；避免相邻帧稳定就冻结积分。水平/相对零位由学生显式设置，保留原始姿态；上电静止不应自动等同于物理水平。六轴 IMU 的 yaw 明确显示为相对角，不承诺绝对航向。

**验收：** 静止漂移、匀速偏航、慢速倾斜、转动中上电、倾斜上电、主动归零及恢复原基准。补充正式算法回归测试，并用实板转台/角度参照验证。

### F3 / P1：命令返回拒绝，却已改变电机控制模式和输出

**证据：** `Framework/Src/px4lite_command.c:180–184` 处理 31013 命令时先切 DIRECT，再逐路设置 PWM。降速过程中非零 PWM 被拒绝时，之前的模式切换不会回滚。

**定向复现：** 姿态辅助模式、roll=10°、基础油门 60%，进入降速后发送四路 1600 μs，ACK 为 `TEMPORARILY_REJECTED`，但 mode 从 1 变为 0，测试中的 PWM 从 **1570 μs 变为 1600 μs**，降速仍在进行。

**建议：** 将模式和四路目标作为一个事务：完整校验、一次提交；拒绝时不得改变模式、目标或当前实验进度。同步检查 31011 的逐路提交路径，避免部分成功。

**验收：** 降速中、低压闭锁、非法参数、四路混合零/非零、并发控制周期；拒绝前后所有控制状态一致，接受时四路同周期生效。

### F4 / P1：远端告警报文缺少长度上限和完整性检查

**证据：** `Framework/Src/px4lite_mavlink_rx.c:635–647` 只检查 payload_length 下限，遍历使用报文声明长度；实际 `mavlink_tunnel_t.payload` 只有 128 字节。声明长度 255、行数至少 19 时，会访问数组边界之外。CRC 正确不代表载荷语义合法。

另外，声明行数与内容长度不符时，循环直接 break，随后仍将部分表作为有效告警表发布（`:665–670`），可能丢失之前显示的完整告警。

**建议：** 解码前校验载荷长度上限、版本及行数与长度的一致性；整表通过校验后一次发布。错误帧只累计诊断信息，不污染上一份有效快照。

**验收：** 正常空表/满表、长度 0/1/128/129/255、截断行、不支持版本；错误输入不越界、不发布部分告警。

### F5 / P2：SD 实验日志会把过期传感器数据继续写成新记录

**证据：** `Framework/Src/px4lite_storage.c:173` 使用当前时间创建新行；`:185–229` 仅按 Copy 返回 OK 写入导航、环境和电池值。`Framework/Src/px4lite_topics.c:47–55` 的 Copy 只表示曾发布过数据，不校验有效位或年龄。Baro 在采集成功时发布，断开后旧 topic 仍在。

**触发与影响：** BME280 曾有效采样后拔出，后续 CSV 仍带着新记录时间重复旧温湿度，没有相应数据有效标志；这会让学生误以为传感器仍在测量。独立故障事件日志不能替代数据行的有效性说明。

**建议：** 存储端使用各模块 freshness/valid 规则；数据行增加有效性/样本时间或明确缺测表示。不能仅写 0，因为 0 本身可能是合法实验值。同步更新 CSV 字段说明与解析端契约。

**验收：** 有效采样→停止更新/拔出→超过阈值→重连，逐行验证有效性、样本时间、事件恢复与显示状态一致。

### F6 / P2：发布界面和资料需要符合实验台的真实能力

**证据：** `Display/Src/display_lvgl.c:2088–2091` 使用“一键起飞/降落”；控制器实际为固定目标 60%、6 秒升速和 8 秒降速曲线（`Framework/Src/px4lite_control.c:35–37`），不能据此宣称具备飞行能力。`Release/Latest/MANIFEST.md` 仍为 2026-06-11 的早期版本描述，Latest 当前仅有清单。功能台账仍将现有 Alarm/Command 描述为占位。

**建议：** 电机页面改为“电机实验”，自动曲线作为“同步升速/缓降停机”等辅助动作并解释目标与时长；更新功能台账、接线/启动说明、按键行为、已知限制与发布清单。固件、日志、map 和校验和绑定同一次最终构建及源码提交。

**验收：** 教师只按交付资料即可完成首次上电、查看传感器、手动电机实验、双机通信和导出日志；界面与说明无能力冲突。

## 4. 发布验证门槛与资源约束

1. **内存预算。** 基线 208 字节是链接区剩余空间，并非运行时可用堆。FreeRTOS 在主 SRAM 预留 40 KB，LVGL 已通过 `LV_MEM_ADR=0x10000000` 使用 CCM 中的 40 KB（该固定地址池不会作为独立执行区列在 map 中）。新增状态或控件前核对两套堆、碎片与各任务栈余量，禁止把 DMA buffer 移入 CCM。M1 后续核查与预算见 [M1 验证记录](../Release/v1.0_M1_VALIDATION.md)。
2. **实板行为。** 两套设备验证本地/远端隔离；无桨验证急停、低压、预解锁、升/降速、手动调节和命令拒绝；验证 IMU、BME280、LoRa、SD 热拔插、半帧/错帧及恢复。
3. **长稳。** 仓库强制规范要求异常注入及至少 24 小时运行测试。本次尚未核验同一发布候选的相应记录；新改动不能仅用编译通过或旧版本记录代替。如果今天没有覆盖本候选的验证证据，先形成 v1.0-rc 候选，正式标签等待门槛满足。
4. **产物可追溯。** 最终修复完成后重新全量构建，归档同批 hex/axf/map/log、提交号、工具链、硬件版本、配置、SHA-256、已知限制和回归结果；本次审查构建不是正式 v1.0。

## 5. 体验增强候选

以下为设计建议，尚未实施。尽量复用现有屏幕、快照和按钮；保护逻辑持续有效，学生交互侧重观察、调节和理解。

| 优先级 | 增强 | 学生如何操作 / 获得什么反馈 | 建议范围 |
|---|---|---|---|
| E1 高 | 手动电机实验 | 独立控制四路；滑块旁加 ±1% 微调；并列显示“设定值、实际输出、PWM μs”；明确当前模式及辅助修正量 | 优先做设定/实际分离和拒绝原因；姿态辅助改为可见的显式选择 |
| E2 高 | 显式校准与归零 | “放稳→开始→采样进度→完成/失败”；区分传感器校准与相对归零，支持恢复原基准 | 配合 F2；避免自动把倾斜姿态记为水平 |
| E3 高 | 操作状态反馈 | 显示“ESC 准备中、已接受、运行中、已停止、被拒绝及原因”；急停入口易找到 | 先复用当前消息区与状态栏，不增加大页面 |
| E4 中 | 通信实验可观察 | 学生选择节点，观察收发计数、丢包、最近收包时间；可显式发送一次测试并看 ACK | 先修现有节点列表计数不随稳定状态更新的问题；单独更新行文字，避免重建全页 |
| E5 中 | 实验记录会话 | “开始记录 / 标记一次 / 停止并保存”；显示文件名、条数、写入状态及安全取卡结果 | 明确保存成功；后台故障日志可继续保留 |
| E6 中 | 模块状态详情 | 点状态灯查看读数单位、采样时间、有效性、故障原因和排查提示；教师可引导拔插观察变化 | 复用现有模块状态与时间戳，避免只有红绿灯 |

E4 的当前证据：`Display/Src/display_lvgl.c:181–190` 的签名只包含节点和状态；RX/Loss 文本在 `:2242–2246` 创建时填入，刷新逻辑 `:2446–2452` 仅在签名变化时重建，因此节点持续在线时数字不会实时变化。

## 6. 建议今天的收敛范围

- **推荐：修复优先的小版本。** 先完成 F1–F5，落实 F6 与 E3 的低成本文案/反馈；E1/E2 仅做与修复直接相关的目标显示和显式基准。然后实板验证并整理候选包。
- **更丰富的课堂版。** 在上项稳定后再加入完整校准流程、微调按钮及记录会话。交互收益更大，但涉及字库、内存和更多实板回归，适合后续增量版本。
- **完整实验引导系统。** 多步课程、实验报告、图表回看等留作后续规划，需要单独明确界面与资源预算，不列入今天的发布承诺。

顺序：报文与控制一致性 → 姿态真实性与数据有效性 → 教学反馈/文案 → 实板回归与长稳证据 → 最终全量构建及发布归档。
