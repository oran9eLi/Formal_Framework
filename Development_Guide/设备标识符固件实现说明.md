# 设备标识符固件实现说明

版本：2026-07-08
状态：已按确认口径落地 STM32 固件侧核心逻辑，RPi 侧暂不改动

补充日期：2026-09-28。第 1—6 节保留既有实现说明，本次更正短编号可能重号的表述；第 7 节记录 V1.0 已确认的配置目标，**尚未实现、尚未验收**。

## 1. 实现结论

固件侧保留两套身份：

| 身份 | 格式 | 来源 | 使用位置 |
|---|---|---|---|
| 现场短编号 | `DCDW-XXX` | STM32 96-bit UID 经 FNV-1a 哈希压缩到 `1..250` | 屏幕显示、LoRa `node_id`、MAVLink `system_id` |
| 厂商唯一产品识别码 | `DCDWCNS1` + 12 位 SN | STM32 96-bit UID 经 SHA-256 派生 | RemoteID `OPEN_DRONE_ID_BASIC_ID.uas_id` |

`DCDW-XXX` 继续自动从板卡 UID 派生，不需要每台设备手工改编号。厂商唯一产品识别码用于实名/RemoteID 等需要更强唯一性的场景。

## 2. DCDW-XXX 短编号

配置入口只保留可读前缀：

```c
#define PX4LITE_DEVICE_NAME "DCDW"
```

数字后缀生成方式：

1. STM32 读取 96-bit 硬件 UID。
2. 对 3 个 32-bit UID word 按原有字节顺序做 FNV-1a 32-bit 哈希。
3. 把哈希压缩为 `1..250`：

```text
node_id = 1 + (uid_hash % 250)
```

4. 屏幕格式化为：

```text
DCDW-XXX
```

同一个数字同时作为：

- 屏幕右上角当前查看对象编号；
- LoRa 内部 `node_id`；
- MAVLink `system_id`。

不同板卡可以刷同一份固件，由各自 UID 自动生成默认短编号。但哈希压缩后只有 250 个取值，**不同 UID 可能生成相同的 `DCDW-XXX`**，不能保证连接页总能区分两台设备。当前接收路径会忽略与本机 system_id 相同的帧；该编号不能当作全局唯一产品身份。

当前代码没有现场修改 Node ID 的应用接口或页面。正常生成默认编号不要求逐台修改源码；需要指定编号或处理碰撞时，缺少配置入口才是 V1.0 要补齐的问题。

## 3. 厂商唯一产品识别码

固定前缀：

```text
DCDWCNS1
```

SN 生成流程：

1. STM32 启动时读取 96-bit 芯片 UID。
2. 按 3 个 32-bit word 的大端字节序拼成 12 字节输入。
3. 对这 12 字节做 SHA-256。
4. 取 SHA-256 输出前 8 字节，按 big-endian 组装成 `uint64_t`。
5. 用字符集 `0123456789ABCDEFGHJKLMNPQRSTUVWXYZ` 做 12 位 base-34 编码。
6. 拼接为 20 字符厂商识别码：`DCDWCNS1XXXXXXXXXXXX`。

实现位置：

- `Framework/Src/px4lite_identity.c`
- `Px4Lite_IdentityFormatSerialNumber()`
- `Px4Lite_IdentityFormatVendorProductId()`

算法是纯函数，同一颗 STM32 的 UID 每次生成结果一致，不需要 Flash 缓存。

## 4. RemoteID 使用方式

RemoteID 的身份字段已改为：

```text
OPEN_DRONE_ID_BASIC_ID.uas_id = 厂商唯一产品识别码
```

也就是发送：

```text
DCDWCNS1XXXXXXXXXXXX
```

`OPEN_DRONE_ID_SELF_ID.description` 只作现场可读描述，格式为：

```text
DCDW-XXX S:XXXXXXXXXXXX
```

其中 `S:` 后面是 12 位 SN。真正的唯一身份以 `BASIC_ID.uas_id` 为准。

## 5. RPi 暂不改动

本次按需求不改 RPi 侧：

- 不新增 RPi 计算 SN；
- 不要求 RPi 作为权威身份来源；
- 原有 STM32 到 RPi 的 MAVLink/RemoteID 镜像链路保持现状。

后续如果要让 RPi/MQTT payload 携带 `vendor_id`、`box_label`、`rpi_serial` 三个字段，应在 RPi 解码侧或专门的 STM32 上报帧里追加，不影响本次 STM32 RemoteID 身份生成。

## 6. 需要注意的配置点

当前远端节点表容量由 `PX4LITE_REMOTE_NODE_MAX` 控制。`DCDW-XXX` 的短编号范围是 `1..250`，远端表现在已经按动态槽位管理，不再要求编号必须小于节点表容量。

实名登记标志字段仍按原文档开放问题处理，本次没有新增真实登记号逻辑。

## 7. V1.0 身份与通信配置目标（待实现）

本节对应 [V1.0 稳定版预发布改动文档 R2](2026-09-28_V1.0稳定版预发布改动文档.md)第 6.6—6.7 节，记录已确认范围，不修改第 1—6 节的现有实现结论。

| 项目 | V1.0 目标 |
|---|---|
| 产品身份 | 保留 `DCDWCNS1` + 12 位 SN，共 20 字符；同一算法和 UID 下保持稳定，不随 Node ID 或信道改变 |
| 现场通信地址 | 增加 `Node ID` 本机设置、保存、恢复；默认值可以继续采用 UID 派生，但不保证无碰撞 |
| 地址范围 | 沿用当前 `1..250` 约定，拒绝无效输入；同一通信网络内避免重复 |
| 生效方式 | Node ID 保存后重启生效，区分当前值与待生效值，避免收发中途身份变化 |
| 常用显示 | 简化为 `Node 01` 等形式；完整产品 ID 在设备信息二级页查看 |
| 制造和课堂配置 | 多设备使用同一份固件，学生或教师在设备上配置，无需逐台重建和烧录 |

当前 LoRa node_id、RPi MAVLink 及 RemoteID 消息帧头共用 system_id 来源。增加可配置地址后必须统一切换，相关 SELF_ID 描述和对端识别同步核对；不能只修改屏幕标签或只让 LoRa 使用新地址。长产品 ID 的身份用途保持独立。

信道是无线收发参数，Node ID 是当前 MAVLink 路径的逻辑身份。修改地址不能消除同信道争用；配置不同信道也不能替代同一通信网络内的身份区分。V1.0 提供手动选择信道、发送间隔、单次/连续发送、停止、应用及恢复，具体过程见预发布文档。

验证至少覆盖：默认地址生成、保存/重启/恢复、无效输入、重复地址、长产品 ID 稳定性、所有出口 system_id 一致性，以及主控配置与 E22 实际参数读回一致性。本次仅更新说明，未修改身份算法、持久化数据或固件。
