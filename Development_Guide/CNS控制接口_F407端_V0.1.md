# CNS 控制接口 F407 端

版本：V0.1 接口评审稿　日期：2026-11-16

本文约定 F407 需要实现的命令、受理应答、动作时序、失败提示和锁状态上报。

## 1 通信方式

UART6 默认 **115200 bit/s、8N1**，使用 MAVLink 2 标准二进制帧及 CRC。串口实验临时改参另行约定。

`S` 为当前 F407 的动态 system ID，不固定为某个设备编号。

| 方向 | 帧头来源 | 消息目标 |
| --- | --- | --- |
| Pi → F407 | `sysid=S, compid=191` | `target_system=S, target_component=193` |
| F407 → Pi | `sysid=S, compid=193` | `target_system=S, target_component=191` |

F407 仅处理发送给本机、来自上述 Pi 端点的命令。

## 2 控制命令

请求使用 `COMMAND_LONG`，消息 ID **76**；`confirmation=0`，未使用的参数全部为 `0.0`。

| 动作 | `command` | `param1` | `param2` | `param3..7` |
| --- | ---: | --- | --- | --- |
| 解锁 `arm` | 31093 | 0 | 0 | 全部 0 |
| 起飞 `takeoff` | 31091 | 0 | 0 | 全部 0 |
| 降落 `land` | 31092 | 0 | 0 | 全部 0 |
| 上锁 `disarm` | 31094 | 0 | 0 | 全部 0 |
| 急停 `emergency_stop` | 31090 | 0 | 0 | 全部 0 |
| 单电机调速 `set_motor_pwm` | 31014 | 电机编号 1～4 | PWM 脉宽 1000～2000 μs | 全部 0 |

单电机参数通过 `float` 承载，但必须是范围内的有限整数值。只修改指定电机，另外三路保持当前输出；脉宽单位为微秒，不是占空比百分数。例如 `command=31014,param1=2,param2=1300` 表示将 2 号电机设为 1300 μs。

## 3 门禁与动作时序

“随后”表示前一阶段结束后开始；“同时”表示并行执行。F407 维护实际锁状态，并完成整次动作内的电机与声光编排。

| 动作 | 锁状态门禁 | 接受后的动作 | 动作后状态 |
| --- | --- | --- | --- |
| 解锁 | 无锁状态前提 | 低音鸣响 1 s，随后四路电机进入怠速 | 已解锁 |
| 起飞 | 已解锁 | 高音快速三声，随后执行内部起飞流程，四路缓慢提速 | 保持已解锁 |
| 降落 | 已解锁 | 执行内部降落，同时高音间歇鸣响，每次约 0.5 s；四路降至怠速后结束提示 | 已解锁、怠速 |
| 上锁 | 已解锁 | 四路立即停车，同时高音鸣响 1 s | 锁定 |
| 急停 | 无锁状态前提 | 立即取消当前动作、四路无条件停车并锁定，随后高音快速两声 | 锁定 |
| 单电机调速 | 已解锁 | 执行成功声光效果，随后调整指定电机 PWM | 保持已解锁 |

怠速约 1200 μs 仅为示例，实际值及停车输出由 F407 配置和驱动确定。起降目标与加减速曲线沿用内部流程。高低音频率、快速鸣响节拍、成功／失败声光颜色和持续时间由 F407 统一定义，本接口不指定具体值。表中未指定 RGB 的动作不增加 RGB 要求。

- 普通动作执行期间，新的普通动作可回“动作忙”拒绝，不改变当前电机动作。
- 已解锁时，锁定可打断起飞、降落或调速，取消后续执行并四路停车。
- 急停可打断所有动作和声光，包括解锁序列；不得等待队列、当前动作、蜂鸣或 ACK 发送结束才停车。
- 被打断的流程不得恢复提速或修改 PWM。解锁尚未进入怠速时仍为锁定，中止该阶段使用急停。

## 4 受理应答

F407 检查目标、参数、锁状态和动作状态后，**在 2 s 内及时返回受理结果**，不等待声光或起降流程结束。

- 接受：回 `MAV_RESULT_ACCEPTED`，随后执行动作及配套声光。急停停车不得被回执发送阻塞。
- 拒绝：回拒绝结果，不执行原动作，等待 Pi 另发失败声光通知。
- **接受不等于完成。** 初版只回受理结果，不发送动作完成 ACK 或完成事件，也不使用 `MAV_RESULT_IN_PROGRESS=5` 表示动作进度。
- 无有效应答会被判为受理超时，表示是否接受未知；Pi 不自动重发原动作。

应答使用 `COMMAND_ACK`，消息 ID **77**：

| 字段 | 类型 | 内容 |
| --- | --- | --- |
| `command` | `uint16` | 原请求命令号 |
| `result` | `uint8` | 受理结果，见下表 |
| `progress` | `uint8` | 固定 255，不提供进度 |
| `result_param2` | `int32` | 细分原因；接受时为 0 |
| `target_system` | `uint8` | `S` |
| `target_component` | `uint8` | 191 |

| `result` | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `MAV_RESULT_ACCEPTED` | 已接受，允许执行 |
| 1 | `MAV_RESULT_TEMPORARILY_REJECTED` | 暂时不能接受，例如普通动作忙 |
| 2 | `MAV_RESULT_DENIED` | 门禁、参数或当前状态不允许 |
| 3 | `MAV_RESULT_UNSUPPORTED` | 不支持该命令 |
| 4 | `MAV_RESULT_FAILED` | 执行准备或内部检查失败，命令未接受 |

| `result_param2` | 原因 | 对应 `result` |
| ---: | --- | --- |
| 0 | 无细分原因；接受也填 0 | 0、3 或无细分的拒绝 |
| 1 | 未解锁 | 2 |
| 2 | 动作忙 | 1 |
| 3 | 参数非法 | 2 |
| 4 | 当前动作状态不允许 | 2 |
| 5 | 起飞内部检查未通过 | 4 |

例如，锁定时起飞应回 `command=31091,result=2,progress=255,result_param2=1`；单电机调速接受应回 `command=31014,result=0,progress=255,result_param2=0`。两者均定向发给 `S/191`。

## 5 拒绝后的失败声光

六类业务动作被接受后，F407 自行完成动作声光，Pi 不再追加通用成功提示。拒绝时 F407 不自行追加失败提示，收到以下通知后再执行：

| 项目 | 内容 |
| --- | --- |
| 外层消息 | `TUNNEL`，消息 ID 385 |
| 来源与目标 | 第 1 节的 Pi → F407 端点 |
| `payload_type` | `0x8040`，十进制 32832 |
| `payload_length` | 2 |
| `payload[0]` | 1，协议版本 |
| `payload[1]` | 0，失败；有效数据区为 `01 00` |

该通知只执行失败蜂鸣与 RGB，不改电机、不重新执行原动作、不回 ACK 或拒绝通知。使用标准 `mavlink_msg_tunnel_decode()`，允许 MAVLink 2 裁剪尾部零字节；按解码后的逻辑长度与数据判断，不要求外层为完整 TUNNEL 结构长度。本节仅约束上述六类业务动作。

## 6 实际锁状态上报

使用 `HEARTBEAT.base_mode` 的第 7 位（掩码 128，`MAV_MODE_FLAG_SAFETY_ARMED`）上报，保留该字段其他位的含义。

| 状态或事件 | 第 7 位 |
| --- | --- |
| 上电、解锁声响期间或尚未真正进入怠速 | 0，锁定 |
| 解锁动作真正使四路进入怠速后 | 1，已解锁 |
| 起飞、降落、调速期间及降落到怠速后 | 保持 1 |
| 接受锁定或急停并停车 | 立即置 0 |

锁状态必须来自 F407 实际状态，不以 PWM 大小、电机 `run_state` 或受理结果代替。

## 7 本项目实现与联调边界（2026-11-16）

本文件前六节按用户提供的V0.1原文保存。以下为当前固件配置和验证事实，面向Pi对接者及固件维护者。

- 默认开启`PX4LITE_ENABLE_CNS_CONTROL=1`。六动作的正常成功声光由F407编排；Pi不再为这些动作追加通用成功通知。拒绝后Pi发送`01 00`失败声光通知，不重发原控制动作。
- 停车为1000μs；本项目CNS怠速配置为1200μs。低音880Hz、高音3136Hz；解锁低音1秒，上锁高音1秒；起飞100ms高音/100ms间隔三声，急停两声；降落500ms高音/500ms间隔，结束于实际怠速输出。单电机先复用成功四音和绿青快闪，再写指定通道。
- 保留原起飞6秒至60%同步目标及降落8秒曲线；仅CNS降落终点改为怠速。原本地页面、旧四路31011/31012/31013参数与原本地起降流程保留；31013不等于新增单路31014。
- UART6所有COMMAND_LONG严格校验动态S/191→S/193，CNS对接按MAVLink2发送。确认参数及未使用参数不能遗漏校验；标准尾零裁剪仍由标准解码补齐。
- 普通动作先受理并排应答，完整UART ACK发送成功才放行；上锁/急停停车不等ACK。ACK仅受理一次，progress255、原因0～5，没有完成ACK或进度事件。上电/ARM声响中armed为0，四路怠速真实写入成功后为1；上锁或急停立即清0。
- CNS ACK使用16项FIFO，其中一项保留给安全撤收；满时不执行新普通动作，不覆盖旧受理。ACK优先于H1/周期数据；发送前读取真实时间并预留现有20ms UART发送预算，过期不放行动作。物理链路错误、严重调度停顿或持续超容量时，Pi仍按前述2秒超时显示是否受理未知，不自动重发控制。
- `0x8040`仍兼容原`01 01`成功通知，供其他保留业务使用；这不是CNS六动作需要补发的提示。关闭CNS开关的构建保留原入口/提示策略，不能当作V0.1运行版。
