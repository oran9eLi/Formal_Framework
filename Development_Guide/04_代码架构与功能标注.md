## 3. 功能与数据模型对应关系

| 后续功能 | 推荐模型 | 所属任务 |
|---|---|---|
| GNSS | Snapshot | 普通采集 |
| MPU6050原始采样 | FIFO | 高频采集 |
| 气压计 | Snapshot | 普通采集 |
| 电池电压/电流 | Snapshot | 普通采集 |
| 姿态与导航融合 | Snapshot | 运算/融合 |
| 报警与故障恢复 | Event Queue | 健康/报警 |
| LoRa小帧 | Frame + TX状态机 | 通信 |
| 5G大帧 | Memory Pool + Frame | 通信 |
| SD日志 | Memory Pool + CRC记录 | 日志 |
| Linux共享数据 | 双缓冲/序号 + Frame | 通信 |
| 电机控制命令 | Snapshot + Command Queue | 控制 |

## 4. 禁止跨层调用

```text
允许：
Task -> Framework API -> Platform Adapter -> Driver -> BSP/HAL

禁止：
Communication Task -> BSP_GNSS_GetRxData()
Logger Task        -> sensor_gnss.c 私有变量
Driver             -> LoRa/显示/报警业务
ISR                -> NMEA解析/printf/SD写入
```

GNSS 当前只有一条正式数据链：

```text
BSP bytes
  -> Sensor_GNSS_Service(Gnss_Snapshot_t)
  -> Px4Lite Platform Adapter
  -> Px4Lite_GnssMeasurement_t Topic
  -> Navigation Domain / Business API
```

已删除旧的 `Sensor_Driver_t`、`Sensor_Sample_t`、通道编号和
`g_gnss_driver` 兼容层。后续传感器直接定义强类型快照，不再恢复通用
`uint32_t value + channel` 样本接口。

## 5. 新传感器接入顺序

1. 复制 `sensor_module_template.*`。
2. 定义该传感器专属测量结构。
3. 实现 BSP 完整采样接口。
4. 在私有临时结构中完成校准和运算。
5. 通过 Snapshot 或 FIFO 发布。
6. 在统一采集任务中增加周期项。
7. 在健康模块中增加超时和状态映射。
8. 加入半包、超时、溢出、恢复和长期运行测试。

不允许先创建任务，再考虑数据完整性和状态机制。

## 6. 周期、所有权和单位标注

| 对象 | 强制约束 |
|---|---|
| Sensor/Estimator/Health | 使用 `vTaskDelayUntil()` |
| LoRa/5G/Logger/Display扩展任务 | 使用 `vTaskDelayUntil()` |
| `s_lora_frame` | 仅 LoRaTask 拥有，发送完成前不可覆盖 |
| `s_fiveg_frame` | 仅 FiveGTask 拥有，发送完成前不可覆盖 |
| 日志记录缓冲 | 仅 LoggerTask 拥有或从内存池租用 |
| `_ms` 字段 | 必须来源于真实毫秒时间基准 |
| `_ticks` 字段 | 只用于RTOS内部调度 |
| 蜂鸣器状态 | 由活动报警集合中的最高等级决定 |
| `Px4Lite_PlatformGetUs()` | TIM6提供真实微秒子计数 |
| 任务心跳 | Sensor、Estimator、Health完成工作后更新 |
| 看门狗 | 仅全部必需心跳健康时允许刷新 |
| GNSS驱动状态 | 只表达数据事实，不判断离线超时 |
| GNSS新数据 | 使用`rx_sequence`，不使用时间戳判新 |
| `bsp_config.h` | 统一管理外设启用、型号、引脚、总线和资源选择 |
| HAL MSP | 只配置外设时钟、GPIO复用、DMA、NVIC和FSMC引脚 |
| BSP Init | 设置波特率、FSMC时序、数据宽度和设备运行参数 |
| Device Driver | 实现SSD1963、GT911等具体器件协议，不管理MCU资源分配 |

## 7. 独立工程依赖

```text
Formal_Framework/Third_Party/
├── Drivers/
│   ├── CMSIS/
│   └── STM32F4xx_HAL_Driver/
└── Middlewares/
    └── Source/                 FreeRTOS内核与ARM_CM4F移植
```

Keil 工程只能引用 `Formal_Framework` 内部路径。禁止重新引用父工程的
`Drivers`、`Middlewares`、`App`、`Display` 或其他源码目录。
