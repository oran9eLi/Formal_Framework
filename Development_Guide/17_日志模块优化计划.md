# 日志模块优化计划

## 1. 背景

当前 Storage 模块已经完成 SD 卡 CSV 写入闭环，`storage` 任务以低优先级独占 FatFs / SD 阻塞 I/O，周期数据和事件记录分别写入当日 `YYMMDD_D.CSV` 与 `YYMMDD_E.CSV`。随着 RTC 时间保持、GNSS 自动校时、LoRa 收发统计和四路电机 PWM 控制接入，日志策略需要持续支撑运行复盘和问题定位。

本计划只描述日志模块后续优化方向和分阶段落地方式。未完成项不得在 README 或功能清单中写成已完成能力。

## 2. 当前问题

1. **SD 文件时间不准确。**
   `Storage/Src/diskio_sd_spi.c:get_fattime()` 仍使用固定日期时间，导致 SD 卡目录中的创建时间和修改时间不可信。

2. **日志文件长期追加到固定文件。**
   旧策略会把所有周期数据和错误记录追加到固定文件。长时间运行后文件过大，不利于按日期定位问题，也不利于后续导出和分析。

3. **错误记录是周期型，不是事件型。**
   当前 `nav_not_ready`、`baro_not_ready`、`battery_not_ready`、`low_voltage` 等记录会随周期数据生产重复写入。持续存在的同一故障会刷屏，降低日志可读性。

4. **周期数据缺少系统上下文。**
   原始 DATA 行主要记录导航、环境和电池字段，缺少本地时间、电机目标、告警摘要、LoRa 统计和 Storage 队列状态。该问题已在本分支第一步扩展。

5. **CSV 展示能力有限。**
   CSV 是纯文本格式，不支持列宽、字体、冻结首行等显示属性。表头可以写中文，但存在 Excel/WPS 编码识别风险，因此固件侧保持英文表头，中文含义写入文档。

## 3. 目标策略

日志分为两类文件：

```text
YYMMDD_D.CSV
YYMMDD_E.CSV
```

时间无效时使用兜底文件：

```text
UNSYNC_D.CSV
UNSYNC_E.CSV
```

规则：

- 文件日期使用本地日期，即当前显示层使用的 UTC+8 日期。
- `DATA` 只记录周期快照，保持 1 s 周期和 CSV 格式。
- `EVENT` 只记录状态变化、告警触发、告警清除、启动、校时、SD 挂载/写入异常等事件。
- 同一个 `source + fault + message` 持续存在时只写一次触发事件；恢复时再写一次清除事件。
- FatFs 文件创建时间和修改时间从 RTC/Framework 时间服务派生，不能继续使用固定时间。
- Storage task 继续保持最低优先级，其他任务不得直接调用 FatFs。

## 4. 已完成的第一步：DATA 字段扩展

本分支已先完成周期 DATA 字段扩展，仍写入当前固定数据文件，尚未启用按天滚动。

新增字段：

| 字段 | 含义 |
|---|---|
| `local_date` | 本地日期，编码 `YYYYMMDD` |
| `local_time` | 本地时间，编码 `HHMMSS` |
| `time_sync_state` | 时间同步状态，见 `Px4Lite_TimeSyncState_t` |
| `motor1_pct` ~ `motor4_pct` | 四路电机目标油门百分比 |
| `motor_run_state` | Control 模块发布的电机运行状态 |
| `active_alarm_count` | 当前活动告警数量 |
| `highest_fault_code` | 当前最高严重度告警故障码 |
| `lora_rx_count` | LoRa/MAVLink 接收完整帧数量 |
| `lora_tx_count` | LoRa/MAVLink DMA 发送完成帧数量 |
| `lora_parse_error_count` | LoRa/MAVLink 接收解析错误次数 |
| `lora_send_error_count` | LoRa 底层发送错误次数 |
| `storage_queue_count` | Storage 记录队列当前占用 |
| `storage_drop_count` | Storage 记录队列累计丢弃次数 |

当前验证结果：

- PC 单元测试：`Tests/Unit/test_storage_csv_extended_fields.c`
- Keil Rebuild 日志：`MDK-ARM/build_storage_csv_extended.log`
- 构建结果：`0 Error(s), 0 Warning(s)`

## 5. 后续分阶段计划

### 阶段 1：修正 FatFs 文件时间

目标：

- `get_fattime()` 不再返回固定日期。
- RTC 有效时，SD 目录项创建时间和修改时间使用当前本地日期时间。
- RTC/GNSS 尚未有效时，返回一个明确的兜底时间，并在事件日志中记录 `time_unsynced`。

建议实现：

- 不让 `diskio_sd_spi.c` 直接包含 Framework 头文件。
- 在 Storage 层增加轻量时间缓存，例如 `Storage_TimeUpdateFromSnapshot()`。
- Framework storage 工作函数从 `Px4Lite_CopyTime()` 取得时间快照后更新 Storage 时间缓存。
- `get_fattime()` 只读取 Storage 层缓存并编码为 FatFs 时间格式。

验证：

- 无 RTC 有效时间时，文件时间使用兜底值。
- RTC 有效后，新建文件目录项时间正确。
- GNSS 校时后，后续文件修改时间随 RTC 更新。

### 阶段 2：按天滚动 DATA / EVENT 文件

目标：

- 使用 `YYMMDD_D.CSV` 保存当日 DATA 周期数据。
- 使用 `YYMMDD_E.CSV` 保存当日 EVENT 事件数据。
- 日期变化时关闭当前文件并打开新日期文件。
- 新文件为空时写 header，已有文件继续追加。

时间无效策略：

- 时间无效时写 `UNSYNC_D.CSV` 与 `UNSYNC_E.CSV`。
- 时间从无效变为有效后，切换到当天日期文件。
- 不自动重命名 `UNSYNC` 文件，避免在嵌入式侧增加目录扫描和重命名复杂度。

验证：

- 同一天多次启动继续追加到当天文件。
- 跨日期运行会生成新日期文件。
- 时间无效到有效的切换不会丢记录。
- SD 拔插恢复后能重新打开当前目标文件。

### 阶段 3：将 ERROR 改为 EVENT 事件日志

目标：

- 停止对同一持续故障进行周期刷屏。
- 告警触发、告警清除、故障码变化、严重度变化时写事件。
- Storage 自身的挂载失败、写入失败、队列溢出、sync 失败也按事件或限频事件记录。

建议事件字段：

```text
time_ms,local_date,local_time,event_type,source,state,fault,severity,active,count,message
```

事件类型建议：

| event_type | 含义 |
|---|---|
| `BOOT` | 启动或模块初始化事件 |
| `ALARM_ACTIVE` | 告警触发 |
| `ALARM_CLEAR` | 告警清除 |
| `STORAGE_ERROR` | SD/FatFs/队列相关异常 |
| `TIME_SYNC` | RTC/GNSS 校时状态变化 |
| `COMM_ERROR` | LoRa/MAVLink 通信异常或统计阈值事件 |

验证：

- 同一个低电压告警持续存在时只写一次 `ALARM_ACTIVE`。
- 低电压恢复时写一次 `ALARM_CLEAR`。
- 故障码或严重度变化时产生新事件。
- 事件队列满时累计 drop，并在恢复后能看到统计。

### 阶段 4：中文字段说明和电脑端查看

目标：

- 固件 CSV 表头继续使用英文，保证脚本、Excel/WPS、上位机兼容性。
- 在文档中维护字段中文含义、单位和取值范围。
- 不在固件 CSV 中写列宽、空格填充或 UTF-8 BOM。

后续如果需要更好的查看体验，应在电脑端增加 CSV 转 XLSX 工具：

- 自动调整列宽。
- 冻结首行。
- 增加筛选。
- 按日期和事件类型生成工作表。

## 6. 不做的内容

- 本轮不做高频 IMU 原始数据日志。
- 本轮不做二进制黑匣子格式。
- 本轮不做 CSV 中文表头。
- 本轮不在固件侧实现列宽自适应。
- 本轮不增加目录扫描、历史文件压缩或自动删除策略。

## 7. 代码边界

- `Framework/Src/px4lite_storage.c` 负责从 Framework topic 和统计接口复制快照并生成 Storage 记录。
- `Storage/Src/storage_csv.c` 只负责 CSV 文本格式化，不访问 SD、FatFs 或 Framework topic。
- `Storage/Src/storage_sd.c` 只负责 mount、open、write、sync 和文件切换。
- `Storage/Src/diskio_sd_spi.c` 只负责 FatFs diskio 到 SD SPI，不直接依赖 Framework。
- `Storage/Src/storage_queue.c` 继续作为固定容量非阻塞记录队列。

## 8. 验证门禁

每个阶段完成后必须验证：

1. PC 侧单元测试覆盖 CSV 表头和格式化。
2. Keil Rebuild All 达到 `0 Error(s), 0 Warning(s)`。
3. SD 卡插卡启动能生成预期文件。
4. 无卡或写失败不影响 sensor、comm、display 和 control 任务运行。
5. 栈水位验证必须通过：开启 Debug 栈监控，覆盖插卡、无卡、写入、sync、文件切换和异常恢复路径；`storage` 任务以及受影响任务的最小剩余栈必须大于配置栈的 25%，且不得低于 100 word。
6. 若栈水位不达标，必须先减少局部对象、格式化缓冲、调用深度或拆分阻塞路径；不得直接通过盲目扩大任务栈掩盖问题。
7. 文档同步更新 `Development_Guide/07_移植进度与功能清单.md` 或 `Change_History/`。
