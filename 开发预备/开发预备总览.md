## 2. Remote ID 身份配置

### 2.1 GB46750-2025 国标要求的身份字段

C-RID 模块通过 DroneCAN 从 F407 接收以下身份数据，再通过 WiFi/BT 广播：

| 身份类型 | DroneCAN/MAVLink 消息 | 关键字段 | 说明 |
|---------|----------------------|---------|------|
| **基本 ID** | OpenDroneID Basic ID | `uas_id[20]`、`id_type`、`ua_type` | 无人机唯一产品识别码，国标要求固定不变 |
| **自描述** | OpenDroneID Self ID | `description[23]`、`description_type` | 飞行用途文字描述 |
| **系统信息** | OpenDroneID System | `operator_latitude/longitude`、`classification_type` | 操作员位置、分类 |
| **操作员 ID** | OpenDroneID Operator ID | `operator_id[20]`、`operator_id_type` | 操作员注册编号 |

### 2.2 id_type 枚举（GB46750 对应）

| 值 | 含义 | 国标对应 |
|---|------|---------|
| 0 | 无 | — |
| 1 | 序列号 | 产品序列号 |
| 2 | CAA 注册号 | 民航注册编号 |
| 3 | UTM UUID | UTM 分配 UUID |
| 4 | 会话 ID | 临时会话标识 |

国标 GB46750-2025 推荐使用 `id_type=1`（序列号）或 `id_type=2`（CAA 注册号）。

### 2.3 ua_type 枚举（无人机类型）

| 值 | 含义 |
|---|------|
| 0 | 无 |
| 1 | 固定翼 |
| 2 | 多旋翼/直升机 |
| 15 | 其他 |

### 2.4 身份信息固化方案

F407 没有真实 EEPROM，但有三种方案存储身份信息：

| 方案 | 存储位置 | 优点 | 缺点 |
|------|---------|------|------|
| **方案 A：编译期常量** | 定义在 `px4lite_config.h` 或新建 `remote_id_config.h` | 最简单，无法运行时篡改 | 换号必须重新编译烧录 |
| **方案 B：Flash 末尾扇区** | 预留 Flash Sector 11 (0x080E0000, 128KB) 用 HAL_FLASH API 读写 | 可一次性编程写入，重新烧录固件不丢 | 需要修改链接脚本预留该扇区 |
| **方案 C：SD 卡配置文件** | SD 卡根目录放 `remote_id.cfg` | 灵活，可随时改 | SD 卡拔了就没了，安全性低 |

**推荐方案 B**：身份信息在出厂时通过专用工具一次写入 Flash Sector 11，正常运行只读不写。这样即便重新烧录固件，身份信息也不丢失；只有专用工具能擦写。

### 2.5 需要在 F407 侧新增的配置结构

```c
/* remote_id_config.h — 需新建 */
typedef struct {
    uint8_t  id_type;             /* 1=序列号, 2=CAA注册号 */
    uint8_t  ua_type;             /* 2=多旋翼 */
    uint8_t  uas_id[20];         /* 无人机唯一识别码 ASCII */
    char     description[23];    /* 自描述文本 */
    uint8_t  operator_id_type;   /* 0=CAA */
    char     operator_id[20];   /* 操作员注册编号 */
    int32_t  operator_lat_e7;   /* 操作员纬度 degE7 */
    int32_t  operator_lon_e7;   /* 操作员经度 degE7 */
    uint32_t crc;               /* 校验，防误读 */
} RemoteId_Identity_t;
```

启动时：F407 从 Flash 读出身份 → 通过 DroneCAN 发送给 C-RID 模块 → C-RID 缓存并开始广播。

## 3. CUAV C-RID 模块要点

### 3.1 关键参数

| 参数 | 值 |
|------|---|
| 处理器 | ESP32 (Xtensa LX7 双核 240MHz) |
| 广播方式 | 2.4GHz WiFi 802.11b/g/n + Bluetooth 5 LE |
| 通信协议 | DroneCAN (CAN 2.0B, 1Mbps) + UART (MAVLink) 备选 |
| 标准 | GB46750-2025 (国标)、prEN 4709-002 (欧盟)、ASTM F3411-22a |
| 固件 | ArduRemoteID 开源 (GitHub: ArduPilot/ArduRemoteID) |
| 工作电压 | 4.7V ~ 5.2V |
| 接口端口 | CAN (GH1.25 4针) + UART (GH1.25 4针) + ANT (MMCX) |

### 3.2 固件升级步骤 (WiFi OTA)

1. 下载国标固件：`https://manual.cuav.net/other/CUAV_RID_GB46750_OTA.bin`
2. 给 C-RID 上电
3. 电脑连接 WiFi：`C-RID_XXXXXXXXXX`，密码 `cuav12345678`
4. 浏览器打开 `http://192.168.4.1/`
5. 滑到页面底部"固件升级"区域，上传 `.bin` 文件

> **国标固件一旦烧录会熔断，之后不能再更新和改配置。** 烧前确认地区和版本。

### 3.3 C-RID 与 F407 的通信

C-RID 在 CAN 上使用 DroneCAN 协议收发 OpenDroneID 消息。F407 侧需要：

1. BSP 层初始化 CAN1（1Mbps，标准帧）
2. 移植 libcanard（UAVCAN v0 轻量 C 库）解析 DroneCAN 帧
3. 将 F407 的 GNSS/姿态/身份数据按 OpenDroneID 消息格式编码后通过 DroneCAN 发给 C-RID
4. C-RID 收到后通过 WiFi/BT 广播到空中

### 3.4 C-RID 静态配置与动态数据

C-RID 可自行存储静态身份信息，无需 F407 参与。动态数据必须由 F407 通过 CAN 实时推送。

| 数据 | 谁来提供 | 配置方式 |
|------|---------|---------|
| 无人机唯一识别码 (UAS ID) | C-RID 可自存 | 网页 192.168.4.1 或 LGC 地面站 |
| 操作员编号 (Operator ID) | C-RID 可自存 | 网页 / LGC 配置 |
| 无人机类型/分类 (UA Type) | C-RID 可自存 | 网页 / LGC 配置 |
| 飞行用途描述 (Self ID) | C-RID 可自存 | 网页 / LGC 配置 |
| GPS 经纬度 | F407 提供 | DroneCAN 实时推送 |
| 高度 (气压/大地) | F407 提供 | DroneCAN 实时推送 |
| 速度 (水平/垂直) | F407 提供 | DroneCAN 实时推送 |
| UTC 时间 | F407 提供 | DroneCAN 实时推送 |
| 航向 | F407 提供 | DroneCAN 实时推送 |
| 飞行状态 (地面/空中) | F407 提供 | DroneCAN 实时推送 |

C-RID 自身没有 GNSS 模块。静态身份可以先在网页填好，但没有 F407 的 CAN 代码，
位置字段为空，广播出去的 Remote ID 包缺少经纬度/高度/速度，不符合国标要求。

### 3.4 libcanard 介绍

| 项 | 内容 |
|---|---|
| 来源 | UAVCAN 联盟开源项目 (https://uavcan.org/)，非 CUAV |
| 协议 | MIT 许可，纯 ANSI C99，代码量 <2000 行 |
| 依赖 | 只需提供 CAN 收发回调 + 内存分配器 |
| 移植要点 | 实现 `canardTxCallback`(发 CAN 帧)、`canardAllocate`/`canardDeallocate`(内存管理)，然后 `canardRxAccept()` 喂入收到的 CAN 帧，库自动分帧/重组/CRC 校验 |

## 4. RM500U-CNV 5G-A 模组要点

### 4.1 关键参数

| 参数 | 值 |
|------|---|
| 厂商 | 移远通信 (Quectel) |
| 芯片平台 | 紫光展锐 V510 |
| 5G 频段 | N1/N28/N41/N78/N79 + LTE 回退 |
| 通信接口 | USB 3.0 / PCIe 2.0 / UART / SPI / I2C |
| UART 默认波特率 | 115200 bps (8N1) |
| **IO 电平** | **1.8V** — 不能直接接 F407 的 3.3V GPIO |
| 供电 | VBAT 3.55~4.4V，峰值电流可达 2.5A |
| 固件 | 出厂自带，不需要烧录 |

### 4.2 电平适配提醒

RM500U 的 IO 是 **1.8V**，F407 是 3.3V。UART 和控制引脚 (PWRKEY/RESET/STATUS) 之间 **必须加电平转换芯片**（如 TXB0108 双向、SN74LVC 单向）。模块的 VDD_EXT 输出 1.8V（≤50mA），可供电平转换器 1.8V 侧。

### 4.3 F407 对 5G-A 的定位

- F407 只发 AT 指令做连接管理、附着查询、信号质量、恢复配置
- AT 指令收发属于 5G-A Driver 控制面，**不向 Business 层暴露原始 AT 命令**
- 实际 5G 业务数据由 **伴生计算机** 通过 USB/PCIe 直连 RM500U 处理，不走 F407
- F407 通过以太网与伴生计算机通信

### 4.4 上电时序

1. 给 RM500U 供 VBAT (3.8V)
2. 等 VBAT 稳定
3. 拉低 PWRKEY >100ms 后释放
4. 模块启动，STATUS 引脚变高表示就绪
5. F407 通过 UART 发 `AT` → 模块回 `OK` 确认通信

## 5. 开发路线图

### 阶段一：Remote ID (CAN + DroneCAN)

| 步骤 | 工作内容 | 产出 |
|------|---------|------|
| 1 | BSP 层：新增 `bsp_can.c/h`，CAN1 初始化、中断收发 | 硬件层能收发 CAN 帧 |
| 2 | 移植 libcanard 到 F407，实现 CAN 收发回调和内存接口 | DroneCAN 协议栈可用 |
| 3 | 新增 `driver_remote_id.c/h`，封装 DroneCAN OpenDroneID 消息编解码 | 能与 C-RID 对话 |
| 4 | 新增 `remote_id_config.h` + Flash 身份固化（Sector 11） | 身份信息持久化 |
| 5 | Framework 层：新增 `px4lite_remote_id.c`，启用 `PX4LITE_ENABLE_REMOTE_ID=1` | Remote ID 服务跑起来 |
| 6 | Keil 工程加入新文件，Rebuild All 0E/0W | 可烧录验证 |

### 阶段二：5G-A (UART + AT 指令)

| 步骤 | 工作内容 | 产出 |
|------|---------|------|
| 1 | 硬件：电平转换电路设计确认 | 1.8V/3.3V 安全对接 |
| 2 | BSP 层：新增 `bsp_5ga.c/h`，UART 初始化、AT 收发 | AT 通信通路 |
| 3 | 新增 `driver_5ga.c/h`，AT 状态机（信号查询、附着、模块状态） | 5G-A 连接管理 |
| 4 | Framework 层：启用 `PX4LITE_ENABLE_5G=1`，5G 状态接入 Health/Alarm | 5G 状态灯反映 |
| 5 | Keil Rebuild All 0E/0W | 可烧录验证 |

### 阶段三：伴生计算机 (以太网)

| 步骤 | 工作内容 | 产出 |
|------|---------|------|
| 1 | 硬件：以太网 PHY 选型（LAN8720A 等），确认 50MHz 时钟方案 | 物理链路通 |
| 2 | BSP/Driver：移植 lwIP 或裸 UDP/TCP 协议栈到 F407 | 网络层可用 |
| 3 | 应用层：定义 F407 ↔ 伴生计算机 IPC 协议 | 数据交换通路 |
| 4 | 伴生计算机端开发 5G 数据面 + IPC 客户端 | 全链路闭环 |
