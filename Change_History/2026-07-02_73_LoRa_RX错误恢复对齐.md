# 2026-07-02 LoRa RX 错误恢复对齐

## 背景

实机反馈 LoRa TX 计数持续增加，但 RX 一直为 0。该现象说明 MAVLink 协议层尚未收到任何完整帧，问题优先排查 USART3 RX DMA、错误中断恢复和 E22 接收链路。

## 改动

- `Core/Src/stm32f4xx_it.c` 中 `USART3_IRQHandler()` 的 LoRa 错误分支改回 `lvgl` 参考工程的处理方式。
- 当 USART3 出现 `ORE` / `NE` / `FE` / `PE` 时，ISR 直接调用 `BSP_LoRa_RecoverRx()`，立即清错误、重启 RX DMA 并恢复 `IDLE` / `ERR` 中断。
- 不再在 LoRa 错误分支里只设置 deferred recover 标志后等待 comm task，避免错误中断后 RX 路径长时间关闭，表现为 TX 增加但 RX 始终为 0。

## 栈和实时性

- 未新增 FreeRTOS task。
- 未扩大 `PX4LITE_STACK_COMM` 或其他任务栈。
- 本次只恢复 USART3 RX DMA 错误恢复入口，不改变 MAVLink 编解码和显示数据结构。
