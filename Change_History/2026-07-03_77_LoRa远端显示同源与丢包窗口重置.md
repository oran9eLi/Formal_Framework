# 2026-07-03 LoRa 远端显示同源与丢包窗口重置

## 背景

- 实机反馈远端页面仍有部分本地同源数据收不到，消息日志不同步。
- 旧丢包率会把中途断链后的大段序号跳变计入同一个窗口，恢复后容易长期显示异常高丢包。

## 代码调整

- `Framework/Inc/px4lite_config.h`：打开 `PX4LITE_MAVLINK_ENABLE_MESSAGE_LOG`，并把 `LOGSYNC` 周期调整为 1000 ms；新增 `PX4LITE_MAVLINK_ENABLE_DATETIME` 和 `PX4LITE_MAVLINK_DATETIME_PERIOD_MS`。
- `Framework/Src/px4lite_mavlink_tx.c`：新增 `BAT2STAT` 第二电池扩展帧和 `GNSSUTC` 时间扩展帧；远端显示数据目录继续保持分项 catalog 调度，不拼全量显示大包。
- `Framework/Src/px4lite_mavlink_rx.c`：接收 `GNSSUTC` 并写回远端导航时间字段；远端槽位丢包率在 RX 间隔超过 3 s 后重置窗口，从下一帧重新计算。
- `Driver/Comm/Src/lora_e22.c`：底层 LoRa 调试统计按同样 3 s 断链窗口重置，避免拔插或长时间无 RX 被累计成持续高丢包。
- `Business/Src/app_data_api.c`：远端显示快照收到 GNSS UTC 后按本地时区派生 `local_date_ymd` / `local_time_hhmmss`，让远端页面头部时间与本地显示口径一致。

## 栈和 RAM

- 未新增任务，未扩大任何任务栈。
- 新增状态为文件级静态标量和一个 256 项 `uint32_t` 序号时间表；未在 `comm` 或 `biz_display` 栈上放全量显示快照、大日志表或大 payload。
