# 2026-07-02 LoRa 旧路线清理

## 背景

教学现场当前只需要两块板通过 LoRa 互发 MAVLink 遥测并观察调试数据。旧的多从机远端查看产品路线已经不作为当前基线，继续保留会占用静态 RAM、增加 comm 任务解析面，并让学生误解链路规则。

## 改动

- 删除 `Framework/Src/px4lite_remote_tunnel.c` 和 `Framework/Inc/px4lite_remote_tunnel.h`，并从 Keil source list 移除。
- `px4lite_mavlink_tx.c` 移除 LORASUM、REMOTE_STATUS、REMOTE_MOTOR、REMOTE_ALARM、REMOTE_LOG 和旧 stream/node poll 调度残留。
- `px4lite_mavlink_rx.c` 移除 MAVLink TUNNEL 告警/日志解码和 MOTORPWM 私有远端电机解码。
- `px4lite_command.c` 不再执行旧 `MAV_CMD_USER_1/2` stream/poll 命令；对本机目标的未知 `COMMAND_LONG` 回复 `COMMAND_ACK UNSUPPORTED`。
- `Px4Lite_RemoteTelemetry_t` 和 App 远端视图移除旧日志、远端电机目标、LORASUM 租约、active viewer 和倒计时字段。
- 远端消息日志 API 当前返回空，Display 远端日志不再依赖 LoRa REMOTE_LOG。

## 栈和 RAM

- 未新增任务，未扩大 `PX4LITE_STACK_COMM`。
- 删除旧 TUNNEL 大 payload 解码、远端日志数组、远端告警表和租约状态后，静态 RAM 压力下降。
- LoRa 教学链路继续使用静态 scratch 和 MAVLink catalog 单帧调度，不在 comm/display 栈上放大对象。
