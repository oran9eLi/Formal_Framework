# 2026-07-02 LoRa 外接电源状态恢复收口

## 背景

现场测试反馈 LoRa 改为外接电源后仍存在状态异常：如果 E22 没有和 STM32 同时上电，后续再接通外部电源仍保持红灯；如果一起上电则红黄闪烁；关闭 LoRa 外部电源后也可能红黄闪烁。根因是 LoRa 本机硬件可用性、初始化恢复过程和对端 MAVLink 链路新鲜度没有完全拆开，recovery 阶段的临时错误会把显示状态反复拉动。

## 修改

- `Lora_E22_Init()` 在 AUX 超过初始化窗口仍不可用时返回 I/O 错误并锁存本机硬件离线事实，避免未供电模块长期停留 STARTING。
- `Lora_E22_GetState()` 在未初始化但 AUX 已恢复高电平时清除本机离线锁存并请求 `comm` task 重新初始化，支持 LoRa 外接电源晚于 STM32 上电的场景；re-init 会同步重建 BSP USART3/RX DMA/TX DMA。
- LoRa ONLINE 只由近期收到合法 MAVLink 对端帧确认；本机 E22 已上电但暂无对端帧时保持 DEGRADED/黄灯；本机硬件不可用时保持 OFFLINE/红灯。
- `Px4Lite_CommWorkRun()` 对 STARTING/recovery 阶段的临时 I/O 错误做降级处理，避免本机可恢复阶段在红黄之间反复跳变。
- AUX 连续超过本机存在超时仍未恢复时，优先判定本机离线，不再被周期性 LoRa TX 重试掩盖。
- SD 卡重新挂载前先关闭旧文件、卸载 FatFS 并复位 diskio 状态，修复启动无卡或热插拔后插回仍不恢复的问题。
- 同步更新 `Development_Guide/02_架构边界与数据流.md` 和 `Development_Guide/05_完成度与后续清单.md`，明确 LoRa 三色状态来源和外接电源恢复规则。

## 验证

- Keil MDK-ARM Rebuild All 通过：`.\Objects\formal_framework.axf - 0 Error(s), 0 Warning(s)`。
- 构建大小：`Code=266424 RO-data=91648 RW-data=1352 ZI-data=97680`。

## 现场判定

- LoRa 未供电或 AUX 长期不可用：红灯。
- LoRa 本机已上电但没有收到对端合法 MAVLink：黄灯。
- LoRa 近期收到对端合法 MAVLink：绿灯。

若仍出现一接 LoRa 就卡死或状态完全不符合上述规则，继续优先排查硬件：外部电源必须与 STM32 共地，TXD/RXD/AUX/M0/M1 必须为 3.3V TTL，避免通过信号线反向供电。
