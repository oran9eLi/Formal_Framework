# 2026-07-03 LoRa VIEW 租约教学链路收口

## 背景

教学场景需要多块板卡在同一 LoRa 信道、频率和空中速率下验证通信能力。原先“所有节点持续外发全量遥测”的方式在多板同时上电时容易提高空口碰撞概率，也会让学生难以判断到底是 LoRa 参数不一致、空口拥塞，还是数据链路没有打开。

## 本次收口

- 远端节点表上限从 17 扩展到 41，用于覆盖 `DCDW-001` 到 `DCDW-040` 的教学编号。
- LoRa/MAVLink 默认只发送 HEARTBEAT；除 HEARTBEAT、COMMAND_LONG 和 COMMAND_ACK 外，GNSS、姿态、环境、电池、告警、电机和日志等全量遥测只在收到 VIEW 租约后发送。
- HEARTBEAT 使用 40 个 150 ms 槽位组成的 6000 ms 周期，并按 DCDW 编号计算初始发送偏移，降低 30 台左右同场测试时的固定碰撞概率。
- 选中远端节点时，Business 通过 `Px4Lite_MavlinkStartRemoteView()` 请求目标节点开启 20 s 全量数据租约；请求端每 5 s 续租一次，未收到 ACK 前按 300 ms 重试。
- 返回本地或切换目标节点时，Business 通过 `Px4Lite_MavlinkStopRemoteView()` 连续发送 3 次停止请求，目标节点收到后立即退出全量发送。
- VIEW_REQ / VIEW_STOP 统一进入 `px4lite_command.c`，RX 只负责字段解码，TX 只负责排队发送命令和 ACK，不把控制策略散落在收发文件中。

## 验证口径

- 本次改动不新增任务，不扩大 `PX4LITE_STACK_COMM`，新增状态均为 `px4lite_mavlink_tx.c` 文件级静态变量。
- LoRa 红灯仍表示本机硬件不可用；黄灯表示本机 LoRa 可用但没有近期有效对端帧；绿灯表示近期收到合法对端 MAVLink 帧。
