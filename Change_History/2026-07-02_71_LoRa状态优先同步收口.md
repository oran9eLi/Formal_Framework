# 2026-07-02 LoRa 状态优先同步收口

## 背景

实机测试中，两机均能发现对端，但远端页面仍出现姿态、告警、油门、电机状态、湿度和消息日志不同步的问题。根因是显示关键状态与日志/大项遥测同优先级竞争，且电机只用单个 `MOTORPWM` 聚合帧，丢一帧就会导致整组数据长时间旧值。

## 改动

- `px4lite_config.h` 将状态类遥测周期收紧：`SYS_STATUS`、`MODSTAT0/1`、告警摘要和电机均为 1000 ms；压力/湿度/电池为 4000 ms；`LOGSYNC` 降为 5000 ms；retry 降为 50 ms。
- 实机反馈 001/002 身份已分开但仍连不上后，新增 `PX4LITE_MAVLINK_TX_SLOT_MS` / `PX4LITE_MAVLINK_TX_SLOT_COUNT` 分时发送门控，并把状态周期回退到更稳的半双工预算：状态/告警/电机 2000 ms，环境/电池 6000 ms，`LOGSYNC` 10000 ms，retry 200 ms。
- `px4lite_mavlink_tx.c` 增加 `ALRMHI` / `ALRMMSK` 告警摘要帧，不在 comm 栈上复制完整告警表，只使用 `Px4Lite_CopyAlarmSummary()` 和逐条 `Px4Lite_CopyAlarmRecord()`。
- `px4lite_mavlink_tx.c` 将电机外发改为 `MOTOR12` / `MOTOR34` 两帧分片，并在油门、run-state 或 speed level 变化时发送 4 帧有界 urgent 数据。
- `px4lite_mavlink_rx.c` 兼容旧 `MOTORPWM`，新增 `MOTOR12` / `MOTOR34` / `ALRMHI` / `ALRMMSK` 解码并写入 `Px4Lite_RemoteTelemetry_t`。
- `app_data_api.c` 远端告警数量改为按 `alarm_active_mask` 计数，避免只显示最高告警导致数量不同步。
- `Development_Guide/02_架构边界与数据流.md` 和 `Development_Guide/03_模块接入手册.md` 同步记录 LoRa 教学链路的状态优先同步规则。

## 栈和内存

- 未新增 FreeRTOS task。
- 未扩大 `PX4LITE_STACK_COMM` 或其他任务栈。
- 新增状态均为文件级静态标量或小结构；告警摘要不使用完整告警快照压栈。
