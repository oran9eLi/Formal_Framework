# 2026-07-01 从机 SRAM 余量收口

## 背景

从机实机出现死机现象。代码审查和 Keil map 复核发现，当前从机构建虽然能够通过编译，但 STM32F407 主 SRAM1 静态占用已经接近 128KB 上限。

修复前 `RW_IRAM1 Size=0x1fc28`，距离 `0x20000` 上限仅剩 984B。此时 LVGL 页面、LoRa/MAVLink 远端缓存、FreeRTOS heap、任务栈和中断现场没有可靠运行余量，容易表现为 HardFault、malloc failed、stack overflow 或任务卡死。

## 修改

1. `Display/Src/lv_port_disp.c`
   - LVGL SSD1963 draw buffer 从 `800x32` 行条带收缩为 `800x16` 行条带。
   - 静态显示刷新缓冲从 51.2KB 降到 25.6KB。
   - 文件头注释同步说明缓冲大小、SRAM1 余量和 CCM 不可用于 DMA 的约束。

2. `Development_Guide/02_架构边界与数据流.md`
   - 增加 LVGL draw buffer、SRAM1 余量和 Display 层私有资源边界说明。

3. `Development_Guide/04_调试验证与发布门禁.md`
   - 增加 Keil map SRAM1 门禁：发布构建必须检查 `RW_IRAM1`，当前参考余量不低于 20KB。

4. `Development_Guide/05_完成度与后续清单.md`
   - 记录从机死机根因、修复内容、构建结果和后续实机验证点。

## 后续实机验证

1. 从机单板启动后观察是否仍进入 HardFault、stack overflow hook 或 malloc failed hook。
2. 双板主从运行时观察 LoRa TX/RX 计数、远端 heartbeat、远端页面数据、告警和消息日志同步。
3. 切换 LVGL 页面时观察 `Display_LvglBudgetStats_t`，确认 `budget_busy_count` 增长不会拖垮 `sensor` 和 `comm` heartbeat。
4. 若后续新增 Remote ID 字段、5G-A 状态或更多从机缓存，必须重新检查 `RW_IRAM1` 余量。
