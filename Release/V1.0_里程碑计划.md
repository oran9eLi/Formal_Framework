## 1. 目标与管理方式

交付可供学生完成传感器、姿态、定位、通信和无桨电机实验的 V1.0 稳定版固件。学生能主动配置、开始、观察、停止和恢复实验；设备持续保证保护、数据真实性和基本收发。

2026-10-14 确定实体交付目标：采用现有 STM32F407 硬件、现有模块及连接方式，组装一台能够完整使用与展示的设备，见[单台组装与展示方案](V1.0_硬件升级与外观设计方案.md)。原 R2 硬件与外观升级归入[V2 方案](V2.0_硬件升级与外观设计方案.md)，不作为 V1 完成前提；H743 在 V1 完成后评估，未承诺归入 V2。原 40 套、约 40 天不作为当前交付承诺，V2 数量及排期重新评估。单台目标保留原功能、通信对端/工装、实板、资源和长稳验收要求。

从本计划起，以 **V1-M0—V1-M8** 管理本轮交付，不继承旧模块台账、旧 M1—M5 或阶段一里程碑的勾选状态。已有代码继续作为开发基础；历史通过记录可供查阅，但须核对版本、配置与覆盖范围，才能作为新台账证据。

## 2. 全局约束

- 六个主要页面保留中文名称；移除品牌区和非自检页重复状态栏，短英文用于日志、诊断和必要状态。
- 本机主要页面使用本机数据；远端数据只进入通信下的一个只读二级页面。取消全局远端切换和 LoRa 完整日志历史同步。
- 学生手动配置 Node ID、信道、发送内容和间隔，主动发送、停止与恢复；不新增自动配对、选信道、分配地址或跳频。
- 屏幕保留数据、单位、操作和短反馈，原理、长说明及排查步骤进入实验手册。
- 低压闭锁、急停、异常撤收、数据过期和看门狗持续工作；观察暂停与页面切换不能改变控制结果。
- 使用 STM32F407、HAL、FreeRTOS、Keil MDK / ARMCC 5.06；保持 App API、平台适配、Driver、BSP 边界和硬件资源单一任务所有权。
- V1 沿用现有硬件与连接体系，完成必要装配、接线修复、固定、绝缘、整理和标识；统一外壳/底座、新连接器与线束、P25 Pro候选、条件罗盘及新增蜂鸣器/指示灯等按V2方案维护。
- 启动后不再动态分配；诊断和绘图采用固定容量与可控刷新。DMA 缓冲在主 SRAM，不能放入 CCM。
- 固件变更执行 Keil 构建验证；候选 Rebuild All 必须为 `0 Error(s), 0 Warning(s)`。具体软件与实板结果分别记录。
- A01—A17、L01—L17 必须逐项处置。删掉页面不能关闭仍在运行的缺陷；P1 保护问题必须修复并验证。
- 尚未确认的减法和性能条件项只进入决策表；未经范围冻结，不当作已批准删除或必做功能。

### V1-M0：范围与基线冻结

**交付：** 本计划、执行台账和本轮配置清单。

- 建立新编号，登记 `develop / v0.1.0-beta.2` 与实际提交、本地工程差异；本轮所有新增能力单独验收。
- 按台账D19—D21记录单台装配目标、现有硬件/接线清单、V2升级迁移和H743评估时点；实物配置仍须核验，范围确认不表示装配完成。
- 逐项决定日志布局、诊断合并、曲线、参数、回放、节点容量、调试和实验状态恢复范围，结论进入台账 D01—D11；为曲线、统计、定位漂移及记录操作列出首批采用/延期清单。
- 固定首批实验数据模式、消息清单/周期、信道候选及实板核验方式、Node ID 生效方式、持久化边界和配置失败行为。
- 给页面、事件历史、原始帧捕获和条件增强分配容量与刷新预算；沿用 2 ms 显示单步预算，并给触摸响应、采样间隔和课堂收发实验确定可量测门限。

**通过条件：** 已确认、延期、退出范围各有记录；涉及当前实现的接口和预算可检查。未选定的增强不能默认进入 M5。建立文档本身不代表 M0 已冻结。

### V1-M1：保护与启动可靠

**问题映射：** A01、A02、A14；心跳门限与启动卡死的验证缺口。

准备材料：[V1-M1 保护与启动准备及验收方案](V1.0_M1_准备与验收方案.md)，含改动前代码路径、XRotor 20A 资料、实施参数和实板用例；[V1-M1 实施计划](V1.0_M1_实施计划.md)将其拆为五步。软件实施与验证结果见[M1 验证记录](V1.0_M1_验证记录.md)，实板待验，进度以执行台账为准。

- 本机低压闭锁持续依据本机电源事实维护，进入远端或诊断页、暂停显示均不能暂停保护。
- Fault / Error / assert / 栈溢出等终止入口及时撤收四路 PWM；独立于正常调度和看门狗复位。
- 明确保护恢复后的输出规则，不恢复旧油门；覆盖手动急停。
- 修复 RTC 保留 LSI 选择后的启动路径，核对任务周期与心跳门限、看门狗启动前失效处理。

**通过条件：** 构建及定向验证通过；低压/断采/恢复和致命异常有实板记录，四路 PWM 撤收有波形与实际时限。实板证据缺失时保持待验证。

### V1-M2：数据、收发与恢复可信

实施范围与接口见 [M2 实施计划](V1.0_M2_实施计划.md)，实际软件/构建/实板结果见 [M2 验证记录](V1.0_M2_验证记录.md)。M1 实板验证按用户安排与后续功能固件合并执行，保持待验。

**问题映射：** A03—A13、A15—A17。

- 修复 MAVLink 解析器重置、CRC/解析/序号统计和远端槽位一致性；核对 GNSS DMA 并发。
- 分离链路活动与测量时间，逐域维护位置、速度、时间、姿态、电源、环境的有效期。
- 修复横滚跨界、ADC 探测开关、BME280 测量推进；高优先级采集路径的诊断打印移交 Debug。
- SD 文件准备失败、触摸首次初始化失败进入可见、限速的恢复流程；保留资源任务所有权。
- 按消息定义修正 RemoteID 时间、地速与航迹，不把相对 yaw 当作地面航迹。

**通过条件：** 每个 A 项有独立处置及验证证据；半帧/错帧/重连、单域断流、恢复和时间边界行为正确。A17 按冻结后的容量验证身份与复制一致性，不因节点数减少跳过并发检查。

### V1-M3：页面与日志收敛

**范围映射：** U01—U03、N01；L01—L13、L15—L16。L14、L17 的最终关闭归 M4。

实施材料：[M3 实施计划](V1.0_M3_实施计划.md)、[M3 验证记录](V1.0_M3_验证记录.md)。D01—D03 于 2026-10-03 确认采用；实际完成状态仍以执行台账为准。

- 删除品牌组合及冗余说明；仅自检保留模块状态网格，保留六个主入口、必要身份/时间/告警。
- 建立两层导航和可复用控件/工作区，取消全局远端模式；给通信二级页保留明确入口。
- 区分活动告警、启动检查和本机事件历史；采用短英文、真实时间、准确严重度和操作名称。
- 事件由所属功能的实际状态转移生成，覆盖接受、拒绝、开始、完成、中止、恢复；切页不重复生成，显示异常不停止核心记录。
- 按 D01—D03 的结论落实布局，不机械地为每个诊断名称新建页面。

**通过条件：** 800×480 实屏确认文字、触摸、返回、冻结与重复操作；日志含义、触发和去重有记录。L15 验证回绕、重启、覆盖及保留消费路径。没有实测依据不宣称删除 Logo 后 CPU 负载达标。

### V1-M4：手动 LoRa 实验闭环

**范围映射：** C02、远端页、L14、L17。

准备材料：[M4 准备与设计方案](V1.0_M4_准备与设计方案.md)。2026-10-12 用户采用 D08/D09 及 D11 的 M4 部分；一个活动对端、四项必要配置及上电不恢复连续发送的范围已确认。具体设计待评审，进度及证据统一记录在执行台账。

- 分开 LoRa 与 RPi 的发送配置和状态，LoRa 只保留必要心跳/身份、状态摘要和一种选定实验数据；退出完整日志同步与历史重播。
- 学生能选择内容、间隔，单次/连续发送和停止；未进入发送状态时不得因切页自动启动实验发送。必要心跳与状态摘要的行为在 M0 固定。
- 本机设置、保存和恢复 Node ID；重启统一生效，显示当前/待生效值。长产品 ID 不变，LoRa/RPi/RemoteID 帧头与身份描述一致。
- 实现信道配置事务：停止实验发送、等待空闲、写入/读回、恢复正常模式、显示实际值、学生重新启动；配置期间所有共用发送调度服从事务独占。
- 明确保存值与 E22 实际参数的校验、掉电和恢复默认行为；失败不得显示虚假成功，配置响应不得进入 MAVLink。
- 远端页只读，显示身份、所选数据、年龄和统计，断流为 `STALE`，无值为 `N/A`；连接事件为本机观察事实。

**通过条件：** 同一固件可在设备上改地址与信道；受验单台配合现有对端或测试工装完成匹配、地址冲突、同信道负载、分信道/降频/轮流发送及恢复。各用例所需节点数、角色及交互行为仍按原验收矩阵配置并留证，不要求本轮为此新组装多台完整实验箱；现有工装不能覆盖的必需用例继续待验。对配置超时、拔插、掉电留证；RPi/H1 与 RemoteID 保留路径无回退。不能仅因隐藏入口认定旧同步已停止。

### V1-M5：教学操作与诊断

**范围映射：** T01、C01、冻结后纳入的 T02、P01。

准备材料：[M5 教学操作与诊断准备方案](V1.0_M5_准备与设计方案.md)。2026-10-12 用户确认共享最多两路曲线、统计、定位漂移、手动 CSV 及已有课程有界参数，屏内回放/通用参数编辑延期。2026-10-13用户授权按R2实施，六步软件/审查修正及电脑LoRa工具已交付；当前候选实板和运行门限待验证，状态与证据以执行台账及[M5验证记录](V1.0_M5_验证记录.md)为准。

- 补齐电源、环境、姿态、定位和电机的有效数据、单位、真实操作对象与结果；PWM 不标为实测 RPM，yaw 不标为真北航向。
- MAVLink Inspector 提供 Messages / Raw / Decoded、LoRa/RPi 与 RX/TX 选择、受控捕获和清除；支持的字段范围明确。
- 从生产收发路径建立独立有界诊断副本，保存真实完整帧；不能消费生产 RX 队列，缓冲满也不阻塞生产业务。Queued、UART TX complete 和对端回显分别表达。
- NMEA 查看采用独立限量副本；串口实验衔接既有 H1 回显和 115200/57600 临时切换，复位恢复规则不变。
- 仅实现 M0 冻结纳入的曲线、统计、漂移、有界参数和记录操作；固定数据源/会话，缺测不补旧值，操作不绕过保护。
- 落实刷新预算、变化更新、字体裁剪、固定缓冲与控件复用；记录静态内存和运行水位。

**通过条件：** 基础与已选增强的“操作—观察—比较”闭环通过实板；捕获与显示负载不破坏采集、控制和通信。FreeRTOS 堆峰值低于 75%，任务最低剩余栈大于配置的 25% 且不少于 100 word；LVGL 峰值/碎片、刷新和触摸指标满足冻结预算。

**交付：** 至少 24 小时长稳记录和放行结论。
