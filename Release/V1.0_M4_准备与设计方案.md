## 1. 目标、授权与推进条件

用户要求继续 M4，并确认一起采用：一个活动对端；界面只开放 `Node ID / Channel / Data / Interval`；上电恢复必要配置，连续发送由学生重新启动。对应 D08、D09 及 D11 的 M4 部分。M5 的曲线、统计等恢复状态仍在 M5 冻结。

学生使用同一份固件，在本机完成地址和信道设置，选择一种数据，单次或连续发送；在通信的只读远端视图观察结果、调整冲突并比较。沿用短英文、两层导航、固定控件和短结果反馈；实验原理与完整步骤放实验手册。

按里程碑计划第 3 节，前一阶段等待实板时可以推进独立的后续软件工作。M3 已有导航、事件与本机化接口，2026-10-12 用户已烧录且首轮显示观察未发现问题，足以启动 M4 准备。M1/M2/M3 未齐的验收证据继续保留，不能据此关闭前序阶段。

基线为 `develop` / `bbf917f81984cd35ad9f075d2d98f7cd981f9e90` 加当前 M1/M2/M3 未提交修改。M3 开发构建资料在 `build/v1_m3/final/`；旧 `v1.0_M4_ACCEPTANCE.md` 属于历史材料，不继承完成标记。本轮已完成代码路径核对和设计准备，尚未修改固件。

## 3. 方案选择与责任边界

采用独立的 LoRa 实验状态机，复用已有编码器、App API 和显示工作区。完整同步方案增加空口负载和多快照一致性工作；单纯增加 UI 开关则无法退出后台旧路径。独立状态机能明确区分学生请求、硬件忙、配置过程和真实发送结果，改动集中在通信边界。

| 层级 | 责任 |
|---|---|
| Display / Business | 编辑候选值，提交请求，复制状态与数据；记录可见操作结果，不做串口或 Flash I/O |
| Framework | 实验会话、基础帧调度、身份加载、参数校验、选中对端和事件；CommTask 消费通信请求并独占 E22 |
| Platform Adapter | 在 `px4lite_platform_f407.c` 中接入 Driver/BSP，并转换类型；其他 Framework 源码不包含 BSP 头 |
| Sensor Driver | E22 寄存器命令及响应、模式切换状态、串口字节分流、硬件事实和恢复请求 |
| BSP | GPIO、UART/DMA、原始收发；配置存储后端只负责边界内读写和结果 |
| Core | 启动顺序编排；地址在任何链路身份初始化前确定 |

新增状态和缓冲静态分配，不新增 RTOS 任务。临界区仅复制请求/快照和索引，禁止把配置 I/O 或日志格式化放入临界区。

## 4. 发送范围与操作状态

### 4.1 消息和参数

首版保留 `HEARTBEAT`、稳定产品身份 `OPEN_DRONE_ID_BASIC_ID` 和 `SYS_STATUS` 基础摘要。建议基础周期分别为 2 s、5 s、5 s；这些是设计值，需由实板空口预算验证。`Stop` 停止实验数据，基础身份/心跳/状态仍可发送；配置独占期间整个 LoRa 出口暂停。

`Data` 首批候选为 `GNSS / Attitude / Power / Environment`，默认选择 Attitude，一次仅发送当前一种：

| Data | 复用消息 | 页面语义 |
|---|---|---|
| GNSS | `GPS_RAW_INT` | Fix、卫星数、位置/高度/速度，逐字段按有效性显示 |
| Attitude | `ATTITUDE` | Roll / Pitch / relative Yaw 与角速度，yaw 不标真北 |
| Power | 主/次 `BATTERY_STATUS` | 电压、电流、电量；缺测为 N/A，不把 0 当未知值 |
| Environment | `SCALED_PRESSURE` 与现有湿度摘要 | Pressure / Temperature / Humidity，各自年龄和有效性 |

`Interval` 候选为 1000 / 2000 / 5000 / 10000 ms，默认 2000 ms；不同数据组合按实际参数读回和最坏完整帧长度校验预算，过快时返回 `Rate limit`，不给虚假频率。多帧数据组先复制一次新鲜快照，再分步发送；忙时不能无界排队或补发积压历史。数据不新鲜时报告 `No data`，接收端独立过期。

上电恢复项限定为 Node ID 与实际 Channel。Data/Interval 回到上述默认选择与间隔；对端选择和实验会话仅驻 RAM。它们的复位规则写入实验手册，不把“恢复配置”扩展为恢复实验过程。

RPi 的现有完整遥测、告警/日志表、H1 回显与临时速率切换保留独立目录、周期、状态和序号。不能通过关闭共用消息宏来缩减 LoRa；RemoteID 与 RPi 身份出口仍能在 E22 缺席或配置时工作。

### 4.2 会话与结果

| 触发 | 行为 |
|---|---|
| 上电、切页、返回 Remote | 实验为 STOPPED；切页只改变显示 |
| `Send` | 接受一次有界数据组；不进入连续发送 |
| `Start` | 当前参数合法、模块已核验且有可发送数据时进入 RUNNING |
| `Stop` | 停止新实验提交，取消尚未提交的组内帧；已开始的 DMA 有界完成 |
| 运行中编辑 Data/Interval | 先停止本次实验，参数提交成功后由学生重新 Start |
| Apply、Restore、模块拔出或配置失败 | 停止实验；恢复后保持 STOPPED，学生重新启动 |
| Freeze | 只冻结观察数据，收发/配置/日志/告警持续工作 |

状态分开表达 `Queued`、`UART done`、`Module idle` 和 `Remote RX`。驱动异步 copy 返回 OK 不是空口发送或对端收到；UART 完成由 DMA TC 回调确认，AUX 空闲是模块事实，接收结果由另一台设备观察。无回显契约时不显示 `Delivered`。

## 5. Node ID 保存与启动生效

地址范围保持 1..250，未设置时用现有 UID 默认值。当前值、编辑值和保存后的待生效值分别显示；保存成功提示 `Saved / Reboot`，本次运行的所有链路继续使用同一当前地址，重启后 LoRa/RPi/RemoteID 和短身份描述一致切换。长产品 ID 不随地址改变。

持久化方案比较：

| 方案 | 取舍 |
|---|---|
| SD 小配置文件 | 能复用文件系统，但移卡、缺卡或 SD 故障会改变地址恢复条件；不宜作为基本通信地址的唯一存储 |
| RTC 备份寄存器 | 小且易读写，但完全掉电保存取决于实际 VBAT，当前工程未提供该硬件证明 |
| 内部 Flash 追加记录（推荐） | 不依赖 SD/VBAT，需保留区、掉电提交规则和写入时延验证 |

推荐在 1 MiB F407 的 sector 11 保留 `0x080E0000..0x080FFFFF`，应用链接区限制到此前。固定 64 B 记录，容量 2048 条，保存格式逐字段编码，含版本、序号、Node ID/恢复默认标志、硬件 UID、CRC 与末尾提交标记。只在完整写入、读回和校验后报告保存成功；启动选择最新有效且属于本机的记录，跳过掉电中断的槽，损坏记录不覆盖旧有效配置。

运行时只向空白槽追加，禁止擦扇区；重复保存同值不写入。CommTask 是配置追加的唯一运行期写者，通过平台适配调用原始存储后端，按字分步执行。请求要求电机已停止、供电事实新鲜稳定；Control 在保存期间持有短时配置维护锁并拒绝新的启动/解锁请求，避免检查后又启动，结束时也不恢复旧输出。维护锁不能屏蔽低压、急停、故障撤收或正常心跳门控。Flash 编程也可能暂停取指，必须测单步最坏时间，不能仅凭“分步”宣称无影响。空间满返回 `Config full` 并保留旧值；首版不加入运行时垃圾回收。维护擦除需在独立安全流程中明确执行，整片烧录擦除会丢配置，烧录说明必须交代保留区行为。

选用 Flash 是地址不依赖 SD/VBAT 的具体产品理由，不引入数据库。STM32F407 的 Flash 写/擦可能阻塞同片 Flash 读取，见 [ST RM0090 第 3.6 节](https://www.st.com/resource/en/reference_manual/dm00031020-stm32f405-and-stm32f407-advanced-armbased-32bit-microcontrollers-stmicroelectronics.pdf)。

## 6. E22 信道事务与恢复

代码指向 E22-400T30D；本机接线与实际模块子版本仍需实板登记。厂商系列手册给出串口寄存器配置模式，配置模式使用 9600 8N1；不能把工作模式常量直接等同配置模式，必须按 M1/M0 定义实现。参考 [E22-T 系列手册](https://www.ebyte.com/Uploadfiles/Files/2024-10-9/202410917046106.pdf) 与 [官方型号入口](https://www.ebyte.com/product/934.html)。

首版界面只改变 Channel；UART/空速/功率、地址/NETID、透明传输等采用经过验收的课堂预设，不开放通用寄存器编辑器。当前源码假定 UART/空速各 9600 bit/s，厂商资料列出的默认空速为 2.4 kbit/s，故启动必须读回核对，不能把源码常量当模块实际值。预设不符时显示 `Profile mismatch` 并保持实验停止，不能无声改写未知参数。

课堂预设首版以现有 USART3 9600 8N1、空速 9600 bit/s 和透明传输作为候选，模块地址/NETID、功率等需在实板准备时登记并固定；这不是已验证预设的声明。首次上电及热恢复先完成有界读取核验，未知状态不开放任何 LoRa 发送。`Apply` 只改变 CH，`Restore` 只恢复下述地址/信道；预设不符需先按实验准备流程在本机模块设置已冻结预设，再重新核验，首版不加入自动改写全部寄存器的维修功能。

信道候选为 23 / 26 / 29 / 32，默认候选 23。它们是软件及课堂验证候选，尚未实测确认相邻组隔离效果。`Apply` 针对当前本机模块执行保存写入，再独立读回；Channel 的权威当前值来自 E22 读回，上电重新读取。首版不在 MCU 再存一份可相互覆盖的信道值。参数未知时显示 `N/A`，不能用默认候选伪装实际值。

事务顺序：

1. App API 接受请求并给出请求号；CommTask 停止实验、暂停所有 LoRa 调度，等待 UART DMA 和 AUX 空闲，不能抢占仍在发送的帧。
2. 清理旧 RX/解析/生产队列的会话边界，进入配置模式；使用真实毫秒等待模式/AUX稳定，不阻塞 CommTask。
3. 读取寄存器并校验支持的课堂预设；保留非目标字段，不把只写/读回为零的字段当真实配置重写。Node ID 是 MAVLink 地址，与 E22 射频地址分开。
4. 持久化写目标 CH，等待明确响应，再独立读取 CH 核验；配置响应只进入配置解析器，不进入 MAVLink 或 CRC/丢帧统计。
5. 成功或失败均执行有界退出，恢复正常模式、UART/RX DMA 和新 MAVLink 会话；未能核验退出状态时保留 unavailable，不开放实验发送。
6. 显示读回实际值、失败原因与停止状态；学生再次 Start。超时、响应错位/截断、拔插、UART错误或掉电均不能生成成功事件。

建议事务总上限 3 s，细分 AUX/响应步骤各 500 ms，按真实 Driver 状态分步推进；这些为实施设计值，须通过模块实测调整。事务期间暂停普通 AUX 在位探测和健康重新初始化，避免预期的模式切换被当拔出；健康任务仍依据专用配置阶段与其期限判断异常，不能无界豁免。

`Restore` 明确作用于本机通信配置：Node ID 追加“恢复 UID 默认”记录并提示重启；Channel 走同一写入/读回事务恢复课堂默认候选。两项结果分别报告，不伪装跨 Flash/E22 的原子成功；不恢复旧发送状态。掉电后依据各自的有效记录/实际读回显示结果。

## 7. 活动对端、冲突与页面

保留 8 条轻量发现信息，只有学生选定的一个对端持有完整数据快照。发现表保存 Node ID、稳定产品身份、心跳时间、统计与冲突位；表满淘汰最旧未活动项，不自动切走学生的活动对端。选择对端时清空旧数据并等待新帧，不能把此前别人的数据挂到新身份下。上电不恢复对端选择。

新增的 BASIC_ID 帧先于“同本机 sysid 忽略”规则处理。相同 Node ID 但产品身份不同，记录 `ID conflict` 并禁止把两者的遥测混合；只能通过学生手动修改地址并重启消除。自身身份回环不算另一台设备。同一远端 Node ID 的多产品身份也采用相同规则。身份未知时明确显示未知，不声称已可靠区分；身份广播丢失和隐蔽节点可能使冲突检测不完整，丢帧/CRC 也不能自动被解释成干扰。

Comm 在一个二级工作区内切换三个视图：

| 视图 | 内容/操作 |
|---|---|
| Experiment | Data / Interval、Send / Start / Stop、当前状态、TX/RX/CRC/Drop/Loss est.、真实提交/完成计数 |
| Config | 当前与待生效 Node ID、编辑 Node ID、Channel 实际值/编辑值、Save / Apply / Restore、短失败结果 |
| Remote | 轻量发现项、学生选择、一个活动对端身份与数据、各域 RX age、STALE/N/A、接收统计；无远程控制按钮 |

三个视图通过一个循环视图按钮切换，Remote 用 Next / Select，Config 用现有滑块和 Save / Apply / Restore；共用页头/返回/最近 3 条日志。保持 48 标签、16 按钮及 4 滑块池容量，每个布局列出实际消耗并处理池耗尽；不为每个视图创建新的屏幕树。屏幕数据年龄是本机接收后经过的时间，不冒充两端时钟已同步的测量时延。

连接可见、丢失、恢复、冲突与发送/配置事件由实际通信状态转移生成，不依赖当前页面。沿用本机 32 条事件环和共享英文目录，只在尾部追加消息编号。退出 LoRa 旧日志 TX、重播和 RX 缓存路径，远端日志区域只显示本机观察事实；RPi 日志表布局保留。

## 8. 后续实施顺序与验收覆盖

设计评审后再编制实施计划。建议顺序为：T01 分离目录并建立实验会话 → T02 地址存储和启动身份 → T03 E22 参数事务与恢复 → T04 单活动快照/冲突识别/固定池页面 → 集成审查和验证。T03 与 T04 的范围已确认，硬件验收仍属于后续必需证据。

| 用例 | 覆盖与应有证据 |
|---|---|
| M4-C01 | 复位、切页、返回不自动 Start；保存/恢复必要参数后仍 STOPPED |
| M4-C02 | Send 单次、Start/Stop、运行中改参数、忙/缺测/过快拒绝；提交、DMA完成、对端RX分开 |
| M4-C03 | LoRa 只发基础帧和选定数据，无旧完整日志/重播/查看租约；抓帧核对 |
