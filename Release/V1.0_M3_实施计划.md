# V1-M3 页面与日志收敛实施计划

日期：2026-10-03

## 范围与基线

按用户“继续 M3”的授权推进已讨论的 U01—U03、N01 与 L01—L13/L15/L16。基线为 `bbf917f` 加当前未提交 M1/M2 改动，改动前源码副本位于 `build/v1_m3/baseline/`。沿用当前工作区，避免另起 checkout 丢失 M1/M2 的未提交依赖。没有合并、标签或发布操作。

本轮以现有 App API、Framework 日志环和 LVGL 为基础。M4 的信道/身份事务、LoRa 轻量发送和远端完整实验页，M5 的 Raw 捕获/曲线不提前扩展。

## 任务及接口

### 1. 事件生产和日志存储

- 本机状态观察移到 `Business_AcquisitionTask` 的 200 ms 服务，与 LCD 初始化、切页和冻结无关。初始化只在启动执行一次，显示恢复不得清空事件。
- 模块状态、GNSS fix、供电、活动告警分别记录。状态稳定确认采用 1500 ms，记录首次观察该候选的时间。启动检查集合明确列出，不写“全部自检”。告警读取失败保留 unavailable。
- 控制和姿态操作在所属状态机追加接受、开始、完成、拒绝、急停/中止事实。保护事件不去抖，区分闭锁与实际撤收。
- 保留 0—37 消息编号，尾部扩展枚举；短英文和严重度由共享目录定义。事件环固定容量，临界区仅复制与更新索引。
- 本机显示采用完整快照版本更新，消除普通序号大小比较。保留传输的序号回绕和启动会话语义，不改变 RPi 既有 TUNNEL 字节布局。

### 2. 页面与导航

- 删除品牌区。六个中文主入口固定本机，头部保留 Node、Uptime、告警和通信入口。
- 非自检页移除模块侧栏，重新分配数据/操作空间。自检区分启动检查和 Active Alarms。
- 增加可返回的二级诊断、事件历史和通信工作区；保留 M4 远端入口。复用对象，切页不触发实验/控制动作。
- 冻结只影响观察数据，日志、告警、急停和底层服务持续运行。
- D01—D03 用户已确认一起采用：最近 3 条日志/集中历史、静态短文案、合并诊断。记录于执行台账。

### 3. 集成与交付

- 同步 `Display`/`Business`/`Framework` 接口与 Keil 工程 source list，移除不再引用的 Logo 资源。
- 审查完整改动，执行 Keil Rebuild All 并记录实际错误/警告、ROM/RAM 与产物身份。
- 本轮未要求新增或运行 host 测试，不增加/执行测试套件；不能将构建结果称作软件回归通过。列出待执行的事件/导航边界用例与 800×480 实屏验收项。
- 实板、触摸响应、刷新负载及 M1/M2 合并验收由后续烧录取得证据，M3 在证据未齐时保持待验证。

## 资源与审查关注点

沿用 2 ms 显示单步预算；固定日志容量、固定控件工作区，不新增 RTOS 任务。重点审查：启动重入是否丢历史、环回绕/覆盖、请求与完成的区别、告警未知状态、冻结期间急停、远端选择影响范围、LVGL 页切换分配、UART 日志 payload 容量以及新增静态 SRAM。

任务进度、裁定、问题关闭与构建证据统一回写 `V1.0_执行台账.md`。
