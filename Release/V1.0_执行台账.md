## 2. 状态与关闭规则

| 状态 | 含义 |
|---|---|
| 未开始 | 本轮尚未开展该任务 |
| 进行中 | 已实际开展，记录当前工作和下一步 |
| 待验证 | 实现已具备，仍缺规定的构建/软件/实板证据 |
| 已通过 | 本任务全部完成条件及证据齐全 |
| 阻塞 | 写明缺少什么、由谁处理、解除条件，不能只写“待定” |
| 已延期 | 仅用于已作出范围决策的条件项；须注明影响与决定依据 |

- 阶段通过要求全部必需任务和对应问题关闭；“待验证”不能折算成通过。
- 范围决策使用“待确认 / 已采用 / 保留 / 已延期”，与实现状态分开。批准一项方案不等于该功能已实现。
- 每项领取时填写负责人；“未分配”是当前事实，不表示已由某人承担。
- 问题可“已修复关闭”或“退出路径关闭”。后者须有运行路径/构建配置和回归证据，不能用于绕过 P1。
- 问题处置状态依次记录为“未处理 / 处理中 / 待验证 / 已修复关闭或退出路径关闭”，并关联执行任务状态。
- 修改任务状态时同步更新证据、问题行和阶段摘要；不按文件数量、代码量或复用旧勾选计算完成率。
