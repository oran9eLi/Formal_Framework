## 内存预算

### 静态与固定地址区域

| 区域 | 基线 | M1 | 约束 |
|---|---:|---:|---|
| 主 SRAM 链接占用 | 130864 B | 118064 B | 总量 131072 B |
| 主 SRAM 链接余量 | 208 B | **13008 B** | 不是运行时剩余堆 |
| 绘图条带 | 800×32×2 = 51200 B | 800×24×2 = 38400 B | 释放 12800 B；480 行满屏条带从 15 次变为 20 次 |
| FreeRTOS 固定堆 | 40960 B | 40960 B | 已计入主 SRAM，峰值占用不得超过 30720 B |
| LVGL 固定堆 | 40960 B | 40960 B | **已使用 CCM**：`0x10000000` 到 `0x10009fff` |
| CCM 其余地址 | 24576 B | 24576 B | 未分配；固定 LVGL 地址不显示为 scatter 的独立执行区，不能当作整个 CCM 都空闲 |

M1 新增控制事务使用栈上小数组，没有新增全局持久状态；整体 RW+ZI 增量为 -12800 B。没有移动任何 DMA 缓冲。缩短绘图条带总像素量不变，但增加窗口设置次数；M4 实测切页扫描感与刷新时长。

### M2/M3 增量上限（计划预算，实施后以 map 与实测复核）

| 后续内容 | 主 SRAM 静态增量上限 | 其他约束 |
|---|---:|---|
| M2 校准请求/状态/结果及姿态状态 | 512 B | 复用估计任务，不新增任务 |
| M2 CSV 有效位/样本时间及格式化空间 | 1024 B | 尽量流式格式化，不再复制完整日志表 |
| M3 控件引用/页面状态 | 256 B | 复用现有对象，不增加全局大快照 |
| M3 状态文字缓存 | 1024 B | 静态字符串优先放 Flash |
| 合计 | **2816 B** | 用满后主 SRAM 仍余至少 10192 B，前提是没有其他增量 |

LVGL 新控件的运行时分配使用 CCM 堆，M3 新增峰值以 **4 KB** 为预算上限；需实测可用内存与碎片才能确认是否可容纳，不把整个 40 KB 当作空闲。增加控件前后记录最小空闲量；分配失败或碎片不足须改布局/复用对象。

### 任务栈与运行时堆

| 任务 | 配置 word | 配置 B | 合格最小剩余 word（严格 >25%，且 ≥100） |
|---|---:|---:|---:|
| sensor / estimator | 各 512 | 各 2048 | 各 129 |
| health / storage | 各 768 | 各 3072 | 各 193 |
| comm / control / biz_system / debug | 各 384 | 各 1536 | 各 100 |
| biz_acq | 512 | 2048 | 129 |
| biz_display | 1280 | 5120 | 321 |
| idle / timer | 128 / 256 | 512 / 1024 | 各 100 |

上述任务全部启用时栈配置合计 **25088 B**，来自 FreeRTOS 堆；TCB、队列及分配管理开销另计。若要满足 75% 堆峰值门槛，它们与其他启动分配合计只能再使用 **5632 B**。当前配置不能仅从链接 map 推导实际余量。

M2/M3 不增加任务或任务栈是本预算的前提；如必须增加，先更新预算并检查最终候选水位。当前 `DEBUG_STACK_MONITOR_ENABLE=0`，M4 采集最小剩余堆、各任务高水位和 LVGL 碎片；使用调试采集配置时必须记录与正式候选的差异，不能直接代替最终候选证据。
