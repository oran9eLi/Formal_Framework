## 1. 目标与执行原则

交付用于**传感器、通信、无桨电机实验的课堂实验台 v1.0**。更多可理解、可操作的交互优于更多自动化：学生能够主动调节、观察变化、理解结果，并清楚知道操作是否执行、为何被拒绝。

本文件管理发布批次和验收状态；问题证据见 [发布前审查](../Development_Guide/2026-09-15_v1.0发布前审查.md)。模块完成度继续以 [功能清单](../Development_Guide/07_移植进度与功能清单.md) 为事实来源。里程碑中的未勾选项均表示尚未完成，不代表能力已经交付。

- 按 M1 → M2 → M3 → M4 → M5 顺序执行；每批通过软件验收并记录遗留实板项后再开始下一批。
- 每批保留独立、可回退的提交和验证记录；不把一次性大改动作为交付单元。
- 单批中发现新的发布阻断问题，归入对应批次并补充复现与验收，不静默扩大功能范围。
- 固件源码、Keil 工程或外设配置变化后，执行 Keil 构建验证；最终候选必须 Rebuild All，达到 `0 Error(s), 0 Warning(s)`。
- 屏幕和业务层沿用现有数据接口；新增命令/校准状态通过所属模块发布，保持硬件资源单一所有者。
- 新增交互前先核对内存：审查基线主 SRAM 静态占用 130864/131072 字节，仅余 208 字节；M1/M2 修复后静态占用 118112 字节，链接余量 12960 字节；这不是运行时剩余堆。
- 急停、低压闭锁、看门狗等保护持续有效；教学交互用于操作与理解，不削弱保护。
