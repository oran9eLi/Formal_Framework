# V1-M6 候选准备与 M5 联合验收方案

日期：2026-10-14；版本：R2（M5已合入develop，后续问题单独修复分支）。进度以[执行台账](V1.0_执行台账.md)为准。

## 1. 目标与安排

按照用户安排，M5 功能验收与 M6 整机验收使用同一最终候选、在同一轮实板工作中完成。操作、报文、文件和资源证据可以共用，M5 与 M6 的任务仍分别判定；前序 M1—M4 的必需待验项并入本轮补验。M7 保留同候选至少 24 小时长稳。

M6 的交付是一台沿用现有硬件和连接方式的完整设备、可追溯候选、逐项验收结果和教师/学生使用展示流程。V1.0 功能以 M5 实现为基础，问题修复后重新核对候选。按产品设计代理已同步的用户决定，原R2硬件升级转V2，H743等V1完成后再评估。

用户确认当前交互和显示未发现问题，下一轮重点核对功能完整性与数据正确性。M5已合入develop并清理已合并分支，后续每个问题从最新develop单独新建codex/fix分支，修复/构建/必要验证后再合入；候选变化按本方案重验。详见[M5合入记录](V1.0_M5_合入记录.md)。

## 5. 候选与证据规则

每轮验收封面登记：候选编号、源码提交、HEX 完整 SHA-256、工程/Target/编译器/Pack、配置清单及校验和、板号、各模块型号/版本、接线、供电、Node ID、Channel、双方 E22 读回预设、PC 工具版本与串口、操作者和起止时间。

1. 正常功能、资源与组合场景使用同一生产 HEX；每个证据文件对应验收编号。
2. 需要侵入式故障钩子或配置变体时，建立独立验收构建，记录其改动与 SHA。该构建只证明对应机制，最终生产 HEX 仍须完成正常保护/资源/组合回归。
3. 表内每项记录实际结果和证据，再判通过/失败/未执行；缺硬件时登记依赖，原任务保持待验证。
4. 一项覆盖多个步骤时，全部步骤完成才能关闭；软件、实板、RF、资源和长稳证据分别登记。
5. M5/M6 共用结果可同时引用原 M5-Cxx、M4-Cxx、M1-Cxx 和 A/L 编号。唯一进度与问题关闭仍写入执行台账。

## 6. 资源和时序门限

| 项目 | 门限与记录方式 |
|---|---|
| 主 SRAM 静态 | 余量至少 4096 B；当前 4616 B，以同次 MAP 为准 |
| FreeRTOS heap_4 | 峰值严格低于 75%；记录最小空闲及峰值，当前配置 40 KiB |
| LVGL | 峰值严格低于 85%，最大连续空闲至少 4 KiB；记录碎片与极值，当前配置 40 KiB CCM |
| 任务栈 | 所有任务最低剩余严格大于配置的 25%，且不少于 100 word；1 word=4 B，记录各任务扫描年龄 |
| 完整显示服务 | 单步不超过 2000 us；保留 whole/render/flush 最近值、最大值和超限次数 |
| 触摸与切页 | 触点到 UI 接受操作不超过 100 ms；切页呈现不超过 300 ms，保留测量方法 |
| 刷新 | Raw/数据/曲线最多 5 Hz，汇总/资源最多 1 Hz；没有新测量时不伪造采样 |
| 页面循环 | 至少 200 次切页，固定控件数与资源无持续增长 |
| 通信与采集 | 记录 Comm 最大实际周期、IMU FIFO/生产 RX 丢弃、诊断覆盖；同负载开/关诊断不增加生产丢弃或保护延迟 |
| 正常保护 | 电源门限 9900/10100 mV、上限 13500 mV；年龄 2500 ms 有效、2501 ms 失效；预解锁 2500 ms |
| fatal 目标 | 入口后 1 ms 内四路不再输出正常油门脉冲；ESC 驱动切断和转子停转分别实测 |

500 ms 观察间隔在当前 200 ms 业务节拍上可能交替为 600/400 ms，应以真实时间戳验收。RPi 阻塞发送最长等待配置为 20 ms，Comm 名义 10 ms 周期不等于最大实际周期已经达标。电压变化至撤收还包含采样与滤波，另测异常样本发布至撤收，不能统一写成 20 ms。
