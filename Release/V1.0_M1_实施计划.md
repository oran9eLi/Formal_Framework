# V1-M1 保护与启动可靠 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 使本机供电保护独立于显示，致命异常及时撤收四路 PWM，并补齐 RTC、任务心跳和启动看门狗的保护缺口。

**Architecture:** Control 依据本机 Battery2 维护供电门禁；BSP 提供异常撤收与看门狗寄存器操作，Core 编排不可恢复停机。任务创建者配置已有的固定心跳槽位，Platform 完成快照检查和启动到运行的看门狗交接；不新增任务或设备注册表。

**Tech Stack:** STM32F407、HAL、FreeRTOS、Keil MDK-ARM / ARMCC 5.06 / C99；已有 host GCC 测试只用于软件逻辑。

**Spec:** [M1 准备与验收方案](V1.0_M1_准备与验收方案.md)。进度以 [V1.0 执行台账](V1.0_执行台账.md) 为准。

日期：2026-09-28；状态：用户已授权直接实施，五步软件、配置构建和最终软件验证已完成；实板步骤保持未勾选。证据见 [M1 验证记录](V1.0_M1_验证记录.md)。

## 1. 固定参数与接口边界

### 1.1 电源与 fatal

| 参数/动作 | 实施值 |
|---|---|
| 初始供电闭锁 | 1；Control 初始化/恢复时清目标、重置供电判断 |
| 低压闭锁 | `voltage_mv < 9900` |
| 闭锁后恢复 | 有效、新鲜且 `10100 <= voltage_mv <= 13500` |
| 已放行时的滞回区 | `9900 <= voltage_mv < 10100` 保持放行 |
| 不可信高值 | `voltage_mv > 13500` 闭锁 |
| 数据年龄 | `age <= 2500 ms` 新鲜；`2501 ms` 起闭锁；取本机 Battery2 的 sample_time_ms |
| 缺失/无效 | Copy 失败或 `header.valid == 0` 均闭锁；不借用主电池/远端状态 |
| 正常急停/供电闭锁 | 四路最小脉宽，清零目标并终止自动过程 |
| fatal | 禁止通道输出，PA6/PA7/PD12/PD13 固定低电平；不恢复、不喂狗 |
| 波形验收目标 | fatal 入口后 1 ms 内撤收；电调停止驱动与转子停转另测 |

供电恢复只解除限制；学生必须重新操作。关闭 Control 的构建保留明确的 NOT_READY 返回，不能出现假成功。

### 1.2 心跳和 watchdog

| 项目 | 实施值/行为 |
|---|---|
| 通用心跳期限 | `max(500 ms, 3 × period_ms, min_timeout_ms)`；不接受 0 周期或乘法溢出 |
| sensor / estimator / health / comm / control | 当前配置各 500 ms |
| biz_system / biz_acq | 当前配置分别 3000 / 600 ms |
| biz_display | 最低 2000 ms，包含一次有界初始化尝试和 500 ms 重试间隔；需实测最长间隔 |
| 必需集合 | 每个任务成功创建后、调度器启动前配置；交接时封存，未配置/空集合不视为健康 |
| 心跳时间 | 一次工作或有界初始化尝试完成后取当前毫秒；外设离线不等于任务卡死 |
| 启动 IWDG | PR code 6（256 分频），RLR 4095；从 main 开始的早期寄存器入口启用 |
| 首轮心跳窗口 | 调度器交接起 10000 ms；到期仍不健康则锁定启动失败，迟到心跳不能解除 |
| 运行 IWDG | 保持 PR code 4（64 分频）、RLR 1249；配置成功后才能声明已进入运行态 |
| 初始化喂狗 | 仅完成的有限进展点；进入任务交接后封闭此入口，不在等待循环喂狗 |
| 运行喂狗 | health 完成本轮工作、记录本轮心跳，再检查全部必需任务；首轮交接/运行刷新均要求毫秒时基较上次检查前进 |

依 [ST DS8626 表 35](https://www.st.com/resource/en/datasheet/stm32f407vg.pdf) 的 LSI 17/32/47 kHz 范围，按 `分频 × (RLR + 1) / fLSI` 计算：启动约 **22.31—61.68 s**，标称 32.768 s；运行约 **1.70—4.71 s**，标称 2.5 s。数值是数据手册条件下的计算范围，未测本机。配置和更新规则参见 [RM0090 IWDG 章节](https://www.st.com/resource/en/reference_manual/rm0090-stm32f407-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)。

首轮 10 s 是软件判定期限；硬件复位还受最后一次启动喂狗及 LSI 影响，不能承诺 10 s 复位。运行心跳超时也需另计 health 调度和 IWDG 剩余时间。暂时超时后若任务恢复健康，沿用现有健康门控语义允许再次喂狗；fatal、启动失败和窗口配置失败为不可恢复状态。

### 1.3 启动预算与覆盖界限

- 当前 HSE 等待配置 100 ms；RTC 的 LSE/LSI 就绪等待各 5000 ms，HAL RTC 初始化/同步等待各有 1000 ms 上限。按 RTC 单步不超过 12 s 加调度前开销留预算，低于启动最短 22.31 s；这不是实测耗时。
- BSP 各项初始化之间设置进展点；如果任何一项失败，不再通过后续进展点续命，最终进入统一错误处理。
- main 的 HAL/系统时钟、Debug、BSP、Platform、Framework 任务、Business 任务完成后可记录一次进展；最后交接点刷新一次并封存。
- 首轮窗口要求任务完成有界工作；显示失败返回并进入重试可上报进展，不要求传感器、存储或通信全部 ONLINE。
- 未证明所有驱动最长耗时；Task 5 必须量测默认/缺件冷启动与最慢合法路径。超预算时细分具体初始化步骤，不扩大运行心跳期限掩盖问题。
- 覆盖从 main 的 early-start 入口起，不宣称覆盖 C 运行库、启动汇编及此前的 SystemInit；软件不能保证主控供电丢失或芯片完全失效时的输出。
