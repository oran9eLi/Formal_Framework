## 一、实验背景

低空无人机正大量用于**火灾早期发现与巡检**：森林与林场巡护、仓储与堆场监控、光伏电站及大型活动安防。相比固定摄像头，无人机机动范围大、视角灵活，能在火情早期发现火光与烟雾并快速定位上报，为扑救争取时间。

真实任务中，无人机并不靠单一传感器判火，而是一条链路：**摄像头远距离发现火光/烟雾（视觉初判）→ 抵近目标 → 温湿压等传感器二次确认 → 记录坐标并上报**。任何单一手段都会犯错——只看画面颜色，会把夕阳、红叶、红色物体误当成火；只看温度，手掌、暖气、阳光也会让读数升高。本实验就复刻这条链路里最核心的**感知与判决**环节，让你亲手看到"单一传感器为什么会误报"以及"融合如何把误报压下去"。

> **注意**：本实验默认已完成前置实验《连接你的树莓派》，能通过屏幕/VNC 进入树莓派桌面并打开终端。

## 二、实验目标

通过本实验，理解 RGB 摄像头在火灾识别中"能做什么、不能做什么"，理解温湿压传感器在火灾场景里是**近场佐证**而非远程探火，并理解多模态融合为何能降低误报；掌握在树莓派 5 上运行教师提供的识别与融合脚本、调节判决阈值、并定量评估**误报率与漏报率**的操作技能；养成"**不轻信任何单一传感器、用多源证据交叉验证**"的工程习惯。

## 四、实验原理

### 4.1 多模态感知与各自的能力边界

**为什么要融合？** 火灾在不同物理量上留下不同"痕迹"：可见的火光与烟雾（图像）、局部空气的温度骤升与湿度骤降（温湿压）。每种传感器只能捕捉其中一类痕迹，且都有各自会犯的错误。把互相独立的证据放在一起交叉验证，才能既少漏报、又少误报。

**视觉通道（RGB 摄像头）——主探测器，但会误报**
- 能看到：明火的颜色（红-橙-黄，高亮度）、火焰的闪烁/摇曳、烟雾的灰白扩散与纹理。
- 看不到 / 会犯错：阴燃（无明火）看不见；被遮挡、夜间/逆光效果差；**夕阳、红叶、红色衣物、暖光灯**等"像火的颜色"会被误判为火（误报）；远处小目标易漏检。
- 脚本输出：每帧给出"疑似火/烟 + 置信度（0～1）"。

**物理通道（BME280 温湿压）——近场佐证，不是远程探火**
- 测的是**传感器所在那口空气**。只有当无人机**抵近、飞进火场热浪**时，温度才会骤升、相对湿度才会骤降；远处的火它感知不到。
- 因此它的角色是"**抵近确认**"，用来给视觉初判提供第二重证据，而不是远距离预警。
- 本实验用**手指接触**制造温度快速上升，脚本按**温升速率（℃/s）**判"热异常"。

> **诚实边界（务必牢记）**
> 1. **手指模拟的是"温度骤升"的形状（突变、上升速率），不是火灾的量级。** 手指让读数从室温升到约 30～33 ℃，真火是几十到几百 ℃。我们用它训练"识别快速上升"这一逻辑，不是把手指当作火。
> 2. **温湿压是近场佐证，不是远程预警。**
> 3. **RGB 摄像头不是热成像**：阴燃、遮挡、夜间都可能看不见。
> 4. 本实验的视觉输入是**数据回放**、温度是**手指实时信号**，二者不是同一团真火，属于"**硬件在环 + 数据回放**"的融合逻辑验证。
> 5. 本实验结论**不可**外推为"该套件可直接用于实战消防"。真机还需热成像、气体/烟雾传感器与自动上报（见附录 9.2）。

### 4.2 流程逻辑

```
   图像帧（数据集回放）            BME280 温湿压（手指制造温升）
         │                                 │
   视觉识别脚本                        温升速率判据
   （疑似火 + 置信度）                （是否“热异常”）
         │                                 │
         └──────────►  融合判决  ◄──────────┘
                          │
             两路证据都成立 → 报警（高置信）
             仅一路成立    → 不报警 / 仅提示（降误报）
```

融合判决规则（概念级，与阈值挂钩）：**视觉置信度 ≥ 阈值 且 判定热异常 → 报警**；只满足一路则不报警。核心演示：夕阳等负样本会让视觉单独误报，但它**不会**伴随温升，融合据此把误报压制掉。

## 五、实验步骤

> 以下命令为**示例**，以教师现场提供的脚本/参数为准。学生只需在终端 `~/fire_lab` 目录下按提示运行，无需修改代码。

**步骤 1：设备核验与进入实验环境**
开机进入树莓派桌面，确认摄像头预览出图、实验箱温湿压数据正常刷新。打开终端：
```
cd ~/fire_lab
ls              # 确认 datasets/ 与脚本存在
```

**步骤 2：视觉通道单独测试（看它的检出与误报）**
先跑正样本，再跑干扰负样本，观察脚本对"火"的判定与置信度：
```
python3 run_visual.py --set fire      # 火焰/烟雾 正样本
python3 run_visual.py --set sunset    # 夕阳/红色物体 干扰负样本
```
记录：正样本是否检出、负样本是否被**误报**为火，填入表 6.1-1。

**步骤 3：物理通道单独测试（手指制造温升，定"热异常"判据）**
运行温度监测脚本，观察实时温度曲线：
```
python3 run_thermal.py
```
先静置记录基线温度与正常波动；再用手指**轻触**传感器，观察温度快速上升，读取最大**上升速率（℃/s）**；松手观察回落。对照做一次"仅呵气"，体会不同刺激的差别。据此确定"热异常"上升速率阈值，填入表 6.1-2。

**步骤 4：融合测试（三种情形对照）**
分别制造三种情形，观察融合判决输出（视觉/热/融合三盏"判决灯"）：
```
python3 run_fusion.py --visual fire   --thermal live   # C：视觉+热 同时（放火焰集 + 手指）
python3 run_fusion.py --visual sunset --thermal live   # A：仅视觉误报源（放夕阳集，不碰传感器）
python3 run_fusion.py --visual normal --thermal live   # B：仅热（普通画面 + 手指）
```
记录每种情形下三路输出与融合是否报警、判决是否正确，填入表 6.1-3。**重点体会**：夕阳负样本让视觉单独误报，但融合因无温升而不报警。

**步骤 5：阈值调优（体会漏报↔误报的权衡）**
调整视觉置信度阈值与温升速率阈值，重复关键情形，观察误报与漏报如何此消彼长：
```
python3 run_fusion.py --visual sunset --thermal live --vis-thresh 0.5
python3 run_fusion.py --visual sunset --thermal live --vis-thresh 0.8
```
把不同阈值下的误报/漏报次数填入表 6.1-4。（结论：阈值越松漏报少但误报多，越紧反之——这就是工程上要权衡的点。）

**步骤 6：局限与故障情景分析（分组讨论）**
结合原理，讨论以下情景该套系统会怎样、为什么、真机怎么补：阴燃初期无明火；火被烟/障碍物遮挡；夜间或逆光；烟被大风吹散；把暖气口/阳光斑当成火。

**步骤 7：实验收尾与设备归位**
关闭脚本，保存记录与截图，关机后整理器材归位。

## 九、附录

### 9.1 术语速查
| 术语 | 含义 |
|---|---|
| 多模态融合 | 综合两类及以上不同传感器的证据交叉验证，提升判决可靠性 |
| 误报率（FP） | 把"非火"误判为"火"的比例 |
| 漏报率（FN） | 把"火"漏判为"非火"的比例 |
| 上升速率 | 单位时间温度变化量（℃/s），用于识别"突变" |
| 置信度 | 识别脚本对"疑似火"判断的把握程度（0～1） |
| 近场佐证 | 传感器只在靠近目标时才响应，用作二次确认而非远程预警 |
| RGB vs 热成像 | RGB 只看可见光颜色；热成像直接测温、能发现阴燃与遮挡后热源 |
| 阴燃 | 无明火的缓慢燃烧，RGB 摄像头难以发现 |

### 9.2 与自动化 / 工程实现的对照
本实验是真实系统"感知与判决"环节的**教学简化版**。工程实机通常还会：
- 采用**可见光 + 热成像双光吊舱**，用热成像直接测温、发现阴燃与遮挡后热源；
- 增加**气体/烟雾传感器**辅助判断；
- 在机载边缘算力上跑更强的**AI 识别模型**，并做多帧时序确认降误报；
- 报警时**自动记录 GPS 坐标并回传地面站**，联动指挥调度。
理解本实验的"单模态会误报、融合降误报"，正是理解这些工程手段为何必要的基础。
